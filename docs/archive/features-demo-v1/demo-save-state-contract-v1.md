# Demo Save State Contract V1

更新时间：2026-06-16

## 用途

本文定义首版 Demo 主路径存档状态契约第一包。它承接已落地的主线、区域、战斗、工业、资源链和 UI 读法，确认 Demo 关键状态能保存、读取、复测和校验。

本专题服务 [Demo Definition V1](demo-definition-v1.md) 中「存档 / 状态」和「自动检查」规格，并支撑「资源 / 生产链」「装备 / 模块」「战斗压力」「区域 / 场景」在读档后的连续性。

## 玩家价值

- 玩家读档后仍在正确区域，角色位置、装备、快捷补给和库存不会错位。
- 基地建筑状态、最近加工配方和整备设施状态能继续支撑下一步行动。
- 核心稳定站前的任务、区域解锁、阶段守卫和核心整备资源不会读档后丢失。
- 存档校验继续拒绝显示名、场景节点路径或错配实例作为真相源。

## 与整体规划的关系

- 服务长期核心：“基地服务冒险，冒险反哺基地”。
- 承接 `Demo Resource Chain State V1`，但不继续加厚资源链文案。
- 承接主线完成感、角色成长与战斗、出发整备和核心稳定站状态，不新增任务链或装备栏。
- 复用 `WorldState`、`CharacterState`、`InventoryState`、`QuestState`、`SaveService` 和 `SaveContentValidator`，不新增存档 schema 字段。

## 当前已有基础

- `SaveService` 已支持默认槽位、命名槽位、备份轮转、旧存档迁移和内容校验。
- `SaveContentValidator` 已覆盖定义 ID、区域、任务关系、地图对象、敌人、建筑、库存和跨块区域一致性。
- `DevelopmentBaselineBuilder` 能生成 S21 核心稳定站开放前置状态。
- 资源链状态 formatter 已能在读档后根据库存和任务状态判断核心整备进度。

## 本轮范围

- 建立首版 Demo 主路径存档契约文档，明确覆盖世界、角色、库存、建筑、任务、区域、敌人和关键整备 / 资源链状态。
- 新增独立 Godot runtime 检查，用真实 `SaveService.save_game_for_slot` / `load_game_for_slot` 做核心稳定站前切面的保存读取。
- 新增静态检查，确保专题、运行时检查和 `check-client` 入口保持接线。
- 校验显示名区域和错配敌人来源会被 `SaveContentValidator` 拒绝。

## 当前不做

- 不新增资源、配方、区域、任务链、完整背包、完整装备栏或自动化物流。
- 不新增存档 schema 字段、不迁移稳定 ID、不做全量旧档迁移专题。
- 不继续加厚资源链状态、非核心场景身份、功能 / 过渡路线支撑、战斗、防护、工具校准、工业主干或主线完成感同类读法点。
- 不切到试玩准备、集中修 bug、纯基线复核或发布准备。

## 玩家操作路径

1. 玩家从 S21 基线进入核心稳定站前，读档后仍保留世界与角色在核心稳定站的区域状态。
2. 玩家已完成核心稳定站进入和核心稳压缓冲包准备，读档后继续面对阶段守卫目标。
3. 玩家背包保留核心稳压缓冲包、修复凝胶、抗污染药剂、基础零件和污染浆液，资源链仍能读出核心整备完成。
4. 基础反应器保留最近核心稳压缓冲包加工记录，污染过滤器、基础储存箱和出发整备台仍是可校验建筑状态。
5. 阶段守卫保留生命、区域、是否击败和核心缓冲包使用状态。

## 运行时、存档与数据边界

- 真相源必须是稳定 ID：`region.*`、`quest.*`、`item.*`、`fluid.*`、`building.*`、`structure.*`、`map_object_instance.*`、`enemy_instance.*`。
- 存档块继续由 `world` 和 `character` 承载；世界侧包含区域、天气、地图对象、敌人、建筑、基地行动和任务状态。
- 角色侧包含稳定角色 ID、位置、装备、快捷槽和库存；库存继续区分 `items`、`equipment` 与 `fluids`。
- 本轮只验证主路径契约，不把检查扩展为完整背包、完整装备栏或自动化物流状态机。

## HUD / 场景 / 对象反馈

- 本轮不新增 HUD 或场景读法；读档后通过既有资源链 formatter 校验核心整备状态仍可读。
- 出发整备台对象状态以 `module_calibrated` 和 `core_archive_maintained` 等既有字段保存。
- 核心稳定站对象与阶段守卫使用既有地图对象和敌人实例 ID。

## 验收条件

- 主路径切面保存后可从命名槽位读取，世界、角色、库存、建筑、任务、区域、敌人和关键整备 / 资源链状态保持一致。
- 存档校验拒绝显示名区域和敌人实例来源错配。
- 新增检查独立成专项文件，不继续推高 `vertical_slice_flow_check.gd`、`vertical_slice_map.gd` 或 HUD 大文件。
- `check-client` 默认静态检查和 Godot runtime 检查都能找到本专题接线。

## 落地状态

- 2026-06-16 第一包已落地：新增 `demo_save_state_contract_check.gd` 和静态接线检查，覆盖核心稳定站前主路径存档契约。

## 验证计划

- 客户端默认检查：`sh ./scripts/check-client.sh`。
- Godot 运行时检查：`sh ./scripts/check-client.sh --with-godot`。
- 文档检查：`./scripts/check-docs.sh`、`./scripts/check-text-files.sh`、`git diff --check`。

## 风险与后续决策

- 风险：存档契约容易扩大成全量旧档迁移；本轮只确认首版 Demo 主路径切面。
- 风险：检查若直接手写无效状态会制造假安全感；本轮从 S21 开发基线生成真实前置链。
- 后续若出现坏档或主线卡死，优先补内容校验或主路径 runtime 检查，不用长文案掩盖状态缺口。
