# Demo Mainline Completion V1

更新时间：2026-06-15

## 用途

本专题定义首版 Demo 主线收束与完成感第一包。它把“核心稳定站写入完成”从分散的任务完成、复测和下一趟外勤提示，收束成玩家能在 HUD、地图、核心对象、前哨核心和结果日志中一致读到的 Demo 终点。

## 玩家价值

玩家完成核心稳定站写入后，应明确知道：

- 这一步就是首版 Demo 主线终点，不只是又一个回访状态。
- 核心稳定站已接管第一条稳定通道，前哨获得了可归档的主线成果。
- 战斗、缓存、写入、补给和整备收益已经串成一次完整外勤回路。
- 回前哨整理是完成后的归档与复测价值，不是开启新章节或新任务链。

## 与整体规划的关系

覆盖 [Demo Definition V1](demo-definition-v1.md) 中这些规格项：

- 主线结构：从新档到核心稳定站完成反馈的一条连续主线。
- UI / HUD：关键操作面读懂目标、状态和完成反馈。
- 存档 / 状态：核心写入完成状态可保存、读取和复测。
- 自动检查：完成态由任务状态驱动，并覆盖真实玩家完成路径的关键判断。

本专题承接角色成长、工业主干、核心场景识别已完成的第一轮支撑，不继续加厚战术扫描、工业主干、污染边界、遗迹外圈或核心场景同一读法点。

## 当前已有基础

- `quest.write_demo_stabilization_core` 已是核心稳定站终点任务，完成后无后续必需任务。
- `QuestCompletionApplier` 已能把该任务标记为 `Demo 完成` 并写入完成日志。
- `CoreStabilizationPressureFormatter` 与 `CoreGuardAftermathFormatter` 已提供核心站复测、守卫缓存、写入材料和下一趟外勤提示。
- HUD、地图路线、对象提示、前哨核心提示和结果日志已有 formatter 接入口。

## 本轮范围

- 新增一个主线完成读法 formatter，统一判断 `quest.write_demo_stabilization_core` 完成态。
- HUD 目标与基地摘要读出“首版 Demo 主线已完成”。
- 地图路线提示读出核心稳定站已接管，并引导回前哨整理归档。
- 核心稳定站对象提示读出 Demo 终点、稳定通道接管和回前哨整理。
- 前哨核心提示读出核心写入归档与整备复测价值。
- 结果日志复用同一完成说明，不让日志、HUD 和对象提示互相分叉。
- 新增专项检查覆盖 HUD、地图、对象提示、前哨提示、结果日志和状态来源。

## 当前不做

- 不新增第 13 区域、第二章节、第二星球或后续主线任务链。
- 不做完整科技树、科技 UI、完整装备栏、完整 `loadout` 或新资源体系。
- 不扩展核心站完成态同构回访口袋，不新增复杂过场或发布 / 试玩准备流程。
- 不把这包扩成集中修 bug、全量 polish 或基线复核阶段。

## 玩家操作路径

1. 玩家推进到核心稳定站，完成守卫战和核心写入材料准备。
2. 玩家与核心稳定站交互，完成 `quest.write_demo_stabilization_core`。
3. 完成面板和结果日志显示 Demo 主线完成。
4. HUD 目标切到“首版 Demo 主线已完成”，基地摘要说明回前哨整理价值。
5. 地图路线与核心稳定站对象提示说明核心站已接管第一条稳定通道。
6. 玩家回到前哨时，前哨核心提示读出写入归档、补给和整备复测价值。

## 运行时、存档与数据边界

- 真相源继续是 `world_state.quest_state.has_completed_quest("quest.write_demo_stabilization_core")`。
- 不新增任务 ID、资源 ID、区域 ID 或长期成长字段。
- 完成态 formatter 只读取既有任务、角色、库存、核心站对象和整备状态。
- 旧存档只要已有核心写入任务完成记录，就应自动读出完成态。

## HUD / 场景 / 对象反馈

- HUD 目标：显示首版 Demo 主线完成，而不是继续暗示必需后续任务。
- HUD 基地摘要：用一行说明核心站接管与回前哨整理。
- 地图路线：根据当前位置给出回前哨整理或前哨归档提示。
- 核心稳定站对象：状态与下一步都指向 Demo 终点完成和归档回前哨。
- 前哨核心：在已有出发整备、工业主干和场景识别提示之外，补一行主线完成归档。
- 结果日志：完成任务时记录同一条主线完成说明。

## 验收条件

- 完成 `quest.write_demo_stabilization_core` 后，HUD、地图、核心对象、前哨核心和结果日志均能读出 Demo 主线完成。
- 完成态由任务完成状态驱动，不依赖显示名、场景节点路径或临时变量。
- 不新增当前冻结事项，也不遮蔽核心站写入前的原有任务提示。
- 默认客户端检查和 Godot 专项检查通过。

## 验证计划

- 新增 `demo_mainline_completion_check.gd`，覆盖完成态 HUD、地图、对象提示、前哨核心和完成日志。
- 接入 `check-client` 静态入口，确保新 formatter、检查脚本和入口脚本同时存在。
- 按改动范围执行 `sh ./scripts/check-client.sh`、必要的 `--with-godot`、文档检查、文本检查和 `git diff --check`。

## 风险与后续决策

- 风险：完成态文案如果过长，会挤压 HUD 行数；本轮 HUD 摘要控制为一行。
- 风险：已有“下一趟外勤”提示仍有价值，但不能盖过 Demo 终点判断；本轮只在完成态入口统一优先级。
- 后续若继续做角色套件，应切到第二个动作或装备状态专题，而不是继续堆主线完成文案。
