# Demo Core Scene Playable Space V1

更新时间：2026-06-19

## 用途

本文定义首版 Demo 可玩内容实质补强中的核心场景空间第一包。它把基地、晶体矿脉、污染边界和核心稳定站从“有场景节点和提示”推进到可验证的场地角色：地表、路线、对象锚点、承压区和回基地 / 回收口袋。

本专题承接 [Demo Playable Content Substance V1](demo-playable-content-substance-v1.md)，不代表首版 Demo 进入验收或试玩准备。

## 玩家价值

玩家在四个核心区移动和战斗时，应能通过场地本身判断：

- 哪里是主要可走地表和路线。
- 哪些对象属于加工、采集、过滤、补给或核心写入锚点。
- 哪些区域表达敌压、污染或终点守卫承压。
- 外勤结果应该回到哪个基地或终点前处理口袋。

这包不依赖日志长文案或检查结论替代真实场景表现。

## 与整体规划的关系

- 覆盖 `Demo Definition V1` 的「核心场景完成度」和「初步美术」规格。
- 承接 `Demo Prototype Visual Pass V1` 已完成的视觉优先级与目标导引，但不继续堆同类 cue、箭头或常驻标签。
- 补足 `Demo Playable Content Substance V1` 中“真实场景、初步美术识别和对象落点”的玩家可见缺口。

## 当前已有基础

- `VerticalSliceMap.tscn` 已有基地、晶体、污染边界和核心稳定站的地表、路线、资源、危险和设备色块。
- `SceneArtFoundationFormatter` 和 `PlayableSceneCompositionFormatter` 已能说明场景身份和构成。
- `PrototypeVisualPriorityLayer` 和 `CurrentObjectiveGuidanceLayer` 已覆盖视觉优先级和当前目标导引。

不足在于核心四区的场地节点还没有统一的空间角色契约，后续容易退化成“有色块但读不出哪个区域承担什么职责”。

## 本轮范围

- 新增 `DemoCoreSceneSpaceProfile`，定义四个核心区的地表、路线、对象锚点、承压区和回基地 / 回收口袋。
- 新增 `DemoCoreSceneSpaceLayer`，在地图运行时给既有场景节点应用空间角色、材质标签和低调区域边框。
- 新增 `demo_core_scene_playable_space_check.gd`，验证四个核心区覆盖、场景层接入、对象 / 敌人落点和 12 区域封顶。
- 接入 `check-client` 默认静态检查和 Godot runtime 检查。

## 当前不做

- 不新增第 13 区域，不新增第二星球、第二章节或支线任务网。
- 不重画完整地图，不做最终美术包、大规模换皮或过场动画。
- 不新增资源、配方、敌人类型、任务链、完整背包、完整装备栏、死亡系统或结算页。
- 不继续用地图提示、目标箭头或长文案替代场景空间表现。

## 玩家操作路径

```text
基地恢复 -> 读出设备垫和出发口 -> 晶体矿脉采集 / 战斗 -> 污染边界过滤与承压 -> 核心稳定站补给 / 守卫 / 写入
```

本包改善的是上述路径中的场景现场读法：玩家看到的不只是目标文本，而是能从地表和对象落点判断当前区域的职责。

## 运行时、存档与数据边界

- 只复用既有场景节点和既有对象 / 敌人实例。
- 不新增长期存档字段，不改变任务、库存、建筑或敌人数据结构。
- 运行时 metadata 只服务场景表现和专项检查，不作为存档真相源。

## HUD / 场景 / 对象反馈

- 场景层通过既有 `ColorRect` 的颜色强化和区域边框表达空间角色。
- 对象锚点覆盖前哨核心、基础反应器、整备台、晶簇、残骸、过滤器、污染沉积、核心写入和终点前缓存。
- 承压区覆盖晶体守卫、污染危险场、污染门前压力、核心守卫场和后勤复测压力点。
- HUD 不新增长说明，后续仍由地图和对象提示读取当前目标、缺料、收益和战斗状态。

## 验收条件

- 四个核心区均有地表、路线、对象锚点、承压区和回基地 / 回收口袋角色。
- `DemoCoreSceneSpaceLayer` 在 `VerticalSliceMap.tscn` 中运行并应用四区 profile。
- 代表对象和敌人中心点落在对应区域的空间角色节点内。
- 自动检查确认仍为 12 个既有区域，不新增第 13 区域。
- 本包完成后仍不能直接判定 Demo 达到可试玩候选质量。

## 验证计划

- `sh ./scripts/check-client.sh --with-godot`
- `sh ./scripts/check-docs.sh`
- `sh ./scripts/check-text-files.sh`
- `git diff --check`

## 风险与后续决策

- 风险：只强化已有色块仍可能不足以形成完整场景美术，需要后续继续补对象尺寸、设备造型或任务节奏。
- 后续若仍读不懂四个核心区，应优先检查场景构图、对象体量和玩家实际路线，不继续堆同类提示。
