# Demo Character Kit V1

更新时间：2026-06-15

## 用途

本文是「首版 Demo 体验主干建设：角色成长与战斗第一版」下的可执行细专题，定义首个角色工具动作的范围、边界、状态和验收。

本专题已落地第一项主动工具动作：`C` 战术扫描。

## 玩家价值

玩家建成出发整备台后，基础多用工具不再只承担采集、清理和普通攻击，还能主动扫描近身敌人或污染采集点。扫描会标记目标，并让下一次反击或污染采集承压下降。

这个动作证明“基地整备改变外勤处理危险的方式”，但不提前建设完整技能树、装备栏或长期 Build。

## 与整体规划的关系

- 覆盖 [Demo Definition V1](demo-definition-v1.md) 中「技能 / 操作」和「角色成长」规格。
- 服务 [Demo Combat Progression V1](demo-combat-progression-v1.md) 的角色成长与战斗差异目标。
- 复用 `equipment.basic_tool`、`building.field_outfitting_station`、基础过滤模块和既有敌人 / 污染采集点。
- 不新增区域、任务链、资源种类、敌人类型或完整装备系统。

## 当前已有基础

- 输入层已有交互、攻击、配方切换、模块切换和快捷栏。
- 战斗承压由 `EnemyCounterattackRuntime` 统一计算。
- 污染采集承压由 `GatherSystem` 统一计算。
- 出发整备台状态由 `FieldOutfittingRuntime` 和地图对象状态保存。
- HUD 已能显示角色状态、整备收益、快捷栏和模块状态。

## 本轮范围

- 新增 `tactical_scan` 输入动作，默认按键为 `C`。
- 新增 `CharacterKitRuntime`，统一处理战术扫描解锁、目标标记、标记消费、承压倍率和 HUD 状态文案。
- 玩家按 `C` 时优先扫描近身可攻击敌人；无敌人时扫描当前可交互的污染采集点。
- 战术扫描需要基础多用工具和已建成出发整备台。
- 被扫描敌人的下一次反击承压下降；被扫描污染采集点的下一次采集污染压力下降。
- 扫描标记和已消费状态写入敌人或地图对象运行态，并纳入存档校验。
- HUD 显示工具动作可用状态；日志显示扫描、消费和收益反馈。

## 当前不做

- 不做完整技能树、职业、等级曲线或多角色队伍。
- 不做完整装备栏、完整 `loadout`、随机词条或武器切换。
- 不新增扫描专属资源、冷却 UI、任务链或教程任务。
- 不扩前线行动台、候选、高压窗口或 `base_action_state`。
- 不把战术扫描继续扩成多个元素分支；后续若要新增第二个主动动作，应先确认新的执行细专题或本专题子范围。

## 玩家操作路径

1. 玩家推进到基地可建成出发整备台。
2. HUD 的角色状态显示 `工具动作：C 战术扫描可用`。
3. 玩家靠近敌人按 `C`，敌人进入扫描锁定；下一次敌人反击时日志说明战术扫描已消耗，生命或防护承压下降。
4. 玩家靠近污染采集点按 `C`，采集点进入扫描标记；下一次采集时日志说明战术扫描已消耗，污染压力下降。
5. 保存 / 读取后，未消费的扫描标记和已消费状态仍能通过存档校验。

## 运行时、存档与数据边界

- `CharacterKitRuntime` 是本专题规则入口；地图只负责选择近身敌人或当前交互对象。
- `EnemyCounterattackRuntime` 只消费敌人扫描标记并应用承压倍率。
- `GatherSystem` 只消费地图对象扫描标记并应用污染采集倍率。
- `SaveContentValidator` 允许 `tactical_scan_marked` 和 `tactical_scan_consumed` 出现在敌人和地图对象运行态。
- `equipment.basic_tool` 增加 `effect.tactical_scan_basic`，用于表达基础多用工具具备该动作。

## HUD / 场景 / 对象反馈

- HUD 角色状态显示工具动作是否等待整备台、是否已接入过滤模块或校准收益。
- 战斗日志显示扫描完成、扫描未命中、扫描已消费和承压收益。
- 敌人标签在扫描后显示“扫描锁定”。
- 污染采集结果会补充战术扫描已消费的承压反馈。

## 验收条件

- 玩家能通过真实输入 `C` 主动触发战术扫描。
- 未建成出发整备台时，扫描给出明确失败原因。
- 扫描敌人后，下一次反击损耗低于未扫描状态，并消费标记。
- 扫描污染采集点后，下一次采集污染压力低于未扫描状态，并消费标记。
- HUD、日志、敌人标签和存档校验都能读出该动作状态。
- 未引入本专题“当前不做”中的系统扩张。

## 验证计划

- 客户端默认检查：`sh ./scripts/check-client.sh`。
- Godot 运行时检查：`sh ./scripts/check-client.sh --with-godot`。
- 文档检查：`./scripts/check-docs.sh`、`./scripts/check-text-files.sh`、`git diff --check`。

## 风险与后续决策

- 战术扫描是首个主动工具动作，只证明角色套件方向成立；后续不应围绕同一个动作继续堆同类倍率。
- 若下一步继续做角色套件，应选择另一个清晰玩家动作或装备状态，并保持与基地整备、HUD、存档和自动检查绑定。
- 若下一步转向工业基建、场景完成度或主线收束，应新建对应执行细专题，不从本专题直接派生。
