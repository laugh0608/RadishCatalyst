# Demo Functional Scene Gameplay Density V1

更新时间：2026-06-19

## 用途

本文定义首版 Demo 功能 / 过渡场景玩法密度第一版。它承接已完成的功能场景玩法第一包，不继续给 8 个非核心区域平均追加路线说明，而是选择锁相框架和锚定桥两条代表路径，检查玩家是否能在同一区域内连续读出“清障 / 回收 / 勘验 -> 回基地加工 -> 下一段路线”的小循环。

本专题覆盖 [Demo Definition V1](demo-definition-v1.md) 的「功能 / 过渡场景」「UI / HUD」「存档 / 状态」和「自动检查」规格。

## 玩家价值

玩家进入功能 / 过渡区时，不应只看到区域标签或单个对象提示，还应能确认：

1. 锁相框架不是一个孤立断面，而是侧路清理、边缕残条回收和框架勘验组成的小循环。
2. 锚定桥不是单个终点提示，而是锚索结点、锚索残股回收和桥体断面勘验组成的小循环。
3. 每个小循环都能把现场结果带回基地处理，并自然接向下一段路线或核心稳定工程。

## 与整体规划的关系

- 继续服务“基地服务冒险，冒险反哺基地”：现场处理必须回到基地加工或整备，而不是停在对象文案。
- 承接 [Demo Functional Scene Gameplay V1](demo-functional-scene-gameplay-v1.md) 的现场阶段读法，但本轮强调同一区域内的连续操作密度。
- 复用既有任务、对象、资源、状态和存档字段，不新增资源、配方、区域、任务链、敌人类型、完整背包、完整装备栏或自动化物流。

## 当前已有基础

- 功能 / 过渡路线支撑、非核心场景识别、可玩场景构成和功能场景玩法第一包均已落地。
- 锁相框架已有 `phase_well_frame_route_blocker`、`selvedge_strip_cluster` 和 `phase_well_frame`。
- 锚定桥已有 `phase_well_tether_knot_node`、`tether_fiber_cluster` 和 `phase_well_tether`。
- `GatherSystem`、`PhaseWellFrontierRuntime`、`HudStatusPresenter` 和 `InteractionPromptFormatter` 已能承载窄职责 formatter。

## 本轮范围

- 新增 `DemoFunctionalSceneGameplayDensityFormatter`，只覆盖锁相框架和锚定桥两条代表小循环。
- HUD 在已有现场玩法摘要后追加小循环步骤进度和下一步，不替换原有路线 / 场景 / 现场阶段读法。
- 对象提示追加玩法密度行，让玩家知道当前对象处于小循环的哪一步。
- 交互结果追加密度回执，让清障、回收和断面勘验都能指向下一步和回基地理由。
- 新增 `demo_functional_scene_gameplay_density_check.gd` 与静态接线检查，并接入默认 `check-client` 和 Godot runtime 检查入口。

## 当前不做

- 不新增第 13 区域，不平均扩厚 8 个非核心区。
- 不新增资源、配方、任务链、敌人类型、完整背包、完整装备栏或自动化物流。
- 不继续加厚路线支撑、场景身份、功能场景玩法第一包、外勤回基地收益兑现或补给节奏同类内容。
- 不改 `vertical_slice_map.gd`、`prototype_hud.gd` 或 `interaction_prompt_formatter.gd` 的大结构；必要接线保持在少量调用点。

## 玩家操作路径

1. 玩家进入锁相框架，HUD 显示锁相框架小循环和当前步骤进度。
2. 玩家清开锁相侧路后，结果提示说明侧路已打开，下一步回收边缕残条。
3. 玩家回收边缕残条后，结果提示说明回收已推进，仍需完成材料回收再回基地整理。
4. 玩家带锁相键栓勘验框架断面后，结果提示说明锚定桥前置收益已形成。
5. 锚定桥沿相同口径读出结点确认、锚索残股回收和桥体断面勘验，并把结果回接核心稳定工程。

## 运行时、存档与数据边界

- 不新增存档 schema；继续读取 `WorldState.map_objects`、任务进度和既有库存。
- 清障、采集和勘验仍写既有 `is_cleared`、`is_gathered`、`is_sampled` 或任务完成状态。
- 玩法密度进度由当前区域、既有对象状态和任务目标进度推导，不作为新的真相源保存。

## HUD / 场景 / 对象反馈

- HUD：显示小循环名、步骤进度、下一步和回基地理由。
- 对象提示：显示当前对象属于哪个小循环步骤，以及待处理 / 已处理状态。
- 交互结果：显示该步骤已完成或已推进，并指出下一步。
- 场景：复用已有可玩场景构成和非核心场景识别，不新增视觉层。
