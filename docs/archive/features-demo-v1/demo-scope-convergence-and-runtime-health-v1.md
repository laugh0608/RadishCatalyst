# Demo Scope Convergence And Runtime Health V1

更新时间：2026-07-11

状态：活跃工程整改专题；`H0` 已于 2026-07-11 完成，`R1` 已恢复；`H1` 到 `H4` 在表现层重建期间暂停，不扩玩法。

## 用途

本文收束首版 Demo 的内容规模、运行时验证和关键代码承载面。它不取代表现层重建，也不新增玩家内容；它解决三个已经妨碍主线收口的问题：

1. 静态内容规模明显超过 [Demo Definition V1](demo-definition-v1.md) 的首版边界，默认路径与长期内容没有明确隔离。
2. Godot 聚合检查同时包含当前玩家契约、历史视觉层契约和易漂移的大型集成断言，现有红灯无法直接判断产品是否回归。
3. HUD、地图、任务恢复、存档校验和检查脚本的单文件体积及每帧刷新职责过重，继续叠加会放大回归成本。

## 与当前主线的关系

- 当前玩家可见主线仍是 [Demo Presentation Rebuild V1](demo-presentation-rebuild-v1.md) 的 `R1`；本专题不改变其场景成立四要件。
- `H0` 先恢复可信运行时基线，再继续 `R1`，避免在无法区分旧断言和真实回归时修改场景。
- `H1` 只建立 `keep / legacy / backlog` 范围账本并隔离默认新档路径；旧 ID 和存档兼容数据先保留，不立即物理删除。
- `H2` 到 `H4` 只在触及相应承载面或表现层阶段允许时推进，不与 `R1` 并行开启大重构。
- 表现层旧脚本和节点仍由 `Demo Presentation Rebuild V1 / P3` 删除，不在本文重复建账。

## 已确认基线

- 当前静态数据约有 92 个任务、82 个物品、49 个配方、19 类敌人，而 Demo 规格要求 1 条连续主线、6 到 8 个核心资源 / 产物、1 到 2 种基础敌人加区域威胁与终点守卫。
- `VerticalSliceMap.tscn` 同时承载约 132 个交互实例和 35 个敌人实例；大量后段内容已接线，但不等于默认 Demo 路径需要展示。
- `H0` 开工时，默认 `check-client` 以静态字符串接线检查为主，Godot 聚合入口阻塞在 `vertical-slice-flow`，后续检查不会继续执行。
- `H0` 开工时的已知失败同时包含三类问题：与 `R0 / R1` 冲突的过期断言、检查宿主空对象错误、需要按当前玩家路径确认的真实交互回归。
- 检查辅助类中存在 `extends RefCounted` 文件，它们不是独立 `SceneTree` 入口，禁止逐文件直接启动。

## 整改原则

1. 以当前专题定义的玩家路径和状态契约为真相源，不为保留历史检查而恢复已禁止的旧视觉层。
2. 删除过期断言时，必须保留或补强同一玩家结果的当前契约；不能简单注释、吞错或无条件判通过。
3. 检查入口与辅助模块分开管理；统一入口只能列出可独立运行的 `SceneTree` 脚本。
4. 范围收敛先做默认路径隔离和兼容标记，后做数据物理删除；任何删除必须先定义存档迁移。
5. 重构以真实职责和状态边界为单位，不新增空泛 `Manager / Helper / Service` 包装。
6. 玩家可见结果仍以正式入口截图、录像和人工路径为主证据；自动检查只证明结构与关键行为没有回归。

## H0：运行时真相修复

目标：让统一 Godot 入口完整执行并返回可信结果。

### 失败分类

- `stale-contract`：断言要求旧规划色块、旧视觉层、过早设备或开局晶体可交互，与 `R0 / R1` 明确冲突；删除或改写为当前显隐门控。
- `test-host`：检查在当前对象可能为空时继续访问属性，或依赖未初始化的场景刷新顺序；修复检查宿主和失败输出，不掩盖空值。
- `product-regression`：当前任务和状态满足条件后，玩家仍看不到或无法交互关键对象；修复直接相关运行时逻辑。
- `obsolete-scope`：只覆盖已退出默认 Demo 路径的长尾内容；从关键聚合入口移出，待 `H1` 归档，不继续拖住当前主线。

### 实施范围

- 先处理 `vertical_slice_flow_check.gd`、`demo_interaction_affordance_check.gd`、`demo_resource_chain_state_check.gd`、`demo_prototype_visual_pass_check.gd` 的已知失败。
- 为当前首分钟保留四条硬契约：新档默认目标是受损前哨核心；修复前晶体与后续设备不可交互；修复后晶体路径和采集对象开放；旧视觉层即使自刷新也保持禁用。
- 当前任务确实到达整备、过滤或守卫奖励节点时，关键交互对象必须按状态显示和启用；若该路径已归为 `legacy`，则从关键入口移除而不是伪造通过。
- 统一脚本入口按顺序完整执行，失败时继续保留明确的检查名和首个根因；不逐个运行辅助类。

### 出口

- `sh ./scripts/check-client.sh --with-godot` 完整执行并退出 0。
- 日志无 `SCRIPT ERROR`、空对象属性访问或为当前禁用旧层写的反向断言。
- 四条首分钟硬契约在运行时检查中有明确覆盖。
- 静态检查、文本卫生、文档篇幅和 `git diff --check` 同时通过。

2026-07-11 结果：以上出口已满足。统一入口完整执行，修复内容包括首屏当前目标优先距离、后期测试状态缺少首分钟完成标记、方向交互测试姿态、空对象失败输出，以及与 `R0 / R1` 冲突的旧视觉 / 旧 HUD 断言。

## H1：Demo 范围账本与默认路径隔离

目标：把“仓库里已有内容”和“首版 Demo 必须可玩内容”分开。

### 分类口径

| 分类 | 含义 | 默认新档行为 |
| --- | --- | --- |
| `keep` | 直接服务 20 到 30 分钟黄金路径和 Demo 终点 | 可按主线解锁 |
| `legacy` | 已有存档可能引用，但不再属于首版默认体验 | 保留 ID 与迁移读取，默认不生成 / 不引导 |
| `backlog` | 未来章节或系统候选，尚无兼容承诺 | 不加载到默认 Demo 路径 |

### 实施范围

- 为任务、物品、配方、敌人和地图对象建立可审计账本，先标分类，不新增同类内容。
- `keep` 口径对齐 Demo Definition：6 到 8 个核心资源 / 产物、5 个核心工业模块、轻量四阶段主干和小型敌人集合。
- 默认新档只生成黄金路径所需对象；长尾 ID 暂留数据表，避免破坏已有存档。
- 范围决策涉及删任务链、改终点或改变存档兼容时，升级给萝卜SAMA 确认后实施。

### 出口

- 所有现有内容都有唯一分类和理由，默认路径不再触发 `legacy / backlog`。
- Demo 黄金路径的资源、配方、敌人和任务数量与完成规格一致。
- 旧存档加载策略、未知 ID 行为和后续物理删除条件写清并有验证。

## H2：运行时职责收束

目标：降低地图、HUD、任务恢复和存档校验的修改耦合。

- 将地图区域判定、对象显隐门控和当前交互选择拆为明确承载面，避免 `VerticalSliceMap` 继续横向增长。
- 将 HUD 按目标、状态、交互提示和设备面板拆成信号 / 脏标记驱动的刷新边界。
- 将任务恢复与存档源定义改为单一结构化注册源，避免手工镜像地图对象、敌人和建筑 ID。
- 移除 `GameRoot._process()` 中无状态变化也执行的全量任务协调、HUD 重建、对象扫描和旧层重复禁用；保留必要的定频空间查询。
- 单个生产源码原则上回落到 800 至 1000 行内；超过目标时按职责拆分，不按行数机械切文件。

出口：关键状态变更由信号、revision 或 dirty flag 驱动；每帧路径没有全量 HUD / 任务 / 视觉层刷新；直接触及的超大文件完成职责拆分并有回归检查。

## H3：验证体系收束

目标：减少“检查代码接近生产代码体积”带来的假绿和维护负担。

- 保留结构化数据校验、场景引用校验、核心纯规则检查和少量正式入口集成路径。
- 合并只验证 `REQUIRED_TEXT_BY_FILE` 的重复脚本；行为目标不得仅靠源码字符串存在证明。
- 为 Godot 入口建立显式 manifest：记录入口类型、覆盖路径、是否关键、所属专题；辅助类不得进入 runner。
- Python 与 PowerShell 保持一个共享检查清单或生成源，避免两套长列表漂移。
- 视觉检查只验证资源与状态门控，画面质量继续用截图 / 录像验收。

出口：关键检查分层清楚；不存在行为目标只靠字符串哨兵通过；重复 wrapper 和失效旧层检查完成合并或删除。

## H4：开发分支 CI

目标：让当前体量下的日常集成在进入稳定主线前就暴露问题。

- `dev` push / PR 至少执行文本、文档、静态数据、场景引用和 diff 卫生。
- 增加少量关键 Godot headless smoke；完整运行时套件保留为里程碑、本地或手动 workflow。
- CI 只使用统一入口，不复制检查清单，不把环境证书噪声判成产品失败。

出口：`dev` 的关键静态检查自动运行；关键 Godot smoke 有稳定执行环境和清晰失败日志；稳定主线规则与 ADR 同步。

## 黄金路径验收

整改后的默认体验必须继续服务以下最短闭环：

```text
修复前哨核心 -> 采集晶体 -> 回基地加工 -> 获得可感知外勤收益
-> 经历一次准备差异可读的压力 / 战斗 -> 返回兑现 -> 推进核心稳定站终点
```

- 前 5 分钟由至少 2 名不了解实现的人在无开发者提示下完成“修核心 -> 采晶体 -> 首次加工 / 收益”。
- 完整 20 到 30 分钟主线能无开发者干预走到唯一 Demo 终点。
- 60 秒正式入口录像能被不了解项目的人识别为 2D 工业科幻 ARPG。
- 自动检查通过不替代以上玩家证据。

- 不用新文档继续分拆本文；每包结果写入本周周志，阶段入口只保留链接和当前闸门。
