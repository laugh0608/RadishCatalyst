# Demo Protective Response V1

更新时间：2026-06-15

## 用途

本专题定义首版 Demo 第二个角色套件 / 装备状态开发包：把基础防护服、基础过滤模块、出发整备台和前哨补给读成一次可确认、可触发、可复测的防护响应状态。

它不是新增装备栏或技能树，而是让玩家在出发前能读懂“当前整备会在下一次外勤反击中替我挡住一段压力”，并在触发后看到回基地补给和重新整备的价值。

## 玩家价值

玩家应能理解：

- 基础防护服不是静态数值背景，而是能承接基地整备的防护载体。
- 基础过滤模块和前哨补给齐备后，出发整备台可以确认一次防护响应。
- 下一次外勤反击触发防护响应后，生命 / 防护承压会下降，战斗反馈会说明来源。
- 触发后回前哨补给、检查整备台，能把本次状态重新整理为下一趟外勤价值。

## 与整体规划的关系

覆盖 [Demo Definition V1](demo-definition-v1.md) 中这些规格项：

- 角色成长：玩家获得一种可持续读出的外勤能力提升。
- 技能 / 操作：角色具备基础战斗和少量工具化外勤动作之外的防护或模块收益动作。
- 装备 / 模块：装备来源服务基地制造和外勤准备。
- 战斗压力：战斗验证准备差异，而不是只做路障。
- UI / HUD、存档 / 状态和自动检查：关键状态可读、可保存、可检查。

本专题承接 `Demo Character Kit V1` 的主动扫描动作，但不继续加厚战术扫描；承接工业主干和主线完成感，但不继续堆同一读法点。

## 当前已有基础

- `equipment.basic_suit`、`equipment.filter_module_t1` 已存在，过滤模块可通过出发整备台装入防护服。
- `building.field_outfitting_station` 已能处理模块装配、模块校准、核心归档维护和后勤维护。
- `item.repair_gel` 与 `item.resistance_vial_t1` 已通过前哨核心 / 基础储存箱 / 污染过滤器形成出发补给读法。
- `EnemyCounterattackRuntime` 已统一处理敌人反击，能读取整备收益并生成战斗反馈。
- HUD、前哨核心、出发口和出发整备台已有出发准备摘要。

## 本轮范围

- 在出发整备台对象状态上新增一次防护响应确认状态。
- 条件只使用既有内容：基础防护服、基础过滤模块、出发整备台、修复凝胶和抗污染药剂。
- 出发整备台提示显示防护响应是否可确认、已待命或已触发。
- HUD / 前哨核心 / 出发口读出防护响应待命或已触发后的回基地价值。
- 下一次外勤反击触发防护响应，降低生命和防护承压，并写入已触发状态。
- 战斗反馈说明本次防护响应来自出发整备台、基础防护服、过滤模块和补给。
- 新增专项检查覆盖确认条件、HUD / 对象提示、反击触发、状态持久字段和反馈文本。

## 当前不做

- 不新增装备栏、完整 `loadout`、随机词条、职业树、等级曲线或新角色。
- 不新增资源、敌人类型、区域、任务链、科技树或新 UI 面板。
- 不继续加厚战术扫描、污染边界后勤维护、遗迹外圈模块承压、工业主干或主线完成态。
- 不把本专题扩成试玩准备、集中修 bug 或全量平衡阶段。

## 玩家操作路径

1. 玩家已有基础防护服，并通过基地制造获得基础过滤模块。
2. 玩家建成出发整备台，将基础过滤模块装入防护服。
3. 玩家在前哨核心补齐修复凝胶和抗污染药剂。
4. 玩家操作出发整备台，确认防护响应待命。
5. HUD、出发口、前哨核心和整备台提示显示下一次外勤反击会读取防护响应。
6. 玩家进入外勤战斗，下一次反击触发防护响应，生命 / 防护承压下降。
7. 触发后反馈提示回前哨补给并复查整备台，以便重新整理下一趟外勤。

## 运行时、存档与数据边界

- 真相源放在 `map_object_instance.field_outfitting_station` 的对象状态里。
- 只新增轻量布尔字段，不扩 `CharacterState`、装备 schema 或存档格式。
- 旧存档没有该字段时默认为未确认，不影响既有模块、维护和补给状态。
- 反击触发后写入已触发状态；回到整备台重新确认可再次待命。

## HUD / 场景 / 对象反馈

- 出发整备台：显示可确认、待命、已触发和缺补给状态。
- 前哨核心：显示补给是否支撑防护响应重新待命。
- 外勤出发口：显示下一次外勤反击是否会读取防护响应。
- HUD 基地摘要：在基地出发准备状态中读出防护响应待命 / 已触发。
- 战斗反馈：触发时明确说明生命 / 防护承压下降来自防护响应。

## 验收条件

- 玩家通过真实整备台交互确认防护响应，不靠调试状态。
- 防护响应能在下一次反击中触发，并降低生命 / 防护承压。
- 触发后状态可持久读取，HUD 和对象提示能说明需要回前哨补给并复查整备台。
- 未新增当前冻结事项。
- 默认客户端检查和 Godot 专项检查通过。

## 风险与后续决策

- 风险：整备台交互已有多种状态，防护响应必须排在核心归档、后勤维护等更具体动作之后，避免抢走已有流程。
- 风险：反击反馈过长会降低战斗日志可读性；本轮只补一段来源说明。
- 后续若继续做角色套件，应切到新的装备状态或战斗动作，不继续围绕同一防护响应堆倍率。
