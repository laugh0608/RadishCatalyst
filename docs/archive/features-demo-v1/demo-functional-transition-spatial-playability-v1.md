# Demo Functional Transition Spatial Playability V1

更新时间：2026-06-19

## 用途

本文定义首版 Demo 功能 / 过渡场景可达空间第一版。它承接已通过退出判断的功能 / 过渡路线支撑、非核心区域场景识别、功能场景玩法和玩法密度专题，不继续给锁相框架与锚定桥同一小循环加厚，而是检查新的代表路径能否在实际场地里读出入口、可走边界、危险 / 资源 / 设施落点和回基地理由。

本专题覆盖 [Demo Definition V1](demo-definition-v1.md) 的「区域 / 场景」「功能 / 过渡场景」「UI / HUD」「存档 / 状态」和「自动检查」规格。

## 玩家价值

玩家进入功能 / 过渡区时，不应只从 HUD 或对象文案理解路线，还应能在场地中确认：

1. 从封锁遗迹到裂相脊的入口、过渡路线和返回方向清楚。
2. 危险、资源和关键设施不挤在一个点上，玩家能通过移动判断下一步。
3. 现场处理结果能回到基地加工、整备或下一段外勤准备，而不是停在区域标牌。

## 与整体规划的关系

- 继续服务“基地服务冒险，冒险反哺基地”：场地可达性必须支持外勤结果回到基地处理。
- 承接 [Demo Functional Transition Route Support V1](demo-functional-transition-route-support-v1.md) 和 [Demo Non-Core Scene Identity V1](demo-non-core-scene-identity-v1.md)，把路线职责和场景身份落到实际可走空间。
- 承接 [Demo Functional Scene Gameplay Density V1](demo-functional-scene-gameplay-density-v1.md) 的退出结论，但选择新的真实玩家路径，不继续围绕锁相框架或锚定桥加厚。

- 封锁遗迹、裂相脊、回声台地和锚定桥已有路线职责、场景身份、对象提示和部分可操作对象。

- 现有 `WorldState.map_objects`、HUD presenter、交互提示和专项检查可以承载新的窄职责场地可达性判断。

## 本轮范围

- 第一包选择封锁遗迹到裂相脊代表路径，验证入口、通行边界、危险 / 资源 / 设施落点和回基地方向。
- 优先复用既有对象、区域 ID、任务状态、资源和检查入口。
- HUD / 地图只补能服务当前可达空间判断的短读法，不新增面板。
- 新增专项 formatter、scene helper 或检查文件时，职责只覆盖本专题，不把逻辑堆回接近硬上限的大文件。

## 当前不做

- 不新增第 13 区域，不平均扩厚 8 个非核心区。
- 不新增资源、配方、任务链、敌人类型、完整背包、完整装备栏或自动化物流。
- 不继续加厚锁相框架、锚定桥、补给节奏、快捷补给、目标箭头或同一批对象提示。
- 不做最终美术包、完整地图重绘、大规模换皮、试玩准备或集中修 bug。

## 玩家操作路径

1. 玩家从污染边界或基地目标进入封锁遗迹入口，能看出入口方向和当前危险。
2. 玩家在封锁遗迹处理代表对象或危险后，能看出裂相脊方向和可返回基地的理由。
3. 玩家到达裂相脊前，不需要依赖长文案猜测通行边界、资源点或设施落点。
4. 玩家把现场结果带回基地处理后，HUD / 对象提示能回接下一段外勤准备。

## 运行时、存档与数据边界

- 不新增存档 schema；继续读取既有区域状态、对象状态、库存、任务和角色位置。
- 场地可达性状态优先由场景节点、区域 ID 和既有对象状态推导，不另建长期真相源。
- 若需要新增辅助数据，只能作为 scene helper 或检查侧配置，不迁移稳定数据 ID。

## HUD / 场景 / 对象反馈

- HUD / 地图：显示当前区域入口、下一段方向和回基地理由。
- 场景：确认入口、边界、危险、资源和设施落点不互相遮挡，能支撑实际移动判断。
- 对象提示：说明当前对象服务哪段通行或回基地处理。
- 交互结果：说明现场结果如何改变下一段路线、基地处理或整备准备。
