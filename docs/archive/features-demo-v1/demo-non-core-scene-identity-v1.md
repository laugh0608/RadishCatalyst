# Demo Non-Core Scene Identity V1

更新时间：2026-06-16

## 用途

本文定义首版 Demo 非核心区域场景识别第一包。它承接已完成的功能 / 过渡路线支撑，把 4 个功能区和 4 个过渡区从“HUD 能说明路线职责”推进到“玩家在场景中能区分这里是什么地貌或设施”。

本专题服务 [Demo Definition V1](demo-definition-v1.md) 中「区域 / 场景」「功能 / 过渡场景」「UI / HUD」「自动检查」和「初步美术」规格。它不是最终美术包，不新增第 13 区域，也不给 8 个区域各自新增独立系统。

## 玩家价值

玩家推进到非核心区域时，应能从场景第一眼读懂：

- 封锁遗迹是旧设施和信号封锁的短副本入口。
- 裂相脊是地表被异常能量撕开的前线回传地貌。
- 回声台地是残留观测信号与异常读数区域。
- 盐壳、碎晶、风蚀、锁相四个过渡区分别承担化学沉积、晶体耦合、旧管廊和压相设施识别。
- 锚定桥是把前线结果接回核心稳定工程的高风险桥区。

## 与整体规划的关系

- 服务长期核心：“基地服务冒险，冒险反哺基地”。
- 承接 `Demo Functional Transition Route Support V1` 的路线职责、当前危险和回基地理由，不继续加厚同一文案密度。
- 承接 `Demo Scene Art Foundation V1` 的核心区识别模式，但本轮只扩到非核心区域第一版标识和读法。
- 复用现有 12 区域和 `VerticalSliceMap.tscn`；不新增区域、任务链、资源、敌人或装备系统。

## 当前已有基础

- `VerticalSliceMap.tscn` 已有核心区 `SceneArtFoundationLayer`。
- `FunctionalTransitionRouteSupportFormatter` 已维护 8 个非核心区的路线职责、当前危险和回基地理由。
- HUD 地图、HUD 摘要和对象提示已能读出非核心区路线支撑。
- `functional_transition_route_support_check.gd` 已覆盖区域数量和非核心区路线口径。

## 本轮范围

- 新增非核心区场景识别 formatter，统一 8 个区域的场景标题、视觉识别、地貌 / 设施读法和对象提示短句。
- 在 `VerticalSliceMap.tscn` 中补一个非核心区场景识别层，包含 8 个区域的标识条带和短标签。
- HUD 地图路线提示在非核心区同时读出场景身份和路线支撑。
- 对象提示补充非核心区场景身份，不替代已有路线支撑和任务状态。
- 新增专项检查，覆盖场景节点、formatter 输出、HUD / 地图文本、对象提示和 12 区域边界。

## 当前不做

- 不新增第 13 区域，不改变现有区域 ID 或任务目标 ID。
- 不做最终美术资产包、动画、照明系统或大规模换皮。
- 不新增资源、敌人类型、任务链、装备栏、`loadout` 或长期成长系统。
- 不继续加厚战术扫描、防护响应、工具校准、路线支撑、工业主干、核心场景识别或主线完成感同一读法点。
- 不把本专题扩成试玩准备、集中修 bug 或静态审计。

## 玩家操作路径

1. 玩家从污染边界进入封锁遗迹，能在场景标识和对象提示中读出旧设施、信号封锁和遗迹短副本身份。
2. 玩家推进裂相脊，能读出裂隙地貌、前线回传和异常撕裂风险。
3. 玩家进入回声台地，能读出观测残响、异常读数和样本回基地解析价值。
4. 玩家经过盐壳、碎晶、风蚀和锁相过渡区，能区分化学沉积、晶体耦合、旧管廊和压相框架。
5. 玩家推进锚定桥，能读出桥区、锚点、稳定窗口和核心稳定站前置价值。

## 运行时、存档与数据边界

- 本轮只从 `WorldState.current_region_id`、区域 ID、既有对象定义和场景节点推导读法。
- 场景识别 formatter 只负责展示文本，不推进任务、不消费库存、不写新存档字段。
- 场景节点只新增可读标识，不改变交互对象实例、敌人、任务、区域边界或存档来源。
- 新检查必须独立为专项文件，不继续推高 `vertical_slice_flow_check.gd` 或 `vertical_slice_map.gd`。

## HUD / 场景 / 对象反馈

- 场景：8 个非核心区都有标识条带和短标签。
- HUD 地图：非核心区路线提示同时包含场景身份和路线支撑。
- 对象提示：非核心区关键对象显示场景身份、地貌 / 设施读法和回基地理由。
- 检查：专项 check 覆盖节点存在、标签文本、formatter、HUD / 地图输出和对象提示关键字段。

## 验收条件

- 4 个功能区和 4 个过渡区在场景节点与 HUD / 地图提示中都能被稳定识别。
- 对象提示至少覆盖封锁遗迹、裂相脊、回声台地、一个过渡区和锚定桥对象。
- 实现不新增区域、资源、敌人、任务链、装备系统或大规模美术替换。
- 自动检查随 `check-client` 和 Godot runtime 检查入口执行。

## 落地状态

- `VerticalSliceMap.tscn` 已新增 `NonCoreSceneIdentityLayer`，覆盖封锁遗迹、裂相脊、回声台地、盐壳浅滩、碎晶沟谷、风蚀管廊、锁相框架和锚定桥。
- HUD 地图路线和对象提示已接入场景身份，同时保留已完成的路线支撑读法。

- Godot 运行时检查：`sh ./scripts/check-client.sh --with-godot`。
- 文档检查：`./scripts/check-docs.sh`、`./scripts/check-text-files.sh`、`git diff --check`。

## 风险与后续决策

- 风险：8 个区域一起做容易平均铺内容；本轮只补场景身份标识和关键对象读法，不扩独立系统。
- 风险：地图、HUD 和提示脚本接近行数边界；实现时优先新增 formatter 和专项 check。
- 后续若某个功能区缺真实操作点，应另建更窄的玩法或场景专题，不把所有机制塞回本专题。
