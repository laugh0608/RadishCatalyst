# Ruin Outer Ring Module Pressure V1

更新时间：2026-06-15

## 用途

本文是 [Demo Combat Progression V1](demo-combat-progression-v1.md) 下的可执行细专题，专门定义“基础过滤模块、模块校准和后勤维护状态如何在遗迹外圈读出承压差异”。

本文是下一次相关代码开发的直接范围来源；阶段级专题只保留角色成长与战斗差异方向，不承载本包的对象、路径和检查细节。

## 玩家价值

玩家在基地完成模块装入、校准或维护后，进入遗迹外圈时应能读懂：相位守卫、回波沉积或外圈中继压力不再只是固定门槛，而会被出发前整备改变。玩家需要从 HUD、对象提示、战斗日志和外圈结果反馈中看到“回基地整备会降低遗迹探索风险”。

## 与整体规划的关系

- 服务长期核心：“基地服务冒险，冒险反哺基地”。
- 覆盖 `demo-definition-v1.md` 中的角色成长、技能 / 操作、装备 / 模块、战斗压力、UI / HUD、存档 / 状态和自动检查规格。
- 承接已落地的基础过滤模块、模块校准、核心归档维护、后勤维护、遗迹外圈、中继台、回波匣和相位守卫。
- 作为污染边界后勤维护承压差异之后的新场景压力包，验证同一套整备状态能在不同危险类型里读出价值。

## 当前已有基础

- 遗迹外圈已有 `region.ruin_outer_ring`、`map_object.outer_ring_barrier`、`map_object.outer_ring_console`、`map_object.signal_echo_cache` 和 `enemy.ruin_phase_guard`。
- 遗迹外圈任务链已有继电残片、稳相信标、外圈中继、回波匣和裂相坐标路径。
- `FieldOutfittingRuntime` 已能读取基础过滤模块、模块校准、核心归档维护和后勤维护状态。
- `EnemyCounterattackRuntime`、`DepartureReadinessFormatter`、HUD / 地图目标和对象提示已经能表达外勤压力与出发整备状态。
- 最近完成的污染边界子专题已经证明后勤维护可以通过专项检查覆盖对象提示、战斗反馈、状态来源和损耗差异。

## 本轮范围

本轮只做一个遗迹外圈压力差异开发包：

- 优先让基础过滤模块和模块校准影响 `enemy.ruin_phase_guard` 的反击压力或败退后的污染回波沉积处理压力。
- 若玩家已经完成后勤维护，外圈反馈可以追加维护收益读法，但不要求把主线顺序改成后勤维护后才能进入遗迹外圈。
- HUD、出发整备台、外勤出发口、遗迹外圈对象提示和战斗日志都要说明该差异来自模块整备状态。
- 自动检查覆盖状态准备、确认前后损耗差异、外圈对象反馈、战斗反馈、存档状态和地图目标。

优先复用既有相位守卫、回波匣或污染回波沉积；只有现有对象无法表达玩家路径时，才允许在 `region.ruin_outer_ring` 内新增一个小压力对象。

## 已落地

- 2026-06-15 已让基础过滤模块、模块校准和后勤维护状态影响遗迹外圈相位守卫反击与污染回波沉积处理压力。
- `FieldOutfittingRuntime` 统一输出遗迹外圈模块承压反馈；`EnemyCounterattackRuntime` 在相位守卫战斗日志中读出模块、校准和维护收益。
- 出发整备台、外勤出发口、HUD 提示、回波匣对象提示和回波沉积采集反馈均已说明遗迹外圈会读取当前模块状态。
- 新增 `ruin_outer_ring_module_pressure_check.gd`，覆盖损耗差异、HUD / 对象 / 战斗反馈、状态来源和序列化字段。

## 玩家操作路径

1. 玩家已通过基地制造或出发整备台获得基础过滤模块，并至少具备模块装入或模块校准状态。
2. 玩家在基地 HUD、出发整备台或外勤出发口看到遗迹外圈风险会读取当前模块状态。
3. 玩家进入遗迹外圈，推进到相位守卫、回波沉积或外圈中继压力点。
4. 玩家战斗或处理回波沉积时，生命 / 防护损耗读取模块整备收益。
5. 战斗、采集或对象反馈明确说明本次承压变化来自基础过滤模块、模块校准或后勤维护。
6. 后续反馈回指回基地补给、继续分析回波或推进裂相坐标，不开启新任务链。

## 运行时、存档与数据边界

- 成长状态继续优先读取出发整备台和既有世界状态，不新增完整装备栏或角色 `loadout`。
- 承压计算优先集中在 `FieldOutfittingRuntime`、`EnemyCounterattackRuntime` 或明确职责的 formatter 中，不把倍率判断散落到 HUD、地图对象和检查脚本。
- 若新增外圈压力对象或实例 ID，必须加入存档来源允许表、场景引用检查和专项 Godot 检查。
- 若实现触及接近行数边界的检查、地图、HUD 或提示脚本，应优先新增专项 check 或拆分 helper。

## HUD / 场景 / 对象反馈

至少覆盖：

- 出发整备台：显示当前模块装入、校准或维护状态，并指出遗迹外圈收益。
- 外勤出发口：把遗迹外圈压力读法列为当前可观察收益之一。
- 主 HUD / 地图目标：在基地和遗迹外圈分别读出准备状态与压力点目标。
- 遗迹外圈对象提示：说明相位守卫、回波沉积或中继压力会读取模块状态。
- 战斗日志：明确说明损耗变化来自基础过滤模块、模块校准或后勤维护。

## 验收条件

- 玩家能通过真实操作获得模块装入、校准或维护状态，并在遗迹外圈读出承压差异。
- 差异至少影响一种生命 / 防护损耗计算和对应反馈文本。
- 离开区域、回基地、再出发后，状态判断仍稳定。
- 自动检查覆盖状态来源、外圈目标、损耗差异、HUD / 对象 / 战斗反馈关键文本和存档状态。
- 未引入本专题“当前不做”中的系统扩张。

- 如果遗迹外圈已有基础过滤模块读法但玩家感知不足，本包应补真实对象、战斗和 HUD 反馈，而不是只改说明文字。
- 如果模块校准和后勤维护同时影响外圈压力，应区分“基础模块已生效”和“维护进一步降低承压”，避免玩家读成重复奖励。
