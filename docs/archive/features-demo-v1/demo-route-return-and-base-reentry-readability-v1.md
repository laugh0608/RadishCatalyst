# Demo Route Return And Base Reentry Readability V1

更新时间：2026-06-19

## 用途

本文定义首版 Demo 外勤返回与基地再进入读法第一版。它承接已通过退出判断的外勤收益、资源链、功能场景玩法、玩法密度和可达空间专题，不继续围绕封锁遗迹到裂相脊同一路径加厚，而是检查玩家带着外勤结果回到基地后，能否在 HUD、设备、对象提示和结果反馈中读出“去哪个设备处理、收益改变了什么、下一次从哪里出发”。

本专题覆盖 [Demo Definition V1](demo-definition-v1.md) 的「工艺 / 科技解锁」「工业基建模块」「资源 / 生产链」「UI / HUD」「存档 / 状态」和「自动检查」规格。

## 玩家价值

玩家回到基地时，不应只看到背包物品增加或任务文本变化，还应能确认：

1. 本趟带回的资源、样本或回波该去基础反应器、污染过滤器、出发整备台还是前哨核心处理。
2. 处理后哪些补给、整备、路线或核心稳定准备已经改变。
3. 下一次出发应该从出发口、相位回投台或当前目标路线继续，而不是重新猜测。

## 与整体规划的关系

- 继续服务“基地服务冒险，冒险反哺基地”：外勤结果必须被基地设备读出、处理和转成下一趟准备。
- 承接 [Demo Field Loop Payoff V1](demo-field-loop-payoff-v1.md) 的外勤收益兑现，但本轮强调回基地后的再进入判断，不继续围绕同一封锁遗迹回波匣路径加厚。
- 承接资源链状态、工业主干和补给节奏专题，只复用既有资源、设备、库存、任务和整备状态，不新增资源或设备。

## 当前已有基础

- 基础反应器、污染过滤器、出发整备台、前哨核心、出发口和相位回投台均已存在。
- `HudStatusPresenter`、`HudDevicePanelPresenter`、`HudMapPresenter`、`InteractionPromptFormatter` 和结果日志已有分层职责。
- 外勤对象处理结果、库存、任务进度、区域状态、整备状态和存档状态已有自动检查。
- 部分专题已能说明单个对象的回基地理由，但缺少“回到基地后此刻先去哪、处理后如何再出发”的统一读法。

## 本轮范围

- 第一包只覆盖回基地后的代表性再进入判断：外勤结果在库存或任务状态中出现后，HUD / 地图 / 设备提示能指向正确基地处理点和下一次出发入口。
- 优先覆盖基础反应器、污染过滤器、出发整备台、前哨核心和相位回投台的既有承载面。
- 新增窄职责 formatter 和专项检查；不把逻辑堆回 `prototype_hud.gd`、`interaction_prompt_formatter.gd`、`vertical_slice_map.gd` 或大型检查脚本。
- 不新增存档 schema；只从既有库存、任务、建筑和整备状态推导回基地读法。

- HUD、地图、设备面板、推荐配方和加工结果日志已接入；通用交互提示暂不继续加厚，后续若接入应先拆 `interaction_prompt_formatter.gd` 的职责。
- 新增 `demo_route_return_and_base_reentry_check.gd` 与静态接线检查，并接入默认 `check-client` 和 Godot runtime 检查。
- 2026-06-19 退出判断通过：代表状态、自动检查和文档边界均满足验收；后续切到交互提示承载面拆分，不继续给同一批返回态加厚。

## 当前不做

- 不新增资源、配方、设备、区域、任务链、敌人类型、完整背包、完整装备栏或自动化物流。
- 不继续加厚封锁遗迹到裂相脊、锁相框架、锚定桥、补给短状态或同一批目标箭头。
- 不做完整基地菜单、完整设备管理、完整科技树、结算页、试玩准备或集中修 bug。
- 不改稳定数据 ID，不迁移旧存档。

## 玩家操作路径

1. 玩家带着外勤结果回到基地，HUD 先读出当前可处理结果和推荐处理点。
2. 玩家靠近基础反应器、污染过滤器、出发整备台或前哨核心时，设备面板或对象承载面说明它能处理哪类外勤结果。
3. 玩家处理或确认收益后，结果反馈说明补给、整备、路线或核心准备如何改变。
4. HUD / 地图把下一次出发入口指向出发口、相位回投台或当前目标路线。

## 运行时、存档与数据边界

- 不新增存档字段；继续读取 `CharacterState.inventory`、`WorldState.quest_state`、建筑状态和既有整备状态。
- 回基地读法只作为 presenter / formatter 推导结果，不作为新的真相源保存。
- 若某个结果无法从现有状态判断，先收束到代表性状态，不新增宽泛兜底。

## HUD / 场景 / 对象反馈

- HUD：显示本趟外勤结果的处理点、处理价值和下一次出发入口。
- 地图：在基地状态下说明从基地继续出发或回投的方向。
- 设备 / 对象提示：在设备面板、前哨核心、出发口或回投台承载面提示可处理结果与收益去向。
- 结果反馈：处理后说明收益改变和下一次外勤准备。

## 验收条件

- 至少两类既有外勤结果能在回基地后读出正确处理点和下一次出发入口。
- HUD、地图、设备 / 对象提示和结果反馈口径一致，不互相指向冲突。
- 不新增资源、配方、设备、区域、任务链、完整背包、完整装备栏或存档 schema。
- 自动检查覆盖 formatter、HUD / 地图、对象提示、结果反馈和状态推导。
