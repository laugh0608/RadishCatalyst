# Demo Playable Scene Composition V1

更新时间：2026-06-17

## 用途

本文定义首版 Demo 可玩场景构成第一版的范围。它不是重新给区域贴标签，也不是继续加厚路线职责文案；它用于检查并补齐玩家从新档到 Demo 完成后回前哨整理时，12 个既有区域的画面构成、关键对象落点、HUD / 地图读法和自动检查断点。

## 玩家价值

玩家应该能在不依赖完整最终美术的情况下，判断自己处在哪类空间、主路朝哪里推进、哪个对象是当前区域的关键落点，以及完成互动后应如何回到基地或继续前进。

本轮目标是让既有地图、对象提示和 HUD 共同回答三个问题：

1. 这个区域的前景、主路和背景关系是什么。
2. 哪个设施、资源、危险或异常是画面中心。
3. 地图提示和对象提示是否指向同一个玩家行动。

## 与整体规划的关系

本专题覆盖 [Demo Definition V1](demo-definition-v1.md) 的「区域 / 场景」「核心场景完成度」「功能 / 过渡场景」「UI / HUD」「初步美术」和「自动检查」。

它承接已完成的 [Demo Playable Experience Coherence V1](demo-playable-experience-coherence-v1.md)：连贯性第一包已确认主路径断点可被检查；本轮转向场景构成读法，避免继续围绕同一整段断点清单加厚。

## 当前已有基础

- 12 区域范围和职责已在 `docs/planning/demo-scope-and-playable-slice.md` 冻结。
- 核心区域已有场景识别、HUD / 地图提示和对象反馈第一包。
- 非核心区域已有场景身份、功能 / 过渡路线支撑和现场阶段反馈第一包。
- `S0`、`S21`、`S22` 与整段体验连贯性检查已经覆盖新档、外圈、核心稳定站和 Demo 完成后回前哨整理。

## 本轮范围

- 为 12 个既有区域建立可维护的场景构成表，说明前景 / 主路 / 背景读法、关键落点和对象识别点。
- HUD 地图提示应在既有目标、路线和场景身份之外，补出当前区域的画面构成提示。
- 代表性对象提示应能读出它在当前画面中的位置职责，而不是只说明用途或状态。
- 自动检查应覆盖 12 区域构成表、HUD 地图读法、代表性对象提示和关键场景对象落点。
- 新增实现优先使用窄职责 formatter 和专项 check，避免继续推高接近硬上限的大文件。

## 当前不做

- 不新增资源、配方、区域、任务链、完整背包或完整装备栏。
- 不切到试玩准备、修 bug 阶段、发布准备、终局菜单或结算页。
- 不新增最终美术资产包、过场动画、完整大地图重绘或大规模换皮。
- 不平均扩厚 12 个区域的机制，也不继续给核心站完成态追加同构回访口袋。
- 不把本轮做成纯文案追加；必须同时有 HUD / 地图 / 对象反馈和自动检查证据。

## 玩家操作路径

本轮检查沿既有主路径展开：

1. `S0` 新档从前哨平台识别出基地设施、出发口和晶体采集方向。
2. 玩家进入晶体矿脉与污染边界时，能从地图和对象提示区分资源线、污染施工带和危险落点。
3. 玩家穿过遗迹外圈、深层遗迹门槛与后续功能 / 过渡区时，能看出主路、封锁点、异常设施和回基地理由。
4. 玩家进入核心稳定站并完成 Demo 后，回到前哨整理时仍能从 HUD / 地图读出已完成后的整理落点。

## 运行时、存档与数据边界

- 不新增存档 schema，不迁移稳定 ID，不改变任务真相源。
- 场景构成只读取既有 `region_id`、地图对象定义和当前任务 / 完成状态。
- 对象提示只补充展示层信息，不改变互动结果、掉落、战斗数值或任务进度。
- 自动检查可以创建测试态世界与对象，但不得要求新增玩家可见任务链。

## HUD / 场景 / 对象反馈

- 地图提示需要同时保留目标 / 路线信息，并追加当前区域的画面构成读法。
- 对象提示需要说明关键对象在画面中的职责，例如入口锚点、主路封锁、处理台、稳定核心或回收落点。
- 12 区域构成表必须覆盖核心区、功能区和过渡区，且不与已有场景身份、路线支撑表互相复制。
- 完成后前哨整理读法必须继续存在，但本轮不继续扩写核心站完成态成果文案。

## 验收条件

- `Demo Playable Scene Composition V1` 建立并作为当前活跃专题。
- 12 个既有区域都有场景构成数据和可读的地图提示。
- 代表性对象提示能读出关键对象落点和区域构成职责。
- 专项检查覆盖构成表完整性、HUD 地图读法、对象提示和关键场景对象落点。
- 未引入当前不做事项，且未把实现堆回既有大文件。

## 风险与后续决策

- 若检查发现真实场景布局和构成表不一致，优先修既有对象落点或构成数据，不新增区域。
- 若 HUD / 对象提示过密，应拆分展示层 helper，而不是继续把长逻辑写进 HUD 或 prompt 主文件。
- 若本轮达到退出条件，下一步应继续对照 Demo 完成规格选择新的非重复玩家可见缺口。
