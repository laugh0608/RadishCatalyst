## 本轮输入与判断

萝卜SAMA明确：终末地只作参考；核心仓库容量上限建议为 99,999，核心分等级成长；起步供电由实际设备预算推导，至少支持完整发电链与部分其他设备；发电采用固定功率 / 固定燃烧时长、低负载仍消耗、手动停机暂停剩余燃烧；考虑 PWM 等进阶操作，并设计循序渐进的科技树。

本轮建议把下一阶段重点设为「统一 Demo 与第一轮成长」，在同一玩家路径中接起核心、仓储、材料、能源、研究和开拓。E3 的开拓回报可成为终点内容；需要的基础改造先完成，不并行铺开完整液气、战斗、多人和全量科技树。

现阶段已经积累建造、物流、生产、发现、电力、统计、制造与存读能力，但各版本入口 / 检查点不等于一段新档可理解、可持续经营的游戏。整合应优先解决主线和规则归属；工程整理随实际模块依赖推进，不以整仓重写作为开工前提。

## 核心与仓库

- 建议每个新 Demo 世界有唯一基地核心，承担仓库、研究 / 等级入口和固定起步供电；玩家可从核心理解基地当前能力。
- 按**每种物品 99,999 件硬上限**设计，不按四档仓容套用终末地。核心等级解锁工艺、设备与控制能力，首包不另设分档仓容；尚未研究的合法实物也可保存，不靠存量解锁科技。
- 核心库存是一个真实库存账；多个实体输入 / 输出口接传送带。输出逐口选择物品，按实际输送节拍取料；缺货不出料，该物品满仓时对应输入回压，其他物品仍可接收。
- 初始具备完成第一条线所需的多个接口；具体足印、端口数、吞吐和扩展方式在实施合同中经布局核对，不先指定一个未经验证的大核心。
- 大库存降低搬运和碎箱管理负担；生产挑战由物料分配、带宽、工艺、副产物、能源和目标承担。99,999 是存量上限，不等于每步遍历实体物品或无限需求；库存用数量账存储。
- 核心物流与基础库存管理建议不依赖额外供电，保证断燃料后可取料自救。机器与带上缓冲继续有界；不把所有终端仓自动变成远程共享仓。
- 核心升级消耗真实材料并对应明确能力，第一版不因升级自动增加起步电力。升级需求不得包含本级尚未开放的产物。

## 起步供电：从体验预算推导

沿现行配方 / 功率作第一轮预算，尚非未来数值冻结：

| 设备组合 | 全部同时运行上界 |
| --- | ---: |
| 三采集器 + 一粉碎机 + 一板材炉 + 一基础催化反应器 + 一电芯组装机 | 3×20 + 20 + 60 + 40 + 40 = 220 kW |
| 再加一台载体炉和一台构件组装机 | 60 + 40 = 100 kW |
| 合计 | 320 kW |

建议以 **360 kW** 为纸面候选（上述 320 + 40 余量），在新档布局中验证；200 kW 不作为本项目承诺。额外采矿、科研设备、待机或核心自耗若引入，必须纳入预算，不能藏在余量中。

验收看首颗电池、能源链持续补产和材料扩建是否可同时运作；既检查峰值，也检查采集 / 输送 / 加工的实际节拍。不得靠免费中间品、强制停机切线或严重欠供来证明开局成立。

起步也不应覆盖整段 Demo 的所有扩建需求：明确下一项真实生产目标，证明新增机组能改善吞吐或开放新布局。若初期无需电池，调整自然目标和设备组合；不用假负载制造需求。燃料耗尽后，核心应足以让玩家留下能源链与必要物流恢复供料。

## 固定燃烧与进阶测控

### 普通玩家路径

1. 从核心取料，建立电芯链，将产出自动送入发电机。
2. 启用且有燃料时按额定功率燃烧；每颗持续固定时长。低负载仍消耗，手动停机保留剩余燃烧进度，恢复 / 重进不重置。
3. 有燃料的连续供料方案足以完成主线；通过清楚的功率、库存和耗材反馈诊断缺电，不要求玩家理解 PWM。

可先用现有 120 kW / 7,200 kJ 推得 60 秒一颗作比较基线；最终发电功率 / 时间须与新产线预算共同确认。可用容量、燃料实际释能、设备用电和累计弃能分开显示。

### 进阶路径

逐步开放储能设施、供料节拍 / 比例控制、传感器与条件控制，再允许基载机组、间歇机组、库存反馈和非关键负载停机组合。控制需要设备、空间、资源与调试，收益来自减少弃能和改善稳定性。

储能是独立设施 / 明确容量，不把装入发电机的燃料电芯同时当成可充电蓄电池。必须定义容量、充放电功率、初始电量与效率；新建储能初始为空。后期是否由核心提供小缓冲另议，不默认免费赠电。

PWM 是控制固定输出机组的运行占比或燃料投喂间隔。平均发电足够只是必要条件；还需考虑最低储能、最长停发间隔、相位、充放电功率与变化负载。没有储能时，间歇供料通常导致周期性欠供，不能称为稳定供电。

候选例子：核心 360、恒定负载 390、机组 120 kW；每 240 秒投喂一颗燃烧 60 秒的电芯，平均补 30 kW。开机阶段有 90×60 = 5,400 kJ 富余，停机 180 秒也需 30×180 = 5,400 kJ 缓冲。理想无损下配 6,000 kJ 储能、先充入 600 kJ，充 / 放能力至少 90 / 30 kW，可以演示稳定循环。

离线 0.05 秒步长的 720 秒算例：有储能时维持 600–6,000 kJ，末值 600，无欠供 / 溢出；相同平均功率无储能时，累计欠供与溢出各 16,200 kJ。结果只证明恒负载理想算式，不能证明 Godot、真实物流、动态负载或断档恢复。细节见忽略目录 `tools/runtime-intake/design-references/2026-11-01-demo-consolidation/arithmetic.json`；600 kJ 须由实际充电获得。

后续合同须规定手动 / 自动开关共同遵循的最小控制时间尺度，避免帧率依赖；它可来自真实输送节拍或设备响应。保留玩家组合空间，不因某个方案省料就临时封堵；同样不通过回收 / 重载刷新燃料或储能。设备级反馈控制可以成为科技成果，不在基础发电机内免费替玩家完成调度。

能源账候选：`燃料释能 + 核心实际供能 + 储能净放电 = 设备用能 + 弃能 + 损耗`。充电时净放电为负；同一物理储能的充放流必须统一结算。核心未用容量不计成已产生能量，不因新增固定燃烧继续沿用旧版「全部发电恰好等于用电」校验。

## 科技树：核心等级与研究分支分工

核心等级提供阶段上限与新的研究能力；科技树提供阶段内的分支顺序与工艺选择。研究以「前置科技 + 样本 / 明确工程事实 + 材料投入 → 新能力」表达，关键主线确定获得；不以随机抽取或等待计时替代学习。

整合总图设计 12 个节点，三档核心承载；实施合同将首个基础整合包收为 I–II 的 7 节点，X2 与 III 档分后续批次交付，不制作可付费但无效果的占位节点。

| 核心档位 | 节点草案 | 玩家学到 / 获得什么 |
| --- | --- | --- |
| I 工业起步 | B0 基础部署（开局已有）、B1 精密装配、M1 粉体加工、X1 样本试制 | 核心多口存取、简单物流与直炼；构件制造、炭粉、催化剂 |
| II 稳定生产 | E1 工业电芯、M2 联产精炼、M3 载体回用、X2 开拓工具 | 燃料发电、替代工艺、副产物去向、生产支持开路 |
| III 测控优化 | E2 电网缓冲、C1 定量调度、C2 储能反馈、C3 负载管理 | 独立储能、节拍 / 比例控制、阈值回差、关键负载保障与可选 PWM |

前置草图：B0→B1 / M1 / X1；B1+M1+X1→E1；M1+B1→M2→M3；X1+B1+E1→X2；E1→E2，M1→C1，E2+C1→C2→C3。各节点另受核心等级 / 发现限制；X2 的具体材料路线还须与既有配方核对，M3 不自动变成开路强制工艺。

核心 II 的升级材料须能由 I 的直炼 / 装配取得；III 须能由普通连续供料完成，不要求先有 PWM。基础故障、当前功率与库存信息开局可见；研究解锁控制能力，不锁住必要的诊断信息。

每个节点须明确前置、解锁效果、投入去向、取消 / 原子扣料、已研究持久化和版本校验。首版默认材料提交后即时完成研究，不叠加挂机计时；自动研究 / 实验设施若后续有真实过程价值，再单独设计。

教学按「先遇到问题 → 能看懂指标 → 获得新工具 → 看见改善」组织。一次只引入一种主要变量：先缺料 / 堵塞，再电力扩容，再工艺取舍，最后储能 / 调度；高阶效率不是主线通关要求，也不要求玩家在游戏外手算。

液气、反应条件、热管理、材料耐蚀和污染治理可成为长期工业研究分支；其价值应来自工艺选择与环境约束，按后续专题逐项开放，不靠增加更多相似物品扩树。

## 一条统一的 Demo 路线

```text
前哨核心与资源 → 建立首条材料线 → 制造构件并升级核心
    → 生产电芯、持续发电 → 扩建并选择回用工艺
    → 制作开拓用品 → 接回新资源 → 用新供给完成一个实际扩建目标
    └→ 可选：储能、节拍控制与效率挑战
```

第一轮主线仍以约 20–40 分钟体验目标设计，实际时长由试玩确认；测控支线支持继续经营，不要求塞入首次主线。终点必须显示高产矿对开路后的持续生产有什么用；已有「四件胶囊后普通炭就够」问题仍需解决。

新 Demo 提供一个清晰的主入口和一份可继续的正式世界。旧基础 / V5 / E1 / V7 / V8 世界保留原规则，作为历史继续或开发入口；具体菜单归类与显式复制策略另经合同确认。不直接在所有旧存档中插入核心或自动迁移。

其模型包含基础源、固定燃料功率 / 时长、输入间隔、分支相位及独立储能，按周期模拟并约束最低储能与浪费；源码明确对充满溢出和缺电分支作处理。仿真从满储能起步并先过预热区间，本项目须单独验证空储能首次启动，不直接沿用该起始条件。借鉴组合、测量和验证方法；工具参数不是本项目数值，也不将社区模型直接视为当前终末地全部规则。工具公式中的 W / J 不直接当作本项目 kW / kJ。

不采用作者攻略中未经独立证明的「全局最优」「必然永不停电」等泛化结论；不同负载、起始库存、输送节拍和储能初值须重验。现有分流器是遇阻跳过的吞吐调度，分流级数不自动保证固定投料频率；迁移 PWM 前要确认供料 / 回收 / 回压语义。
