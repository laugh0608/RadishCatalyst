1. **玩家结果：**从空白新档连续完成核心修复、首条真实产线、首次充能、步枪装备、战斗、样本交付，并正确理解 Demo 已结束且可以继续自由建设。

3. **跨包验证：**在同一路径确认地表 / 足印 / 接驳、制造 / 放置、容器直接操纵、保存节流、HUD 安全区和设备反馈没有彼此回归；核心与常用设备不打开面板也能读到主要状态。

5. **退出判定：**只有专题九项退出条件共同成立才恢复阶段验收；任一失败先按 R01—R11、R13—R20 / A01—A09 和现有权威合同归因，不把新内容或效率专题当补丁。

推荐落地顺序：

1. 先按运行时指南从当前正式 `Boot → 新建世界` 建立隔离真实新档、窗口配置、截图目录和观察清单；不使用旧开发基线、GM 控件、状态注入或正式证据夹具，不预填资源或跳过首程。
2. 在 16:9 完成主 S0 连续路径，逐节点记录耗时、阻断、返工、理解和保存结果；关键里程碑完全重启复核。
3. 在窗口化非 16:9 复核 HUD、安全区、容器与设备画面，并补路径中最易受比例影响的关键节点，不重复伪造一条独立状态链。
4. 汇总专题九项退出条件；通过则收口整改专题并重新评估下一阶段，不通过则只开范围最小、根因明确的整改补丁。

S0 不扩完整有限电力、工业总览、传送带拖铺、无线回传语义或新内容层。包 4 已冻结并实现保持 16:9 内容画幅与非 16:9 上下黑边的合同，S0 只验证该结果在完整玩家路径中成立。

## 防跑偏规则

- 不把“样本交付后没任务”解释为立即扩第二段剧情；先给明确 Demo 完成态与自由建设入口。
- 不用接驳贴片、长提示或更大碰撞掩盖空间合同错误；先统一设备基座、外接格和地表规则。
- 不照搬《终末地》的体量、移动端 HUD、角色编队或完整工业简报，只借用信息架构原则。
- 不在旧布局上先批量生成动画或音频；代表设备必须逐个通过世界画面人工复核。
- 玩家可见目标以正式 `Boot`、实机截图与人工路径为主证据，自动检查只兜底。
