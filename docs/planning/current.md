## 当前问题结论

1. 主流程在样本交付后没有显式 Demo 完成态，玩家会把终点理解为任务中断。
2. 传送带层级、碰撞、设备足印、反应器轮廓和采集器端口存在互相矛盾的空间合同，必须作为一组治理。
3. 制造自动进入放置、资源依赖不可预见、地板与中继过度消耗、步枪缺少装备页，共同造成主流程反复退出面板和返工。
4. 背包 / 仓库默认展示空物品，设备面板以“取出 / 放置”按钮为主；需要改为“仅持有 + 全部平铺 / 分类筛选 + 成对容器拖拽”。
5. 核心和设备反馈静态，HUD 深底细字、硬编码偏移和常驻输电线降低可读性；参考《终末地》的信息架构，不照搬体量与移动端外观。
6. 每发步枪同步写盘与世界根职责风险已由包 0 治理；连续射击只进入共享防抖，`SliceWorld` 不再拥有保存计时器，但包 1 仍需做玩家侧连射观察。
7. 窗口化 16:10 基线确认生产配置仍把内容保持为 16:9 并出现上下黑边；该事实进入 A07，留到包 4 与 HUD 安全区一组处理。

## 边界与冻结

- 不增加第二只敌人、后续剧情、新地图、新建筑、新配方、Boss、技能树、联机或完整有限电力。
- Demo 完成继续从既有 `field_encounter.state == delivered` 派生；只有装备选择确需持久化时才升级 schema 10，其他 UI 状态保持会话态。
- 采集器容量、存档校验和面板必须共用同一常量；保存防抖必须在制造、放置、拆除、交付、暂停与退出等关键点强制落盘。
- 传送带和地板为可通行地表层；设备按“基座足印阻挡、上部轮廓参与排序”处理，不以整张透明画布充当碰撞。
- UI 只移植参考图的状态分离、容器并排、直接操纵、强层级和可诊断结果，不复制角色编队、复杂成长、移动端按钮或完整工业简报。
- `SliceWorld` 不得继续增长；新行为先确定权威所有者，不通过更多按类型分支兜底。
- 陌生玩家盲测、试玩分发、打包和发布继续冻结，直到本专题 S0 全链退出条件通过。
