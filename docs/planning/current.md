## 当前最高优先级

1. 完成玩家可见命名第一包：清理物品、任务、配方、敌人和地图对象中的旧“相位井 / 井心 / 井纺 / 井纹 / 井系”口径。
2. 只改本地化显示文本和必要文档，不迁移 `region.*`、`item.*`、`quest.*` 等稳定 ID。
3. 对照 `docs/planning/milestone-review-checklist.md` 记录冷启动审计通过结论，并确认下一阶段入口。
4. 命名包通过自动检查后，下一步进入「首小时引导可玩」的轻量规划：只补首次玩家理解和引导节奏，不扩横向系统。
5. 不因为命名 polish 继续扩行动台、高压窗口、区域、长期成长线或完整菜单。

## 区域策略

- `核心区域 4 个`：基地、早期资源区、主要危险区、demo 终点区。优先扩面积、目标密度、资源和战斗节奏。
- `功能区域 4 个`：承载特定资源、设备材料、风险类型或回访目标。
- `过渡区域 4 个`：承载连接、氛围、少量采集和路线变化，不追求完整玩法密度。

参考《银河破裂者》的空间感，但不照搬大地图模板。现阶段只要求外出区域有可探索余量、资源点、危险压力和回基地理由。

## UI 策略

UI 当前进入必要开发项，不作为纯美术打磨处理。优先级：

1. 主 HUD：生命、防护、当前目标、当前区域、关键资源。
2. 地图 / 区域提示：玩家知道自己在哪、要去哪、为什么去。
3. 基地状态摘要：当前可制造 / 可升级、缺什么、升级收益。
4. 角色状态摘要：工具、攻击、防护、抗性、已生效模块。

已完成第一包：主 HUD 不再显示 `Prototype` 标题，高频目标提示和任务完成反馈已切到新区域口径。已完成第二包：HUD 左侧聚合当前目标和关键资源，右侧聚合基地摘要和角色状态；关键资源按当前任务、配方输入和建造消耗推导，基地摘要显示可制造 / 待制造项、缺料、完成后产物或设备加工状态，并已通过人工读法复核。当前第三包聚焦玩家可见命名，不改 UI 结构。

不做完整菜单、设置页、背包大重构、完整装备栏、动画过场或大规模美术替换。核心稳定站先按最小 demo 终点处理：读取锚定桥稳定窗口和高压窗口归档状态，复用短战斗节奏设置阶段守卫，写入稳定数据后给出 demo 完成反馈；不重构 `base_action_state`，不新增第 4 个行动台分支。

## 节奏规则

个人开发阶段只做足以判断方向的完成度。一个阶段达到退出条件后，必须及时进入下一阶段；不允许因为 `P2` / `P3` 细节、局部读法、文案密度或状态字段洁癖无限打磨。

只让这些问题阻塞阶段：

- 崩溃
- 主线卡死
- 坏档
- 任务无法完成
- 关键资源断档
- UI 完全无法判断下一步

其他问题进入 backlog 或后续 polish。冷启动审计已通过后，命名口径属于可收束 polish，但不得扩大成系统重做。
