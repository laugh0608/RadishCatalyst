# Current Plan

更新时间：2026-09-08

## 当前阶段

```text
Godot 3D 画面方向与操作已认可 · 可保存、可扩建工厂首包设计
```

本轮方向以 [Production-Centered Direction](../product/production-centered-direction.md) 为产品真相源：化工生产经营为核心，探索为生产提供资源、空间和长期目的。既有二维切片、schema 10 和历史验证继续保留；旧整改 S0 暂缓。

## 最新决定

萝卜SAMA认可当前独立 Godot Demo 的画面和操作，但对精细度尚不满意，明确当前不必抠细节，并要求继续下一步。按此前建议，进入“可保存、可扩建的三维工厂”首包设计，不再等待同一画面 / 操作的重复认可，也不继续追加同范围画风探索。

本次授权覆盖反馈同步与首包设计。Godot 3D 是本轮设计路线；正式工程接入、新旧存档与规模等新增合同形成可审阅方案后再实施。画面认可不等于美术定稿、完整生产亲测或大工厂性能通过。

## 当前活跃任务

- [Factory Foundation And Persistence V1](../features/factory-foundation-and-persistence-v1.md)：玩家路径、普通构件供给、扩大同类设备数量、P1–P3 实施顺序与规模验收提案。
- [Factory World State And Save V1](../architecture/factory-world-state-and-save-v1.md)：正式状态、Boot 路由、工厂独立 schema / 目录、旧世界保留、保存和故障恢复提案。
- [Godot First Production Line Demo V1](../features/godot-first-production-line-demo-v1.md) 与 [Web First Production Line V1](../features/web-first-production-line-v1.md) 保留为同规则实现、画面和操作参照；技术比较依据见[路线评估](../architecture/production-client-technology-assessment-v1.md)。

## 当前边界

- 保留已认可的设备造型、50° 视角、配色、光照、单枚接口箭头、拖铺与真实弯道；本阶段只修影响辨识或操作的问题，精细美术留待后续。
- 首包提案先保持三种设备与固体带，建设多条产线并保存成果；预供电、预发构件继续用于验证，不混入旧切片电力 / 仓储规则。
- 64×64 场地、普通构件数量、100 台设备 / 1,000 带工程负载和工厂 schema 1 均为新专题中的待审阅合同，没有提前写入运行时或存档。
- 保留正式 `client/` 的旧入口、旧世界和回归证据。新工厂独立存档，不自动转写 schema 10；未决定旧世界导入或删除旧内容。
- 本机旧三机与小窗口采样不能证明高分辨率、多产线或 Windows 性能；Windows 目标硬件仍待指定。

## 当前不做

- 不批量精修 / 重做模型、角色、材质或全部 UI，不重新发起美术介质对照。
- 不增加设备种类、液气、经济解锁、战斗、多人、随机地图、多星球或离线收益。
- 不用一次性样件代替正式入口与跨进程存读验证，不把工程负载世界冒充完整经营循环。
- 不恢复陌生玩家盲测、分发、打包、发布、上传或推送；不安装依赖或引入外部资产。

## 下一步

审阅首包的正式接入、独立存档和扩建 / 负载范围；合同确认后按 P1 正式入口与状态 → P2 保存恢复 → P3 扩建与规模推进。本机实施可先行，Windows 性能项在目标机明确后完成。不得将新增架构 / 存档合同写成已经批准或实现。

## 本阶段退出条件

- 用户认可与精细度暂缓的事实已同步，后续任务不再默认要求同范围画风打磨。
- 首包专题明确玩家路径、范围、供给、状态 / 存档 / 界面、验证和失败边界，架构提案与源码证据一致。
- 新旧世界保留方案与待审阅项具体可执行；没有把未知硬件、候选容量或自动检查写成性能承诺。
- 合同经萝卜SAMA审阅后才切换为实施状态；具体实现退出条件由新专题 P1–P3 承载。

## 当前验证

本次设计变更执行文档预算、文本规范、仓库治理与 diff 检查，不启动 Godot 或修改存档。实施后的客户端静态、正式 Boot、存读、截图和负载验证由新专题规定；运行前先告知。
