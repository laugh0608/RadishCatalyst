## 当前最高优先级

1. 从 `S0` 新玩家前 15 到 30 分钟体验检查目标引导、基地加工原因、外出可做事密度和再次推进危险目标是否清楚。
2. 优先在既有基地、晶体矿脉区和污染边界补可选资源点、低压敌人、污染压力点和回基地收益；不重排任务链。
3. 玩家可见旧命名第一包已收束，稳定 ID 与存档兼容层继续保留。
4. 每个小改动用匹配的自动检查兜底，只有主线卡死、坏档、关键资源断档或 UI 完全无法判断下一步才阻塞阶段。
5. 不扩行动台、高压窗口、区域、长期成长线或完整菜单。

## 区域策略

- `核心区域 4 个`：基地、早期资源区、主要危险区、demo 终点区。优先扩面积、目标密度、资源和战斗节奏。
- `功能区域 4 个`：承载特定资源、设备材料、风险类型或回访目标。
- `过渡区域 4 个`：承载连接、氛围、少量采集和路线变化，不追求完整玩法密度。

参考《银河破裂者》的空间感，但不照搬大地图模板。现阶段只要求外出区域有可探索余量、资源点、危险压力和回基地理由。

## UI 策略

UI 当前进入必要开发项，不作为纯美术打磨处理。优先级：

1. 主 HUD：生命、防护、当前目标、当前区域、关键资源。
2. 地图 / 区域提示：玩家知道自己在哪、要去哪、为什么去。
3. 基地状态摘要：当前可制造 / 可升级、缺什么、升级收益。
4. 角色状态摘要：工具、攻击、防护、抗性、已生效模块。

已完成第一包：主 HUD 不再显示 `Prototype` 标题，高频目标提示和任务完成反馈已切到新区域口径。已完成第二包：HUD 左侧聚合当前目标和关键资源，右侧聚合基地摘要和角色状态；关键资源按当前任务、配方输入和建造消耗推导，基地摘要显示可制造 / 待制造项、缺料、完成后产物或设备加工状态，并已通过人工读法复核。玩家可见命名第一包已收束。当前包聚焦首小时内容厚度和必要短提示，不改 UI 结构。

不做完整菜单、设置页、背包大重构、完整装备栏、动画过场或大规模美术替换。核心稳定站先按最小 demo 终点处理：读取锚定桥稳定窗口和高压窗口归档状态，复用短战斗节奏设置阶段守卫，写入稳定数据后给出 demo 完成反馈；不重构 `base_action_state`，不新增第 4 个行动台分支。

## 节奏规则

个人开发阶段只做足以判断方向的完成度。一个阶段达到退出条件后，必须及时进入下一阶段；不允许因为 `P2` / `P3` 细节、局部读法、文案密度或状态字段洁癖无限打磨。

只让这些问题阻塞阶段：

- 崩溃
- 主线卡死
- 坏档
- 任务无法完成
- 关键资源断档
- UI 完全无法判断下一步

其他问题进入 backlog 或后续 polish。冷启动和命名包已通过后，首小时阶段只补既有核心区内容厚度和必要读法，不扩大成系统重做。
