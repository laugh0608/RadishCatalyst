## 区域策略

- `核心区域 4 个`：基地、早期资源区、主要危险区、demo 终点区。当前不再默认继续加厚，先用试玩判断断点。
- `功能区域 4 个`：承载特定资源、设备材料、风险类型或回访目标。只修阻塞理解或主线连续性的断点。
- `过渡区域 4 个`：承载连接、氛围、少量采集和路线变化，不追求完整玩法密度。

参考《银河破裂者》的空间感，但不照搬大地图模板。现阶段不继续横向扩大区域数量。

## UI 策略

UI 和场景表现进入可试玩呈现建设，不做纯美术打磨，也不只围绕提示修补。优先级：

1. 主 HUD：生命、防护、当前目标、当前区域、关键资源。
2. 地图 / 区域提示：玩家知道自己在哪、要去哪、为什么去。
3. 基地状态摘要：当前可制造 / 可补给 / 可整备、缺什么、收益是什么。
4. 角色状态摘要：工具、攻击、防护、抗性、已生效模块。

已完成 HUD 分区、设备面板、对象反馈、短条、基地摘要、出发口、核心站复测读法和首屏可读性第一轮。后续重点是统一全路线呈现：HUD 不压住主画面，场景地面和路线能读出前进方向，设备 / 资源 / 敌人 / 当前目标有稳定视觉语义，完成态和回基地理由能被玩家自然读到。不做完整菜单、设置页、背包大重构、完整装备栏、动画过场或大规模美术替换。

## 冻结与放宽

继续冻结：

- 前线行动台、候选、窗口复盘、高压窗口和 `base_action_state` 保持冻结，只修 `P0` / `P1`。
- 不新增第 13 区域，不平均扩 12 个区域，不继续给核心站完成态追加同构回访口袋。
- 不新增随机成功率、新货币、队员、完整装备栏、完整 `loadout`、联机入口或完整长期成长系统。
- 不迁移稳定数据 ID；旧 ID 先作为存档、任务和数据兼容层保留。

允许放宽：

- 允许以整段试玩呈现为单位调整 UI、场景、战斗反馈、路线压缩和节奏衔接；取样和自动检查用于验收整体体验质量。
- 允许首版 demo 级角色成长与战斗第一版，范围控制在少量明确差异，不扩成完整装备系统。
- 允许为维护工程边界拆分检查脚本、地图脚本、提示 formatter 或系统职责。

## 节奏规则

个人开发阶段只做足以判断方向的完成度。一个阶段达到退出条件后，必须及时进入下一阶段；不允许因为 `P2` / `P3` 细节、局部读法、文案密度或状态字段洁癖无限打磨。

只让这些问题阻塞阶段：

- 崩溃
- 主线卡死
- 坏档
- 任务无法完成
- 关键资源断档
- UI 完全无法判断下一步

其他问题进入 backlog 或后续 polish。本阶段主要工作是 Demo 可试玩呈现建设与完整取样验收，不再默认新增同类内容包，也不把局部读法问题单独升级为阶段主线。

## 当前默认验证

客户端相关改动优先执行默认检查：Windows 用 `pwsh ./scripts/check-client.ps1`，macOS / Linux / Git Bash 用 `sh ./scripts/check-client.sh`；该入口不启动 Godot。需要导入工程或运行项目自定义 GDScript 检查时，确认本机 Godot 可启动后加 `-WithGodot` / `--with-godot`。

涉及文档、规划、协作规则或仓库入口时额外执行：

Windows 用 `pwsh ./scripts/check-docs.ps1`、`pwsh ./scripts/check-text-files.ps1`；macOS / Linux / Git Bash 用 `./scripts/check-docs.sh`、`./scripts/check-text-files.sh`；最后执行 `git diff --check`。
