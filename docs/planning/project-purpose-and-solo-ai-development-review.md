# Project Purpose And Solo AI Development Review

更新时间：2026-07-12

状态：当前唯一活跃规划议题；五项决策产物主体已确认（见「已确认结论」），文档口径整改已执行，余项见「仍待确认」。实现开发仍暂停。

## 为什么现在暂停

RadishCatalyst 已经证明任务、资源、采集加工、存档、HUD 状态与纵切路径可以运行，但还没有证明当前产品目标能由一名个人开发者借助 AI，以稳定、可重复、可维护的方式做成目标品质。

表现层先后经历程序几何、SVG / `Polygon2D`、脚本生成栅格、独立 AI 切图、tile 场景组合和生成式宽幅场景板。最后两轮 `R2-A` 候选能够分别满足透视、晶体方位、路径或插槽，却不能同时满足精确空间、交互语义、HUD 避让和统一整景。继续追加提示词或接入代码只会把生产方式的不确定性转移到工程里。

因此当前决策不是再选一个视觉补丁，而是暂停实现，重新确认项目为什么存在、什么结果值得完成、产品结构是否适合个人长期维护，以及 AI 应承担哪些职责。

## 已确认的事实

- 核心玩法逻辑和运行时系统具有复用价值，不因表现路线失败而失效。
- 当前首版 Demo 同时要求 ARPG 移动战斗、基地化工、12 区纵切、状态叙事、统一场景美术和复杂 HUD，对个人项目形成多专业叠加。
- AI 擅长快速探索、代码实现、结构化数据、检查、文档整理和受控变体，但不能仅靠自然语言稳定保证多约束场景的精确空间关系与长期资产一致性。
- “生成一张完整场景，再为交互留插槽”与“运行时场景需要精确路径、遮挡、状态显隐和 HUD 安全区”存在结构冲突。
- 自动检查全绿只能证明工程仍可运行，不能证明产品目标、画面介质或开发方式成立。
- 现有参考图表达了理想气质，但尚未证明它适合作为当前人力、工具与资产管线下的可执行生产基线。

## 本次复核必须回答

### 1. 项目目的

- 第一目的究竟是完成一款可持续扩展的商业游戏、做一段可玩的个人作品、验证“基地服务冒险”的设计、建立异星化工 IP，还是探索个人 + AI 的游戏开发方法？
- 哪一个结果是第一优先，哪些只能作为副产品？
- 什么情况下即使功能更多，也应判定项目偏离目的？

### 2. 产品形态与体验承诺

- 当前 2D / 2.5D 工业科幻 ARPG 是否仍是最适合的载体？
- 首个可交付结果应持续多久、包含多少玩家动词、多少场景和多少状态变化？
- 化工基地、探索战斗、角色成长和未来联机中，哪些是不可替代的核心，哪些可以延后或删除？
- 是否需要从连续大地图改为少量精制场景、节点式行动、关卡式远征或其他更可控结构？

### 3. 个人开发者与 AI 的职责分工

- 人负责产品判断、体验取舍、参考选择、最终视觉审阅和不可逆决策。
- AI 适合承担代码与数据实现、重复性编辑、候选探索、文档同步、测试与可验证的局部资产处理。
- 对透视统一、整景构图、角色动画、视觉叙事等高一致性工作，必须决定使用成熟素材包、可编辑 3D / DCC 管线、人工绘制 / paint-over、外部协作，或主动降低视觉目标。
- 任何新方案都要说明失败后如何退出，不能把“继续生成更多候选”当作生产管线。

### 4. 工程与内容结构

- 现有纵切系统中哪些是产品核心，哪些只是早期试验累积？
- 是否继续维护 12 区地图和多层表现脚本，还是收束为更少、更清楚的场景与系统边界？
- 新结构应让玩法坐标、场景构图、HUD 和资产生产从同一份可编辑布局出发，避免分别设计后再强行对齐。
- 必须决定现有代码、素材和文档是保留复用、归档、重写还是停止维护；不默认整仓推倒，也不因沉没成本强行保留。

### 5. 可持续生产方式

- 新介质必须先证明能稳定生产第二张、第三张，而不只做出一张偶然成功的封面图。
- 需要明确时间预算、现金预算、工具依赖、授权边界、可编辑源文件和返工成本。
- 美术方向必须能由个人持续审阅和维护；如果需要同时承担环境概念、角色、动画、UI、技术美术和关卡美术，应主动缩减产品承诺。

## 需要形成的决策产物

复核不是继续写大量设想文档。重新开工前只需要形成以下可执行结论：

1. 一页项目章程：第一目的、目标玩家、核心体验、明确不做和完成定义。
2. 产品结构图：首个交付版本的场景数量、玩家动词、系统边界和体验时长。
3. 个人 + AI 生产协议：人和 AI 各自负责什么，哪些工作必须依赖资产包、DCC、人工或外部协作。
4. 介质证据计划：先证明哪一项最危险的生产能力，成功与失败证据是什么；未证明前不恢复大规模实现。
5. 仓库处置方案：现有系统、场景、美术、检查和文档分别保留、冻结、归档或替换的边界。

## 已确认结论

2026-07-12 起由萝卜SAMA逐项确认；未列入项仍为待决。

### 第一目的（已确认）

证明产品可行性：产出一段 20 到 40 分钟、可被朋友完整玩完并识别为“一款游戏”的可玩切片。商业化不作为当前目的，个人 + AI 开发方法探索只作为副产品。

### 美术介质（已确认）

- 放弃写实 2.5D 整景路线；宽幅参考图与反应器锚点降级为气质参考，不再作为任何验收对照。
- 切换为像素 + 2D 俯视网格，采用 3/4 立面读法；一致性来自生产前锁定的机械约束（固定网格、限定调色板、统一光向），由脚本归一强制，允许人工逐像素修补。
- 参照系：星露谷（基地经营节奏与亲和力）、Factorio（网格与自动化纪律）、银河破裂者（基地建设与 ARPG 战斗融合的循环，仅取玩法不取其 3D 画面管线）、CrossCode 式“像素世界 + 二次元对话立绘”。
- 差异化元素：高分辨率二次元立绘只用于对话与角色界面等 UI 层，世界层保持纯像素，两种介质分层不混排。

### 网格与细腻度口径（方向已确认，档位待证据轮）

- 玩法网格 32px 定死；网格是玩法与碰撞单位，不是精灵分辨率上限，建筑按 2x2 / 3x3 起占多格。
- 细腻度由相机虚拟分辨率与作画密度决定：默认瞄准 960x540（1080p 整数 2 倍），证据轮以同一批素材对比 2 倍 / 3 倍取景后定稿。
- 上限口径：停在“仍可人工点修、仍可脚本强制一致性”的档位，不追 HD 像素插画档。

### 介质证据计划（已确认，先于任何引擎实现）

1. 锁定网格、调色板与光向规范。
2. 第一屏证据：同一屏内地形 + 3 台设备 + 角色 + 4 帧行走。
3. 重复性证据：第二、三屏（新设备与新地形变体），三屏并排无违和，且不了解项目的人能识别为一款游戏。
4. 立绘类别单独小样：1 个角色 x 3 个表情差分的一致性验证。
5. 失败退出：同类两轮不成触发既有决策闸门，退向扁平几何风或 CC0 像素包基底；图像会话遵守单会话最多 3 张等既有稳定性约束。

### 产品结构（2026-07-13 已确认）

- 首个交付版：单基地场景 + 单远征小区域，5 到 7 个玩家动词，20 到 40 分钟完整体验。
- 12 区纵切与多区域大地图降级为长期愿景，不作为首个交付版结构；对应文档已归档。
- 系统层运行时（任务链、存档、资源链、采集 / 加工、HUD 状态）保留复用，换皮接入新结构。

### 个人 + AI 生产协议（2026-07-13 按建议稿采纳）

- AI 承担：代码与数据实现、检查与归一化脚本、像素出稿、文档同步、受控局部资产处理。
- 萝卜SAMA承担：产品判断与体验取舍、候选选稿、逐像素修补、编辑器构图、最终视觉验收和不可逆决策。
- 图像生成会话稳定性约束不因新介质放宽；架构级口径变更仍按决策闸门升级。

### 仓库处置（2026-07-13 已确认并执行）

- 已执行：约 60 个旧 features 专题归档至 `docs/archive/features-demo-v1/`；12 区与纵切规划文档归档至 `docs/archive/planning-demo-v1/`；上位定位、视觉方向、美术生产真相源、流程闸门、规划入口与索引全部切换像素口径；新建 [Pixel Art And Grid Standard](../reference/pixel-art-and-grid-standard.md) 为介质机械真相源。
- 冻结保留：客户端代码（含旧视觉层）与已接入旧素材暂不删除；介质证据轮通过、首个切片专题成立后，再定保留 / 删除清单。
- 保留原貌：`docs/devlogs/`、`docs/archive/` 与失败批次候选作为历史证据不改写。

### 一页章程建议稿（2026-07-13 由 Claude 起草，待萝卜SAMA定稿）

第一目的已确认（证明产品可行性），以下补齐其余四要素：

目标玩家：

- 切片阶段：萝卜SAMA本人与朋友圈试玩者；不预设自动化游戏经验，无人指导也能在 40 分钟内走通。
- 长线定位：喜欢“自动化基地 + 动作冒险”混合体验的单机 / 小圈子联机玩家（Factorio、Rimworld、Mindustry、星露谷玩家群的交集），能接受像素低保真，在意系统咬合与成长反馈，对二次元人物叙事不排斥。
- 不是：追求 3A 画面的玩家、纯 MMO 社交玩家、要求真实化工仿真的专业向玩家。

核心体验：

- 一句话：在危险异星上，把一座废弃化工前哨亲手拉回运转，用它产出的装备与补给走进更深的禁区，再把禁区的收获带回来壮大基地。
- 节拍要求：每 10 分钟内，工程感（修好 / 接通 / 产出一样东西）、冒险感（一次有风险的外出与带回）、成长感（角色或基地肉眼可见变强）至少各发生一次。
- 化工特色以“看得懂的配方链 + 优化有回报”表达，不做专业考试；污染既是化工代价也是战斗压力来源，构成题材闭环。

明确不做（切片与当前阶段）：

- 不做联机（仅存档结构预留）、不做多星球、不做 12 区大地图。
- 不做完整科技树 / 技能树；切片只保留 1 条 3 到 5 节点的短升级链。
- 不做剧情分支、过场动画与配音；叙事只用开场引导、立绘对话和环境讲述。
- 不做守家敌潮 / 塔防模式；战斗只有外勤遭遇与终点守卫。
- 不追星露谷 / CrossCode 级像素精度，定档“低保真但成立”；世界层不混高清素材，立绘只进对话与角色界面。
- 不做手柄 / 触屏 / Web / 移动端；切片只交付 Windows 桌面。

完成定义（全部满足即切片完成）：

1. 一位不了解项目的朋友，无人指导 20 到 40 分钟从新档玩到切片终点：修复前哨核心 → 建立首条化工链 → 远征区带回关键样本 → 完成阶段目标。
2. 过程中他能用自己的话说出“我在干什么、为什么出门、为什么回基地”。
3. 全程像素资产读法，无 debug 色块、流程图地图或长说明依赖；HUD 只承载目标、状态和交互提示。
4. 中途退出再读档可继续；主线零不可逆卡死，全程零崩溃。
5. 试玩者能回答“愿不愿意再玩一段、最想要什么”；无论答案如何，可行性证明即成立，继续、调整或停止都有依据。

玩家动词（产品结构细化，6 个）：移动、采集（矿物 / 样本）、战斗（攻击 + 闪避）、建造 / 放置设备、加工（配方生产）、交互（修理 / 装备 / 写入）。

## 暂停期间边界

- 不修改 `client/`、`server/`、玩法数据、场景、HUD、存档或检查脚本。
- 不生成新图片、不审阅新素材批次、不接入 `R2-B` / `R2-C` / `R2-D`。
- 不推进 `P2`、`P3`、`H1` 到 `H4`、试玩准备、发布或玩法扩展。
- 不为“保持进度”整理工程、删除旧层、重写架构或补自动检查。
- 允许只读审阅仓库、分析历史证据、比较可选产品形态与生产管线，以及在萝卜SAMA确认后更新本复核文档。

## 恢复开发的条件

只有萝卜SAMA明确确认上述五项决策产物，并指定新的当前专题、首个实现包、成功证据和失败退出条件后，才恢复代码、素材或 Godot 实施。在此之前，`R2` 与原首版 Demo 路线均视为暂停，不自动续接。
