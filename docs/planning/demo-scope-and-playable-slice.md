# Demo Scope And Playable Slice

更新时间：2026-06-10

## 用途

本文承接「首版 Demo 范围冻结与可玩切片收束」阶段，只回答五件事：

- 12 个 demo 区域如何封顶和分层。
- 第一批 3 到 4 个核心区域如何准备扩尺度。
- 核心稳定站如何作为第 12 区域和 demo 终点落地。
- UI baseline 覆盖哪些可读性问题。
- Demo 内容包如何开工、收口和避免用提示替代开发。

本文不替代 `docs/planning/current.md`。阶段边界、当前不做和退出条件仍以 `current.md` 为准。

## 计数口径

首版 demo 区域按玩家可识别、可回访、可承载目标的区域计数。它们应被理解为首颗星球上的不同地区，而不是一个遗迹或地下副本里的层层房间。当前 HUD 地图标记已有 12 个区域：基地、晶体、污染、封锁遗迹、裂相脊、回声台地、盐壳浅滩、碎晶沟谷、风蚀管廊、锁相框架、锚定桥、核心稳定站。

`region.locked_ruin_gate` 继续作为污染边界到遗迹外圈之间的门槛 / 路标处理，不扩尺度、不承载独立玩法密度，也不占本轮 12 区域扩尺度名额。客户端数据可以继续保留该区域 ID 以兼容任务、存档和提示。

区域显示名要让玩家先读懂“这是星球上的哪类地貌 / 这里大概危险在哪里”，再承载科技感或远古遗迹感。后段区域不继续使用“井心、井纺、井纹、井系”这类只对任务链内部有意义、且暗示垂直副本层级的命名。

第 12 个区域确定为：

```text
region.demo_stabilization_core / 核心稳定站
```

它不是继续向东追加相位井断面，而是首版 demo 的终点地区：把前线行动、高压窗口和基地加工收益收束为一次明确的阶段目标，例如修复核心设备、稳定第一条生产链，或击败守卫后打开稳定通道。

分层规则：

- 核心区域要有面积、路线选择、目标密度、资源和危险节奏，不能只是任务节点房间。
- 功能区域只承载一个清楚系统价值，不追求完整地图密度。
- 过渡区域用于连接、节奏变化和少量采集，不继续横向追加独立机制。
- 这些区域是星球地表 / 近地表的地区网络，可以有门槛和推荐顺序，但不按地下楼层或单一副本深度命名。
- “遗迹”按一个有限地区处理，类似可探索短副本；探索完封锁遗迹后，后续区域转入星球异常地貌和旧前哨 / 远古结构混合区，不再都叫遗迹内部区域。
- 当前 ID 可先保留，玩家可见名称和规划名称先按上表收敛；若后续改数据 ID，必须同时处理存档兼容、任务引用、HUD 地图标记和静态数据检查。
- 锚定桥后的前线行动台、窗口复盘、高压窗口和 `base_action_state` 已冻结，只作为 demo 终点的前置收益和状态来源。

## 主线串联与命名依据

首版 demo 的地区命名应服务三个主线问题：

1. 这个星球为什么不稳定。
2. 人类前哨为什么失败。
3. 遗迹或旧设施到底在稳定什么。

区域串联不是“越走越深的副本”，而是前哨周边逐步暴露星球异常机制：

```text
基地平台恢复生存能力
-> 晶体矿脉区建立第一条资源链
-> 污染边界区证明污染不是普通泄漏
-> 封锁遗迹留下旧结构或旧前哨事故线索
-> 裂相脊显示地壳与异常能量正在撕裂
-> 回声台地保留曾被观测或干预的残留信号
-> 盐壳浅滩展示污染和化学沉积造成的危险地貌
-> 碎晶沟谷把高价值晶体与异常能量耦合起来
-> 风蚀管廊暴露旧前哨设施或远古工艺通道
-> 锁相框架说明有人或某种系统试图压住异常相位
-> 锚定桥把前线行动结果接回稳定工程
-> 核心稳定站收束为修复、稳定或打开后续通道的 demo 终点
```

这些解释是阶段规划口径，不是完整剧本对白。后续任务名、HUD 地图标记和本地化文本应优先沿这条口径收敛。

## 第一批扩尺度区域

优先扩 4 个核心区域：

| 区域 | 扩尺度目标 | 资源 | 危险 | 回基地收益 | 回访理由 |
| --- | --- | --- | --- | --- | --- |
| 基地平台 | 从单点设备区变成可读后勤 hub | 基础零件、溶剂、设备产物 | 无直接战斗，压力来自缺料、补给耗尽和设备停机 | 加工、补给、模块、储存箱整备、核心设备进度 | 查看缺料、完成制造、确认下一目标 |
| 晶体矿脉区 | 从采集点扩成首个外勤小场 | 晶体矿物、残骸、异常样本 | 低强度敌人与路线绕行 | 反应器校准、修复凝胶、过滤模块前置 | 补资源、补样本、教学采集战斗 |
| 污染边界区 | 从门槛扩成第一危险场 | 污染沉积物、异常样本、精英节点收益 | 防护消耗、污染敌人、地块阻挡 | 抗污染药剂、处理点、通行能力 | 采样、清障、压制污染源点 |
| 核心稳定站 | 新增为 demo 终点场 | 稳定核心读数、高压窗口稳定数据、核心修复材料 | 阶段守卫、环境高压、最终门槛 | 修复核心设备或打开稳定通道 | 完成 demo 主线并展示后续钩子 |

第一轮不扩 12 个区域。功能区和过渡区只补必要路线、资源点、门槛提示和地图标记，避免平均摊薄。

## Demo 内容包准入与完成检查

本阶段借鉴外部工作流时只采用轻量清单，不引入完整多 agent 体系、生产目录或故事文件。

开工前必须回答：

- 玩家实际能做什么，动作落在哪个既有区域、设施、对象或敌人上。
- 复用哪些已有资源、配方、状态或任务，不新增哪些系统和范围。
- 完成后玩家为什么回基地、继续外出或改变准备方式。

完成时必须具备：

- 场景对象或可操作入口已落地，不只改文字提示。
- 运行时逻辑会改变世界状态、库存、角色状态、任务或承压结果。
- HUD、设备面板、对象反馈或短条能解释收益、缺料、去向或准备差异。
- 存档来源、兼容读取或不需要存档的理由明确。
- `check-client` 或对应单项检查覆盖主路径；文档改动同步周志和必要设计源。

阶段门禁只给建议 verdict，不用 `P2` / `P3` 阻塞推进。只有崩溃、主线卡死、坏档、任务无法完成、关键资源断档或 UI 完全无法判断下一步时，才阻塞内容包收口。

## 核心区域第一轮尺度规划

第一轮尺度规划只定义地图扩展方向、目标密度和检查口径，不立刻承诺完整美术、完整敌群生态或新增系统。4 个核心区域应形成“基地整备 -> 外出采集 -> 污染推进 -> demo 终点”的可试玩路径。

| 区域 | 首轮尺度目标 | 路线结构 | 目标密度 | 检查口径 |
| --- | --- | --- | --- | --- |
| 基地平台 | 从单设备点扩成可读后勤 hub | 中央加工区、补给边、回投 / 出发边和核心进度提示位 | 2 到 3 个常用设备状态、1 个当前缺料提示、1 个下一目标出口 | 玩家回基地后能在 10 秒内判断缺什么、能做什么、下一步去哪 |
| 晶体矿脉区 | 做成首个外勤小场，而不是一排采集点 | 主路采集线、侧向残骸线、轻敌巡逻线 | 3 到 4 个晶体 / 残骸点、1 到 2 个低压敌人、1 个样本目标 | 新玩家能学会采集、战斗和带资源回基地，不需要读长说明 |
| 污染边界区 | 做成第一危险场和处理点扩建证明 | 安全入口、污染阻挡带、处理点施工位、遗迹门前压强点 | 多处污染采样 / 清障点、处理点地基与过滤器目标、污染残核和门前压力敌人 | 玩家能感到过滤模块、修复凝胶和抗污染药剂会改变二次外出结果，且知道回基地制造能改变通行能力 |
| 核心稳定站 | 做成 demo 终点场，而不是单个交互物 | 入口确认段、守卫压制段、侧向回收点、核心设备平台 | 1 个入口目标、1 个阶段守卫、1 个核心写入目标、1 个完成反馈 | 玩家能理解高压窗口收益被用于稳定核心，并看到明确 demo 收束反馈 |

首轮实施顺序：

1. 先定 4 个核心区域的地图边界、主路长度和可回访点，不调整 12 区域总数。基地平台、晶体矿脉区、污染边界区和核心稳定站第一轮实际重排已完成。
2. 再补资源点和危险点密度，避免每个区域只有单任务节点。
3. 最后复核 HUD / 地图提示是否能在区域间说清“为什么去、带什么回、回基地做什么”。

冻结边界：

- 不扩展行动台、窗口复盘、高压窗口或 `base_action_state`。
- 不新增第 13 区域，不把功能区和过渡区平均扩成同等密度。
- 不把核心稳定站做成完整大迷宫；它只服务首版 demo 终点和后续钩子。

## Demo 主线终点候选

首版 demo 终点只选一个主目标，推荐优先级：

1. 修复稳定核心设备：最贴合基地建设和 demo 完成感。
2. 完成第一套稳定生产链：更强调化工基地，但需要 UI 解释足够清楚。
3. 击败阶段守卫并打开稳定通道：战斗反馈最直观，但不要变成纯打怪结尾。

建议落点：核心稳定站内先打阶段守卫，再把前线带回的稳定数据写入核心设备，最后打开稳定通道。这样战斗、基地加工和阶段终点都能同屏成立。

## 核心稳定站最小落地方案

`region.demo_stabilization_core / 核心稳定站` 是首版 demo 的第 12 区域和终点，不再引入第 4 个行动台分支。它只读取已完成的主线、锚定桥稳定窗口和高压窗口归档状态，把这些收益收束成一段明确目标。

| 环节 | 最小落地 | 不做 |
| --- | --- | --- |
| 入口条件 | 完成锚定桥稳定窗口校准，并归档高压窗口稳定数据；地图提示从锚定桥指向核心稳定站 | 不新增随机钥匙、队员或长期声望门槛 |
| 区域内容 | 一条主路、一个侧向资源回收点、一处核心设备平台和一名阶段守卫 | 不做完整大迷宫或 12 区平均扩尺度 |
| 阶段守卫 | 复用现有短战斗节奏，守卫压住核心设备写入；击败后允许写入稳定数据 | 不新增复杂 Boss 阶段、掉落池或完整技能树 |
| 核心写入 | 玩家在核心设备写入稳定数据，消耗或标记前线归档收益，生成 demo 完成反馈 | 不重构 `base_action_state`，不新增高压窗口分支 |
| 完成反馈 | 显示“核心稳定站已接管第一条稳定通道”，解锁后续钩子但不继续展开 | 不开启第二星球、联机或完整后续章节 |

首轮客户端实现顺序应为：

1. 已补 `regions` / 地图标记 / 本地化名 / 地图边界识别，让第 12 区域可被 HUD 和任务指向。
2. 已补 4 个任务节点：进入核心稳定站、整备核心稳压缓冲包、击败阶段守卫、写入核心设备。
3. 已补 demo 完成反馈、自动检查、`S21` 开发复测基线和人工短跑记录；阶段复核已通过，后续转入 `S0` 冷启动试玩审计。

若实现时高压窗口稳定数据尚未物品化，可以先按 `base_action_state` 中的高压窗口归档状态判断入口；只有当 UI 需要清晰展示“已携带的数据”时，再新增单个稳定数据物品，并同步存档兼容和检查。

## UI Baseline 状态

UI baseline 的目标是“不像 debug 草稿”，不是完整 UI 换皮。

## UI 信息分层

| 信息 | 显示策略 | 数据来源 | 收口标准 |
| --- | --- | --- | --- |
| 生命 / 防护 / 污染承压 | 常驻边缘显示 | `CharacterState` 与承压规则 | 玩家能判断是否需要补给、药剂或撤回基地 |
