## 用途与范围

本轮只核对保留报告、来源哈希、检查入口和已有审图记录，新增计划与索引；不运行 Godot、不改供给 / schema / 产品代码，也不扩大玩法。目标是让后续验证有可执行顺序、清楚的通过条件和独立结论。

## D4-P0 / P1：当前普通负载验证方案

已确认的入口缺口：`client/scripts/checks/factory_statistics_performance_check.gd` 明确拒绝非 schema 2；现有 Shell / PowerShell `check-factory-statistics-performance` 仅提供 V2 `prepare/window`。本篇不提供伪装已支持 V5 的执行命令。新增支持应保持明确版本校验和真实 codec，不删除版本检查或改快照版本号绕过拒绝。

1. **来源与负载**：从 C 成功完成恢复批次保留的合法快照派生，记录提交、来源路径 / SHA-256、规则 / 地图 / 供给身份、实体数及每种状态数量。C 的 G4 用尽是正确状态；若要持续交付制剂，应在独立准备副本中通过正式空载配置 / 重置操作开放接收，并记录前后变化。不修改自然 C 证据和亲测副本，也不据 G4 停料认定性能失败。
2. **有效工作检查**：保留双原料、两类加工、A / B 附件与真实电网；预检实际活跃生产和收货空间。若准备后满仓 / 回压，按合法取放或调整布局形成明确的可持续工况，记录负载变化，不能每帧清仓、无限供电或只测空机器。空载 / 堵塞可另作诊断对照，不能替代工作负载。
3. **准备与采样分离**：仅准备阶段允许真实模型显式推进 600 秒，校验全部 600 个完整桶和当前半桶；准备后保存严格可读的唯一快照。三段分别由正式 Boot 在新的双根恢复同一快照，统计窗口固定 10 分钟；采样时按真实活动时钟推进，不加速、不清历史、不隐藏保存尖峰。
4. **窗口条件**：请求 1920×1080、固定相机 / 缩放、正式渲染器与画质，记录实际窗口、3D 与截图像素。准备页手动开始，采样连续前台；失焦或关闭终止整个序列，保留部分结果并换新 batch 重试，不抢焦点或拼接通过。普通对照沿用各 45 秒，不能外推最大化或规模长测。
5. **检查与产物**：每段报告帧 / 单步 p50、p95、p99、最大值、积压、活动时间与模拟时间及余量、分物料实际产出 / 入仓、自动保存次数与耗时、载入耗时、内存和绘制调用。严格沿用采样器的时钟与积压判据；保存帧计入总帧统计，同时单列尖峰。缺少自动保存或真实交付不得写通过。
6. **失败处理**：先排除错误来源、失焦、空负载和驱动误报，再判断产品问题。真实持续慢帧才启用现有分析器；额外分析器数据单列，回到正式配置重验后才谈通过，不因历史未归因问题先追加渲染补丁。

9 月 29 日 V2 普通对照为 57 实体、完整 600 桶、三段各 45 秒；帧 p95 8.757 / 9.004 / 8.850ms，单步 p95 0.298 / 0.264 / 0.282ms，保存尖峰已计入。它继续作为历史对照。V5 有自动电网与共同物流 / 准入口路径，因此计划一次当前版本对照有明确风险依据；不能把数值差直接归因于某个功能，负载与版本同时变化需注明。

## D4-S0 / S1：工程规模合同的决策边界

首档沿用基础工厂目标：100 台生产 / 仓储设备、1,000 带、最多 1,000 个在途物品；电源、节点和附件应另列类型与数量，不能挤掉生产设备后仍称同规模。100 台放置不等于 100 台持续加工，必须按真实运行状态分列。历史 25 条基础产线夹具只有 25 台采集器、25 台工作反应器、25 台备用反应器和 25 仓，不能暗改口径。

建议采用**独立工程供给身份与专用检查入口**，普通新建继续 326 实体且不出现工程选项；不放宽所有世界的上限。具体合同须先明确以下四项，尚未授权改动产品边界：

- 地图 / 矿点与足印能否承载真实采集源和 1,000 带；现有少量矿点不能凭空放置历史 25 个采集器。若需要工程地图身份，与供给一起明确隔离和拒绝规则，禁止暗增普通矿点或开放矿壳。
- 足够的有限电源、节点覆盖与真实连通图，完整统计与电量记账；不得用预供电掩盖现行电力开销。供电数量根据确定的配方 / 活跃负载计算，当前 240 kW 不能照搬为全规模供能保证。
- 合法供给、构件 / 物料守恒、工程身份的保存 / 恢复和严格拒绝；schema 5 是否能以明确身份白名单扩展，须核对 codec 后在架构合同中决定，不预先声称无需改版本。
- 实际多原料、分流 / 汇合竞争、准入口及回压工况的数量，真实工作与稳定满载分开；初始物料 / 历史准备明确标夹具，不冒称自然首程，采样不能冻结货物或反复注入。

合同确认与状态 / 跨进程检查通过后，先短测排除明显问题，再沿原四档窗口 / 最大化 × 局部 / 拉远各 450 秒，共 1,800 秒连续前台采样。正式画质、60 FPS 目标、16.7ms 帧 p95 / 10ms 单步 p95 和无持续积压保持；各档起始原图、实际分辨率、自动保存、原始帧 / 步样本与中断原因一并保留。若需统计页叠加下的规模对照，另做同状态关闭 / 物料 / 电力短段，不用三段 45 秒替代四档长测。

## D4-U / X：亲测与平台证据

亲测分两类：[统计专题的空世界四步](../features/factory-production-statistics-v1.md#d4-普通供给对照与亲测准备)记录首次理解、建线、等待、两次开路与独立诊断；[C 检查点](../features/factory-conveyor-combination-v1.md#playtest)专测双原料去向、7+1、停止接收仍排空、8/8 与显式重置及一次堵塞修复。检查点不作首次游玩计时。A / 交互反馈同表收集，优先整改真实阻塞，不要求用户背坐标或按自动脚本复演。

每条反馈记录“起点 / 用户目标 / 实际操作 / 看到的反馈 / 能否独立恢复 / 耗时与困惑 / 证据 / 整改结果”。20–40 分钟仍是设计目标，不把自动化 444 秒、读过说明后的熟练路径或中途存档试玩当达标证明。

平台执行前登记 OS、CPU、GPU、内存、屏幕缩放、Godot 版本 / 哈希、渲染器、画质、提交与脚本版本；目标硬件未确定前保持待验，Windows 可用环境与目标性能机器分开。先跑 `pwsh ./scripts/check-repo.ps1` 与 `pwsh ./scripts/check-client.ps1` 静态，再按现有 PowerShell 入口覆盖 V5 状态 / 独立 Boot 继续和关键原生界面；缺失入口先补工具并检查，不能声称 Shell 结果覆盖 PowerShell。窗口尺寸与路径 / 锁 / 备份等平台风险单列；性能仍用上述同负载标准。
