# Base Action Choice Prototype

更新时间：2026-05-24

## 目标

「基地行动选择原型」验证一件事：玩家在基地确认下一趟短行动前，能从 2 到 3 个方案中做出可感知取舍，并在同一趟前线目标和返回反馈里看到结果。

当前稳场补给 / 相位测绘 / 压力清障三选一已完成首轮自动验证，并已升级为 2026-05-21 首轮通过的「基地行动调度与整备系统」：行动台、队列、清障分支和风险收益快照都已进入运行路径。后续扩展只要服务出发前决策，就可以继续沿用这套系统；不得退回堆同构短行动。

## 首轮方案表

| 基地行动前选项 | 玩家选择含义 | 前线差异 | 返回收益 | 失败兜底 |
| --- | --- | --- | --- | --- |
| 稳场补给 | 把本趟行动定位为低风险补给回收。 | 前线只读取 / 标记一处补给投放点，不额外刷战斗目标；路线靠近井系桥前线第三锚点。 | 回基地解析为少量 `基础零件`、`修复凝胶` 或下一趟短行动补给，强调基地把前线回执转成整备资源。 | 读点未完成时不消耗选择；返回基地仍保留该方案，可重新回投读取，不造成资源断档。 |
| 相位测绘 | 把本趟行动定位为侦测与路线确认。 | 前线需要读取两处相位测绘点，位置比补给方案更分散，但不强制战斗；HUD 可提示测绘进度。 | 回基地解析为下一趟行动提示、局部目标显形或一次前线回投默认点确认，强调信息收益。 | 只读到一处时给出“粗测记录”，允许回基地解析成较弱提示；另一处保持可读，避免卡任务。 |
| 压力清障 | 把本趟行动定位为高风险清障。 | 前线需要清掉一处压力钉 / 小型扰动体后读取清障回执；风险来自一次短战斗或危险点。 | 回基地解析为额外防护 / 抗性补给、稳定碎片或更高价值回收，强调风险换收益。 | 清障失败不回滚已确认行动；已清目标保留，敌压重试从前线锚点开始，不要求回基地重做。 |

## 首版实现口径

- `S19` 之后已接入一轮选择：基地行动台展示稳场补给 / 相位测绘两个互斥选项，选择后立即进入对应前线短目标。
- 当前行动调度状态已进入 `WorldState`：稳场补给反馈会准备低风险补给计划，相位测绘反馈会准备信息侦测计划；两类反馈会写入当前计划槽，玩家需先在前线行动台确认出发整备槽，再由下一次相位回投消耗。
- 行动队列最小版已接入：行动台会展示当前计划槽和下一计划候选，方案终端可替换下一候选，但不会改动当前已准备的出发槽；本趟相位回投只执行已确认的风险收益快照，随后下一候选会晋升为当前可确认计划，并滚动生成新的下一候选；晋升后的计划可继续确认和回投执行。
- 稳窗回访、补给短行动和巡线短行动的确认目标已统一到前线行动台；旧补给 / 巡线分台仅保留定义与存档兼容，不再作为玩家可见的必经确认点。
- 三个方案共享“基地选择 -> 前线短目标 -> 回基地基础反应器解析反馈”的骨架，只让目标数量、风险和收益产生差异；行动台、方案终端和相位回投台已统一展示目标、收益、风险与代价。
- 当前首轮已实现 `稳场补给`、`相位测绘` 和 `压力清障`；清障先只清一处前线压力扰点，不引入新战斗系统。
- 返回收益只使用现有资源、补给、HUD 地图 / 任务提示能力；不得为首版新增长期成长货币。

## 后续承接

- 阶段收口复核已于 2026-05-21 通过；后续扩展必须继续复用已有整备槽、行动候选和风险收益计划。
- 稳场补给反馈应影响下一次补给包、资源缓冲或前线补给标记。
- 相位测绘反馈应影响下一次路线提示、地图标记、回投建议或目标预告。
- 队列、取消 / 改签、轻量整备模块和更完整风险等级不是禁区；只有当它们不能服务当前基地整备目标时才暂缓。队员、随机成功率和新成长货币仍暂缓，装备 loadout 只允许作为单一变量的小原型验证。

## 下一循环原型

暂定方向为「整备结果驱动同一前线窗口」：玩家仍在行动台确认补给 / 测绘 / 清障计划，但下一趟不再进入彼此孤立的短行动，而是把已确认计划应用到同一个井系桥前线异常窗口。

| 已确认计划 | 同一前线窗口变化 | 返回反馈 |
| --- | --- | --- |
| 低风险补给 | 前线窗口目标更短，只读取补给缓存并带回稳定样本。 | 回基地整理成资源缓冲和下一轮整备确认依据。 |
| 信息侦测 | 前线窗口显形两处路径读数，允许玩家确认更清楚的风险来源。 | 回基地整理成目标预告、地图提示或回投建议。 |
| 压力清障 | 前线窗口保留一处高风险扰点，清除后降低下一轮风险。 | 回基地整理成防护整备和后续清障收益。 |

实现边界：

- 复用前线行动台、当前计划槽、下一计划候选、风险收益快照和相位回投出发整备槽。
- 新增目标应是“同一窗口的三种解法”或复盘后的新取舍，不是同构轻量行动。
- 首版不同时引入队员、装备 loadout、随机成功率、长期派遣收益或新成长货币。
- 自动检查至少覆盖：已确认计划影响窗口目标、返回反馈写入 `WorldState`、候选轮转不被破坏、未确认 queued 状态不会被顺带执行。

2026-05-23 复核结论：相位回投执行已确认整备计划后，会激活 `整备异常窗口`；窗口提示、处理结果和 `WorldState` 反馈按补给 / 测绘 / 清障计划变化。人工复核发现并修复自动循环和地图目标问题：处理窗口后 HUD / 地图指向回基地，行动台先归档本趟反馈，不自动派发下一趟。

## 窗口复盘整备

归档后的第一版扩展已接入：行动台把本趟窗口反馈保存为归档摘要，并重新开放当前计划槽 / 下一计划候选。玩家必须再次在前线行动台确认出发整备槽，相位回投才会执行新的风险收益快照；未确认候选不会被顺带执行。

首版只复用既有三类计划。稳定样本、路线读数和扰动残压会改变行动台预告与候选说明，不新增同构短行动；连续两轮复盘整备已纳入自动检查，第二次归档后收口不再循环。

2026-05-23 轻量整备模块小变量已接入：低风险补给默认携带 `稳相垫片`，相位测绘默认携带 `回波透镜`，压力清障默认携带 `防护涂层`。模块不新增资源、队员、loadout 或随机成功率，只随风险收益快照进入行动台预告、出发确认、相位回投提示和同一前线窗口反馈，用来加强玩家的出发前判断。2026-05-24 起，三类模块的窗口目标、处理结果、完成态收益和下一轮承接文案改为结构化结果表驱动，并在出发前预览窗口结果，避免模块只停留在展示文本。

同日，确定性风险拆解已接入：行动台和相位回投提示会把 `低` / `中` / `高` 风险拆成目标密度、路线扰动和防护消耗三项摘要。该拆解只解释已确定的行动差异，不引入随机成功率。

风险 / 模块摘要随后改为三层展示：行动台作为完整决策入口，概览层显示计划、模块和风险等级，判断层显示目标密度、路线扰动和防护消耗，结果层显示目标、收益和代价。

2026-05-23 可读性复核后，候选终端、相位回投台和同一前线窗口不再完整复制行动台三层文本，只显示计划、模块、压缩风险摘要和当前执行收益 / 目标。风险收益快照仍使用同一数据源，展示治理只改变信息密度，不新增玩法变量。

随后补强反馈承接：稳定样本、路线读数和扰动残压都会在行动台当前计划里转成下一轮预告。信息侦测窗口归档后，会把既有路线风险说明转成目标预告；补给样本和清障残压则分别说明资源缓冲与风险回落如何影响下一轮补给 / 测绘 / 清障判断。候选终端沿用同一归档反馈，不新增短行动、资源或随机变量。

2026-05-23 收口复核：自动检查已覆盖三类计划、同一窗口反馈、当前计划 / 候选预告、第二轮手动确认、两轮后停止和旧归档存档防循环；窗口复盘整备按阶段通过处理。后续若继续推进，只做路线情报或清障风险回落的展示治理，不扩成第 4 条短行动。

路线情报 / 清障风险回落展示治理已接入：路线读数和扰动残压的行动台承接行按目标预告、路线扰动和防护消耗三段展示，帮助玩家把反馈结果对回风险拆解；该治理只改显示密度，不改变队列、奖励或前线目标。

行动队列二级预告已接入：行动台、方案终端和候选替换结果都会说明保留当前下一候选或替换为某方案的判断依据；候选替换仍只改变 `NEXT_PLAN_CANDIDATE_KEY`，不影响当前出发整备槽，也不会自动派发前线目标。

## 二阶段入口

2026-05-24 之后的下一阶段不再以新增短行动为目标，而是把已经证明有效的路线情报、清障风险回落和轻量整备模块整理成可复用的出发前判断框架。允许继续扩展的只有三类：复用结构化窗口结果表的模块结果、复用当前计划槽 / 下一候选的队列判断，以及复用风险拆解的路线或清障说明。

二阶段新增代码必须满足：

- 仍由前线行动台确认出发整备槽，相位回投只执行已确认风险收益快照。
- 同一前线窗口或回基地归档能看到出发前取舍结果，不能只改行动台文案。
- 自动检查优先覆盖真实交互入口、存档状态和预览 / 实际窗口反馈一致性。
- 不新增第 4 条同构短行动、随机成功率、新成长货币、队员或完整装备 loadout。

2026-05-24 已补二阶段入口真实交互回归检查：相位测绘路径会通过行动台确认、相位回投执行、前线窗口 `inspect` 交互和回基地行动台归档，验证窗口结果预览、实际处理反馈和归档后的路线情报承接仍来自同一结构化结果口径。

同日已补存档状态回归检查：相位测绘路径会分别在已确认整备、激活中的同一前线窗口、归档后的路线情报承接三个时点保存读取，验证 `base_action_state` 中的计划、模块、窗口状态和归档摘要不会丢失。

随后补充 `base_action_state` 内容校验：坏档若包含未知行动状态键、错误类型或非法行动计划，会在读取时被拒绝，避免二阶段状态机被不受控字段污染。

候选终端也已补回归检查：方案终端真实交互只替换 `NEXT_PLAN_CANDIDATE_KEY`，不会改动当前计划槽或已确认出发整备槽；替换后的候选保存读取后仍保持。

候选终端随后接入结构化窗口结果预览：候选预览和替换结果会显示该计划对应的同一前线窗口目标与处理结果，但仍只作为下一候选判断，不自动派发新行动。

二阶段入口收口复核已补齐到三类计划：补给 / 测绘 / 清障都会通过真实行动台确认、相位回投执行、同一前线窗口 `inspect` 和回基地行动台归档，验证行动台、当前计划槽、下一候选、风险收益快照、结构化窗口结果表和相位回投仍是唯一出发口径。

坏档校验随后补强二阶段窗口状态一致性：`active` 窗口必须带有 `frontline_window_plan_key`，`resolved` 窗口必须带有计划和反馈，归档反馈必须带有归档计划，避免不完整状态绕过入口检查后让前线窗口缺少可处理快照。

小地图测绘预告也按二阶段入口口径收束：只有无活跃任务、由路线整备状态驱动的井系目标会追加“测绘预告”；普通任务目标即使同在井系区域，也不借用路线情报标签。

已确认出发槽的坏档校验也补齐：只要 `departure_plan_key` 非空，对应补给 / 测绘 / 清障状态就必须是 `queued`，避免存档里出现“相位回投看似有确认计划、实际没有已确认整备槽”的半确认状态。

候选终端闸门随后补漏：同一前线窗口仍在 `active`，或窗口反馈尚未回基地行动台归档时，方案终端真实交互会明确拒绝替换下一候选，避免不可替换阶段掉到通用 `inspect` 成功文案。

前线行动台空闲闸门也已补齐：当没有当前可确认计划、没有待归档窗口反馈、也没有早期前线行动确认任务时，行动台会明确提示未开放，不再回落到通用 `inspect` 成功文案；连续两轮复盘完成态仍保留专用完成提示。
