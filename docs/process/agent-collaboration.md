# Agent Collaboration

更新时间：2026-08-22

## 用途

本文承接 `AGENTS.md`、`CLAUDE.md` 不适合在每次任务启动时全量加载的协作细则。根入口只保留跨任务、跨阶段且必须立即生效的长期约束；当前状态仍以 [Current Plan](../planning/current.md) 为准，具体功能、架构和验证合同仍以对应专题文档为准。

## 三层文档职责

| 层级 | 职责 | 典型内容 |
| --- | --- | --- |
| 根入口 | Agent 启动即生效的长期契约 | 授权边界、协作原则、核心红线、任务路由 |
| `docs/` 专题 | 稳定但按任务读取的详细规则 | 架构、接口、验证、图像流程、开发闸门 |
| 当前规划与记录 | 会随阶段变化的状态和事实 | 当前顺位、冻结项、“当前不做”、批次证据 |

根入口不是项目手册副本，`docs/README.md` 也不是阶段规则正文。短入口负责说明“去哪里读”，专题文档负责解释“规则是什么”，当前规划与记录负责说明“现在处于什么状态、已经发生了什么”。

## 判断顺序

1. 先遵循萝卜SAMA在当前任务中的明确要求。
2. 再遵循 `AGENTS.md` / `CLAUDE.md` 的启动级约束。
3. 根据根入口的任务路由读取必要 `docs/` 真相源。
4. 通过当前代码、配置、测试和验证结果确认实现事实。
5. 文档与实现冲突时，不静默选择一方；先判断哪一侧过期，再在当前范围内统一口径。

## 任务推进

### 开始任务

- 先检查工作区状态，确认已有修改、当前分支和任务影响面；已有修改属于萝卜SAMA，不覆盖、不回退、不顺手整理无关内容。
- 先判断任务属于回答、诊断、设计、实现、验证还是发布，不从一个请求推导范围外的写入、外部操作或发布动作。
- 只读取任务需要的文档。涉及当前阶段、优先级或下一步时，先读 `daily-start.md`、`current.md`、活跃专题和最新周志；只有追溯事实时才进入归档。
- 若当前阶段、专题、代码和验证基线不一致，先判断过期方；会改变阶段或专题边界时停止实施并升级给萝卜SAMA。

### 方案与批准

- 萝卜SAMA明确要求直接修改，且范围清晰、风险可控时直接实施。
- 未明确要求修改时，编写代码前先说明目标、边界、影响和验证方式。
- 架构、协作规则、阶段 / 专题、接口、依赖、存档 / 联机、验证基线或画面介质发生变化时，先给出证据与方案，等待确认后实施。
- 不同合理解释会造成明显不同的玩家行为、数据模型、兼容边界、外部影响或工作量时，先澄清。
- 已批准方案出现实质范围变化时暂停扩张并重新确认，不把变化隐藏在实现细节中。

### 实现与收口

- 优先治理根因和同类问题，避免只修表象后留下重复缺陷。
- 交付必须覆盖主要使用路径，不使用占位逻辑、玩具式最小实现或不可维护的临时拼接冒充完成。
- 不做与当前目标无关的重构；直接阻碍需求的结构问题应做职责清楚的必要修正。
- 抽象必须服务于真实复用、边界隔离、复杂度下降或契约稳定；简单逻辑不通过多层包装制造间接性。
- 错误处理只覆盖明确风险，不吞异常、不伪造成功、不用默认值掩盖契约问题。
- 每完成一个可分割子步骤执行匹配的最小验证；最终交付说明完成内容、验证结果和真实未验证风险。

## 设计先行与玩家证据

- 玩家可感知功能、跨系统开发包或阶段性玩法推进，先确认对应 `docs/features/` 专题存在且边界清楚，再进入实现。
- `docs/planning/` 只承载阶段方向、当前边界、冻结项和退出条件；功能专题承载玩家路径、状态 / 存档、HUD / 场景反馈、检查和验收。
- 单点 typo、局部文案、格式、链接、低风险清理和不改变功能边界的小修复不强制新建专题。
- 玩家可见开发包按 [Development Decision Gates](development-decision-gates.md) 判断玩家结果、实现介质、成功证据和失败退出；连续两次同类实机失败后必须停手复盘。
- 自动检查通过不等于玩家可见目标通过。画面、玩法、HUD、场景、叙事节拍和存读结果按风险使用实机截图、录像或人工路径复测作为主证据。
- 介质与风格锚点变更、阶段与专题切换、两次失败后的路线选择、存档 / 联机边界和协作规则修改属于架构级升级点，由萝卜SAMA确认。

## 验证与留痕

- 按风险选择定向测试、静态检查、构建、运行时断言、截图和人工路径；不要求每个改动都运行全量检查，也不把未执行验证写成通过。
- 人工复测优先从 [Development Retest Baselines](../design/development-retest-baselines.md) 选择相关段落；涉及早期链路、共享任务 / HUD / 地图、存档迁移或大包收口时，再回到适用的全链基线。
- 玩家可见功能按 [Godot Runtime Verification Guide](../reference/godot-runtime-verification-guide.md) 使用正式入口、隔离存档和截图；启动 Godot 前仍需先告知萝卜SAMA。
- 自动检查和人工复测产物使用仓库内忽略提交的规定目录，不写系统临时目录，不覆盖生产版 `user://saves/slice/`。
- 重要阶段性推进、关键决策、失败复盘和验证证据追加到本周周志；单次小修不要求制造流水记录。

## 授权与外部边界

- 仓库内代码、文档、配置的读写和非破坏性只读检查可直接执行；范围明确的本地提交在完成最小验证后可直接进行。
- Godot、桌面程序、有窗口测试和 `--with-godot` / `-WithGodot` 在执行前先告知。
- 依赖安装、依赖更新、大文件下载和外部资产包引入必须说明命令、版本、许可证与落盘影响，并取得当前任务授权。
- 系统环境、证书、注册表、全局 Git / 编辑器配置、打包、发布、上传、远端推送和 Release 必须取得明确授权。
- 跨工作区写入、破坏性文件操作和历史重写不属于普通实现步骤；没有明确授权时不得执行。
- 授权只覆盖当前任务已经说明的命令、目标和影响；范围发生实质变化时重新确认，不沿用旧会话授权。

## 文档归位

- `docs/planning/current.md`：当前阶段、活跃专题、冻结项、退出条件和当前边界。
- `docs/planning/daily-start.md`：日常读取顺序、最近进度和下一步，不记录开发包流水。
- `docs/features/`：玩家目标、实现范围、状态 / 存档 / HUD / 场景边界、验收和非目标。
- `docs/process/`：跨专题复用的协作流程、决策闸门、图像工作流和执行规则。
- `docs/architecture/`：工程结构、权威状态、存档、联机、数据流和长期技术边界。
- `docs/devlogs/`：完成事实、验证证据、关键决策、风险和后续建议。
- `docs/reference/`：长期参考方法、提示词、外部分析和可复用操作指南。
- `docs/archive/`：历史原貌，不作为当前规范。

一次改动若只回答“这包做了什么”，优先写周志；若改变“接下来怎么做”，更新规划或专题；若改变“以后所有同类任务怎么做”，更新对应稳定专题。只有满足根入口条件时才同步 `AGENTS.md` / `CLAUDE.md`。

## 根入口维护判定

一条规则只有同时满足以下条件，才应进入 `AGENTS.md` / `CLAUDE.md`：

1. 跨任务成立，而不是某个功能、素材类别或批次专属。
2. 跨开发阶段成立，不会随当前里程碑自然失效。
3. 必须在 Agent 读取专题文档前生效，否则容易产生高风险或大范围错误。
4. 无法只通过任务路由和对应专题文档可靠承载。

两个根入口只允许标题和首段入口名称不同，从第 4 行开始必须完全一致。修改根入口时同步检查相关 `docs/` 是否仍为真相源，并执行 `check-docs` 与 `check-repo`；修改阶段状态、临时门禁或批次事实时不应反向更新根入口。
