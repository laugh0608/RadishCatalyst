## 包 1 前现状审计

| 耦合面 | 当前运行事实 | 迁移风险 |
| --- | --- | --- |
| 贴图与足印 | `SliceBuildingDefinition.normalized_rotation()` 同时选择四向贴图、交换足印长宽，并影响原点、中心、底边排序、碰撞与交互框。 | 固定正面若只换单帧，旧旋转仍会从其他路径改变几何或锚点。 |
| 物流端口 | 储物箱只有一个随旋转变化的双向口；反应器的对置 `IN / OUT` 随旋转变化；物流网、放置叠层、方向诊断和设备面板都调用这些结果。 | 新储物箱左入右出、反应器左入右出不能靠把 `allows_rotation` 改成 `false` 静默获得。 |
| 供电 | 采集器 / 反应器的供电探针随旋转变化；中继按足印中心建图。`powered_connections()` 只给核心—中继和中继—中继边，不提供中继—消费者表现边。 | 固定正面的逻辑供电探针、设备顶部画线锚点和中继端子必须分离，否则视觉锚点会改变供电判定。 |
| 放置与调整 | 放置控制器以 `rotation_index` 驱动预览；`R` 修改它。调整暂存原格与原旋转，提交 / 取消后重建占用、供电和物流。 | 固定设施仍需可移动和无损取消，但不再允许 `R` 改变朝向；传送带必须继续旋转。 |
| 存档 | schema 7 对每个建筑严格保存 `{instance_id, building_id, origin_cell, rotation, state}`，`rotation` 必须为 `0–3`；载入后按它恢复建筑，再派生占用、供电和物流。 | 直接改变 schema 7 中同一字段的语义会让旧档静默变形，也会让旧客户端误读新档。 |
| 核心与采集器物流 | 核心是 `SliceMap.tscn` 中固定 `Sprite2D`，不是建筑实例；`core_storage` 只支持背包手动存取、充能和交付。物流网只登记传送带、储物箱与反应器。采集器缓冲同样只能手动取出。 | Gate A 的核心左入右出和采集器右出都尚不存在；只换图会显示无法使用的假端口。 |

结论：`building_rotation` 不是单纯视觉参数，而是贴图、空间几何、物流、供电、调整与存档的共享不变量；核心 / 采集器也缺少目标稿所展示的物流职责。正式接入必须做版本化、原子化迁移。

## 目标合同

### 方向、贴图与端口

建筑定义改为显式声明三件互不替代的事实：

1. `orientation_mode`：`fixed_front` 或 `cardinal`，只决定玩家是否可按 `R` 及 `rotation` 是否有方向语义。
2. `visual_mode`：固定单帧或四向固定帧；运行时仍禁止旋转像素图。
3. `logistics_ports`：每个端口有稳定 ID、`input / output` 角色、本地端口格、外向方向和 `fixed_local / follows_orientation` 策略，不再用一个可空字段兼任多种设备。

| 对象 | 朝向 / `R` | 固定物流合同 | 供电角色 |
| --- | --- | --- | --- |
| 前哨核心 | 场景固定正面 / 无 `R` | 左侧 `IN`、右侧 `OUT`；只在修复后启用 | 唯一电源 |
| 晶体采集器 | `fixed_front` / 无 `R` | 右侧 `OUT`，只输出 `crystal` | 现行二值消费者 |
| 基础反应器 | `fixed_front` / 无 `R` | 左侧 `IN` 只收 `crystal`；右侧 `OUT` 只出 `catalyst` | 现行二值消费者 |
| 储物箱 | `fixed_front` / 无 `R` | `supply` 只启用右 `OUT`；`transfer` 只启用左 `IN` | 新二值消费者 |
| 电力中继 | `fixed_front` / 无 `R` | 无物流口 | 现行二值中继 |
| 传送带 | `cardinal` / 保留 `R` | 输出方向继续跟随 `rotation` | 被动设施 |
| 工业地板 | 固定 / 无 `R` | 无物流口 | 被动承载 |

- 固定设施保存的规范旋转值恒为 `0`；`building_rotation` 仅继续服务传送带及未来明确声明为 `cardinal` 的对象。
- 当前所有待切换设施均为正方形足印，规范化不会改变 `origin_cell`、占用格、碰撞或底边排序；代码仍须通过显式方向模式保证未来非正方形设施不会复用旧耦合。
- 反应器固定端口等价于旧 `rotation = 1` 的左入右出；储物箱从旧单一双向口升级为左入右出；采集器新增右出。端口内格和外接格必须落在 32px 网格上，sprite 的可见领口只负责对齐，不反向决定拓扑。
- 以足印左上格为局部原点：采集器 `OUT (1,1) → RIGHT`；反应器 `IN (0,1) → LEFT`、`OUT (2,1) → RIGHT`；储物箱 `IN (0,1) → LEFT`、`OUT (1,1) → RIGHT`；核心固定 2×2 足印为 `IN (0,1) → LEFT`、`OUT (1,1) → RIGHT`。普通端口与核心外接格均为端口格加外向方向；反应器保留显式 `connection_distance = 2`。核心和反应器的未连接底图只显示设备自有短方形口、接驳颈与承重肩，真实终端带在连接态覆盖短口外缘。
- 储物箱模式、逐类容量、输出筛选、无线传输和面板合同以 [分类库存与通电储物箱 V1](slice-category-inventory-and-powered-storage-v1.md) 为唯一真相源；本专题只负责让锁定 sprite、固定端口、供电探针和世界锚点与该状态一致。

### 物流端点与所有权

- `SliceLogisticsGrid` 改为登记统一的窄端点描述，而不是按 `SliceStorage` / `SliceReactor` 写多组并行映射；储物箱、反应器、采集器和核心分别提供端点与权威库存 / 缓冲引用。
- 核心继续使用现有 `core_storage`，不创建第二份核心库存；采集器继续使用现有 `buffer`，不新增重复计数。自动搬运和手动操作必须读写同一真相源并发出既有刷新 / 自动存档信号。
- 物理传送带白名单保持 `crystal`、`catalyst`；机械零件与建筑套件可手动存取但不进入首版工业物流，关键样本继续走独立状态。每次传输先确认目标可接收，再从源移除，保持回压和守恒。
- 核心未修复时两个端点均不存在；修复后左口入库、右口按现行 `crystal → catalyst` 稳定顺序输出。采集器右口只在缓冲非空时输出，手动“取出全部晶体”继续保留。
- 储物箱 `supply` 模式只从右口输出选中类别，`transfer` 模式只从左口接收并按 `5s / 50件` 无线写入同一 `core_storage`；无线链不是第二份库存，也不占用核心物理左口。

### 供电判定与表现锚点

- 二值电网、核心 6 格、中继 6 格和设备 4 格范围不变；不引入发电量、耗电量、端子容量或负荷存档。
- 固定设施的逻辑供电探针使用稳定足印中心，不再跟随 sprite、物流口或旧旋转。核心 / 中继建图位置与设备顶部画线锚点分开。
- Gate A 锁定的设备画线锚点按 PNG 左上角计为核心 `(84,16)`、储物箱 `(52,18)`、反应器 `(92,22)`、采集器 `(48,2)`；中继西 / 北 / 东 / 前端子为 `(4,14)`、`(24,3)`、`(43,14)`、`(24,23)`。运行时从 texture-local 像素转换到世界坐标，不把这些数值用于范围判定。
- 供电父节点和消费者连线继续全部派生且不进存档；同一布局按距离与稳定实例 ID 得到确定结果。Gate A 四个端子各自唯一是基准截图合同，不构成新的四连接容量限制。
- 储物箱升级为真实消费者：手动访问不受断电影响，存储模式自动供货与传输模式无线回库需要通电；Gate A 的第四条中继线因此可以由真实电网结果派生，不再是假状态。

## schema 8 与旧档迁移

1. schema 8 由本专题与分类库存专题共同拥有，只能在联合包 2 一次启用；建筑继续保留必填 `rotation`，固定设施 / 地板只能为 `0`，传送带仍允许 `0–3`。
2. schema 2–7 先走现有迁移得到 schema 7 结构，再联合迁移逐类库存、储物箱模式和设备方向：原样保留稳定 ID、建筑 ID、`origin_cell`、全部物品、反应器在制批次 / 进度、传送带货物 / 进度 / 合流游标；只去掉旧容器总容量、补储物箱模式状态，并把固定设施 / 地板旋转规范为 `0`。
3. 不自动移动设施、旋转传送带或重排玩家产线。供电和物流本来就是派生状态，载入后按新固定探针 / 端口重建；旧反应器 `rotation = 1` 可自然保持左右链，其他旋转及旧储物箱单口线路可能断开。
4. 兼容承诺是“世界可载入、持久状态与物料不丢、布局不被偷偷搬动、断链可诊断并可修复”，不是任意旧端口方向的拓扑逐边不变。为避免终端带上货物卡死，包 2 必须给传送带面板增加容量预检后的单件货物回收；玩家回收后才能调整或拆除旧终端带。
5. 迁移成功、当前 schema 校验和世界重建全部通过后才写 schema 8；原候选与备份仍按现有多世界回退规则保留。重复迁移必须幂等，schema 8 保存—重启—载入结果一致。
