# Slice Visual Hierarchy And Color Separation V1

更新时间：2026-08-03

状态：**关键设备第 3 轮 V3 的轴向、高度、色调与独立基座获得条件认可，但滚轮式端口和四向对称接口判废；8 月 4 日先做固定正面、左 / 右 / 前可见端口的小样，Gate A 仍未通过。**

## 目的

在不改变第一可玩切片玩法、存档和既定像素介质的前提下，统一地表、世界设备、HUD / 面板与功能色的明度和材质职责。

玩家应先读出“在哪里、哪台设备、当前状态、正在操作什么”，而不是看到浅色地面上的一组深色设备和另一组深色界面。专题完成后，基地仍保持克制的工业科幻现场感，但地表、设备、界面和状态提示不再挤在相近的深色明度带。

本专题承接 [第一可玩切片全链串通](slice-first-playable-journey-v1.md)、[图形化建造 / 合成 / 背包 UI V1](slice-graphical-crafting-and-inventory-v1.md) 与 [设备操作面板统一 V1](slice-unified-device-operation-panels-v1.md)。它只调整视觉表达，不重写已人工通过的操作和权威状态。

## 现状与根因

- 功能全链、建造 / 背包鼠标主路径和建筑设备面板包 1 已人工通过，当前阻塞是整体表现仍像开发草稿，不能直接进入陌生玩家盲测。
- 全局 `ui_theme.tres` 当前主要承担字体；HUD、制造面板和建筑设备面板分别内嵌多组相近的深青黑 `StyleBoxFlat`，共同视觉角色没有稳定真相源。
- 世界设备普遍以深色金属为主体；如果顶面、侧壁、底座、端口和状态灯没有足够材质分区，会与深色 UI 一起形成大面积近似色块。
- 浅岩地已经提供基础对比，但工业地板、设备阴影、高亮与功能色之间缺少明确优先级；单独调透明度、边框或整体深浅不能治理根因。
- 青色同时承担大量标题、边框、运行和连接表达，容易从状态语义退化为通用装饰色。
- 2026-07-30 实测浅岩地中位明度约 `160/255`，设备主体仅 `42–46/255`，首轮修正 UI 外壳更低至 `23/255`；局部层级成立但整屏缺少中间明度，是“黑色岛屿”感的直接根因。

## 专题开工十问

1. **玩家新增动作：**不新增动作；本专题是表现层专题，豁免动作扩展。玩家会更快识别世界、设备、界面和状态。
2. **世界明确变化：**同一基地中，地表退为稳定背景，设备恢复体积和材质层级，HUD / 面板成为明确前景，功能色只强调真实状态。
3. **服务基地—冒险闭环：**玩家更容易发现采集、供电、物流和反应器状态，并把工业产出与外勤目标连接起来。
4. **感知时长：**进入新世界、打开制造面板或靠近设备后的数秒内即可感知，不依赖完成整条产线。
5. **系统范围：**复用现有 Godot Theme、场景组件、tile、sprite 和状态快照；只新增窄职责视觉资源，不建设通用 UI 框架。
6. **现有介质：**保持 32px 网格、960×540 相机、高斜角俯视、左上光与现行基础色相锚点；地表恢复审定基线，设备用逐资产材质区，不改几何、Alpha 或状态色。
7. **成功证据：**正式 `Boot` 四态截图联系表、灰阶复核、现有自动检查和萝卜SAMA人工实机判断共同成立。
8. **失败处理：**先判断 UI 资源、世界资产或场景组合哪一层失效；同类两次失败后停手复盘，不继续叠边框、透明层或整体换色。
9. **旧系统关系：**不复活旧 Demo HUD、程序绘制设备、旧地图、旧主题或旧任务面板。
10. **切片推进价值：**解除当前首要表现风险，直接接近内部试玩门槛和后续陌生玩家盲测解冻条件。

## 视觉合同

### 四层职责

| 层级 | 目标角色 | 必须保留 | 禁止做法 |
| --- | --- | --- | --- |
| 地表 | 明亮、低干扰的空间基底 | 浅岩地、晶体地与工业地板区域差异，32px 网格和宏块纹理 | 提高纹理噪声、靠大色块或流程图标记抢主体 |
| 世界设备 | 明亮壳面与独立基座主导的工业设施模组 | 设备剪影、足印、左上光、右下接地阴影、可接物流端口和族特征 | 深色成为整机主面积、机器脱离基座悬空、用小插头代替物流出入口 |
| HUD / 面板 | 最前景的工程终端承载 | 标题、内容卡、操作区、结果区和文本对比 | 所有区块同深度、全框高亮、只换一档背景色 |
| 功能反馈 | 短时或局部强调真实状态 | 状态灯、进度、按钮状态、合法 / 非法与危险提示 | 把功能色铺满壳层、仅靠颜色传达结果、伪造不存在的数值 |

整体明度关系不是“越重要越亮”，而是：

```text
浅色地表稳定承托
→ 设备以明亮壳面 / 基座 + 中灰侧壁 + 深色骨架建立体积
→ UI 以最稳定的前景壳层 + 分级内容面承载操作
→ 功能色只在状态、交互和危险节点形成最高局部对比
```

### 材质分工

- 浅岩地偏干燥矿物；晶体地偏冷色异星矿脉；工业地板偏暖灰金属。三者不能只靠亮度微差区分。
- 设备的大面积顶壳、侧壳和自有基座使用工程白、浅暖灰与中灰金属；暗青只用于骨架、凹槽、底部结构和接地阴影，不得再次成为整机第一读法。青能量窗与琥珀灯不能代替材质本身。
- 核心与生产设备都按“设备本体 + 独立设施基座 + 占地边缘物流接口”设计。核心基座必须有真实仓储输入 / 输出泊位，反应器基座必须有配方加工 `IN / OUT`；端口不能退化成贴在机身上的小圆塞。
- 设施端口使用中性深色停靠口与顶面方向箭头：输入箭头指向设备，输出箭头背离设备；滚轮只属于外接传送带，不得用不同朝向的端口滚轮承担流向读法。颜色只作冗余，不能替代箭头方向。
- 核心与反应器的设备正面固定朝向玩家，端口围绕屏幕可见的左、右、前三侧组织；不再要求上 / 下 / 左 / 右各有一个接口，同一可见侧可按真实功能布置多个端口。
- HUD / 面板使用克制终端材质：外壳、标题 / 主状态、普通卡片、操作区和结果区形成有限且可复用的深度梯度。
- 世界设备只在局部骨架和凹面使用深色；UI 可以使用深色承载，但不能与设备共享同一种连续大面积暗青面。设备靠实体材质和光照成形，UI 靠平面承载、边距和组件层级成形。

### 功能色语义

| 语义 | 颜色角色 | 使用位置 |
| --- | --- | --- |
| 通电、运行、有效连接、合法确认 | 玉绿 / 收窄后的青色 | 状态灯、进度、短标签、选中或确认节点 |
| 任务、交互、等待、工业注意 | 琥珀色 | 当前目标、键帽、等待态、需要玩家处理的中性提示 |
| 敌人、危险、故障、非法 | 警示红 | 敌人 HUD、故障状态、非法预览、危险操作 |
| 污染与异星危害 | 污染黄绿 | 污染地貌、污染状态和对应危险提示 |
| 被动、离线、禁用、次要 | 中性灰 | 被动设施、关闭状态、不可用次级操作 |

- 功能色必须同时配合图标、短文字、形状或明度差，不能只靠色相。
- 玉绿 / 青色不再作为所有标题、描边和装饰的默认颜色；琥珀色也不等同于所有“重要”内容。
- 基础状态语义保持不变；2026-07-30 的跨层统一明度后处理已被后续实机否决。若证据要求修改光向、投影或分辨率，仍须停手升级。

## 实现介质与职责

- `ui_theme.tres` 可扩展为共享字体与少量稳定视觉角色；复杂页面仍保留自己的布局，不建立响应式系统、主题编辑器或空泛 UI 框架。
- 至少两个现行界面真实复用的壳层、卡片、状态和操作样式，才允许提取为共享资源或 Theme variation。
- HUD、制造面板和建筑设备面板继续读取既有权威状态与控制器；视觉资源不得保存业务状态、改变输入或触发写盘。
- 世界层以现有 tile / sprite 为基础。能通过确定性点修解决时不重新生成；需要重出时按单一素材类别、独立批次、归一和人工审阅流程执行。
- 程序绘制只保留合法预览、端口、状态灯、选中描边和危险等动态反馈，不成为设备材质或地表主读法。
- `SliceWorld` 不接视觉分支、主题选择或按设备类型调色逻辑。

### 失败证据：包 1 / 2 跨层明度校准

- 萝卜SAMA二次反馈确认 UI、面板和世界设备仍整体过深，与浅色场景形成过大反差；这证明 UI 单独收口、随后再处理世界的顺序不能建立整屏标尺。
- 按“连续两次同类实机失败”闸门停止继续给深色 Theme 调色，改为地表、工业地板、设备与 UI 同屏校准；包 1 不再独立宣布通过，包 2 也不另起一套明度口径。
- 零依赖归一管线新增媒介后处理：地表 RGB 各减 `8`；设备非状态像素按暗部 / 中间调 / 高光增加 `24 / 18 / 12`，青、琥珀、红和污染色保持不变。反应器、储物箱、采集器、中继、传送带、核心和地表均由原始或审定基线离线重出，没有运行时 `modulate`。
- 实测校准后浅岩地中位明度为 `152/255`、工业地板 `99/255`、核心 / 采集器 / 储物箱 / 反应器主体 `64–68/255`；UI 外壳 `65/255`、卡片 `76/255`、下沉面 `52/255`。
- UI 同时降低全屏遮罩至 `0.34 / 0.38`，使制造与设备面板打开时仍能读到世界关系；布局、权威状态和输入路径不变。
- 完整 `check-client --with-godot` 通过；供电专项增至 85 项，旅程专项增至 69 项。正式 `Boot → 新建世界` 六态通过 51 项断言。
- 六张 `3024×1701` 原图与联系表位于 `assets/art-intake/2026-07-30-cross-layer-luminance-preview/`；隔离自动存档位于 `tools/runtime-intake/2026-07-30-cross-layer-luminance-calibration/save-root/`。
- AI 联系表复核未见新截断、互叠或主体遮挡，但萝卜SAMA实机确认整屏仍灰蒙、偏暗；中性 RGB 偏移降低了色彩活力，也没有把设备顶壳、侧壁、骨架和缝隙变成不同材质。
- 结论：自动断言和中位明度连续不代表视觉方向成立。地表偏移、设备统一提亮函数、派生哈希和数值明度合同全部撤回；本段只作为失败证据保留。

### 路线复盘：明亮工业样板

- 参考 [《终末地》DEV Comm//02](https://endfield.gryphline.com/en-us/news/1340)、[Factorio 官方内容页](https://factorio.com/game/content) 与 [The Riftbreaker 官方 Press Kit](https://www.riftbreaker.com/press-kit/)；只提取明亮工业表面、完整设施基座、物流接口、设备剪影 / 材质分区和局部状态发光，不复制洁净 3D、具体设备外形、脏褐主色或霓虹 HUD。
- 玩家结果：同屏首先读到有色异星地表，其次读到中明度设备的顶壳 / 侧壁体积，最后由轻色 UI 承载操作；暗色只留给骨架、缝隙、凹槽、进度轨道和少量键帽。

## 失败判据与停手

以下任一项视为当前包未通过：

- 只调整背景透明度、边框颜色或整体深浅，原有层级问题仍存在。
- UI 仍由多块近似暗色矩形平铺，标题、主状态、内容与操作区无法快速区分。
- 设备仍主要靠青灯、文字或动态描边识别，主体材质和体积本身不可读。
- 灰阶下地表、设备和 UI 糊成同层，或功能色移除后状态完全不可理解。
- 为完成视觉效果修改玩法结果、schema、端口、电网、物流、足印、碰撞或输入规则。
- 使用程序贴图、全局 sprite `modulate`、大面积线框或 debug cue 冒充资产与材质治理。

同类方案连续两次实机失败后停止追加调参，按决策闸门选择继续、换介质、拆专题、降范围或暂缓。

若二次实机仍确认文字整体偏糊，停止继续调字重、描边或面板颜色，升级评估“原生 UI + 低分辨率世界 viewport”的渲染分层；该项属于当前冻结的 viewport 架构变更，不在包 1 内自行实施。
