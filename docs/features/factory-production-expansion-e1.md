## 玩家结果与交付边界

玩家从零物料建立直接工艺，做出两包构件，装配并实际放下第二台精炼炉；随后分离板材 / 载体工序，用混料回用再做同样两包，决定下一次扩建或停止备料。增加的是“制造生产能力、比较工艺、分配原料”的动作，工厂实际多出设备，后续才接能源与开拓用途。

进入相应生产检查点后 5–10 分钟内看见新行为仍是设计目标；不把纸面加工秒数当玩家首程承诺。成功须有自然生产、真实装配放置、保存重进、可辨端口与阻塞反馈，并由短试玩判断是否愿意继续扩建。

- 当批新增八物品：`iron_ore / carbon_ore / iron_powder / carbon_powder / metal_plate / mineral_slag / porous_carrier / construction_pack`。连同原五物品共 **13 种**；R01–R04 保持，增加 R05–R11，共 **11 配方**。
- 新设备 `crusher / refinery / assembler`，复用已有采集、反应、物流附件、终端仓、同网电力、近身取放与统计。E1 交付直接与回用两条路线，不只交付物品枚举或一条不能消费的生产线。
- E2 的工业电芯 / 发电机、E3 的胶囊 / 高产支路 / R14 不在当批菜单中作为可制造内容，不预填虚假状态。整个内容包的 15 物品 / 14 配方规划保持。
- 液气、自动出仓、物流桥、自动蓝图、通用科技树、交易、战斗、多人、随机地图、离线收益均不纳入。开发范围不包含依赖安装、外部资产下载、推送、打包或发布。

## 配方、缓存与生产状态

R05–R11 以母专题配方表为唯一数值源，本合同不改其数量 / 秒数 / 功率。新机器默认 C=R06、F=R05、A=R11；这些配方开局可见，原反应器解锁仍沿样本 / 试制条件。

1. 三类新加工设备按每种原料独立容纳**两批输入**，不与在制投入共用容量；每个产物槽只容纳**一批输出**。原反应器容量与 R01–R04 行为不变。满仓 / 输入满仅拒绝本次交接，不吞料。
2. 输出全空、配方可用且输入齐全才开始一批；在有供能的生产步原子扣齐输入到 `invested`，分配批次 ID。按真实同网供能比例推进；缺电保留投入与进度。
3. 完成时同一事务清空在制，生成全部主副产物并记账；两出口共享同一生产批次。任何剩余输出都阻止下一批开始，不允许主口出空后覆盖未出的矿渣，也不允许完成时只生成一半产物。
4. 取消仅退回本批原始投入，完整放得进背包才成功；已消耗的电量不返还。改配方要求输入 / 在制 / 两输出全空，完全相同配方不重置；错误操作零变更。
5. 手动取放、取消、设备回收继续要求两格内与可达，背包 / 仓容量均 200。取放沿现有“1 / 全部按可容纳数量转移”的语义；回收 / 取消仍是全量校验后提交，满包整次拒绝。不增加任意数量输入、跨仓取料或自动搬运。
6. 回收返回同型构件及全部输入、在制、输出物料；没有进度或产物补发。新设备固定方向，足印及各端口详见布局表，不额外解冻机器旋转。

## 主副物流与统计

- 新世界沿共同快照物流：单格一件、1 秒推进、每个源和目标每步至多一次交接；多输入设备不因有多个口而同一步多收。新精炼炉按输出端口分别选择合法物品，不能沿旧 `_output_item` 单一物品路径把矿渣发到主口。
- 一个源在主 / 副出口间从持久化游标开始轮询，只考虑非空且可接收的出口，成功后移动游标；副口堵时允许主口剩余板继续排出，但所有输出清空前不再加工。稳定 ID、目标竞争与已有带 / 附件语义保持。
- 新世界准入口支持 12 种可运输物品（13 种扣除样本），两种模式、尾件预约、关闭排空和重置条件保持；旧 V5 白名单仍为原四种，不全局扩成新列表。
- 生产 / 消耗按真正完成的配方计；转入在制、取消、手动搬料、运输不伪造生产或消费。构件装配记构件包消费；拆设备返构件不记生产包。矿产提取、唯一拾样、开路消费各有明确来源。
- 统计展示新物料的产出、消耗、库存 / 在制 / 在途与实际电量；不把所有矿物套进旧晶体当量。配方页同时显示单机标称批次与用途，不把单机速率标成整线保证。

## 构件装配与预算

建造菜单提供装配目标、消耗、所得数量、背包可用包数与预算缺口；只从背包扣包，不从仓库远程扣取，不新增工作台。一次命令只做一批，下表中传送带的整批八段不可部分发放。成功后选择对应建造工具；库存增加与落位分别反馈。

| 构件包消耗 | 装配所得 |
| --- | --- |
| 1 | 传送带 8 段 |
| 1 | 分流器 / 汇合器 / 准入口 / 配电节点中的一种 1 件 |
| 2 | 采集器 / 反应器 / 终端仓 / 粉碎机 / 精炼炉 / 组装机中的一种 1 件 |

封装电源不可制造；电芯发电机等 E2 开放后另定合同。拆回返回构件，不返构件包，也不允许构件兑包。

**已确认预算：326 限制“已放置 + 未放置的构件总拥有量”。** 这把原固定供给形成的规模上界延续为可制造世界的明确上界；不是只限制场上实体。初始 165，最多还能制造 161 件构件，传送带一批占 8。界面分别显示总额、已放置及库存；余额不足八件时，装配传送带整批拒绝，不先扣一包再发部分。

这个选择保证回收始终有构件库存位置，避免场上满额时继续制造大量无处放置的构件；代价是闲置预配构件也占预算。若要改成仅场上 326、另设大型库存，须在实现前替换本条及校验上界，不能悄悄放宽。首次两包装配后总额 166，不阻挡当前路径。

令 `S[t]` 为预配、`M[t]` 为按类型累计装配次数、`q[t]` 为每次所得（带为 8，其余 1）、`P[t]` 为在场数量、`K[t]` 为构件库存：

```text
K[t] + P[t] = S[t] + q[t] × M[t]
sum(K + P) ≤ 326
construction_pack 已装配消耗 = sum(cost[t] × M[t])
```

所有值为有界非负整数，类型集合严格匹配；放置只在 K/P 之间移动，回收相反。装配校验已知目标、背包材料、整批预算、计数上界后一次提交扣包 / 加构件 / 增制造账 / 统计事件，失败不改变任一项。无自动回收、构件删除或超额兜底。

| --- | --- |

| 新加工 | 配方、分物料输入、主 / 副输出、invested、processing、进度、active_batch / output_batch、出口游标、供电连接；类型 / 配方 / 容量匹配 |

| 生产账 | `extracted_by_item`、`completed_by_recipe`；原拾样和开路事实、装配账导出显式取得 / 消费，不允许无来源库存 |
| 活批来源 | `batch_recipes` 记录仍在制或仍在机器输出 / 运输实体上的批次与配方；无活引用即移除，不保存无限历史 |
| 首次扩建 | `first_expansion_placed` 布尔事实；至少已有一次精炼炉装配，且放置成功后场上精炼炉达到两台才置真，回收不撤销；不能由当前“两台炉”推断历史 |

新设备加工中必须投入恰好等于配方输入、输出为空、有效进度低于批次时长；非加工态在制为空 / 进度零 / active_batch=0。输出非空时有合法 output_batch，主副物品归属正确；副口出空后剩余主口继续保留批次。所有计数、序列、浮点沿现有安全整数 / 有限值约束，溢出或未知字段拒绝。

同批可包含金属板和矿渣，必须按该配方的**产出向量**校验，不能继续使用“同 batch 只能一种物品”。所有活引用必须有唯一配方记录；同批不可同时处于在制与输出，跨所有机器输出 / 在途的每种产物数量不超过一批配方产出。进入背包、仓或下游输入后仍沿聚合库存，不伪称有完整逐件谱系；配方累计账承担全局数量校验。活记录数由引用实体数约束，不给无引用记录兜底。

对于每种物品 i，持有 H 包括背包、采集缓冲、设备输入 / 输出 / 在制、仓、带和附件，逐物料核对：

```text
H[i] = 实际采集[i] + 唯一拾样[i]
     + sum(完成配方数[r] × (产出[r,i] - 投入[r,i]))
     - 装配消费[i] - 开路消费[i]
```

投入暂存在制仍计入 H，完成才转换配方投入 / 产出，取消返料不变；所有提案物料均由这张账覆盖。统计累计事件与这些事实相互核对，滚动图表不是守恒真相源。该账用于一致性 / 坏档检测，不宣称防止人为同时伪造所有计数。

电图仍可重建，按真实节点集合重算连通和最邻近供电。连接数上限由合法节点数 `n(n-1)/2` 得出，请求功率按当批合法设备与最大配方功率约束；不能沿用旧普通固定 91 条连接 / 1,440 kW 上界，也不放宽旧世界校验。最多两封装电源，装机仍为 240 kW。

新建 / 继续采用独立 world_id 目录，列表明确规则标签；不提供 V5→E1 转换，不覆盖亲测档。未知未来版本 / 身份阻断回退，备份不得跨规则 / 地图 / 供给身份恢复。沿用失败保留与锁释放，不用清货、清在制或重发供给修复坏档。

1. 数据 / 新世界身份 / 地图与配方模型，连同生产账、原子制造和严格 codec 落地；按实际职责扩展现有模块，避免单一模型无限长或引入通用配方框架。默认 / 旧世界入口保持。
