# Demo Field Loop Payoff V1

更新时间：2026-06-17

## 用途

本文定义首版 Demo 外勤回基地收益兑现第一包。它承接已完成的功能场景玩法第一包，把封锁遗迹代表性外勤结果从“现场阶段已处理”推进到“回基地加工 / 解析后改变下一趟外勤准备”。

本专题服务 [Demo Definition V1](demo-definition-v1.md) 中「基地恢复 -> 外出采集 / 战斗 -> 回基地加工 -> 整备获得能力差异」主轴，以及「资源 / 生产链」「UI / HUD」「存档 / 状态」和「自动检查」规格。它不是新任务链、不是完整背包，也不是试玩准备。

## 玩家价值

玩家完成封锁遗迹的回波匣回收、污染回波沉积处理和深段回波解析后，应能在基地读出：

- 外勤对象已经转成基地处理结果，而不是只留在任务完成文本里。
- 出发整备台可以把回波匣解析和污染处理结果登记成下一趟外勤收益。
- HUD、整备台提示和交互结果能说明下一趟污染 / 遗迹承压会读取这次回基地收益。
- 状态能保存、读取和通过检查验证。

## 与整体规划的关系

- 继续证明“基地服务冒险，冒险反哺基地”：外勤回收物必须回到基地处理，再改变外勤准备。
- 承接 `Demo Functional Scene Gameplay V1` 的现场阶段结果，但不继续扩同类现场提示。
- 复用 `quest.salvage_signal_echo`、`quest.analyze_deep_signal`、基础反应器解析、污染过滤副产、出发整备台和基础过滤模块。

## 当前已有基础

- 回波匣和污染回波沉积已有真实外勤目标、任务、资源与基础反应器解析配方。
- 出发整备台已能写入模块校准、核心归档维护、后勤维护、防护响应和工具校准状态。
- HUD 基地摘要、整备台提示和承压计算已经读取 `FieldOutfittingRuntime`。
- 存档校验允许为地图对象状态增加明确白名单字段。

## 本轮范围

- 新增 `DemoFieldLoopPayoffFormatter`，集中描述外勤回基地收益兑现的 HUD、提示、确认结果和承压反馈。
- 出发整备台在深段回波解析完成、基础过滤模块已装入且收益尚未确认时，允许确认“外勤收益整备”。
- 确认后在整备台对象状态写入 `field_loop_payoff_confirmed`。
- 污染采集、污染反击和遗迹外圈相位承压读取该状态，形成下一趟外勤准备差异。
- 新增静态检查和 Godot runtime 专项检查，接入默认 `check-client` 和 `--with-godot`。

## 当前不做

- 不新增资源、配方、区域、任务链、完整背包、完整装备栏或自动化物流。
- 不继续扩 8 个非核心区的同类现场阶段读法。
- 不修改 `vertical_slice_map.gd` 的路线 / gate 逻辑。
- 不把本包扩成完整长期成长或发布前存档兼容专题。

## 玩家操作路径

1. 玩家在封锁遗迹压制相位守卫，回收污染回波沉积和外圈回波匣。
2. 玩家回基地，用污染过滤器处理沉积物并保留污染浆液，再用基础反应器解析深段回波。
3. 玩家到出发整备台，看到外勤收益可确认。
4. 玩家确认外勤收益整备，整备台写入状态。
5. 下一趟污染采集、污染反击或遗迹外圈承压反馈读出这次回基地收益。

## 运行时、存档与数据边界

- 真相源放在 `map_object_instance.field_outfitting_station` 的 `field_loop_payoff_confirmed`。
- 第一包只读取既有任务完成态、既有对象状态和既有装备状态。
- 不新增存档 schema；只扩展保存内容字段白名单。
- 旧对象 ID、任务 ID 和配方 ID 保持不迁移。

## HUD / 场景 / 对象反馈

- HUD：基地摘要显示外勤收益待解析、可确认或已兑现。
- 整备台提示：显示深段回波解析、基础过滤模块和外勤收益确认操作。
- 交互结果：确认后说明回波匣解析、污染回波沉积处理和过滤模块已串成下一趟外勤整备。
- 承压反馈：污染采集和遗迹外圈反馈读出“外勤收益整备已接入”。

## 验收条件

- 外勤回收 -> 基地解析 -> 整备台确认 -> 下一趟承压差异形成闭环。
- HUD、整备台提示、交互结果和承压反馈都能读出外勤收益兑现状态。
- 状态可保存、读取，并通过保存内容校验。
- 自动检查接入默认 `check-client` 和 Godot runtime 检查。

## 风险与后续决策

- 风险：继续在出发整备台堆状态会降低读法清晰度；后续若再加整备收益，应优先拆更窄的整备收益 presenter。
- 风险：本包只选封锁遗迹代表路径，不代表 8 个非核心区都要平均建设收益兑现。
- 第一包完成后应重新对照 `Demo Definition V1` 判断剩余缺口，优先选择真实玩家路径，而不是继续堆同类收益文本。
