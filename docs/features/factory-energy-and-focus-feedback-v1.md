# Factory Energy And Focus Feedback V1

更新时间：2026-10-27

状态：**2026-10-27 萝卜SAMA已确认整组数值、交互与存档方案，进入实现；设计基线尚未修改客户端。** 承接 [E2](factory-production-expansion-e2.md)亲测反馈：接网设备空闲时完全不耗电、准入口太小难找、密集设备难以辨认当前焦点。萝卜SAMA要求先确认规则与数值，再修改代码。现行能源合同仍以 E2 / V7 为准，本文不把建议写成已实现。

## 玩家结果与范围

玩家能区分运行、待机和手动停机，看见电力真实去向；直接从准入口上方识别允许物品，指向密集设备时准确知道将打开哪个对象。本包不新增物品、配方、制造成本或物流规则；基础供电仍为 240 kW，电芯仍为 7,200 kJ，单台 G 上限仍为 120 kW。

建议耗电新规则只进入 E2 的新版世界；旧 E2 显式复制接续，旧档继续按旧规则。图标与焦点属于共同三维工厂的派生视图，适用于支持这些设备的既有世界，不新增物料或状态字段。旧二维、独立样板与工程规模验收不随本包扩展。

## 运行、待机、停机

| 设备 | 运行额定 kW | 待机 kW | 手动停机 kW |
| --- | ---: | ---: | ---: |
| 采集器 | 20 | **2** | 0 |
| 粉碎机 | 20 | **2** | 0 |
| 冶炼炉 | 60 | **6** | 0 |
| 组装机 | 40 | **4** | 0 |
| 反应器 | 按配方 40 / 60 / 80 | **4** | 0 |

运行值沿现有配方；待机以设备基础工况约 10% 为起点。反应器待机固定 4 kW，不因切换高功率配方变为 6 / 8 kW：空闲控制系统相同，也避免靠换配方节约待机。运行功率已含本机附属耗电，不能再叠加一份待机功率。没有启动耗能、预热时间或启停冷却。

| 状态 | 请求与行为 |
| --- | --- |
| 启用且具备加工条件 | 请求运行功率；供电不足按既有满足率推进，未完成批次保留 |
| 启用但无可做工作 | 请求待机功率；包括缺料、当前配方未开放、输出堵塞或采集缓冲已满；不凭待机电产生进度 |
| 玩家手动停机 | 请求与实际耗电均为 0；输入、在制、输出和进度保留，被动物流仍按现有规则工作 |
| 未接网 / 接网无供电 | 保留运行或待机请求及缺口，实际耗电为 0；不能显示成手动停机 |
| 供电不足 | 各消费者同一满足率；运行 / 待机实际用电同比缩减，不引入待机优先或生产优先 |
| 世界暂停 / 离线 | 无时间推进，不累加运行或待机能量，恢复不补账 |

“因为没电不能加工”属于请求运行但供电不足，不改成小额待机来掩盖缺口。有在制的设备沿现有工作条件继续请求；产物完成并因下游堵塞无法开始下一批时，才进入待机。

传送带、分流器、汇合器、准入口、仓库、供电节点维持被动零耗电，不新增启停按钮。封装电源与电芯发电机是供电端，不收自身待机电；G 无缺口时仍不消耗电芯。准入口的“停止接收”不是消费者停机，槽内尾货继续排出。

## 数值影响与自举

| 既有样板 | 所有消费者启用但待机 | 全部消费者同时运行上界 | 240 kW 基础电源下全待机时 G 输出 |
| --- | ---: | ---: | ---: |
| C 能源子线 | 22 kW | 220 kW | 0 kW |
| P 自动备建 | 20 kW | 200 kW | 0 kW |
| D 扩建负载 | 56 kW | 560 kW | 0 kW |

C 为三采集器、一炉、一粉碎、一基础反应、一组装；P 为两采集器、两炉、一组装；D 为四采集器、五炉、三组装、一粉碎、一基础反应。数字按 [E2 能量收支](../reference/factory-production-expansion-e2-energy-balance.md)的指定设备 / 配方核算，额外启用设备另计。D 全待机时基础源合计实际输出 56 kW，两源同网均分为 28 kW；G 为 0，并明确“基础电源已满足需求”。

新增待机负载使“开着设备就有少量耗电”成立，但不保证任意布局都需要燃料发电。全部有料时的上界不变；E2 自救仍是停下不用的负载、留下最高 220 kW 能源子线，基础电源足够。停下 D 的其余负载可额外消除其 34 kW 待机请求。

一颗电芯的纯加工 / 采集工作能量仍为 1,960 kJ。待机成本取决于设备开启多久和闲置多久，不能改写成每颗固定增加一笔。以 C 七台消费者全程开启、充分供电、无额外采料 / 中间品积累的理想周期为例：

| 稳态产量假设 | 每颗工作电量 | 每颗待机电量 | 合计 | 相对 7,200 kJ 的净贡献 |
| --- | ---: | ---: | ---: | ---: |
| 1 电芯 / 分钟 | 1,960 kJ | 1,124 kJ | 3,084 kJ | 4,116 kJ |
| 3 电芯 / 分钟 | 1,960 kJ | 244 kJ | 2,204 kJ | 4,996 kJ |

计算式为 `待机电量 = Σ 待机功率 × (周期时长 - 各设备实际工作时长)`。每颗工时依次为铁 2s、炭 20s、晶体 2s、炉 8s、粉碎 6s、反应 10s、组装 12s；对应待机总功率 22 kW。长带、空出料步、起停库存与瞬时缺电未计，上表不是实际吞吐承诺。长期闲置可以耗去净收益，玩家需停机；若基础电源停用、C 全待机只由 G 供电，一颗电芯约支撑 327.27 秒，不能仍标“空闲不烧料”。

现有 D 四包 55.05 / 41.10 秒是旧规则证据；引入待机后须同起点重测，不沿用其提速百分比，也不拿旧稳态公式代入新规则。

## 固定步与能量账

保留 20 Hz、基础源优先、G 按实际同网缺口补电及有上限均分，不增加调度优先级。每步先按起点状态制定工作 / 待机预算，再统一分配并提交：

```text
dt = 0.05 秒
w = 有生产条件时 min(dt, 配方剩余工作秒数)，否则 0
启用设备请求能量 = 运行功率 * w + 待机功率 * (dt - w)
请求功率 = 请求能量 / dt
f = 该网实际供电 / 请求总量，限于 0..1
本步工作进度 = w * f
实际运行能量 = 运行功率 * w * f
实际待机能量 = 待机功率 * (dt - w) * f
手动停机：上述请求、进度及实际能量全部为 0
```

沿现有单步预算模型：分配后不把欠供的工作时间再次变成新待机请求、不在同一步反复重算，也不立即开下一批。末步只计剩余工作和其余预算中的待机；例如 60 kW 炉剩 0.01s，本步请求 `0.6 + 0.24 = 0.84 kJ`，平均 16.8 kW。供电 50% 时进度 0.005s，运行 0.30 kJ、待机 0.12 kJ；供电零则两项均为零。这是离散预算，不将其解释成精确的步内先后开关时刻。

累计与最近 600 秒趋势应能分辨实际运行 / 待机用电，满足：`基础供电 + 电芯供电 = 运行用电 + 待机用电 = 总实际用电`。G 激活、余能、回收损失及完整物品守恒沿 V7；取消加工不退已用电。派生视图、状态刷新与拓扑查询不计能量。

## 可见反馈与存档边界

设备面板同时显示“运行额定 / 待机额定 / 当前请求 / 实际用电”，例如“待机 · 缺料，实际 6 / 请求 6 kW”或“运行 · 供电不足，实际 30 / 请求 60 kW”。停机明确“已停机 · 0 kW”。电网摘要显示请求、实际供电及其中待机用电；G 面板继续区分基础满足、燃料耗尽、停用和无负载。电力状态图标表示供电条件，生产状态文字解释为何待机，避免把待机画成断电。

建议为此建立工厂 **schema 8 / `factory_expansion_e2_v2`**，地图和供给身份不变；新版 E2 新建入口使用新规则。V7 原档继续按旧规则，菜单明确“复制为待机耗电新版”，保留源字节与来源追踪，生成新世界 ID；既有 E1→能源复制入口可直接生成新版，复用现有复制事务，不要求玩家先经过旧 E2。

新版持久账增加实际待机能量（累计与桶），运行能量由总量减待机派生，严格校验非负及守恒。复制旧档时待机历史为 0，旧实际用电全部保留为运行用电；从复制时刻起才计待机，不能追扣旧时长。源锁、主档 / 备份、失败原子性沿 [V7 架构](../architecture/factory-energy-save-v7.md)，具体字段在确认后同步架构文档与 codec。仅图标 / 高亮不触发迁移。

## 准入口的浮动物品图标

参考萝卜SAMA提供的终末地截图中“闸口上方圆框物品”读法，使用本项目物品 SVG 和界面颜色；不复制截图素材，不推断截图红弧的功能。

- 常驻显示已经应用的 `filter_item`（允许物品），不是当前槽内货物，也不是面板尚未应用的候选。缺料、空载、暂停接收或配额完成时保留图标，避免最需要排查时消失；未配置显示明确的“待配置”通用符号。
- 首版采用屏幕尺寸稳定的圆形底框：外框 **32 逻辑像素**、物品 **24 逻辑像素**，可点击区 **40×40**；焦点态外框 40、物品 30。随 UI 缩放而缩放，不随相机拉远缩成几像素。图标位于模型顶上方，至少留 8 逻辑像素间距，用短引线对应本体。
- 底色增加对比，右下独立小标记表达停止接收 / 配额完成；不把环形颜色误当进度或供电。未配置优先，其后配额完成、手动停止接收；正常不挂额外状态标。焦点提示给出物品名与实际状态，尾货仍用现有“正在排空”说明。
- 点击图标与点击本体指向同一个准入口，近身开面板，远处只选择并提示走近；悬停图标也高亮本体。图标不截获面板、建造 / 铺带、拖动镜头等已有模式的输入；屏幕边外不吸附成可点远程按钮。
- 常规密集布局通过同一投影层把相交图标向上错层（不超过两层、每层 36 逻辑像素），引线保持对应；排布按稳定 ID 固定，焦点放大预留空间，不因悬停反复换位。仍无法分开的远景图标按距离 / 稳定 ID 只展示部分，焦点与已选对象保留，鼠标命中区只覆盖实际展示图标。近身 Tab 仍能逐个访问被遮挡准入口。

图标是导入设备的状态辅助，不改准入口 1×1 占地、碰撞、真实端口或运输节拍；不靠把整格点击范围扩大到邻设备解决瞄准问题。普通 / 最小窗口与远近缩放须实机检查尺寸，允许在上述目标内调整排布。

## 密集设备的焦点高亮

现有实现已有附近 F / Tab 候选与地面框，但自动附近目标优先于鼠标指向，地面框也容易被模型遮住。本包统一可见焦点与动作目标，保留角色两格内且无遮挡的操作校验。

| 输入情形 | 焦点与动作 |
| --- | --- |
| 鼠标指向设备本体或准入口图标 | 同一 ID 成为焦点；左键打开它，F 也操作它；不满足近身时只选择 / 提示走近，不跳开另一台 |
| 鼠标未命中对象 | 回到既有附近候选供 F 使用；空地左键不打开附近候选、不移动角色 |
| Tab | 切换附近可达候选并保持，焦点、名称和 F 同步；没有候选时不选远处物体 |
| Tab 后鼠标静止 | 保持键盘焦点；相机移动不会使静止指针自动抢走 Tab 选择 |
| Tab 后主动移动鼠标至少 4 逻辑像素，或左键点击 | 回到鼠标命中模式；点击时按当时实际命中重算，不能打开陈旧目标 |
| 鼠标模式下角色 / 相机移动、缩放 | 重新投影命中，轮廓跟随当前指针下对象，不沿用旧位置 |
| 面板、建造、铺带等独占模式 | 暂停普通悬停 / F / Tab 竞争；设备面板只保留当前面板对象标记，关闭后重新解析 |

鼠标继续使用现有近表面模型拾取；准入口图标是唯一新增明确命中入口。前景实体优先，不透过机器选择背后传送带；被遮挡的近身模块可用 Tab。F / 点击执行时再次校验 ID、距离、遮挡与实体存活，移出范围或拆除后清除失效候选。角色移动保留有效 Tab 目标，失效后按原附近候选规则更新。

焦点设备增加**模型外轮廓 2 逻辑像素**（最小窗口仍可辨认）和既有地面足印，辅以轻微亮度变化；用固定高对比青白色，不占用红 / 黄电力故障语义。只描当前实体：单段带、单个分流器、单个准入口或一台设备，不沿整条产线扩散。远处对象仍可显示轮廓，但提示“走近后操作”，不显示可用 F。

使用现有导入网格的动态描边 / 覆盖反馈，不新增替代设备的程序几何、不改资产风格。地面框作为定位辅助；不做透墙轮廓。只出现一个强焦点高亮，普通历史选中可留弱地面标记，不能与当前可操作对象争夺视觉。HUD 给出类型 / 名称与 ID、可操作提示、Tab 候选序号；不常驻展开每台设备名称。

## 确认后的实施与验收

整组范围已确认；按能源与存档、共同交互与视图两个可分割步骤实施，每步先完成定向验证再整体验证。客户端模块沿现有职责：规则给定功率，电网制定计划，模型固定步提交，统计 / codec 管账；焦点解析由输入与目标模块统一提供，视图 / HUD 只读显示。

| 验证层 | 必须证明 |
| --- | --- |
| 状态与守恒 | 运行 / 缺料 / 堵塞 / 采集满 / 停机 / 断网 / 欠供；满步 / 尾步；启停往返与暂停；总供用电守恒、待机不产物、重复查询不烧电芯 |
| 存读与复制 | V7 原样继续；V7 / E1 显式复制新版，源哈希不变；旧桶待机零，新版运行 / 待机累计独立恢复一致；坏账与失败 IO 拒绝 |
| E2 用途 | C 自举与 220 kW 自救仍成立；D 全待机 56 kW、G 不消耗；相同自然起点重测有限目标开关收益，区分新旧证据 |
| 准入口 | 未配置 / 有料 / 空载 / 停收 / 配额完成 / 尾货的图标语义；未应用配置不变图标；近远点击一致，重叠 / 错层仍能关联本体 |
| 焦点 | 机器 / 分流器 / 带紧邻时逐一准确高亮；鼠标、Tab、F、相机移动与面板切换一致；不误操作邻机、不绕过距离或遮挡 |
| 窗口与反馈 | 正式 Boot 普通 / 最小窗口、远近缩放、图标密集与高亮原图；真实鼠标 / 键盘操作路径；用户理解与瞄准体验另行亲测 |
