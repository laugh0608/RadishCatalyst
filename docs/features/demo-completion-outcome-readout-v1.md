# Demo Completion Outcome Readout V1

更新时间：2026-06-17

## 用途

本文定义首版 Demo 终点完成后的玩家可见成果整理第一包。它承接已完成的终点前综合准备读法，把核心稳定数据写入后的主线完成状态、终点前准备成果、基地收益和回前哨整理方向汇总到现有 HUD、地图提示、前哨核心、核心设备提示和完成日志。

本专题服务 [Demo Definition V1](demo-definition-v1.md) 中「完成 Demo 终点」「UI / HUD」「主线结构」「资源 / 生产链」「装备 / 模块」「自动检查」规格。它不是终局菜单、结算页、试玩准备或发布 polish。

## 玩家价值

玩家完成核心稳定设备写入后，应能读出：

- 首版 Demo 主线目标已经完成，而不是只看到一次任务完成弹窗。
- 终点前投入的侧边补给、稳压缓冲包、守卫缓存和药剂承压在完成态里被记录。
- 基地整备、外勤收益和后续复测读数仍能作为成果整理的一部分被看见。
- 回前哨后该做的是整理补给、整备记录和复测读数，而不是误以为开启了新章节或发布流程。

## 与整体规划的关系

- 继续证明“基地服务冒险，冒险反哺基地”：终点完成态要回读玩家此前的基地准备和外勤收益。
- 承接 `Demo Endpoint Readiness V1`，但不继续加厚核心写入前提示。
- 复用 `DemoMainlineCompletionFormatter`、核心稳定站对象、前哨核心、地图路线提示和完成日志。

## 当前已有基础

- 核心写入完成后已有 `DemoMainlineCompletionFormatter`、完成日志、HUD 目标和地图路线提示。
- 核心设备完成态已能复测守卫战消耗、侧边补给、缓冲包和守卫缓存。
- 出发整备台和外勤收益状态已经可被 HUD / 出发口读取。

## 本轮范围

- 新增 `DemoCompletionOutcomeFormatter`，集中描述完成后的成果摘要、地图提示、前哨整理、核心设备完成态和完成日志。
- `DemoMainlineCompletionFormatter` 调用成果 formatter，保持原主线完成入口不变。
- 完成日志可以读取当前世界 / 角色状态，说明完成成果和回前哨整理方向。
- 新增静态检查和 Godot runtime 专项检查，接入默认 `check-client` 和 `--with-godot`。

## 当前不做

- 不新增终局菜单、结算页、制作人员名单、试玩准备、发布准备或大规模 polish。
- 不新增资源、配方、区域、任务链、完整背包、完整装备栏或完整长期成长系统。
- 不改变核心写入完成逻辑、任务完成条件、承压公式或存档 schema。
- 不继续扩核心站完成后的回访链。

## 玩家操作路径

1. 玩家击败核心阶段守卫，回收守卫缓存。
2. 玩家在核心稳定设备写入核心稳定数据。
3. 完成日志显示主线完成、终点准备成果和回前哨整理方向。
4. HUD / 地图提示说明 Demo 终点已完成，并把玩家导回前哨整理补给和整备记录。
5. 前哨核心和核心稳定设备提示继续显示完成态成果，而不是开启新章节。

## 运行时、存档与数据边界

- 本包只读取既有任务完成态、对象状态、敌人状态、库存、装备和整备台状态。
- 不新增存档字段，不迁移旧 ID。
- 完成态成果读法不推进任务、不产生奖励、不改变承压或掉落。

## HUD / 地图 / 对象反馈

- HUD：显示“Demo 成果”摘要和回前哨整理方向。
- 地图提示：显示核心稳定站已接管、回前哨整理补给 / 整备 / 复测记录。
- 前哨核心：显示完成成果和当前可整理的补给 / 整备状态。
- 核心稳定设备：显示终点成果、守卫战投入和复测方向。
- 完成日志：记录主线完成、终点准备成果和不新增必需后续任务的边界。

## 验收条件

- 核心写入完成后，HUD、地图、前哨核心、核心设备提示和完成日志都能读出成果整理。
- 成果整理包含核心稳定通道、终点前准备成果、基地整备 / 外勤收益和回前哨整理方向。
- 完成态不显示终点前准备读法，不暗示新章节或发布流程。
- 自动检查接入默认 `check-client` 和 Godot runtime 检查。

## 验证计划

## 风险与后续决策

- 风险：完成态读法容易变成终局菜单替代品；本包只做现有界面上的成果整理。
- 风险：继续加完成态文案会稀释玩家下一步判断；后续只处理阻塞理解的断点。
- 第一包完成后应做阶段退出判断；若通过，继续对照 `Demo Definition V1` 选择新的非重复玩家路径缺口。
