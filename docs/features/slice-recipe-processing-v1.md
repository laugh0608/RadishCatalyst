# Slice Recipe Processing V1

更新时间：2026-07-19

状态：进行中（文档先行；关键取舍已定档 2026-07-19，待萝卜SAMA确认后进入实施）。切片第七个实现专题（化工链第二步、首次工业转化）。前序 [Slice Viewpoint Correction V1](slice-viewpoint-correction-v1.md) 已收口。

## 背景与定位

采集与建造已落地化工链第一步：采集器自动产晶体，晶体能修核心、能造采集器。但晶体始终是**同一种原料**——没有任何"工业转化"，反应器（`World/Reactor`）至今是纯摆设 `Sprite2D`，储存罐（`World/Storage`）同样。章程主线节点 2"建立首条化工链"只完成了采集自动化，"把原料加工成第二资源"这一真正体现化工差异化的环节仍是空白；修完核心后除了继续造采集器也再无目标节拍。

本专题让反应器获得真实功能：**晶体经反应器自动加工为催化剂，催化剂反哺核心充能**，形成"采集 → 自动产出 → 加工 → 产物用途"的完整化工链，并填补"修完核心无事可做"的空白。

素材条件：反应器、储存罐、整备台精灵均在场（视角修正轮已换装），催化剂为抽象计数走 HUD 文本，本专题零新素材。

## 玩家价值

- 看到：反应器激活后持续运转、晶体计数下降 / 催化剂计数上涨、储存罐存量读法（X/上限）、核心修复后的新充能目标行、充满后的里程碑文案。
- 做：修完核心 → 到反应器按 `E` 激活 → 派采集器补晶体喂料 → 反应器自动把晶体炼成催化剂 → 攒够后到核心注入催化剂充能，直到充满达成主线里程碑。
- 理解：原料不是终点——粗晶体经反应器变成更高价值的催化剂，催化剂让核心真正"活过来"。这是化工基地"把资源逐级增值"的第一课，也第一次让玩家在"喂反应器"和"造采集器 / 修核心"之间分配晶体。

## 方案与口径

### 第二资源命名（已定档 2026-07-19）

- **催化剂**（定档）：呼应项目名「异星催化 / RadishCatalyst」，反应器精炼晶体产出催化剂、催化剂驱动核心，叙事自洽。
- 备选「精炼晶浆 / 能量胶体」不采用，记录备查。

### 加工方式（已定档 2026-07-19：自动加工）

- **自动加工**（定档）：到反应器按 `E` 一次性激活；激活后反应器每 `T` 秒自动消耗 `N` 晶体产 `M` 催化剂，晶体不足或催化剂满仓则暂停等待，条件恢复即继续。复用采集器 `_tick_production` 的帧率无关 tick 范式，形成"采集器补晶体 → 反应器耗晶体产催化剂"的真正自动产线。
- 备选「每次按 E 手动换一批」「手动装料后自动加工」不采用，记录备查。
- 加工为自动、**充能为手动**（见产物用途）：设备自动生产、玩家决策投放，保留主线推进的主动感。

### 产物用途（已定档 2026-07-19：核心充能）

- **核心充能**（定档）：核心修复（`core_repaired`）后解锁充能目标；到核心按 `E` 把储存的催化剂注入核心，推进核心能量 `core_energy`（0 → 充能目标），充满即达成主线里程碑。复用现有 `OutpostCore` 节点与交互点，直接填补"修完核心无事可做"的空白，产线闭环落在核心上。
- 充满反馈无新素材：以 HUD 目标行 `core_energy / 目标` 表达为主，核心贴图维持修复态；充满后可选给核心轻微 `modulate` 泛光（属允许的状态高亮，非程序绘制主介质），作打磨项不作硬性范围。
- 催化剂作通用货币 / 升级建造货币的用途本专题不做（落点仅核心充能），留后续专题。

### 储存罐功能化（已定档 2026-07-19：容量上限 + 存量读法）

- 催化剂存量 `catalyst_count` 受储存罐容量上限 `CATALYST_CAP` 约束：满仓时反应器暂停产出，注入核心消耗后恢复——形成"储存满了就去用掉"的真实产出压力与消费动机。储存罐第一次获得真实功能。
- 存量读法：HUD 常驻催化剂计数行 `催化剂：X/上限`；储存罐节点挂只读交互点，走近显示同一存量读法，让此前纯摆设的储存罐"有反应"。只读交互无副作用。

### 数值草案（可调，实机手感定）

- 加工配比 `2 晶体 → 1 催化剂`：精炼有损耗符合直觉；修完核心（消耗 10）后全图余 7 晶体，激活反应器可先炼出几个催化剂起步。
- 加工间隔 `10 秒 / 批`：与采集器同节奏、观感"设备在运转"。单台采集器（10 秒 /1 晶体）供不满单台反应器（10 秒消耗 2 晶体），需约 2 台采集器供 1 台反应器——产线平衡第一课，属良性张力，比例可调。
- 催化剂容量上限 `20`；核心充能目标 `10 催化剂`。
- 缺料 / 满仓暂停时不累积超额度：加工计时余量钳在单批间隔内，避免长时间停摆后补料一次性爆产。亚周期加工进度不入存档（同采集器口径，读档从 0 重计）。

### 存档接入

- `SliceWorld` 状态追加 `catalyst_count`、`reactor_active`、`core_energy`（`core_charged` 由 `core_energy >= 目标` 派生，不单独存）；写入沿用 `SliceSaveService`，schema 保持 1、追加可选字段（旧存档缺省为 0 / false，无迁移成本）。
- 读档还原：催化剂存量、反应器激活态（激活则读档后继续运转）、核心充能进度全部回填；HUD 与目标行按还原后状态刷新。

## 范围（串行推进）

### 包 1：反应器自动加工与催化剂储存

- 反应器挂激活交互（未激活提示"按 E 激活"，已激活显示运转 / 缺料 / 满仓状态）；`SliceWorld` 增反应器 tick——激活后每批消耗晶体产催化剂，缺料 / 满仓暂停。
- 催化剂存量 + 容量上限；HUD 新增催化剂计数行；储存罐挂只读存量交互点。
- `catalyst_count` / `reactor_active` 随本包进存档，读档还原（避免"激活后未存"的中间态丢失）。
- 出口：实机激活反应器，晶体自动转催化剂，HUD 显示 `X/上限`，缺料与满仓暂停正确，存读还原催化剂与激活态。

### 包 2：核心充能与产线闭环

- 核心修复后交互转充能：按 `E` 注入催化剂推进 `core_energy`，充满置里程碑；HUD 目标行三态（未修复 → 修复后充能中 → 已充能）。
- `core_energy` 进存档、读档还原。
- 出口：攒催化剂注入核心充能，充满达成里程碑；存档 → 重启 → 读档，核心能量与全部新状态还原。

### 包 3：全链路验证与收口

- 运行时脚本走真实入口断言完整链路：激活加工、缺料 / 满仓暂停、催化剂产出与容量、核心充能推进与充满、"存档 → 重启 → 读档"还原全部新状态。
- 实机截图：反应器运转 + 催化剂计数、储存罐存量读法、核心充能目标行与充满里程碑，记入当周周志。

## 成功证据

- 正式入口：修完核心 → 激活反应器 → 补晶体喂料 → 反应器自动产催化剂（HUD `X/上限`，缺料 / 满仓暂停可见）→ 到核心注入催化剂充能 → 充满达成里程碑；退出重进后催化剂存量、反应器激活态、核心充能进度全部还原。
- `sh ./scripts/check-client.sh` 通过；`--import` 与运行时复核按需执行（启动 Godot 前先告知萝卜SAMA）。

## 失败退出

- 按 [Development Decision Gates](../process/development-decision-gates.md) 两次失败停手规则执行。
- 反应器 tick 或核心充能两轮实现仍有重复扣费、数值穿透（负晶体 / 超容量 / 超充能目标）或读档丢新状态，停手复盘承载结构，不继续追加同类调参。

## 不做

- 不做多种产物 / 多级配方 / 副产物 / 污染排放；不做管道 / 传送带等物理物流（催化剂为抽象计数）。
- 不做反应器多台建造 / 升级 / 拆除移动；不做催化剂作通用货币或升级建造货币（落点仅核心充能）。
- 不生成新素材 / 图标；不做敌人、战斗、任务链、立绘对话、八方向动画、viewport 重构。
- 不迁移、不修改冻结的旧系统与旧检查。

## 状态 / 存档 / HUD / 检查

- 世界状态追加 `catalyst_count`、`reactor_active`、`core_energy`，与既有循环状态同层存于 `SliceWorld`；存档沿用 `SliceSaveService` 追加可选字段，schema 不升版；亚周期加工进度不入存档。
- HUD 沿用 `SliceHud`：新增催化剂计数行，目标行扩为三态，提示行复用；不新建面板、不做图标。
- 只要求 `check-client` 静态通过与无导入错误，不新建检查脚本文件。
