# Slice Unified Device Operation Panels V1

更新时间：2026-08-13

状态：**已完成。包 1 功能与 P2-C 视觉、包 2 核心仓库与首次充能的行为及 P2-D 整面视觉均已获萝卜SAMA人工通过。**

## 目的

把采集器、储物箱、反应器、电力中继、传送带、地板和前哨核心现有“长文字列表 + 数字键记忆”操作面，升级为同一套工业科幻设备界面。玩家应先看见设备身份、当前状态、物料流和异常原因，再通过明确按钮完成取料、转移、回收、调整或拆除。

本专题是 [第一可玩切片全链串通](slice-first-playable-journey-v1.md) 的当前表现层子专题。它不新增设备能力，只让已经通过全链验收的权威状态与操作对陌生玩家可读。

## 专题开工十问

1. **玩家新增动作：**不记数字键也能用鼠标查看设备状态、转移物料、回收产物、调整位置和确认拆除。
2. **世界明确变化：**世界规则不变，但每台设施从文本命令表变为有设备身份、物料槽、余量条、端口诊断和动作区的现场终端。
3. **服务基地—冒险闭环：**玩家能发现采集、物流或加工为什么停住，取回产物并继续核心充能与外勤准备。
4. **感知时长：**修复核心后的 5–10 分钟基地整备中，玩家会连续接触核心仓库、采集器、储物箱和反应器面板。
5. **系统范围：**复用现有建筑实例、`Inventory`、电网、物流网和世界操作 API；只增加窄职责展示快照与 UI 组件，不建设通用工厂管理框架。
6. **现有介质：**复用建筑 sprite、晶体 / 催化剂 / 零件图标、面板容器、进度条和按钮，不生成新世界美术或大幅背景图。
7. **成功证据：**正式 `Boot` 鼠标路径、专项断言、三态截图联系表和萝卜SAMA人工复核共同成立。
8. **失败处理：**若仍像换皮文字表，先调整组件层级与信息密度；两次同类失败则停手复盘，不继续叠字段、边框或说明。
9. **旧系统关系：**不复活旧 Demo 设备面板、全局计数、旧反应器或旧仓储系统。
10. **切片推进价值：**解除设备操作草稿层后，陌生玩家才有可能独立读懂完整产线，直接接近盲测解冻条件。

## 信息架构

### 共同壳层

- 顶部固定显示设备 sprite、名称、类型短标签、主状态徽标和关闭按钮。
- 主状态只使用“运行 / 等待 / 警告 / 故障 / 被动”五类语义；颜色必须同时配短文字或图标，不能只靠色相。
- 中段按对象显示物料槽、容量条、加工进度或端口卡；没有某类能力时不保留空框。
- 底部“现场操作”和“设施维护”分区；取料 / 转移 / 回收属于主操作，调整 / 拆除属于次级维护。
- 操作结果使用固定反馈区，不在每次刷新时向列表末尾追加句子。

### 设备专属读法

- **采集器：**电力状态、晶体输出槽、缓冲余量条、当前生产进度、“全部取出”按钮和背包空间阻塞。
- **储物箱：**晶体 / 催化剂双槽、总容量条、`IO` 端口状态；每种物料各有“存入全部 / 取出尽量”按钮。
- **反应器：**固定配方 `2 晶体 → 10s → 1 催化剂`、输入 / 输出槽、加工进度条、电力状态、`IN / OUT` 端口卡和“原子回收”按钮。
- **中继：**通电状态、上游连接与“调整后预计掉电 N 台”提示；不伪造功率、负载或发电量。
- **传送带：**方向、当前货物图标和进度；不增加吞吐统计、路径预览或手动装料。
- **地板：**标记为被动承载，只显示支撑 / 可维护状态，避免套用机器输入输出。
- **核心：**保留仓库和首次充能两个专用控制器，但视觉壳层、状态色、物料卡、按钮和反馈区与设备面板一致。

## 权威状态与展示快照

- UI 不保存任何业务状态，也不修改 schema 7。
- 允许增加一个窄职责、只读的设备展示快照，汇总名称、图标、状态语义、容量、进度、端口和动作可用性；每次都从当前建筑实例与世界系统派生。
- 物流网应提供结构化端口结果，例如 `unconnected / connected_input / connected_output / wrong_direction`；面板不得解析“未接传送带”或“方向错误”等用户文案反推状态。
- 电力、反应器加工、库存数量和维护阻塞继续读取现有权威对象；实际操作仍调用 `collect_from_collector()`、各类 `transfer_*()`、`recover_reactor_contents()`、调整和拆除 API。
- `SliceWorld` 不新增按设备类型拼 UI 的业务分支；展示组装应留在面板侧或独立快照组件。
- 采集器 / 反应器可按现有 `0.15s` 节奏刷新视觉，库存与物流仍优先由信号触发；刷新不得写盘或触发生产。

## 输入与危险操作

- 鼠标点击是完整主路径，现有数字键继续作为同义快捷键；`Esc` 与右上关闭按钮等价。
- 按钮禁用时直接显示具体原因，不允许点击后才用“操作失败”兜底。
- 拆除采用显式两阶段确认：第一次进入警示态，第二次确认执行；取消后返回维护区。键盘 `2` 两次的既有语义保持兼容。
- 面板打开时继续与合成、仓库、充能、放置、战斗和暂停前台互斥；关闭后要求新的攻击按下。

## 实现包

### 包 1：统一建筑操作面板

- 重建 `SliceBuildingActionPanel`，让全部六类已放置建筑进入同一壳层；采集器、储物箱、反应器获得完整设备组件，地板 / 中继 / 传送带使用匹配能力的精简版本。
- 接入结构化电力 / 物流 / 生产展示快照、鼠标主操作、维护区和可见拆除确认。
- 保留所有现有操作 API、快捷键、配方、物流、生产、容量、放置和存档规则。
- 正式入口至少取证：采集器待取、储物箱断链或已接、反应器加工 / 堵塞三态；包 1 先经人工确认，再进入核心面板。

实现结果：

- `SliceBuildingPanelSnapshot` 从建筑实例、背包和世界查询派生设备身份、主状态、物料槽、进度、操作可用性与维护阻塞；展示状态不写盘。
- `SliceLogisticsGrid.building_status_snapshot()` 提供储物箱 `IO` 与反应器 `IN / OUT` 的结构化连接结果；旧文字接口由同一快照生成，兼容既有提示与检查。
- 建筑面板改为设备抬头、主状态、状态卡、物料 / 流程区、鼠标操作区、维护区和固定结果区；数字键调用同一操作方法，拆除保留两阶段确认。
- 正式 `Boot → 新建世界 → 重载` 69 项验证覆盖权威电网、采集器可取、储物箱断链、反应器加工中三态、三类鼠标操作、各区可视范围与复核档还原；截图、联系表与可载入复核世界均保留在项目内忽略目录。
- 萝卜SAMA人工确认包 1 整体可通过；收尾删除“下一步：……”描述行，状态、端口、按钮和阻塞原因直接承担读法。包 2 暂停；下一步已确定先建立视觉层级与色彩分离专题，再建立有限电力专题。

视觉定稿结果：

- P2-C 以专用深钢壳层、中性表面、钢蓝 `A1` 与局部琥珀 / 红状态替换等权浅色卡片；没有修改全局 Theme、设备能力、物流、电网、schema 或世界资产。

- 三张原生图和六张同帧低饱和 / 灰阶图已经逐张检查，流程、异常、选择和结果均不只靠色相表达；萝卜SAMA于 2026-08-11 人工确认通过，P2-C 收口。

## 边界

- 不改设备配方、生产速度、电力范围、端口位置、物流方向规则、库存容量、维护门控或 schema。
- 不做配方选择、单件转移、拖拽物品、设备改名、升级、远程总览、吞吐统计或报警历史。
- 不做新的 UI 框架、主题编辑器、响应式系统或空泛 `Manager`；只提取两个以上面板真实复用的窄组件。
- 不改世界 sprite、3/4 投影、HUD、地图或角色动画；世界体积感由独立架构级专题承载。

## 验收与失败判据

- 不看说明即可用鼠标完成采集器取料、储物箱双向转移、反应器回收、建筑调整和拆除确认。
- 玩家能在三秒内指出设备是断电、缺料、加工中、待出料还是堵塞，并知道下一步应接线、补料、等待或清空。
- 六类建筑和核心的面板使用一致视觉语言，但不会给被动地板 / 传送带伪造生产参数。
- 键盘与鼠标路径结果一致；任何失败操作不丢失、复制或部分转移物品。
- `1920×1080` 正式窗口下无截断、重叠或中心主体异常遮挡；正式入口截图和人工路径是主证据。
- 若结果仍主要靠长说明、记键位、字符串解析或换边框后的旧列表理解，本包失败，不得以自动检查全绿收口。
