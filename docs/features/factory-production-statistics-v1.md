# Factory Production Statistics V1

更新时间：2026-09-25

状态：萝卜SAMA要求纳入统计系统，并提供终末地截图作为参考。本文记录界面目标与统计口径提案；采样参数、持久化字段和实现范围待与基础电力、发现生产包联合确认，尚未实现。

## 玩家目标与参考

玩家打开工厂统计，比较物料库存、实际产消和理论产能，发现制剂原料不足、物流堵塞或供电不足，定位相关设备并调整产线。统计页本身不改变世界；调整后的趋势必须反映真实生产变化，服务“准备开拓物资 → 扩展矿区 → 改善基地”的循环。目标是在一次 5–10 分钟建线 / 调整中提供可读收益，不增加独立报表任务。

参考为用户提供的 `Screenshot_2026-08-09-16-08-58-590_com.hypergryph.endfield.jpg`，原图 3200×1440，已直接查看；来源位于本机下载目录的“终末地UI参考”。文档保留可独立理解的需求，不依赖该个人路径存在，也不将截图复制为游戏素材。

图中可见：每种产物一行，图标 / 名称和本地仓储，蓝色生产与黄色消耗趋势，当前每分钟数据，独立的理论数据列，收藏星标、排序 / 筛选、区域选择及“10分钟内”范围。截图不能证明其内部采样、均值算法或统计边界；以下算法是本项目提案。

借鉴信息组织与比较方式，沿用本项目既有 UI 视觉，不复制品牌、图标、整套配色或移动端排版。首包范围为当前单个工厂世界，区域 / 多基地选择随真实区域经营需求再加入，不先做空选择器。

## 界面与玩家路径

1. 从工厂 HUD 打开“生产统计”，默认查看当前世界最近 1 分钟；新增页面为只读，阻断世界鼠标操作，但不自动暂停生产。显式暂停和失焦仍遵守现有活动时钟合同。
2. 每行显示“物料 / 终端仓库存 → 产消趋势 → 实际生产、消耗、净增减 → 理论生产、需求”。生产与消耗用独立线型 / 图例，配合色彩；同一行共用数轴，不把两条曲线堆叠成总量。
3. 可切换最近 1 / 5 / 10 分钟，收藏关键材料，按名称、净缺口或库存排序；筛选已掌握物料或当前有活动物料。未发现物料不提前泄露配方 / 开拓内容；已掌握但零产出的物料仍可查看。
4. 点开物料行，查看仓库、背包、设备缓冲、在途、在制占用，以及生产 / 使用该物料的设备清单；点设备定位场景并打开现有设备信息。无设备或已拆除时明确显示状态，不跳到错误实例。
5. 电力页与物料页并列，关联用电设备；在电力规则落地后提供真实供需、趋势与设备状态。调整供电或物流后，玩家回看同一窗口，确认实际速率恢复。

| 信息 | 要帮助玩家判断 | 首包约束 |
| --- | --- | --- |
| 仓储与库存分解 | 材料存在哪、是否还在路上或已投入加工 | 总库存不冒充可立即从仓取出的数量 |
| 实际产消趋势 | 刚才的断料 / 停电是否影响交付准备 | 明示时间范围、单位、覆盖时长，允许真实批次尖峰 |
| 理论产消 | 已建配方能力是否足够配平 | 与真实运行值并列，不能叫作预计交付量 |
| 设备明细 | 从统计异常走到可调整的设备 | 使用稳定实体 ID，不另造一套状态原因 |
| 电力供需 | 该扩电源还是修连接 | 区分未接电与供给不足，不只显示总发电图标 |

采用 Godot Control、现有面板与物料图标体系；趋势曲线属于数据图表，可程序绘制，不涉及世界画面主介质变更。普通窗口 / 最大化分别审阅，长名称、大数、空数据和列表滚动不能遮住关闭入口或保存失败提示。没有合适图标时先列资产缺口，不把参考截图切片用作正式图标。

## 物料口径提案

| 指标 | 定义与计入时机 |
| --- | --- |
| 实际生产 | 采集器真实生成，或配方完成并把产物写入输出缓冲时，按物品计件；一批产三件计三件，不等到入仓才算产出 |
| 实际消耗 | 配方完成时确认消耗本批投入；开路等不可逆使用在成功命令提交时计入。开批只登记在制占用，取消返料不产生虚假消耗 / 产出 |
| 转移 | 带上运输、入仓、取放、拆回与原样取消返料均为世界内部搬运，不计生产 / 消耗；入仓吞吐如另显示，必须独立命名 |
| 外部取得 | 拾取唯一样本等非工业来源单列取得，不混入工业生产速率；若将来允许丢弃 / 出口，再定义对应去向，不提前假设这些功能已存在 |
| 当前库存 | 分列终端仓、背包、设备可取缓冲、带上在途和本批原投入的在制占用；总持有量包含这些位置，避免因开批而虚假丢失原料 |
| 实际净增减 | 同窗口生产减消耗，单位件 / 分钟；外部取得等另列，因此不保证等于仓库库存差值 |

生产 / 消耗事件与权威模型成功状态变更一起发生，界面刷新、存读、重建视图和相机切换不重复记账；命令失败零计入。样本研究消耗按试制完成统计，取消不消耗唯一样本。玩家面板是经营信息，不替代原有材料守恒校验。

建议核对恒等式：某物料全世界总持有量变化 = 工业生产 − 已确认消耗 + 外部取得 − 外部移出。需比较同一世界和同一时段；在制原投入纳入持有量，转移不改变总量。仓库库存单独变化不满足此式，不能拿它反推全局产消。

### 实际速率与时间窗

- 建议以工厂实际已推进的模拟时间采样：每 1 秒一个桶，保存最近 600 个完整桶及当前未完成桶；各桶记录物料数量与有效时长，不按帧数采样。
- 所选窗口实际速率 = 覆盖区间内数量 × 60 / 有效模拟秒数；不足 1 / 5 / 10 分钟时使用真实已有时长，明确显示“已采样 N 秒”，不除以完整目标时长稀释数据。时长为零显示“暂无样本”，不是 0 产量。
- 曲线的点 / 区段按桶的真实时长归一为件 / 分钟；缩图合并相邻桶时先合数量和时长，不平均已归一的比率。提示允许查对应区间的数量与均值，轴尺度明示，跨物料行不以相同高度暗示相同绝对量。
- 暂停、失焦与关闭期间不补零、不推进采样，也不生成离线收益；无生产但模拟在正常推进时才记录真实零。活动时间积压尚未模拟时不先画未来数据，待模型追赶后按所属模拟时间落桶。
- 当前窗口最多包含完整桶和部分桶；以明确时间边界选择，实施前冻结边界取整规则并验证边界事件恰计一次。UI 可每秒刷新，不需要每帧遍历所有设备和历史数据。

### 理论产能与差额解释

- 理论生产 / 消耗按当前已放置、配方有效的生产设备数量 × 单批产物 / 输入数量 × 60 / 加工秒数计算；采集器按有效矿点与采集周期计算。是“充分供电、供料、无回压”的配置上限，不因当前缺电 / 缺料而降成实际值。
- 唯一试制、手动开路和拾样不折算成持续理论速率；实际使用仍计入相应实耗或取得，明细区分一次性用途，避免与连续配方配平混淆。多件输出上带的时间与物流限制也不在理论上限内。
- 理论值随增拆设备 / 改配方更新，表示当前配置；历史曲线表示过去运行，两者不能直接计算历史“效率评分”。首包不绘制伪造的历史理论线或据一次差额断言故障。
- 实际不足时，明细呈现当前缺料、回压、未接电 / 供电不足及涉及设备；不把当前状态反推为整段历史低产的唯一原因。短窗批次波动不自动标红为失败，净消耗超过生产也可能是玩家主动使用储备。

例如两台普通反应器的理论催化剂产能为 12 件 / 分钟；实际某完整分钟只产 6 件时，可据设备反馈排查供料、出料或供电。把这 6 件搬过三段带再入仓，产出仍是 6 件；向矿壳使用 4 份制剂计 4 件消耗，不能把之前从仓取出又计一次。

## 电力统计的联合合同

电力页须在基础电力专题冻结功率 / 能量单位后确定精确公式；参考截图只直接支持物料统计的布局，电力页是本项目新增需求提案。

- 当前及趋势区分装机发电能力、实际供电、设备请求负荷与实际用电；请求负荷由电力模型定义的运行状态派生，避免缺电使实际用电下降后显示“电力充足”。不同独立电网不得互相抵消缺口。
- 电网明细至少呈现供需缺口、未连接设备和受限设备，能定位需要延伸供电的矿区；首包电网范围和选择方式随基础电力定义，不提前模拟不存在的多区域管理。
- 功率是瞬时值，窗口平均需按时间加权；能量按功率乘有效时长累计，并与物料的件 / 分钟分开。储能、燃料库存及充放电只在玩法已纳入时增加，不能显示未实现系统的虚假零值。
- 停电、恢复、负荷变更、暂停与跨进程恢复均须有对应图表证据。电力未实现时不将预供电解释成无限大发电机，也不宣称已具备电力统计。

## 状态、持久化与实施顺序

现有 `factory/model.gd` 只有 `generated`、`completed`、`delivered` 等窄计数，不能覆盖多物料历史、实际消耗和电力。沿现有权威模型记录成功事件，保留有限的按物品时间桶及窗口元数据；不建立无限事件流水、外部数据库、遥测服务或通用分析平台。

- 近期统计与同一世界快照一致保存，恢复时接续未完成桶，不重复计入加载状态。理论能力、当前库存与设备异常清单由当前状态派生；收藏和排序不反向影响模拟。
- 统计格式、桶上限、有限数值 / 非负数量校验及历史缺失的处理，在新的生产 / 电力存档联合设计中明确；不靠忽略非法历史字段伪装恢复成功。
- 原 schema 1 / 旧二维世界不因本专题被自动迁移。若后续给旧工厂开放统计，明确“从本次开始记录”，不能把旧累计数均摊成历史曲线；是否支持另行确定。
- 下一步先完成基础电力与本统计专题的指标 / 事件边界联合审阅，然后冻结新世界存档。生产代码实现时同步接入计数；统计页面和电力明细随真实功能接入，纳入发现生产包 D3–D4 验收，不能最后再从库存猜历史。
- 首包暂不做区域对比、产线自动识别、全历史导出、离线收益统计、预测补货或自动经营建议。保持单世界、短时间窗、可定位设备的完整路径。

## 验收与失败判据

自动验证须覆盖：一批多产物、开批 / 完成 / 取消、开路消耗、反复搬运、满输出暂停、取放与拆回、零样本和不足窗口、桶边界、正常空转与失焦暂停、环形覆盖、保存半桶 / 跨进程继续及异常历史拒绝。电力就绪后补充独立电网缺口、功率加权与能量一致性；缺电不把理论能力一并抹零。

正式 Boot 中通过真实生产展示至少一条“正常生产 → 断料或回压 → 修复”的趋势，并从行明细定位设备；电力链再补“未接电 / 供需不足 → 修复”。普通窗口与最大化保留原图，图例、单位、空态、列表与关闭操作实际审阅。人工路径应证明玩家能从差额找到可调整对象，并看到改善，不以数值断言替代。

使用 `tools/runtime-intake/check-runs/factory-statistics-v1/` 与 `tools/runtime-intake/review-worlds/factory-statistics-v1/` 隔离世界，截图存于 `assets/art-intake/<date>-factory-statistics-preview/`；遵循[运行时指南](../reference/godot-runtime-verification-guide.md)，启动 Godot 前告知。检查页面关闭 / 打开时的首档性能影响，保留原预算，不以缩小历史长度或负载冒称通过。

如果搬运抬高产量、取消产生负消耗、理论与实际含义不清、图表正常却无法定位设备，或读档断线被当成真实停产，本包不通过。先修口径与交互；连续两次同类视觉失败按[开发闸门](../process/development-decision-gates.md)复盘，不继续堆图表装饰。
