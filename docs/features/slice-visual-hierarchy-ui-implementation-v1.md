## 开工闸门五问

1. **玩家结果：**制造时先选择对象，只展开当前配方、阻塞、操作和结果；操作设备时沿身份、物料 / 流程、状态、操作和结果判断。两类面板打开后，世界、HUD 和当前现场仍可感知。
2. **实现介质：**重组现有 `SliceCraftPanel`、`SliceBuildingActionPanel` 的 Godot `Control` / 容器节点和窄职责 Theme 资源；复用现行 sprite / tile 图标、控制器与业务 API，不绘制新世界贴图。
3. **成功证据：**静态场景 / 脚本检查、制造与建筑操作专项、正式 `Boot` 的制造阻塞 / 可制作、反应器加工与储物箱断链截图，以及萝卜SAMA人工实机判断共同成立。
4. **失败判据：**面板仍覆盖大多数世界；七张长卡或重复设备状态卡继续主导；当前配方、阻塞、主操作或结果需要翻找；鼠标 / 快捷键行为分叉；任何权威规则、端口或存档被视觉重构改写。
5. **文档落点：**本子包保存结构映射与验收；父专题只保留双目标和总边界，规划入口只记录当前执行状态，W32 周志记录实现与验证证据。

## 实现范围

### P1：共享舷窗几何

- 两个面板统一右侧锚点、`1216×768px` 外框、深色抬头 / 页脚和三列内容节奏。
- 不建立通用 UI 框架；只有两类现行面板实际共用的壳层、卡片、状态、操作与结果角色才继续复用既有 Theme 资源。

### P2：制造 / 背包结构

- 增加不写盘的当前配方选择；鼠标点对象行只切换展示，主按钮继续调用现行权威制作路径。
- `1–7` 继续直接制作对应配方，`Shift + 1–7` 继续选中已有套件；快捷键结果与鼠标主按钮一致。
- 制作成功、材料不足、容量不足、已有套件和放置中仍由现行规则派生，最近结果不保存到存档。

### P3：建筑设备面板结构

- 只重排已有设备身份、主状态、物料 / 流程、端口、操作、结果与维护节点；六类建筑的能力裁剪保持现状。
- 反应器固定配方、储物箱双向转移、采集器取料、调整和两阶段拆除继续调用现行 API；不增加新设备能力或数字。

## 边界

- 不改配方、产量、库存容量、设备生产、电力、物流、端口位置、旋转、足印、碰撞、schema 7 或存档目录。
- 不解冻核心仓库包 2、有限电力、固定正面 / 显式端口迁移、世界目标接入、viewport 重构、陌生玩家盲测或发布。
- 不启动 Godot 前先告知萝卜SAMA；最终玩家可见结论必须基于正式入口原图和人工实机判断。

## 验收矩阵

- 制造阻塞：当前反应器明确显示缺少机械零件、制作禁用，其他可制作对象仍可选。
- 制造成功：鼠标制作后权威库存、九格数量、容量和最近结果同步；快捷键路径一致。
- 反应器加工：身份、电力、`IN / OUT`、输入 / 输出、`4.5 / 10s`、回收和维护可在同屏读取。
- 储物箱断链：双物料、总容量、`IO` 阻塞和恢复条件不依赖长说明。
- 面板边界：正式窗口不截断、不互叠，不覆盖左侧核心 / 世界关系和上下 HUD；关闭后攻击输入门控不回归。
