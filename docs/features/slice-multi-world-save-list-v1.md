# Slice Multi-World Save List V1

更新时间：2026-07-26

状态：**已收口（2026-07-26）**。承接已收口的 [Slice Save Persistence V1](slice-save-persistence-v1.md) 与 [配方加工 arc](slice-recipe-processing-v1.md)，把单个自动存档升级为最多 30 个彼此隔离、可选择、可命名并可供自动化复核的本地世界。本文记录目录功能在 schema 6 时的实现边界；外勤专题随后把世界状态升至 schema 7，目录所有权与三份备份规则不变，当前口径见 [Slice Runtime Systems](../architecture/slice-runtime-systems.md)。

## 玩家结果

玩家可以创建多个独立世界，在启动菜单查看世界名称、更新时间和进度摘要，选择任一世界继续；“新游戏”不再静默覆盖已有进度。自动化测试也能保留命名复核世界，让萝卜SAMA从同一套列表直接载入检查。

## 专题开工十问

1. **玩家新增动作**：创建世界、打开世界列表、选择并载入、重命名、把不需要的世界移入可恢复回收区。
2. **世界变化**：每个世界拥有独立目录、稳定 ID、自动存档和备份，最多同时保留 30 个有效世界。
3. **服务基地—冒险闭环**：多世界让玩家保留不同基地布局、玩法路线和后续联机房主世界，不必互相覆盖。
4. **感知时长**：启动后 1 分钟内即可创建第二世界并在列表中往返验证两个世界互不串档。
5. **系统范围**：保留 `SliceSaveService` 的单世界职责；新增窄职责 `SliceSaveCatalog` 处理枚举、创建、选择、迁移和回收，不把 30 槽逻辑塞进世界状态。
6. **地图与素材**：只使用启动菜单的现有 UI 语言与标准 Godot 控件，不新增世界层素材或程序绘制游戏画面。
7. **成功证据**：目录 / 迁移 / 容量 / 损坏隔离自动断言，真实 `Boot` 创建与选择输入链，列表截图，以及萝卜SAMA载入保留测试世界人工复核。
8. **失败路线**：若列表只能靠固定 30 个按钮、扫描全量 autosave 才能显示或损坏一档拖垮全部列表，则停手修正目录与元数据边界，不堆 UI 兜底。
9. **旧系统边界**：不复活冻结旧 `SaveService`、三槽旧 Demo HUD 或旧 `GameRoot`；只迁移当前切片单档。
10. **切片推进价值**：直接消除新游戏覆盖风险，并把自动化复核产物变成稳定可选世界；为后续多角色、房主世界和云备份保留正确边界。

## 开工前五问

1. **玩家结果**：启动菜单可看最近世界摘要；进入列表后可创建、选择、重命名、回收并载入最多 30 个世界，世界状态互不污染。
2. **实现介质**：文件目录 + JSON 元数据 + 单世界 `SliceSaveService` + `SliceSaveCatalog` + `StartupMenu` 列表面板；不新增世界画面资产。
3. **成功证据**：30 世界上限、稳定 ID、元数据轻读、单档迁移、主档 / 备份回退、损坏隔离、可恢复删除、真实 Boot 与保留复核世界全部成立。
4. **失败判据**：新游戏仍覆盖旧档；列表依赖读取每个完整世界；世界 ID 随重命名改变；迁移删除旧档；测试档污染正式目录；一档损坏导致列表或其他世界不可用。
5. **文档落点**：本专题保存功能与包边界；长期归属同步到存档架构；阶段入口指向本专题；实现、验证和人工结论进入周志。

## 核心模型

### 30 个世界，不是 30 份手动快照

- 槽位单位是“世界”：每个世界有一个持续自动保存的主状态和自己的备份。
- `MAX_WORLDS = 30` 只统计当前世界目录；内部备份和回收区不占世界名额。
- 本专题不引入任意时间点手动快照、快速存档 / 读档或跨世界复制物资。
- 达到 30 个世界后禁止创建新世界，并引导玩家先把一个世界移入回收区。

### 目录结构

```text
user://saves/slice/
  worlds/
    world_<opaque_stable_id>/
      metadata.json
      autosave.json
      backups/
        autosave.bak.1.json
        autosave.bak.2.json
        autosave.bak.3.json
  trash/
    world_<opaque_stable_id>_<deleted_at>/
```

- 世界 ID 是生成后不变的内部标识；重命名只改 `display_name`，不改目录名或世界归属。
- `metadata.json` 是列表摘要，不承载权威玩法状态；至少保存 `world_id`、显示名、创建 / 更新时间、版本、存档 schema、游玩时长和最近进度摘要。
- `autosave.json` 继续承载 schema 6 世界状态；目录升级不借机修改反应器、库存、建筑或地图字段。
- 列表只扫描一层世界目录并读取元数据；元数据缺失或损坏时显示该世界不可读取，不扫描整个世界状态来伪造正常摘要。

## 服务边界

### `SliceSaveService`

- 继续只负责一个已选世界的 `save_state`、`load_state`、原子写、schema 迁移和备份回退。
- 构造时接收明确世界目录；世界列表、30 上限、命名和删除不进入该类。
- 备份由当前单份升级为最近三份；任何轮转失败都不能覆盖现有主档。

### `SliceSaveCatalog`

- 负责 `list_worlds`、`create_world`、`rename_world`、`move_world_to_trash`、`restore_world` 和 `service_for_world`。
- 生产默认根目录为 `user://saves/slice/`；自动化可注入 `/private/tmp/<topic>/` 等独立根目录。
- 枚举按最近更新时间降序稳定排序；同时间使用世界 ID 排序，避免界面抖动。
- 单个世界损坏只影响该列表项；不得阻止其他世界创建、载入或复核。

## 单档无损迁移

当前切片单档位于：

```text
user://saves/slice/slice_world.json
user://saves/slice/slice_world.bak.json
```

首次启动新目录模型时：

1. 若 `worlds/` 已有世界，不重复导入旧单档。
2. 若只有旧单档，先用现有 schema 2–6 读取和校验链确认可读。
3. 创建一个稳定世界目录，以“前哨 01”为默认显示名，写入新主档、备份和元数据。
4. 再从新目录读回并比较关键状态；成功后把旧文件保留为只读导入来源，不删除、不覆盖。
5. 迁移失败时不创建半成品世界，旧单档保持原位，列表显示明确失败原因。

## 启动菜单与列表

- 启动页保留“新游戏”“载入存档”，摘要改为最近可读世界；“载入存档”打开世界列表，不直接进入固定单档。
- 世界列表使用可滚动条目，不创建 30 个固定按钮；每条显示名称、更新时间、核心状态、建筑数、催化剂数和兼容 / 损坏状态。
- 选中条目后提供“载入”“重命名”“移入回收区”；回收必须二次确认。
- 回收区不计入 30 上限，并提供恢复入口；本专题不做永久删除。
- 新游戏创建世界后再进入 `SliceWorld`；创建失败或达到上限时停留在菜单，不生成内存世界或覆盖其他档。

## 自动化与人工复核

- 自动化使用注入的目录根创建语义化世界名，例如“L5 完整产线”“schema 迁移失败样本”。
- 测试开始前可清理自己的隔离根建立基线；通过后保留最终世界目录、主档和备份，并报告人工复核入口。
- 需要复核多个互斥状态时建立多个世界，不在一次脚本中反复覆盖同一复核档。
- 人工启动器只注入同一测试目录并打开真实世界列表，不重建、不迁移、不删除测试世界。

## 实现包

### 包 1：世界目录、目录服务与单档迁移

- 新增 `SliceSaveCatalog`、世界元数据契约、30 世界上限和可注入根目录。
- `SliceSaveService` 切换为单世界目录，并补三份备份轮转；世界状态 schema 保持 6。
- 自动断言覆盖创建 / 枚举 / 稳定排序 / 上限 / 重命名 / 回收恢复 / 损坏隔离 / 旧单档无损迁移。
- 本包不改启动 UI；先证明目录与所有权。
- 2026-07-26 完成：新增可注入根的 `SliceSaveCatalog`，30 个世界上限、稳定不随重命名变化的世界 ID、元数据轻读、损坏项隔离和可恢复回收成立；`SliceSaveService.for_world` 使用 `autosave.json` 与三份降序备份，旧构造方式和单份 `.bak` 保持兼容。
- 当前单档通过“现有 schema 2–6 校验 → 隐藏暂存目录写两代新档 → 读回关键状态 → 原子发布”导入，旧主档 / 备份档不移动不删除。目录专项 89 项、完整 `check-client --with-godot` 与既有 schema 138 项全绿；本包尚未接 `Boot` 和列表 UI。

### 包 2：世界列表 UI 与 Boot 选择

- `StartupMenu` 增加可滚动世界列表、详情、命名输入、载入、回收 / 恢复和上限反馈。
- `Boot` 只在创建或选择世界后构造对应 `SliceSaveService` 并启动 `SliceWorld`。
- 自动与正式入口覆盖两个世界互不串档、新游戏不覆盖、重命名不改 ID、损坏世界不阻断正常世界。
- 2026-07-26 完成：启动菜单以单个可滚动 `ItemList` 提供世界摘要、命名输入、创建并进入、载入、重命名、二次确认回收、恢复与 `30` 上限反馈；回收 / 损坏项存在时仍可进入列表处理，不创建固定槽按钮。
- `Boot` 启动时执行旧单档导入，只在玩家创建或按稳定 ID 选择世界后取得对应 `SliceSaveService`；损坏元数据不能绕过目录边界构造服务。完整 Godot 回归全绿；有窗口真实入口 32 项证明两个世界的核心、建筑与催化剂不串档，第三个新世界不覆盖既有主档。
- 正式截图 `01-two-worlds-selected.png` 实审确认青黑列表、选中 / 焦点、进度摘要、命名框和操作区无截断遮挡。通过态在 `/private/tmp/radishcatalyst-multi-world-package2-review` 保留三个命名世界及各自主档 / 备份。

### 收口修正：游戏内暂停与返回

- 萝卜SAMA人工复核发现进入 `SliceWorld` 后无法返回启动页；这会阻断同一进程切换世界，包 3 不得据此收口。
- `Esc` 优先取消放置或关闭合成 / 仓库 / 建筑操作；无前台操作时打开暂停面板并暂停世界 tick。
- 暂停面板提供继续游戏、轻量设置、保存并返回主菜单、保存并退出；返回与退出前必须成功写入当前世界，失败时留在面板显示错误。
- `Boot` 保持进程根节点；返回时只释放当前 `SliceWorld`、清空选中服务并重建 `StartupMenu`，不得重启进程、改 schema 6 或误写其他世界。
- 正式入口须覆盖 `Esc → 设置 → 返回 → 继续`、保存返回菜单、同一世界重新载入与状态一致；玩家可见面板补有窗口截图。
- 2026-07-26 自动证据完成：新增青黑暂停层、轻量设置、保存返回 / 退出二次确认；放置与合成 / 仓库 / 建筑操作优先消费首个 `Esc`，无前台操作时才暂停世界 tick。保存失败留在当前世界，不释放节点。
- 真实 `Boot` 19 项断言覆盖暂停、设置返回、确认、写入最新状态、释放世界、重建启动页和同世界重载；复核根保留在 `/private/tmp/radishcatalyst-slice-pause-return-formal`。四图联系表为 `1280×784`、SHA-256 `78884772...d239ff2`。
- 列表交互修正：未选中条目时允许创建；选中已有世界后禁用“创建并进入”，并以提示说明应载入、重命名或回收。正式 `Boot` 19 项断言还证明禁用态不能通过信号误建世界，重新从“新游戏”进入后会清除选择并恢复创建；复核根保留在 `/private/tmp/radishcatalyst-create-disabled-formal`，截图 SHA-256 `c3b48f9c...bbed0e`。
- 2026-07-26 萝卜SAMA直接使用保留的包 3 复核根，确认选中已有世界时创建禁用而载入可用、`Esc` 暂停 / 设置 / 返回确认、保存返回、世界切换及原世界重载状态一致；人工证据闭环，专题收口。

## 不做

- 不做云存档、账号同步、Steam Cloud、跨设备冲突合并或联机世界上传。
- 不拆分角色档案 / 玩家档案，不允许角色或资源跨世界搬运。
- 不做手动快照、快速存读、存档导出分享、永久删除或自动清理回收区。
- 不修改冻结旧 Demo 三槽 UI、旧 `SaveService` 或旧 `GameRoot`。
- 不借目录升级改世界 schema 6 玩法字段，不顺带推进敌人、战斗、任务、HUD 换皮或发布。

## 验收

- 可创建并列出最多 30 个独立世界；第 31 个被明确拒绝，已有世界不受影响。
- 新游戏不覆盖旧世界；选择任一世界只读写自己的目录，重命名不改变稳定 ID。
- 当前单档无损导入，旧文件保留；主档损坏可按三份备份恢复，单档损坏不拖垮列表。
- 回收与恢复可逆；回收世界不占 30 上限，UI 不提供永久删除。
- 自动化保留的命名世界能通过真实列表直接载入，且不污染用户正式存档。
