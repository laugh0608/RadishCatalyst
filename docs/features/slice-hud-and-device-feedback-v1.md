# Slice HUD And Device Feedback V1

更新时间：2026-08-30

状态：4A、4B 已完成，下一步为 4C 常用设备扩展

上级专题：[试玩反馈整改 V1](slice-playtest-remediation-v1.md)

## 玩家目标

本专题只收口整改包 4：玩家在 16:9 全屏与窗口化非 16:9 下都能稳定读到 HUD，小地图真正贴合右下安全区；核心和常用设备不打开面板也能看出关键状态；电力连线只在需要诊断时出现；启动与暂停设置可以调整窗口模式、主音量和音效音量。

本包完成 R02、R05、R18、R20 与 A02、A03、A06、A07。传送带拖铺、无线回传语义、基地级工业总览、完整有限电力、新内容和完整按键重映射继续冻结。

## 开工前审计

- 生产视口为 `1920×1080`，实际 `1440×990` 窗口把内容保持为居中的 `1440×810`，上下黑边。像素与网格标准已冻结 16:9 虚拟画幅，因此本提案保留世界画幅与黑边，不扩相机可见区域；HUD 只在真实内容安全区内排版。
- 小地图虽然锚定右下，但底部固定留出 `152px`；上下文提示还通过运行时绝对偏移切换宽度。任务、物资、角色、提示和小地图尚未形成共同边缘栈。
- HUD 仍有 `12—13px` 正文和多处低明度文本；基地浅地与晶体区需要用同一批正式截图验证，而不是只看深色面板背景。
- 小地图 `SubViewport` 使用 `UPDATE_ALWAYS`，覆盖层每帧重绘；当前没有同场景 A/B 帧时证据，不能先猜测改成低频刷新。
- 电力连接层始终以高亮青色绘制完整网络，没有普通游玩、放置和设备检查三种上下文。
- 核心只有破损 / 修复两张既有主体资产，修复后的待充能、充能运行和样本安装主要靠整体染色；反应器已有两帧加工覆盖层，采集器、储物箱和中继大多只有通用红绿指示。
- 项目没有音频总线布局、`AudioStreamPlayer`、音效资产或用户设置服务；启动与暂停设置页均为占位。世界存档 schema 10 不应承担窗口和音量偏好。
- 既有运行时已经拥有核心修复、核心充能、样本交付、设备供电、加工、缓存和堵塞事实。表现层应读取这些权威状态；`SliceWorld` 当前约 `1490` 行，不再承接按设备类型增长的表现分支。

## 已确认开工五问

1. **玩家结果：**保留既有 16:9 世界内容和非 16:9 上下黑边，HUD 在内容安全区内形成统一边缘栈；小地图距右、下边缘使用同一安全间距，任务、物资、角色和上下文提示无互叠、截断或漂移。正文不再使用 `12—13px` 小字，并在基地浅地与晶体区保持足够明度。核心可凭主体轮廓、状态构件和动画节奏区分“破损 / 修复待充能 / 充能运行 / 样本已安装”；反应器先代表性区分无电、待机、加工和阻塞。设置页在启动与暂停入口共享窗口 / 全屏、主音量、音效音量及当前控制说明，重启后保留偏好。
2. **介质与权威：**HUD 使用 `Control` 锚点、`Container` 和统一安全边距收口，不改变相机、世界坐标、虚拟画幅或像素网格。核心和设备继续复用已锁定像素主体，只增加允许的局部状态灯、分段构件、选中描边与短时脉冲；不得用整体染色作为唯一通道。独立表现协作者订阅既有核心 / 设备状态，不复制玩法字段。用户偏好使用独立 `user://settings.cfg` 与 `Master / SFX` 总线，不进入世界目录、备份或 schema 10。首批音频为项目内自制、来源可追溯的短电子 WAV，只做修复、充能、样本安装、反应器启动 / 阻塞等状态切换提示，不加入音乐或常驻机器噪声。
3. **实施顺序：**4A 先建立共享设置面板、用户偏好边界、音频总线、HUD 安全区 / 边缘栈和小地图右下合同；同批把电力线改为普通游玩隐藏或极弱、放置相关设备和打开相关设备面板时完整显示，并对小地图 `UPDATE_ALWAYS` 做同机器、同世界、三轮 A/B 帧时测量，只有差异稳定超过测量噪声且不损失读图及时性才改刷新策略。4B 再实现核心四状态、反应器四状态及对应一次性视觉 / 音频反馈。代表路径人工通过后，4C 才把同一反馈矩阵扩展到采集器、储物箱和中继；不预先批量制作整套动画与声音。
4. **成功证据：**专项检查锁定两种内容尺寸的安全边界、无绝对漂移、小地图右下间距、正文最小字号、设置读写与世界存档隔离、总线音量 / 静音、电力叠层上下文、核心 / 反应器状态映射和无重复玩法状态。正式 `Boot` 至少覆盖 `1600×900` 与实际 `1440×990` 外窗，逐图检查基地浅地、晶体区、普通游玩、设备放置 / 面板、核心四状态和反应器四状态；逐耳确认主音量、音效音量、静音及重启恢复。小地图性能结论保留原始三轮 A/B 中位数与高分位帧时，结果可以是“证据不足，维持 `UPDATE_ALWAYS`”。最后回到整改专题 S0 新档全链。
5. **失败判据与文档落点：**若偷偷扩展非 16:9 相机视野、继续用大段绝对偏移、只靠颜色表达状态、正常游玩仍常亮完整电网、表现层改写玩法状态、设置混入世界存档、音效没有同批音量 / 静音、凭单次 FPS 猜测优化小地图、代表设备未通过就批量铺开，或继续向 `SliceWorld` 增加设备表现业务，则路线失败。本五问与稳定玩家 / 设置边界留在本专题；确认、实现取舍、性能原始值、检查数量、截图、试听和失败复盘进入 W35 周志。用户设置与世界存档的长期隔离在实现后同步存档架构真相源；只有包 4 实际完成后才更新 Current Plan 与 Daily Start。

萝卜SAMA于 2026-08-26 确认以上玩家结果、16:9 内容安全区、用户设置 / 音频边界、4A—4C 顺序、成功证据和失败判据。4A 与核心 / 反应器代表反馈 4B 已按下述证据完成；下一可分割批次为 4C，仍只把同一矩阵扩展到采集器、储物箱和中继。

## 状态反馈矩阵

| 对象 | 权威事实 | 持续反馈 | 一次性反馈 |
| --- | --- | --- | --- |
| 核心破损 | 未完成核心修复 | 破损主体 + 不规则危险闪烁 | 无 |
| 核心修复待充能 | 已修复且未充能 | 修复主体 + 空段状态构件 + 慢呼吸 | 修复脉冲与短电子确认音 |
| 核心充能运行 | 已充能且未交付样本 | 分段循环构件 + 稳定运行节奏 | 充能点亮序列与短电子上升音 |
| 样本已安装 | 遭遇状态为 `delivered` | 锁定构件 + 稳定常亮标记 | 安装收束脉冲与完成确认音 |
| 反应器无电 | 既有供电结果为否 | 暗灯 + 断电形状，不播放加工覆盖层 | 由有电转无电时一次警示 |
| 反应器待机 | 有电但未加工 | 单点稳定待机灯 | 进入待机不连续鸣叫 |
| 反应器加工 | 既有加工进度有效 | 复用两帧加工覆盖层 + 循环状态构件 | 开工一次提示，不做常驻噪声 |
| 反应器阻塞 | 输出或既有运行条件阻止继续加工 | 与无电不同的双段警示节奏 | 首次进入阻塞时一次提示并设冷却 |

颜色只承担辅助分组；形状、分段数量、明暗或动画节奏至少再提供一个通道。所有一次性反馈都由权威状态边沿触发，读档恢复到稳定状态时不得重复伪造里程碑。

## 4A 完成结论

- 新增独立 `SliceUserSettings`、`user://settings.cfg` 与 `Master / SFX` 总线；启动和暂停入口实例化同一设置场景，窗口模式、主音量和音效音量即时生效并独立持久化。试听音使用运行时生成的短电子波形，只验证总线路径，不提前占用 4B 正式反馈资产范围。
- HUD 统一使用 `18px` 内容安全边距，小地图贴合右下边缘；任务、物资、角色、上下文提示和小地图形成互不覆盖的边缘栈，正文不再使用 `12—13px` 字号。非 16:9 仍保持居中的 16:9 内容和上下信箱区，没有扩展世界视野。
- 新增独立电力表现协作者：普通游玩隐藏完整网络，放置用电设备或检查用电设备时才显示由既有供电拓扑派生的连接；地板、传送带等无关放置不会误触发。
- 同机器、同世界三轮 A/B 的 `UPDATE_ALWAYS` 中位数分别为 `8.334 / 8.320 / 8.319ms`，临时 `10Hz` 候选为 `8.324 / 8.367 / 8.366ms`；两者聚合中位数为 `8.320 / 8.366ms`，聚合 P95 为 `8.644 / 9.210ms`。候选没有稳定收益且高分位更差，产品维持 `UPDATE_ALWAYS`。
- 包 4A 专项 `47` 项、完整 Godot 回归和两种比例正式 `Boot` 均通过；`1600×900` 与 `1440×990` 外窗各通过 `46` 项，后者内容严格为 `1440×810` 并保留上下黑边。`SliceWorld` 为 `1489` 行，设置、HUD、电力表现和测量逻辑均未进入世界根业务分支。

## 4B 完成结论

- 新增无状态 `SliceDeviceFeedbackState`，只从既有核心修复 / 充能 / 交付、反应器供电 / 加工 / 输出阻塞事实解析八种表现态与状态边沿；表现层不写玩法状态，不新增 schema 字段。首次观察只建立基线，读档恢复稳定状态不会伪造里程碑。
- `SliceCoreVisual` 在既有破损 / 修复主体上增加局部分段构件、故障 / 锁定形状、慢呼吸 / 循环节奏和短时过渡脉冲，分别表达破损、修复待充能、充能运行和样本已安装；颜色不再是唯一通道。
- `SliceReactor` 复用既有加工覆盖层并增加分段构件、断电形状、阻塞双段标记和不同节奏，分别表达无电、待机、加工与输出阻塞；无电时不会继续显示加工覆盖层，阻塞提示具有 `1.25s` 冷却。
- `SliceFeedbackAudio` 以源码可追溯的确定性 PCM 构造六种短电子提示，统一通过 `SFX`；修复、充能、样本安装、反应器失电、开工和阻塞只在权威边沿触发。专项与正式运行时确认提示已播放、受 `Master / SFX` 静音控制且读档不重放；本轮没有把自动断言记录成主观人工听感结论。
- 包 4B 专项 `71` 项与完整 Godot 客户端回归通过。正式 `Boot` 在 `1600×900` 与 `1440×990` 外窗各通过 `63` 项，后者内容保持 `1440×810` 与上下黑边；两种比例的八态原图逐图复核通过，静态画面以形状 / 段数锁定差异，运行时再由动画节奏补足。
- 正式证据位于忽略提交的 `assets/art-intake/2026-08-30-playtest-remediation-package4b-preview/` 与 `tools/runtime-intake/2026-08-30-playtest-remediation-package4b/`，隔离世界位于 `tools/runtime-intake/review-worlds/playtest-remediation-package4b-16x9/` 和 `playtest-remediation-package4b-16x10/`；没有污染正式存档或用户设置。
- 首轮正式夹具使用非法反应器固定 ID，被生产 schema 正确拒绝；修正为合法自动 ID 后通过。随后证据截图过早捕获过渡脉冲，夹具改为先断言脉冲出现、再等待清除后记录持续态；这暴露并修正了状态切换后脉冲晚一帧刷新的确定性缺口，没有放宽产品规则。
- `SliceWorld` 最终为 `1485` 行，低于 4A 的 `1489` 行；世界根只把核心事实交给纯状态解析与既有视觉节点，没有承接按设备类型增长的表现或音频业务。schema 10、二值供电、反应器生产状态和存档迁移合同均未改变。
