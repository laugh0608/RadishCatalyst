# Demo Scene Art Foundation V1

更新时间：2026-06-15

## 用途

本文是首版 Demo 进入试玩准备前的可执行细专题，定义核心场景与初步美术识别第一包。

本专题服务 [Demo Definition V1](demo-definition-v1.md) 中「核心场景完成度」「区域 / 场景」「UI / HUD」和「初步美术」规格。目标不是制作最终美术包，而是让玩家在现有原型场景里能区分基地、晶体、污染和核心稳定站，并知道每个空间为什么要来、危险在哪里、为什么要回基地。

落地状态：2026-06-15 已完成第一包，覆盖场景识别层、HUD / 地图提示、对象提示和专项自动检查。

## 玩家价值

玩家从基地出发后，需要在第一眼读懂四件事：

- 基地是整备、加工、储存和出发的回路。
- 晶体区是资源带回基地的采集线，并有残骸侧路和异常回访点。
- 污染区有安全施工带、危险沉积带和过滤回基地理由。
- 核心稳定站是 Demo 终点，守卫、防护和稳定写入都指回基地整备。

## 与整体规划的关系

- 承接已完成的角色成长、战斗承压差异、工业主干读法和出发整备台收益。
- 覆盖 `Demo Definition V1` 中待建的「核心场景与初步美术」专题。
- 复用 12 区域封顶和现有 `VerticalSliceMap.tscn`；不新增区域或任务链。
- 让场景识别、HUD、地图目标和对象提示共同解释“基地服务冒险，冒险反哺基地”。

## 当前已有基础

- `VerticalSliceMap.tscn` 已有 `OpeningSceneLayer`、路线色块、基地设备垫、晶体采集线、污染施工带和核心稳定站路线带。
- `HudMapPresenter` 已能显示 12 区域标记和路线阶段。
- `HudStatusPresenter` 已能显示基地摘要、角色状态、工业主干和整备收益。
- `InteractionPromptFormatter` 已能按对象类型显示用途、状态、产物和下一步。
- `first_hour_readability_check.gd` 已覆盖首小时路线可读性，但不应继续加厚到场景专题检查中。

## 本轮范围

- 新增核心区场景识别 formatter，统一基地、晶体、污染、核心稳定站的短标题、视觉读法、外勤能力和回基地理由。
- 在 `VerticalSliceMap.tscn` 中补 4 个核心区识别条带 / 标牌 / 边界提示，强化现有色块而不是替换大规模美术。
- 让 HUD 地图路线提示读出当前核心区的场景用途和回基地理由。
- 让 HUD 基地摘要在非更高优先级状态下补一句当前核心区读法。
- 让关键对象提示能在资源、污染和核心稳定站对象旁读出“这里属于哪类场景，以及为什么要回基地”。
- 新增自动检查，覆盖场景节点、HUD / 地图文本和对象提示关键点。

## 当前不做

- 不新增第 13 区域，不平均加厚 12 个区域。
- 不做完整美术资产包、过场动画、完整照明系统或大规模换皮。
- 不做完整科技树、完整装备栏、完整 `loadout`、新资源体系或新敌人体系。
- 不继续加厚战术扫描、污染边界后勤维护、遗迹外圈模块承压或工业主干同一读法点。
- 不把本专题改成试玩准备、修 bug 或纯 UI 文案整理。

## 玩家操作路径

1. 玩家在基地看到整备回路、加工垫、出发口和回收理由。
2. 玩家进入晶体区，能看懂主采集线、残骸侧路和带资源回基地加工的目的。
3. 玩家进入污染边界，能区分安全施工带和危险沉积带，并看到过滤 / 药剂回基地理由。
4. 玩家推进到核心稳定站，能读懂守卫、防护、稳定写入和 Demo 终点反馈。
5. HUD、地图目标和对象提示在这些区域给出一致的场景身份与下一步收益。

## 运行时、存档与数据边界

- 本轮只从 `WorldState.current_region_id`、任务状态、现有对象和地图节点推导读法，不新增存档字段。
- 场景识别 formatter 只负责展示文本，不推进任务、不写库存、不改承压计算。
- 场景节点只补可读标识和色块，不改变可交互对象实例 ID、任务目标 ID 或区域边界常量。
- 若后续需要真实资产、动画或更细区域调度，应另建美术或场景专题。

## HUD / 场景 / 对象反馈

- 场景：4 个核心区都有明确色彩 / 地貌 / 设施识别与边界提示。
- HUD：当前区域在地图路线提示中显示场景用途，基地摘要在空闲态显示回基地理由。
- 对象提示：晶体、污染沉积、核心稳定站和基地关键对象能读出所在空间的用途。
- 检查：专项 check 覆盖节点存在、标牌文本、HUD / 地图提示和对象提示关键字段。

## 验收条件

- 基地、晶体、污染、核心稳定站 4 个核心区在场景节点和 HUD / 地图提示中都能被稳定识别。
- 对象提示至少覆盖一个基地设备、一个晶体资源、一个污染资源和核心稳定站对象。
- 实现不新增区域、资源、装备栏、科技 UI、任务链或大规模美术替换。
- 自动检查随 `check-client` 和 Godot 运行时检查入口执行。

## 验证计划

- 客户端默认检查：`sh ./scripts/check-client.sh`。
- 文档检查：`./scripts/check-docs.sh`、`./scripts/check-text-files.sh`、`git diff --check`。
- 因本轮新增场景节点与 GDScript 专项检查，按需执行 `sh ./scripts/check-client.sh --with-godot`。

## 风险与后续决策

- 本专题第一包只补核心区识别；若玩家仍读不懂 Demo 终点完成感，下一步应评估 `Demo Mainline Completion V1`。
- 如果后续做真实资产替换，应先定义资产清单、镜头读法和检查方式，避免把原型色块直接扩成长期美术规范。
