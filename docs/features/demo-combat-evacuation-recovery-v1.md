# Demo Combat Evacuation Recovery V1

更新时间：2026-06-17

## 用途

本文定义首版 Demo 战斗撤离恢复读法第一版的范围。它不是死亡系统、结算页或试玩准备；它用于检查并补齐玩家在外勤战斗、污染承压或核心守卫压力中生命 / 防护耗尽后，自动撤回前哨、恢复补给、HUD / 地图 / 对象反馈、状态 / 存档和自动检查之间的读法断点。

## 玩家价值

玩家失败或被迫撤回时，不应该只看到“回到基地”。他需要知道：

1. 这次撤离是生命、防护还是双重承压导致。
2. 外勤目标、敌人、关键对象和已取得收益是否保留。
3. 回到前哨后应该先补什么、确认哪个设备、下一趟从哪里继续。

本轮目标是让撤离成为可理解的基地恢复段，而不是隐藏的失败重置。

## 与整体规划的关系

本专题覆盖 [Demo Definition V1](demo-definition-v1.md) 的「战斗压力」「污染与防护」「UI / HUD」「存档 / 状态」和「自动检查」。

它承接已完成的 [Demo Playable Scene Composition V1](demo-playable-scene-composition-v1.md)：场景构成第一包已让 12 区域读法可定位；本轮转向战斗 / 污染承压后的恢复读法，避免继续围绕区域构成、路线职责或场景标签加厚。

## 当前已有基础

- 敌人反击、污染采集、防护模块、修复凝胶、抗污染药剂和出发整备台收益已能形成生命 / 防护承压差异。
- 生命或防护耗尽后，现有原型已有自动撤回前哨和撤离反馈面板雏形。
- HUD、地图、前哨核心、出发口、设备面板和存档系统已有第一轮 presenter / check 拆分。
- `Demo Endpoint Readiness V1`、`Demo Completion Outcome Readout V1` 和 `Demo Playable Experience Coherence V1` 已覆盖终点前后读法，但没有把撤离恢复作为独立玩家路径收束。

## 本轮范围

- 检查并补齐代表性撤离路径：污染防护耗尽、遗迹 / 深段战斗生命承压、核心守卫战后恢复。
- 撤离反馈应说明撤离原因、当前区域、保留的关键进度和回前哨后的恢复动作。
- HUD / 地图应能从前哨状态读出下一步：补生命 / 防护、补药剂、确认整备或回到当前外勤目标。
- 前哨核心、出发口或相关设备提示应能说明恢复后从哪里继续，而不是把玩家引向新任务链。
- 状态 / 存档检查应确认撤离后角色与世界位置、任务、敌人、对象和补给状态不会丢失关键进度。
- 新增实现优先使用窄职责 formatter、presenter helper 和专项 check，避免继续推高接近硬上限的大文件。

## 当前不做

- 不做死亡惩罚、尸体回收、失败结算页、终局菜单或发布准备流程。
- 不新增资源、配方、区域、任务链、敌人类型、完整背包或完整装备栏。
- 不调整战斗数值平衡曲线，不扩复杂 Boss 阶段或刷怪养成。
- 不改写行动台、高压窗口、候选队列或完整 `base_action_state`。
- 不把撤离恢复做成纯提示修补；必须有 HUD / 对象反馈、状态 / 存档和自动检查证据。

## 玩家操作路径

本轮检查沿三类既有玩家路径展开：

1. 污染边界：玩家防护不足时采集或被污染敌人反击，触发防护耗尽撤回前哨。
2. 遗迹 / 深段：玩家在相位守卫或深段敌人压力下生命耗尽，回到前哨后判断补给与继续目标。
3. 核心稳定站：玩家经历核心守卫承压后回前哨整理，读取守卫缓存、补给恢复和写入前后下一步。

## 运行时、存档与数据边界

- 不新增存档 schema，不迁移稳定 ID，不新增任务真相源。
- 撤离只读取既有生命、防护、区域、敌人、对象、任务、库存和整备状态。
- 自动检查可以构造代表性撤离状态，但不得要求新增任务链或新敌人。
- 若发现撤离后状态丢失，应优先修现有状态写入或读取，不添加掩盖问题的默认兜底。

## HUD / 场景 / 对象反馈

- 撤离面板：显示原因、承压来源、已保留进度和恢复建议。
- HUD 状态：回前哨后能读出生命 / 防护恢复、补给缺口、当前外勤目标和下一步。
- 地图提示：如果当前目标仍在外勤，应指回原目标；如果需要整理，应指向前哨核心、出发整备台或对应设备。
- 对象提示：前哨核心、出发口、整备台和关键设备应能解释撤离后继续路线。

## 验收条件

- `Demo Combat Evacuation Recovery V1` 建立并作为当前活跃专题。
- 代表性撤离路径能读出撤离原因、恢复动作、保留进度和下一步目标。
- 撤离后的 HUD、地图、对象提示、状态 / 存档和自动检查互相一致。
- 未引入当前不做事项，且新增检查走独立专项文件。
