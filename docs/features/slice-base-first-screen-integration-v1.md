# Slice Base First Screen Integration V1

更新时间：2026-07-15

状态：当前唯一活跃功能专题；首个切片实现包，2026-07-15 由萝卜SAMA指定并结束项目级暂停。

## 背景与定位

项目级复盘五项决策产物已全部确认，介质证据轮 S1 到 S6 全绿（见 [复盘文档](../planning/project-purpose-and-solo-ai-development-review.md) 与 W29 周志）。本专题把证据轮定稿素材真正接入 Godot 正式入口，让新像素世界的第一屏跑在引擎里——这是恢复实现开发后的第一个包，也是切片（单基地 + 单远征区，20 到 40 分钟）的起点。

介质机械口径以 [Pixel Art And Grid Standard](../reference/pixel-art-and-grid-standard.md) 为准：32px 玩法网格、960x540 相机虚拟分辨率（已定稿）、限定调色板、左上光向、地面 4x4 宏块归一。

## 玩家价值

- 看到：连续浅暖砂岩像素地面上的基地首屏——损坏的前哨核心、反应器、储存、整备台，全部来自定稿像素家族。
- 做：以像素工程师形象移动（含 4 帧行走动画），走近损坏核心。
- 理解：这是一款像素工业科幻游戏的开场，而不是拼贴示意图。

## 范围（串行推进）

### 包 1：归一管线与素材入库

- `tools/` 新增像素归一脚本（Python，零依赖或声明依赖）：整数缩放、限定调色板量化、地面 4x4 宏块切分、近黑底去背景、核心双态横版切分。
- 输入 `assets/art-intake/` 定稿候选，输出 `client/assets/sprites/slice/` 与 `client/assets/tiles/slice/`，英文资产名。
- 归一注意点（证据轮审阅结论，W29 周志）：核心双态切成 `outpost_core_damaged` / `outpost_core_repaired` 两张；行走帧表整体提亮到 d1 静态明度基线后再切 4 帧；立绘不归一、原图另存 `client/assets/portraits/`。
- 出口：归一产物入库并可被 Godot 导入，无 import 报错。

### 包 2：单基地场景与相机

- 新建切片基地场景（不复用 `VerticalSliceMap` 旧场景树）：`TileMapLayer` 按宏块坐标铺 C1 岩地，金属平台 C2 承托核心区。
- 摆位对齐证据轮拼合预览：损坏核心居中偏上，反应器 / 储存 / 整备台环绕，比例按 32px 网格与尺寸口径。
- 相机虚拟分辨率 960x540、整数缩放到窗口；项目显示设置按像素游戏配置（nearest 采样、无插值模糊）。
- 出口：Godot 正式入口打开场景，画面与拼合预览同构。

### 包 3：玩家接入

- 玩家挂 d1 静态 sprite 与 4 帧行走动画（`AnimatedSprite2D` 或 `AnimationPlayer`），移动时播放、静止回静态帧。
- 首版允许单向行走帧 + 水平翻转表达左右；不做 8 方向。
- 碰撞按 32px 网格对齐，可在基地首屏内自由行走、被设备阻挡。
- 出口：正式入口新档可控角色在基地首屏行走。

## 成功证据

- 正式入口（`Boot` 起）实机截图与证据轮拼合预览对比：地面连续、设备同族、比例一致、无旧视觉层混入。
- 人工路径：新档 → 移动 → 走近损坏核心，行走动画与阻挡正常。
- `sh ./scripts/check-client.sh` 通过；涉及场景与脚本改动时按需执行 `--with-godot` 单项验证。

## 失败退出

- 按 [Development Decision Gates](../process/development-decision-gates.md) 两次失败停手规则：同一问题同类方案两轮实机复核不过，停手升级萝卜SAMA，不追加同类调参。
- 归一脚本对某类素材两轮处理不达标（色带、糊边、宏块断裂），该类素材退人工点修或 CC0 基底,不无限调脚本。

## 不做

- 不做晶体区 / 污染区 / 远征区场景（后续包）。
- 不接入任务链、资源链、HUD、存档到新场景（系统层换皮是后续专题）。
- 不删除冻结的旧场景、旧视觉层与旧检查（清理清单另定）。
- 不新增玩法、配方、敌人；不生成新素材（证据轮素材足够本包）。
- 不做 8 方向行走、待机动画组或角色换装。

## 状态 / 存档 / HUD / 检查

- 本包不改存档结构、不接 HUD；新场景暂为独立入口，不影响旧 `VerticalSliceMap` 链路与既有检查。
- 旧运行时聚合检查维持现状；本包只要求 `check-client` 静态检查通过与新场景无导入错误，不新建检查脚本文件。

## 验收与移交

- 三包各自出口截图记入当周周志；专题收口时正式入口截图对比拼合预览判定。
- 收口后下一专题候选：晶体远征小区域场景、系统层换皮接入（任务 / 资源 / HUD 最小集）、立绘对话框最小接入；由萝卜SAMA按章程节拍择序。
