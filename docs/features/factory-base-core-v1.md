## 玩家结果与范围

玩家从唯一核心看见库存、各口用途、等级 / 研究与供电；通过真实传送带存入 / 取出物品，制造扩建构件，升级获得下一层能力。固定核心与多个接口提供布局中心，旧终端仓继续是独立缓冲，不自动共享库存。

核心由新地图预置一座，不占背包、不允许制造第二座、回收、移动或旋转。等级不改占地、碰撞、端口位置、基础功率和库存上限，避免升级破坏已建线。核心无自身耗电，基础库存 / 物流可在燃料耗尽时继续使用。

## 库存与物品

- 核心拥有一份 `items` 数量账，每种合法物品 `0..99,999`；零项省略，未知物品、负数、小数与超限拒绝。容量按物品分别算，不是全仓总和。
- 所有当期合法物品可手动入核心；`crust_sample` 等非物流物品仍不能走带，不能用新端口绕过原约束。尚未研究的加工品可存 / 取已合法获得的实物，存量本身不解锁科技或配方。
- 放入 / 取出沿既有两格近身要求；手动批量操作最多移动两端实际允许数量。研究 / 升级 / 装配成本要求整笔足够才扣，失败不部分消费。
- 仓库、背包、机器缓冲、在途与在制均进入同一全世界物料账。自动出仓只改变位置，不新增生产、采集或交付计数；取消 / 回收原子核对接收容量。

## 端口合同

几何采用 6×6，四边各三进一出，共 12 输入 / 4 输出；具体局部格与朝外法向见[布局预算](../reference/factory-integrated-demo-layout-and-budget.md#核心局部端口候选)。各口共用一个核心库存账。所有等级使用同一套口，研究与升级不收回已使用端口。

每个输入口接任一可物流物品；每个输出口配置 `{item, enabled}`，默认空 / 关闭，玩家明确应用后供料。首包不支持按秒定量、比例和条件信号；这些归测控科技。缺货、关闭、未配置、下游不接 / 已满分别显示原因。

输出每口沿既有 1 格/秒、一格一件的运输节拍，带就绪且首格空时最多交付 1 件；`cooldown_ticks` 为剩余冷却 `0..20 tick`（20 Hz，界面派生为秒），启用口每步减至 0，成功出料后重置 20，不累积多件突发。改物品或重新启用也重置 20，避免切换绕过节拍；关闭 / 暂停不推进，余值持久化。旧下游货物保留，按真实堵塞处理。

核心可在同一步经不同端口收 / 发多件，不能沿旧「同一实体每步至多收一件」的仲裁无声限制吞吐。采用步起点库存 / 带占用制定计划，先为每物品预留输入容量与输出数量，再一次提交：

1. 同一物品输出按稳定端口顺序与持久轮询游标公平取料，库存不足时只批准实际有的数量；每个口每步最多一件。
2. 输入按同样方式预留该物品剩余仓容，多个口不能同时挤进最后一个空位。未获批准的源保留货物与状态。
3. 不以本步正在出仓的数量提前腾仓位，也不把本步入库的物品立即再输出。无库存 / 满仓时最多延后一固定步，换取清楚的守恒与恢复。
4. 同一带 / 运输附件在本步不能既发又收；核心作为多口库存有明确例外，不能扩大到其他实体。

游标必须轮转到实际获准端口之后，不按运行时字典遍历决定结果。端口配置、冷却和游标均属权威状态；图标和选中高亮属于派生视图。

## 制造与核心等级

核心面板提供 `库存 / 接口 / 研究 / 等级 / 装配`。研究、升级和构件装配均在核心近身操作，先显示本次成本及结果，再从**核心库存**整笔扣除，不在背包和核心间自动凑料。背包可手动存入所缺材料。

装配沿已有构件包成本 / 产出：带 1 包→8 段，炉 / 组装等沿现行表，G 为 3 包→1 台；新包缺少的研究 / 类型一律拒绝。装配产出进入构件库存，使用新包自己的供给账和总拥有量上限，不能套旧 165 / 326 校验。

| 等级 | 首包规则 | 升级材料核算候选 |
| --- | --- | --- |
| I | 新档已有 B0，开放 I 档研究；库存 / 功率 / 多口齐备 | 无 |
| II | 要求 B1、M1、X1 已研究；开放 E1 / M2 / M3 | 核心扣 2 构件包；由 I 的直接工艺可生产 |
| III | 后续测控包开放，不在首包提供可支付升级 | 材料 / 研究与内容版本另定，不预留免费通路 |

升级采用“校验当前等级 / 前置 / 核心库存 → 原子扣料 → 递增一级 → 记录一次消费”的事务。重复请求不再次消费 / 赠送；保存失败沿既有失败面板暂停并重试，不回退内存制造第二笔成本。已发布事务由存档校验重新推导等级消费账。

## 交互与视觉

新核心模型、中心原点、低位端口锚点、等级模块与贴图需求见[R1 资产设计](../design/factory-representative-asset-brief-v1.md)。R1-B 的四面端口轮廓和短直带用于几何审阅；I / II 只切换网格。真实库存、物流和供电按本文另行实现。

核心使用导入模型，六格足印候选保持通行 / 点击与多口可读性。应用后的输出物品常驻标注，与物品准入口图标语义一致；未提交配置不改变供料。核心显示基础功率、库存上限、当前等级和下一步解锁；不把当前存量画成总仓容量条。

面板正常查看不额外暂停世界；研究与扣料发生在模拟命令边界，玩家可显式暂停规划。远处选择可定位，但近身要求与其他设备一致，不额外赋予远程库存传送。

## B1 首包

首个可验证结果是新核心 I 从零库存接入真实物流。玩家放置采铁器与直炼炉，将铁矿送入核心、经一个已配置的输出口送炉，最后把板材自动送回核心。采用四面版 S0 的 B0 路线子集，分别经 `IN_N2` 收铁、`OUT_S0` 供炉、`IN_N0` 收板。三段路线共 99 带，来自[已复算坐标](../reference/factory-integrated-demo-layout-and-budget.md#four-sided-layout)。反应器与催化剂需要 X1，归 B2 研究路径验证。

| 顺序 | 实施位置与检查 |
| --- | --- |
| 1. 新模型和占格 | 通过独立定义预置一座核心 I，按现有占用、实例与带入口索引建表。使用同一份正式端口定义校验 16 个 GLB 锚点。预置占用与构件拥有量可核对，制造、旋转及回收核心均拒绝 |
| 2. 单步物流事务 | 沿 `RoutingModel._logistics` → `Logistics.step` 的步初快照、方向匹配和单次提交。普通请求按实体 ID 归组，核心输出用端口 ID 区分请求，并在同一轮按步初库存预留出料和仓容。普通带继续与所有来源共享同一仲裁 |
| 3. 正常交互 | 用已有近身命令通路接核心的库存和输出配置。模型回传端口状态供面板及图标读取。按 [R2 首件规范](../design/factory-representative-asset-brief-v1.md#r2-first-asset-baseline) 装配导入轮廓并复核点击、行走、接带与箭头 |
| 4. 隔离路径 | 先跑状态断言，再用 Boot 的隔离诊断入口验证首次板材回仓。正式世界退出等待 Store 保存成功，临时内存入口明确不保存并正常返回。正式菜单与 schema 9 继续按总合同的联合门槛接入 |

仲裁时应同时覆盖普通带与核心的目标冲突。若核心和普通来源争同一空带，只允许一个请求写入。若同物品只剩一件或只剩一个仓位，拒绝另一口并保留对应货物或库存。输入、输出额度各用步初值，保持同一步进出顺序与遍历顺序无关。

B1 使用获认可的 `outline-06` 和 C2；M1 材质仍为样板。复核世界只在内存中运行，普通菜单不显示此入口，Store 拒绝写入该模型。用 `sh tools/check-factory-base-core.sh play` 进入空物料、已铺 S0 子路线的复核场；`empty-yard` 仅预置核心。研究和 II 升级归 B2，固定燃烧归 C。正式身份、旧档保护及持久化接入沿[整合存档合同](../architecture/factory-integrated-demo-save-v1.md)。

## 验证与失败退出

- 单 / 多口、同物品末件争用、最后一个仓位、不同物品同时流动、关闭 / 改物品 / 满仓、回压及输出冷却跨进程恢复；旧单实体仲裁不限制核心多口。
- 99,999 边界、样本禁走物流、未知物品、手动批量 / 装配 / 升级原子性、重复命令及总拥有量；所有位置的物料守恒。
- 正式 Boot 新档采矿→核心→加工→核心→研究 / 装配，实际行走与设备面板、升级前后碰撞 / 端口不变、保存继续。
- 端口过密无法辨认、物流必须靠手工反复搬运或升级挤坏产线，说明几何 / 交互候选失败；先改布局与参数，不以更多文字代签。

独立身份与失败恢复见[存档合同](../architecture/factory-integrated-demo-save-v1.md)。B1 的状态、窗口证据及边界见 [W45 周志](../devlogs/2026-W45.md#b1-core-first-plate)。跨进程冷却恢复与正式新档留联合门槛。
