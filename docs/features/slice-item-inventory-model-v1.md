# Slice Item Inventory Model V1

更新时间：2026-07-19

状态：配方加工 arc 的 **L0 资源模型改造** 可执行细专题。关键取舍已定档（2026-07-19，含核心兼任仓库），**进入实施**。arc 总览与层状态见 [Slice Recipe Processing V1](slice-recipe-processing-v1.md)。

## 定位

arc 地基层：把晶体 / 催化剂从全局 `int` 计数改为**空间物品 + 容器库存**——机器有进出料库存、核心兼任中央仓库、储存罐是容器、玩家背包有限、物品靠玩家手动搬运。替换抽象实现（包 1+2）的全局计数版。纯逻辑，**不依赖新素材**（沿用现有反应器 / 储存罐 / 采集器 / 核心精灵 + HUD 数字）。是 L1–L5（合成 / 电力 / 放置 / 传送带 / 反应器接入）的共同前提。

## 关键取舍（已定档 2026-07-19）

1. **采集器产出去向 = 输出缓冲 + 手动取料**：采集器产出进自身输出缓冲，满则暂停，玩家走到采集器取料；空间自洽，L4 传送带后自动化。
2. **存档兼容 = schema 升 2·旧档重开**：旧抽象存档（schema 1）不迁移，版本不匹配按新档重开，切片期单份原型存档可接受。
3. **背包有上限 + 核心兼任仓库**：玩家随身背包容量有限；**修复后的核心除承担（L2 起）初始供电外，兼任基地中央仓库 `core_store`**——容量近无限，玩家把背包物资卸进核心、从核心取用，背包满 → 回核心卸货，强化"基地服务冒险"。储存罐保留为机器旁次级容器（L4/L5 传送带端点用）。

## 玩家价值

- 看到：背包晶体 / 催化剂（带上限）、核心仓库存量、反应器进 / 出料格存量、储存罐与采集器缓冲存量——物品有"在哪里"。
- 做：采集晶体进背包 → 背包满回核心卸货 → 带晶体到反应器存进进料格 → 反应器炼出催化剂 → 取走 → 卸进核心仓库 → 核心把库存催化剂转能量充能。
- 理解：资源不再是一个总数，而是**分布在世界各处容器里的实物**，核心是基地中央仓库、玩家（之后是传送带）在容器间搬运——工厂自动化的第一性认知。

## 数据模型

- **物品 id**：字符串常量 `"crystal"` / `"catalyst"`（可扩展零件 / 建筑材料），集中定义避免散字符串。
- **`Inventory`**（`RefCounted`，非节点）：`Dictionary` item_id→count + `capacity`（总量上限，0 表示无限）；方法 `add(item, n) -> int`（返回实际放入，满则少放）、`remove(item, n) -> int`、`count(item)`、`total()`、`is_full()`、`to_dict()` / `from_dict()`（存档序列化）。
- **归属**：玩家背包 `pocket`（有上限）；**核心中央仓库 `core_store`（近无限）**；反应器 `input` + `output`；每个储存罐 1 个；每台采集器 1 个输出缓冲。机器与核心不再读写全局计数，只操作自己的库存。

## 交互改造（全部走库存，替换全局计数）

- 采集簇：采集 → `pocket.add("crystal", 产量)`（背包满则按余量少放并提示"背包已满，回核心卸货"）。
- 采集器：`_tick_production` 产出进采集器输出缓冲（满则暂停）；走近按 E 取料 缓冲 → pocket。
- 核心仓库：走近核心 存 / 取 pocket↔`core_store`（近无限，背包满时的卸货点、取货点）。
- 反应器：`_tick_reactor` 从 `input` 取晶体、往 `output` 放催化剂（缺料 / 出料满暂停，逻辑不变、数据源改库存）；走近存料 pocket→input、取料 output→pocket；激活态保留。
- 储存罐：次级容器，走近存 / 取 pocket↔box。
- 核心充能：从 `core_store` 取催化剂注入 `core_energy`（充能逻辑不变、源改核心仓库——存进核心的催化剂就地转能量，手动按 E 触发，保留玩家决策感）。
- 整备台造采集器：消耗 `pocket` 晶体（造价逻辑不变、源改 pocket）。

## HUD 改造

- 常驻计数改为随身背包：`背包晶体：X/上限` / `背包催化剂：Y/上限`。
- 就近容器读法：靠近核心 / 反应器 / 储存罐 / 采集器时提示行显示该容器存量与 存 / 取 操作；核心额外显示仓库存量。
- 目标行（修复 / 充能）不变；不新建面板、不做图标。

## 数值草案（可调）

- 背包容量 `30`（总量上限）；核心仓库 `core_store` 近无限（容量 0 = 无限）。
- 反应器进料格容量 `10 晶体`、出料格容量 `10 催化剂`（出料满暂停 = 消费压力，替代旧 `CATALYST_CAP`）。
- 储存罐容量 `50`；采集器输出缓冲 `10`。
- 加工配比 `2 晶体 → 1 催化剂`、间隔 `10 秒`、核心充能目标 `10`（沿用抽象实现草案）。
- 亚周期加工 / 产出进度不入存档（同现口径，读档从 0 重计）。

## 存档 / schema 改造

- `SliceSaveService` schema 升 **2**：序列化 pocket、核心仓库 `core_store`、反应器 input / output、各储存罐、各采集器缓冲库存（以稳定节点名为键），保留 `core_repaired` / `core_energy` / `reactor_active` / `collectors` / `harvested_clusters` / 玩家坐标。
- 旧 schema 1（抽象存档）按取舍 2 不迁移：版本不匹配 → 按新档重开，切片期单份原型存档可接受。
- 原子写 / 备份 / 读校验范式不变。

## 范围（串行推进）

### 包 1：库存模型 · 背包 · 核心仓库 · 采集侧

- `Inventory` 类 + 物品 id；玩家背包 `pocket`（有上限）+ 核心中央仓库 `core_store`（近无限）+ 背包↔核心存取；采集簇 → 背包、采集器 → 输出缓冲 + 手动取料；HUD 背包读法 + 核心仓库读法；schema 2 序列化背包 / 核心仓库 / 采集器缓冲。
- 出口：采集进背包、背包满回核心卸货、采集器缓冲满暂停并可取料，存读还原背包 / 核心 / 缓冲。

### 包 2：机器容器化与产线改造

- 反应器 input / output 库存 + 存取交互；储存罐容器化 + 存取；核心充能改走核心仓库、整备台造采集器改走背包；就近容器读法。
- 出口：背包 → 反应器进料 → 加工 → 出料 → 背包 → 核心仓库 → 核心充能 全走库存，存读还原全部容器。

### 包 3：全链路验证与收口

- 运行时真实入口断言手动搬运闭环 + 各容器容量 / 暂停 + 存档 → 重启 → 读档还原全部库存；实机截图；回填 arc 层状态表 L0 = 已收口；记周志。

## 成功证据

- 正式入口：采集晶体进背包 → 背包满卸进核心仓库 → 带晶体存入反应器进料 → 反应器产催化剂进出料 → 取出卸进核心 → 核心把库存催化剂转能量充能，全程无全局计数、全靠容器与手动搬运；退出重进后所有容器内容还原。
- `sh ./scripts/check-client.sh` 通过；`--import` 与运行时复核按需（启动 Godot 前先告知萝卜SAMA）。

## 失败退出

- 按 [Development Decision Gates](../process/development-decision-gates.md) 两次失败停手：库存增删数值穿透（负数 / 超容 / 丢件）、读档丢容器内容、或搬运交互两轮仍不成立，停手复盘承载结构，不继续追加同类调参。

## 不做

- 不做电力（L2）、建造放置泛化（L3）、传送带 / 自动搬运（L4）——L0 只做数据模型 + 手动搬运。
- 不做多物品合成树 / 配方面板（L1）；不生成新素材；不迁移、不修改冻结旧系统与旧检查。

## 状态 / 存档 / HUD / 检查

- 世界状态由全局计数改为容器库存，存于 `SliceWorld` 与各机器 / 容器节点；`SliceSaveService` schema 升 2。
- HUD 沿用 `SliceHud`：背包读法 + 就近容器读法；不新建面板。
- 只要求 `check-client` 静态通过与无导入错误，不新建检查脚本文件。

## 验收与移交

- L0 收口 = 手动搬运闭环实机成立 + 存读还原 + 截图；回填 arc 总览层状态表（L0 已收口）、同步三入口、记周志。
- 下一层 L1（手持合成面板）或 L2（电力）由萝卜SAMA择序；美术授权（传送带等）可并行推进。
