# Slice Item Inventory Model V1

更新时间：2026-07-19

状态：配方加工 arc 的 **L0 资源模型改造** 可执行细专题。**纯数据地基**：把资源从全局 `int` 计数改成"空间物品 + 背包"，并把起始场景收窄为"只有一个受损核心"。核心逻辑已随包 1 实现（2026-07-19）。原计划的核心仓库 / 机器进出料 / 手动搬运经实机复核判定抢跑上层，已撤回重分配（见"移出 L0 的能力"）。arc 总览与层状态见 [Slice Recipe Processing V1](slice-recipe-processing-v1.md)。

## 定位

L0 只做两件地基事：(1) **晶体从全局计数改为背包 `pocket` 里的空间物品**；(2) **起始场景清成只有一个受损核心**（+ 地面 + 晶体区 + 玩家），其余设备一律改为后续"制作 + 放置"。它不引入任何机器喂料 / 中央存储 / 物品搬运 / 建造机制——那些属上层。L0 是 L1–L5 的共同前提，纯逻辑、不依赖新素材。

## 玩家价值（地基层）

- 看到：进入游戏只有一个受损核心和自己；背包晶体计数（带上限）；晶体是"实物、背包装得下才拿得走"。
- 做：走到东侧晶体区采集晶体进背包（满则拿不动）→ 走回用背包里的晶体修复受损核心。
- 理解：这是"白手起家"的第一步——资源是要靠玩家搬运的实物，核心是第一个要靠采集来修复的目标；工厂的其余部分都要玩家后续亲手造出来。

## 数据模型

- **物品 id**：字符串常量 `"crystal"`（其余在其产出层引入），集中定义避免散字符串。
- **`Inventory`**（`RefCounted`）：`Dictionary` item_id→count + `capacity`（0 = 无限）；`add` / `remove`（返回实际量）、`count` / `total` / `is_full` / `to_dict` / `from_dict`。
- **归属（L0 范围内）**：玩家背包 `pocket`（上限 30）。其余容器在各自层引入。

## 交互（L0 范围内）

- 采集簇：采集 → `pocket.add("crystal", 产量)`，背包空间不足则拒采并提示。
- 核心修复：走近受损核心按 E，消耗背包晶体（`REPAIR_COST`）换修复态精灵。
- 起始场景：`SliceMap.tscn` 只保留受损核心（+ 地面 + 晶体簇 + 边界）；反应器 / 储存罐 / 整备台节点已移除。

## 数值草案（可调）

- 背包容量 `30`；核心修复 `10 晶体`。
- 采集簇产出沿用（小 1 / 中 2 / 大 4）。

## 存档 / schema

- `SliceSaveService` schema `2`：序列化背包 `pocket`（及已备但暂不可达的采集器 `[{cell, buffer}]`），保留 `core_repaired` / `harvested_clusters` / 玩家坐标等。旧 schema 1（抽象原型档）不迁移、按新档重开（切片期单份原型可接受）。

## 范围

### 包 1：库存模型 · 背包 · 起始场景收窄（已实现 2026-07-19）

- `Inventory` + 背包；采集簇→背包（满则拒采）；核心修复改走背包晶体；起始场景清成只有受损核心；HUD 收为 `背包晶体：X/30` + 修复目标行。schema 2。
- 出口（已达成）：进入游戏只有受损核心；采集进背包、背包满拒采、背包晶体修核心，存读还原；运行时断言全过、实机截图留档。

**L0 到此为止**。收口 = 包 1 实机确认后回填 arc 层状态表 L0 = 已收口。

## 移出 L0 的能力（重分配，防再次抢跑）

- **采集器**（制作 + 放置 + 输出缓冲 + 取料）：代码已备（`SliceCollector` / `CollectorPickupSite` / 放置与产出逻辑，随采集建造专题与包 1 落地）但**在 L0 不可达**（无制作入口）→ 由 **L1 手持合成面板**（造）+ **L3 建造放置**（放）接管。
- **核心 = 电力 + 中央仓库**（参照《终末地》基地核心）→ **L2 核心功能化**，含背包↔核心手动存取。
- **反应器进出料 + 催化剂 + 核心充能** → **L5 反应器接入**（供电 + 传送带自动进出料，不做手动喂料）。
- **储物箱** → **L4 传送带物流**（传送带两端）。

## 不做

- 不做核心仓库 / 电力 / 建造放置 / 传送带 / 催化剂 / 充能（均属上层）；不做任何"手动按键给机器装 / 取料"（机器物流一律走传送带）；起始不预置除受损核心外的任何设备。
- 不生成新素材；不迁移、不修改冻结旧系统与旧检查。

## 验收与移交

- L0 收口 = 包 1 实机（进入只有受损核心 → 采集 → 背包 → 修核心，存读还原）经萝卜SAMA确认；回填 arc 层状态表、同步三入口、记周志。
- 下一层 L1（手持合成面板：造零件 / 采集器等）或 L2（核心功能化：电力 + 中央仓库）由萝卜SAMA择序。
