## 玩家结果与取舍

玩家制造工业电芯，将它自动送入自己制造的发电机；扩建有实际产出的工厂后，发电机按同网缺口消耗电芯，提高加工速度。燃料耗尽时仍有基础供电，玩家能就地停下部分负载、恢复电芯生产，再继续扩建。成品用途从一次性制造延伸到随实际用电发生的消费，为后续开拓增加可用产能；E3 的高产矿与胶囊仍未开放。

**保留两套封装电源合计 240 kW。** E1 样板实测峰值约 100 kW，不能把额定功率相加当成已有缺电。本合同提供 C 紧凑启动、P 自动备建、D 扩建负载三个阶段：C 的请求上限仅 220 kW，应当显示发电机有燃料但不消耗；D 用三板炉、两载体炉、两构件组装机产生真实物料需求，必须在正式运行中证明缺电与产出改善。

D 是较大规模的工程与试玩样板：累计制造成本 30 包、总拥有量 256；它不是第一颗电芯的强制前置，也不要求玩家逐格照抄。C 从 E1 复用加工设备，只额外制造一台发电机，花 3 包。扩建可以逐步进行，短时缺口也允许触发发电；不得为演示关闭一套基础电源、降低旧世界供给、注入耗电器或免费补发负载设备。

已有启动检查点后 5–10 分钟内看见“电芯进入设备、待机不烧料、扩建后开始补电”是体验目标。完整 D 的备料、重布线与新手操作另计，不能承诺从零五分钟建成；若只有做完大批重复施工才能感知收益，应调整布局 / 目标或缩小交付，不以新增更长教程掩盖问题。

## 玩家操作流程

### 1. 接续 E1 与第一台发电机

1. 从菜单显式选择“复制为能源世界”，保留原 E1；也可新建 E2，从零材料按 E1 完成第二炉目标。复制不会把旧世界改成新规则。
2. 用已有直接工艺或混料回用制造 3 包，近身取入背包，装配并放下 G。E1 的 B 完成态通常有两包，此时还缺一包；以实际库存显示差额，不发补助。
3. 参考 C 复用铁 / 炭 / 晶体采集器、粉碎机、反应器、一炉、一组装机。清空后分别选 R05 / R07 / R01 / R12；停用不用的旧线，取回旧输入 / 在制 / 输出必须沿既有容量与近身规则，不能删除余料或强制清槽。
4. 先停用 G，配置原料准入口：首轮两电芯需铁矿 4、炭矿 2、晶体 4；燃料准入口放行 2。自然加工并观察两电芯进入 G，再启用 G。
5. C 没有基础电力缺口，G 应保持两件完整燃料、余能 0、输出 0，明确提示“基础电源已满足需求”。这一步验证自举与不空耗，不作为电力价值验收。

### 2. 自动备建与扩建负载

1. P 用 E1 已制造的第二炉分开直炼板材与直接烧结，专用组装机自动做构件包，免去每两包切一次配方。两原料准入口按实际待制造包数设置 `铁矿=4n、晶体=3n`；完成后停收且余料继续排空。
2. C 与 P 是可选重布置样板，不是同时存在的两套免费机器。可先停用 / 排空 C、保留燃料并复用其组装机制造构件；有实际库存后再造专用 E。移机返回原构件，不返制造包，也不增加任何资源。
3. D 的最低累计装配账为 30 包；若从 E1 已花两包制造第二炉且背包另有两包的 B 完成态出发，尚需自然生产 26 包。若已走 C，则发电机的 3 包属于同一总账，不能重复计费。原有库存、其他制造和货物均按实际状态增减。
4. D 将板材、载体、炭粉和催化剂分线；组装机三个入口同时接三种材料，仓库仍只收成品。先停机备料，确认有效负载、原料与输入端口，再逐台恢复生产。两套基础电源均启用且同网。
5. 对照 G 停用 / 启用，观察实际请求、缺口、满足率、进度和构件入仓；供电改善必须伴随实际加工改善。世界有料在途时不能只凭灯色判断断料或配额已空。
6. 自然做出新的 4 包，取入背包制造第二台 G（3 包）和分流器（1 包），按 D+ 放置；现有带库存刚好补所需 3 段。两机共同补缺口，不强制同时满载，也不要求把所有燃料烧光才算成功。

### 3. 耗尽、恢复与保存

1. 关闭燃料准入口的接收，先让已接收尾货排出；走近 G 取回未激活燃料，保留现有余能。启用有料的扩建负载后观察余能自然归零；若期间没有缺口，应解释不再消耗，不得制造虚假倒计时。
2. 耗尽仅失去发电补充，基础电源继续提供最多 240 kW。未完成加工保留投入和进度，不丢料、不重启批次。
3. 需要确定性恢复时，走近停下 D 的 `Q、F2、F3、H1、H2、A1、A2`，留下 `I、QE、K、F1、C、R、E`：这些能源设备请求上限 220 kW。补齐 / 恢复能源原料和燃料准入口，原基础电源足以重新制造电芯。
4. 恢复停机设备，观察新电芯自动接入并按缺口消耗；在余能非零、加工半批、传送带有货时保存，独立进程继续应从同一状态接续，不补离线产量。

路径中不开隐藏优先级，不通过暂停全世界充电。用鼠标选择 / 近身操作、WASD 行走、F / Tab / I 的既有规则；停机 / 启停 / 取放须近身，统计定位只改镜头。

## 单步供电与燃料合同

继续使用 20 Hz、同网按实际剩余工作请求分配。查询与视图必须是只读派生：刷新 HUD、重建拓扑、读取 `power_state` 或存档校验都不激活电芯、不计消费。

对每个电网及一步 `dt=0.05s`：

```text
D = 该网已启用、具备生产条件的设备实际请求 kW
B = 启用封装电源容量之和
base = min(D, B)
gap = max(0, D - B)
cap[i] = enabled[i] ? min(120, (remaining_kj[i] + 7200 * fuel_count[i]) / dt) : 0
generation[i] = min(cap[i], lambda)
sum(generation) = min(gap, sum(cap))
fraction = min(1, (base + sum(generation)) / D)  # D=0 时不加工、不扣能量
```

`lambda` 采用有上限的均分：余能很少的设备先达到上限，其余缺口继续由有能力的设备均分，不因平均给空机而浪费另一个发电机的能力。基础电源按原容量比例分担 `base`；全部消费者仍按同一满足率工作，无源孤网与未接网分别保留缺口，别处的空闲容量不抵账。

分配计划及本步加工变化一起提交。仅在 `generation[i] * dt > 0` 且现有余能不足时，从该机缓冲原子激活所需整件电芯；一件变成 7,200 kJ 后扣本步实际输出。恰好归零时不预开下一件；跨零的同一步可以使用下一件余能，不能凭空少算尾步、延后一整步或复制电芯。电芯最后不足 6 kJ 且无后备时，本步可供功率由余量 / dt 限定。

本步物流排在生产 / 供电提交之后，新到燃料最早下步参与。取消加工不退电，停用发电机或全局暂停保留余能。发电机可以在无外部电源的网中启动，但必须先有实体燃料；不允许引用尚未完成的 R12 产物给本步发电。

### 拓扑与启停

- G 同时是电网节点，沿节点 12 格 / 消费者 6 格和真实地形遮挡；即使无燃料或停用，仍导通既有电图。它不会要求先被外部供电才发电。
- E2 接入偏好使用“有启用额定供电设备的网络 → 最近节点 → 稳定 ID”；其中 G 按启用的 120 kW 额定能力参与偏好，实际分配再看燃料。燃料变化不改变拓扑或自动把消费者跳到别的孤网；启停与建设命令才触发必要重算。E1 及旧世界接入行为不变。
- 启停消费者只改变本机 `enabled`。停机时请求为零，输入 / 在制 / 输出 / 进度 / 批次全部保留，仍可被动收发允许的物料；恢复不能越过缺料、堵塞、接网和供电校验。默认启用，旧 E1 复制到 E2 时初始化为真。
- G 默认启用；未激活燃料可取回，已激活部分不能变成物品。回收确认明确“将损失当前余能，最多一件 7,200 kJ”，建议先停用再拆；取消确认不改变任何状态。
- 回收命令用执行时的全部燃料 / 背包 / 余能再次校验，背包不足整次拒绝；成功才返构件和未激活燃料、记录余能损失并移除实体。不能先清余能后发现容量不足。

## 物料、能量与统计账

R12 沿 E1 每种原料两批输入、一批输出、在制原始投入、活批来源与失败原子性。发电机输入只收工业电芯，5 件上限独立于已激活余能；不是反应器，不伪造配方完成数、输出批次或发电物品。

设 `N` 为全世界累计激活电芯数，`S` 为累计电芯实际供能，`L` 为已确认回收损失，`R` 为现存发电机余能总和：

```text
7200 * N = S + L + R
完整电芯持有量 = R12 完成产量 - N
实际总供电 = 封装电源供电 + S = 实际总用电
```

完整电芯持有量包括背包、仓、组装输出、在途及发电机未激活缓冲；激活当步记一次物品消费，不等到用完再扣一次。世界逐物料账在 E1 公式上加入这项显式消费；其他物品、制造账及已发生的开路消费不重置。

统计同时保留原请求 / 供电 / 缺口 / 用电，增加基础供电与电芯供电分项、激活数和损失能量；最近 600 秒桶有对应能量分项。装机额定、启用额定与当前可供能力分开，不把空燃料机的 120 kW 算作当前可供电。能量有限且非负；守恒容差沿旧能量合同，整数精确，禁止截断超额或用默认值“修复”。

## 玩家反馈与实现边界

G 主面板显示未激活件数、余能 kJ、当前输出 / 120 kW、网络缺口、启停和具体原因。无缺口显示“基础电源已满足需求，电芯未消耗”；无燃料显示“燃料耗尽，基础供电仍在”；孤网 / 无负载不写成供电成功。余时只按当前输出估算，零输出显示“当前不消耗”；提示负载变化会改变估计，不能把 60 秒标为固定燃烧时间。

电力常驻标志继续表示实际可用性，与生产、手动停机、缺料并列。停用消费者仍可能接网有电，不能变成断线图标。配额完成提示继续展示货物是否排空，不把 G 缓冲中的电芯或储存余能误报成“仍在加工”。电芯用途、3 包制造代价和 326 预算必须在玩家菜单可见。

实现由 `energy_model` 扩展 `expansion_model`，`power_grid` 只计算分配，模型固定步提交燃料消耗；共同物流、物品 / 设备面板和独立 codec 保持原职责。自动接网、端口接收、近身取放、回收确认、物料账、统计、存读、常驻状态在同一包中交付。持久字段、严格校验和显式复制事务见 [V7 架构](../architecture/factory-energy-save-v7.md)。资产使用自有 GLB / SVG，不换画面介质。

## 确认后的实施顺序与验收

1. 先完成 V7 身份、显式复制、启停、分配计划 / 提交、物料及能量账的定向检查，再接共同物流和菜单；实现时才能修改客户端与正式检查脚本。
2. 接 G 资产、R12、三入口读法、燃料 / 电量反馈和恢复提示，完成正常 / 最小窗口与关键操作；不能只交后台模型。
3. 普通零材料 E2 通过 E1 目标后自然制造 C；独立复制成功 E1 继续也须有证据。自然制造 D 所需构件，再比较供电、耗尽 / 恢复与保存；所有父检查点保留哈希，人工副本单独复制。
