# Slice Harvest And Build V1

更新时间：2026-07-18

状态：当前唯一活跃功能专题；切片第五个实现专题（系统层换皮第三步、首条化工链第一步），2026-07-18 由萝卜SAMA择序确认并定档开工。三包实现与运行时验证已于 2026-07-18 完成，待萝卜SAMA实机确认后收口。前序 [Slice Save Persistence V1](slice-save-persistence-v1.md) 已收口。

## 背景与定位

最小核心循环与存档持久化已成立：采集 → 修核心的进度存得住、读得回。但循环是一次性的——修完核心后无事可做，章程"每 10 分钟三感受"中的成长感与主线节点 2"建立首条化工链"仍是空白，建造 / 放置与加工两个玩家动词未落地。

本专题落地化工链第一步：**用晶体建造采集器，放进晶体区自动产出**，让玩家第一次体验"投入资源建设备、设备替你干活"的自动化回报。加工（配方生产第二资源）留作化工链第二步专题。

素材条件：采集器精灵（S5 定稿、07-15 归一入库 `collector` 87x90）至今未上场，本专题零新素材。

## 玩家价值

- 看到：整备台建造提示、携带采集器时的放置预览（可放 / 不可放高亮）、落地的采集器设备、晶体计数随自动产出上涨。
- 做：攒晶体 → 到整备台按 `E` 制造采集器 → 走到晶体区选点放置 → 回头看它持续产出；想多产就再造一台。
- 理解：晶体不只用来修东西，还能变成"替我采晶体的设备"——基地反哺采集，采集壮大基地，自动化第一课。

## 方案与口径

### 建造链路（已定档 2026-07-18：方案 A）

- 方案 A（定档）：两步"制造 + 放置"——整备台交互消耗晶体进入携带态，走到目标点再按 `E` 放置；覆盖建造与放置两个动词，整备台第一次获得真实功能。
- 方案 B（一步直接建造）不采用，记录备查。

### 放置约束（已定档 2026-07-18：方案 A）

- 方案 A（定档）：仅晶体地 tile 可放置并工作——"放对位置才有产出"是化工链"优化有回报"的第一次教学，晶体地即矿区的读法自然。
- 方案 B（任意开阔地）不采用，记录备查。

### 数值草案（可调）

- 建造消耗 5 晶体：修复核心（10）后全图余 7，手动攒够即可造第一台，第二台起靠自动产出滚动。
- 产出 1 晶体 / 10 秒：观察半分钟即可确认"它在替我干活"；多台叠加线性提升。
- 放置网格对齐 32px，占 1x1 tile 足印碰撞（与晶体簇同口径）；不可与既有足印 / 玩家重叠。

### 放置预览读法

- 携带态在玩家面朝的相邻格显示半透明采集器预览，可放为青色调、不可放为暗红色调；属允许的动态高亮 / 状态表达，非程序绘制主介质。

### 存档接入

- `SliceWorld` 状态追加 `collectors`（已放置采集器的网格坐标列表）与产出计时；写入沿用 `SliceSaveService`，schema 保持 1、追加可选字段（旧存档缺省为空列表，无迁移成本）。
- 读档还原：按坐标重建采集器节点并继续产出；晶体计数口径不变。

## 范围（串行推进）

### 包 1：建造与放置

- 整备台挂建造交互（晶体不足提示所需数），携带态 + 放置预览 + 网格校验，放置生成采集器节点（足印碰撞、y_sort）。
- 出口：实机从整备台造出 1 台采集器放进晶体区，扣费正确、非法位置被拦。

### 包 2：自动产出与存档还原

- 采集器计时产出入世界计数（HUD 联动既有信号）；`collectors` 进存档，读档按坐标重建并继续产出。
- 出口：放置后计数随时间上涨；存档 → 重启 → 读档，采集器还原且继续工作。

### 包 3：全循环验证与收口

- 运行时脚本走真实入口断言：建造扣费、不足拦截、非法放置拦截、tick 产出、存读还原。
- 实机截图：放置预览、落地采集器、产出后计数，记入当周周志。

## 成功证据

- 正式入口：修完核心后继续攒晶体造出采集器，放进晶体区看到自动产出，退出重进后采集器与产出仍在。
- `sh ./scripts/check-client.sh` 通过；`--import` 与运行时复核按需执行。

## 失败退出

- 按 [Development Decision Gates](../process/development-decision-gates.md) 两次失败停手规则执行。
- 放置校验或产出计时两轮实现仍有穿模、重复扣费或读档丢台，停手复盘放置承载结构。

## 不做

- 不做配方 / 第二资源 / 加工链（化工链第二步专题）；不做储存罐功能化与容量上限。
- 不做拆除 / 移动已放置设备；不做采集器升级与多种设备。
- 不做敌人、战斗、任务链、立绘对话；不生成新素材。
- 不迁移、不修改冻结的旧系统与旧检查。

## 状态 / 存档 / HUD / 检查

- 世界状态追加 `collectors` 与产出计时，与既有循环状态同层存于 `SliceWorld`；存档沿用 `SliceSaveService` 追加可选字段，schema 不升版。
- HUD 沿用 `SliceHud` 三要素，携带 / 放置提示走既有提示行，不新建面板。
- 只要求 `check-client` 静态通过与无导入错误，不新建检查脚本文件。
