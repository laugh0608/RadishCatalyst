# Demo Interaction Affordance V1

更新时间：2026-06-17

## 用途

本文定义首版 Demo 交互可辨识度第一版的范围。它不是最终美术包、动画 polish、试玩准备或修 bug 阶段；它用于检查玩家在真实场景中能否从画面、焦点标签、HUD、对象提示和状态反馈中判断哪些目标可交互、哪些已处理、哪些仍被阻挡或危险压制。

## 玩家价值

玩家沿主线推进时，不应该只依赖记忆或日志猜测下一步。他需要在靠近目标时直接读出：

1. 当前对象是否可交互、已完成、缺条件或被敌人 / 工具能力阻挡。
2. 交互后画面和提示是否同步变化，避免已处理对象仍像未处理状态。
3. 战斗目标、清障目标、建造点、设备和核心对象的状态是否能和 HUD / 地图目标互相印证。

## 与整体规划的关系

本专题覆盖 [Demo Definition V1](demo-definition-v1.md) 的「UI / HUD」「初步美术」「区域 / 场景」「战斗压力」「自动检查」规格。

它承接已完成的 [Demo Combat Evacuation Recovery V1](demo-combat-evacuation-recovery-v1.md) 和 [Demo Playable Scene Composition V1](demo-playable-scene-composition-v1.md)：前者补齐撤离恢复读法，后者补齐区域画面构成；本轮转向对象层和战斗 / 交互层的可辨识度，避免继续加厚路线、区域构成或撤离恢复同类文本。

## 当前已有基础

- 交互对象已有焦点标签、通用提示、处理状态和部分视觉刷新。
- 地图、HUD、对象提示和专项检查已能读出主线、场景、撤离恢复和完成成果。
- 敌人、清障、建造点、设备和核心稳定站对象都有稳定 `definition_id` / `instance_id`，可用于自动检查。

## 本轮范围

- 检查代表性对象的可交互 / 已处理 / 缺条件 / 阻挡状态是否在提示和画面状态上互相一致。
- 覆盖前哨核心、出发口、基础反应器、建造点、污染沉积、遗迹回波匣、清障点、深段锚点、核心守卫缓存和核心稳定站设备。
- 覆盖敌人仍在、敌人已击败、对象已采集 / 已采样 / 已清理、设备可启动 / 缺料等玩家可见状态。
- 新增检查优先放在独立专项文件，不继续推高 `vertical_slice_flow_check.gd`、`vertical_slice_map.gd`、`prototype_hud.gd` 或 `interaction_prompt_formatter.gd`。

## 当前不做

- 不新增资源、配方、区域、任务链、敌人类型、完整背包或完整装备栏。
- 不做最终美术资产、动画过场、音效、设置页、终局菜单、结算页、试玩准备或发布准备。
- 不重做 HUD 布局系统，不把本轮变成全量 UI 设计替换。
- 不继续加厚撤离恢复、完成成果、可玩场景构成、路线职责或区域身份同类文案。

## 玩家操作路径

1. 前哨：恢复核心、查看出发口、靠近设备和建造点，判断是否可执行或缺条件。
2. 外勤：靠近采集 / 采样 / 清障对象，判断对象是否仍可处理、已处理或被敌人压制。
3. 战斗：敌人仍在与已击败后，相关对象提示和 HUD / 地图目标应同步变化。
4. 核心站：守卫缓存和核心稳定设备应能区分守卫未处理、缓存已回收和写入准备状态。

## 运行时、存档与数据边界

- 不新增存档 schema，不迁移稳定 ID。
- 只读取既有 `WorldState.map_objects`、`WorldState.enemies`、任务进度、设备状态、库存和角色状态。
- 若发现状态读法断裂，优先修现有状态写入、视觉刷新或提示接线，不添加掩盖问题的默认兜底。

## HUD / 场景 / 对象反馈

- 焦点标签：对象名称和可交互状态不能和真实交互条件冲突。
- 对象提示：缺条件、已处理、被阻挡、可处理和下一步应明确区分。
- 场景状态：已处理对象、已击败敌人、建造完成和核心对象状态应有可检查的画面或提示差异。
- HUD / 地图：目标区域和对象状态变化后，应继续指向当前真实目标。

## 验收条件

- `Demo Interaction Affordance V1` 建立并作为当前活跃专题。
- 代表性对象和敌人状态能通过提示、HUD / 地图、场景节点或视觉状态检查互相印证。
- 未引入当前不做事项，新增检查走独立专项文件。

## 风险与后续决策

- 若本专题只发现低优先级美术细节，记录到后续 polish，不阻塞阶段推进。
- 若发现对象可见状态与任务 / 存档状态冲突，优先按主线连续性或坏档风险处理。
