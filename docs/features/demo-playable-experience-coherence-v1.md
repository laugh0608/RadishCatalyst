# Demo Playable Experience Coherence V1

更新时间：2026-06-17

## 用途

本文定义首版 Demo 从新档到 Demo 完成后回前哨整理的完整体验连贯性第一包。它承接已完成的 Demo 完成成果整理，不继续加厚核心稳定站完成态文案，而是检查并补齐整段玩家路径中的场景、HUD、地图、对象反馈、状态 / 存档和自动检查断点。

本专题服务 [Demo Definition V1](demo-definition-v1.md) 中「主线结构」「区域 / 场景」「UI / HUD」「存档 / 状态」和「自动检查」规格。它不是试玩准备、修 bug 阶段、发布准备、终局菜单或结算页。

## 玩家价值

玩家从新档推进到 Demo 终点后，应能持续读出：

- 当前处在基地整备、外勤推进、回基地处理、终点准备还是完成后整理，而不是只看到局部提示。
- 每个关键阶段的 HUD、地图和对象提示互相指向同一件事。
- 外勤获得物、基地加工、整备收益、守卫战记录和完成后整理不会在存档读取后断开。
- 完成 Demo 后回前哨整理时，不会误以为开启了新章节、试玩准备或发布流程。

## 与整体规划的关系

- 继续证明“基地服务冒险，冒险反哺基地”：整段体验要让外勤、基地和终点成果互相回读。
- 承接 `Demo Main Path Continuity V1` 和 `Demo Completion Outcome Readout V1`，但不重复做单点主路径或完成态读法。
- 第一包优先补代表性开发基线和专项自动检查，让后续人工复测可以定位断点。

## 当前已有基础

- `S0`、`S2` 和 `S21` 开发基线已覆盖新档、外圈和核心稳定站开放状态。
- 主路径连续性检查已能从 `S21` 跑到核心稳定站写入完成。
- HUD、地图、对象提示、完成日志、外勤收益、资源链、整备状态和存档契约已有多个专项检查。
- Demo 完成成果整理第一包已覆盖核心写入完成后的 HUD、地图、前哨核心、核心设备提示和完成日志。

## 本轮范围

- 新增完成后回前哨整理代表基线，用于记录 Demo 已完成、玩家已回到前哨整理状态。
- 新增整段体验连贯性专项 runtime 检查，覆盖新档、外圈、核心稳定站开放和完成后前哨整理四个断点。
- 检查每个断点的 HUD 目标、地图路线、代表对象提示、任务 / 区域状态和存档读取后状态。
- 新增静态接线检查，并接入默认 `check-client` 和 `--with-godot`。

## 当前不做

- 不新增资源、配方、区域、任务链、完整背包或完整装备栏。
- 不新增终局菜单、结算页、制作人员名单、试玩准备、发布准备或大规模 polish。
- 不改变核心稳定站写入逻辑、战斗承压公式、掉落、存档 schema 或任务完成条件。
- 不继续扩核心站完成后的回访链，不把本专题变成纯人工基线复核。

## 玩家操作路径

1. 新档从前哨恢复开始，HUD / 地图 / 前哨核心能读出基地整备和外出目标。
2. 玩家推进到封锁遗迹外圈，地图和对象提示能读出场景身份、现场玩法和回基地理由。
3. 玩家通过锚定桥进入核心稳定站开放状态，HUD / 地图能读出终点路线和进入核心站的下一步。
4. 玩家完成核心稳定站写入后回前哨，HUD、地图、前哨核心和存档读取状态都能读出成果整理。

## 运行时、存档与数据边界

- 本包只新增代表性开发基线和检查，不新增存档字段。
- 完成后整理基线复用既有任务、区域、敌人、对象、库存、装备和整备状态。
- 存档 roundtrip 只验证已有状态能保存和读取，不做旧档迁移或全量发布兼容。

## HUD / 场景 / 对象反馈

- HUD：每个断点都必须显示当前目标或 Demo 成果，并保留关键资源和基地摘要。
- 地图：每个断点都必须显示当前路线阶段、目标或完成后整理方向。
- 对象提示：前哨核心、封锁遗迹代表对象和核心完成后整理都必须说明状态与下一步。
- 状态：任务完成、区域位置、关键对象和整备收益必须在存档读取后保持一致。

## 验收条件

- 新增完成后前哨整理代表基线，并纳入 demo 开发基线序列。
- 专项 runtime 检查覆盖 `S0`、外圈、`S21` 和 Demo 完成后前哨整理断点。
- 静态检查确认专题文档、基线、runtime 检查和脚本入口已接线。
- 未引入新资源、配方、区域、任务链、完整背包、完整装备栏、终局菜单、结算页或发布准备流程。

## 风险与后续决策

- 风险：本专题容易滑向试玩准备或集中修 bug；第一包只补玩家路径断点和自动检查。
- 风险：重复已有主路径检查会增加维护成本；本包只用少量代表断点串起跨界面一致性。
- 第一包完成后再判断是否仍存在阻塞理解的断点；若没有，不继续做同类提示加厚。
