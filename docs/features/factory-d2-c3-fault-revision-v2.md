# D2 C3 故障对照修订 v2

更新时间：2026-11-14

方案状态：**萝卜SAMA已确认并授权执行**。执行状态：**O2 / L2 成对固定步预检完成，故障资格与收益门禁未通过，停止自然长测**。本文修订 [D2 长期对照](factory-d2-production-comparison.md)的故障时表。11 月 13 日 v1 无效样本见 [W46](../devlogs/2026-W46.md#d2-long-comparison-preflight)，v2 实测与停止原因见 [W46](../devlogs/2026-W46.md#d2-c3-fault-v2-preflight)。

## 建议与适用结论

**沿用生产负载与产品参数，O2 / L2 使用加工期供燃、低储备断燃与恢复的固定时表。** `v2` 只标识实验版本，继续使用 schema 15。正常供燃 N / B / T / F 继续原合同。

目标是让无控制参考在每窗真实遭遇至少 100 kJ 缺口，使 C3 推迟 A 的新批有可观察的作用，再用原交付、欠单、耗芯与恢复门槛检验其代价。方案不保证 C3 必然通过；有效对照应能得出“达到收益”或“收益不足”的结论，不能为通过而选窗。

结论仅适用于**低储备、加工期供燃及后续断燃**下的这条生产线，不据此宣称满储能工厂遇到任意 240 秒断燃都需要 C3。旧样本正好说明储能已足以应对该类短故障，这个结果继续保留。

## 复核依据：旧故障为何没有信号

来源为 `tools/runtime-intake/check-runs/factory-d2-production-v1/20261113-d2-feasibility-02/` 的 `result.json`、B / O 逐步轨迹和订单，准备来源仍为 `20261113-d2-prepare-04`。

| 原 O 事件 | G / C2 状态 | 储能变化 | 实际结果 |
| --- | --- | --- | --- |
| `[360,600)` 关闭供燃 | G 全程无燃料；关闭开始时 C2 已为 block | 2,092.540 → 1,381.840 kJ | 4,800 步缺口均为 0 |
| `[1080,1320)` 关闭供燃 | 同上 | 2,553.698 → 1,960.598 kJ | 4,800 步缺口均为 0 |

O 在 1.10 / 720.10 秒激活电芯，主要在低负载准备段燃烧，为随后峰段存下能量。两段故障均未触及 1,100 kJ 补燃低阈值；关闭并未打断当时需要的供燃。把第一次故障仅延长到 720 秒也不足：旧轨迹在 600–720 秒没有再次激活 G，720 秒仍存 1,025.440 kJ。跨过窗口才耗尽不能补签第一窗有效。

对已有 B 的**真实请求功率轨迹**进行只读分段汇总：

| 区间 | 观测 / 算术结果 | 对方案的用途 |
| --- | --- | --- |
| `120–660` 秒 | 请求超出 360 kW 的面积为 1,423.3 kJ | 若没有预先充出的储能，第一段正式故障及恢复等窗期间存在明显压力 |
| `720–1380` 秒 | 同类面积为 1,639.4 kJ | 第二窗也有压力机会，不能只证明第一窗 |
| `60–120` / `660–720` 秒 | 请求最低均为 138 kW | 已有轨迹中，120 kW 的 G 在这段没有充电余功率 |
| `1380–1440` 秒 | 请求最低 120 kW | 同上；恢复落在加工段而非准备段 |
| `120–121.10` / `720–721.10` 秒 | 请求最低均约 124 kW | 关闭供燃后的燃烧尾段也未出现余电；新运行仍须实际记录 |

这些面积是旧 B 的负载形状分析，**不是新 O2 缺口预测或新 L2 成绩**。缺电会改变加工、物流和后续就绪时刻，C3 也会改变请求；不能把上述数字代入新验收表。分析输入哈希和汇总位于 `tools/runtime-intake/design-references/factory-d2-c3-fault-v2/20261114-review-01/analysis.json`。

## 修订时表：不重置 C1 相位

O2 / L2 均从同一 P0 字节副本开始：G 空缓存 / 零余时，B 为 0 J，无计分在制；C1 为 120 秒周期、10 秒窗口、额度 1，C2 为 1,100 / 2,000 kJ。与原 F 参数相同，但**首个计分步前不启用节拍器**。C3 配置仍只有 A、100 kJ；O2 关闭，L2 首步前启用为 pending / 0。

| 相对活动时刻 / tick | 两组共同命令及其后果 |
| --- | --- |
| `0 / 0` | 保持节拍器停用，G / B 均为空。前 60 秒只按原准备段生产，作为共同启动等待，不当成正式故障收益来源 |
| `60 / 1200` | 启用节拍器，相位从 0 运行。第一轮加工和两项 A 订单照常开始；让首颗 G 在加工期燃烧，随后观察真实余燃耗尽 |
| `120 / 2400` | 下一步开始前停用节拍器，开始第一段正式故障 **`[120,600)`**。C1 已运行 60 秒，冻结相位为 1,200 tick；G 剩余燃烧继续 |
| `600 / 12000` | 原样启用；从相位 60 秒继续，此刻尚未进入放行窗口。第一次恢复计时从 600 秒开始，包含后续等待 |
| `约 660 / 13200` | C1 自然回绕到相位 0，进入下一放行窗口；与第六轮加工对齐。这是派生事件，不补发命令或额度 |
| `720 / 14400` | 下一步开始前停用，开始第二段正式故障 **`[720,1320)`**。上段启用持续 120 秒，C1 再次停在相位 60 秒，G 余燃继续 |
| `1320 / 26400` | 原样启用；相位仍从 60 秒继续，第二次恢复计时立即开始 |
| `约 1380 / 27600` | C1 自然进入下一放行窗口，与第十二轮加工对齐 |
| `1440 / 28800` | 第二窗结束，冻结最终账和正常保存退出；两窗仍连续，不在中点重新开始 |

以原直连 G 的物流时延和充足队首电芯估计，三次激活约在 **61.10 / 660.10 / 1380.10 秒**，不是强制时刻。首颗和第二颗分别会在约 121 / 720 秒自然燃尽，给两段故障留下真实“已有余燃耗尽后仍无法补燃”的观察链。必须记录启用、放行、G 激活、余时耗尽、受控新批和新成品入仓的实际 tick；不能设余时、清 B 或强行点火。

第一次仅在准备段末尾才开放供燃，是明确的新增启动时表，不伪装成正常 F 的启动条件。已有 B 轨迹显示三段预计燃烧主体都处于请求不低于 G 额定 120 kW 的加工段，减少预先充满 B 的机会；真实新轨迹有变化就按实际电量记录，不能把“低储备”变成人工设置的电量上限。

固定命令时表对 O2 / L2 完全相同，不按各自 B 电量、C3 决定或缺口移动故障。`set_dispatch_active` 停用时冻结相位 / 额度；恢复后继续，不把它当墙钟周期。关闭不回收槽内或在途电芯，不中断已激活燃烧；G 全程保持启用。两次正式故障分别长 480 / 600 秒，取代原来的两个 240 秒窗口，不能说故障强度未变。

两次供燃恢复的原 120 秒期限分别截止 **720 / 1440 秒**，包含约 60 秒的 C1 等窗。R11 仍按每周期末结算，不能因恢复等待延后订单期限。样本资格另核对：每窗至少 100 kJ 的 O2 缺口确实发生在本次正式断燃到恢复供能的区间内，不能用第一次启动点火的短延迟凑满故障门槛；全窗缺口及 L2 的 50% 比较仍计完整 720 秒。

720 秒边界统一保存“前 14,400 步已完成、720 秒停用命令尚待执行”的状态，sidecar 保存下条事件、订单及恢复事件结果；原进程和独立恢复都在第 14,401 步前执行该命令一次。保存不补步、不重设相位，命令不漏发或重复。跨窗余燃及 B 的真实电量完整继承。

## 为什么保留原负载与 A 一台

现有实测请求峰值为 400 kW。空储能 / 无足够燃烧余时的 G 时，A 的额定批次工时 10 秒，C3 按全网候选功率估算；在 400 kW 候选点，360 kW 核心对应 −40 kW 余量，理应阻断新批。A 从工作 40 kW 变为待机 4 kW，只能移走 36 kW，可能仍有 4 kW 缺口，不承诺零缺电。

原命令在相位 85 秒后停止 Fd 新开批，保留其尾批。待其真正完工停机，若其余条件不变，全候选需求可由 400 降至 340 kW，达到 C3 恢复所需的 20 kW 余量。A 可以在同一周期剩余时间内完成两单；但 Fd 尾批可能因缺电延长，A 也可能缺料，所以必须实测首次开批、逐单入仓与欠单，不能用此预算算式宣布通过。

本次不增设备、不扩仓、不增订单、不换配方、不扩大准备库存、不提升保留量，也不人工拉平机器功率。保留真实波动，先验证既有 A 是否能在每周期两单不逾期的条件下削减缺口。若做不到，记录策略未达标，再讨论负载设计；不顺带把 F / Fd 加进控制组或改变 C3 产品规则。

## 与正常供燃对照的关系和影响

| 项目 | 修订范围 |
| --- | --- |
| 共用起点与成本 | 六组继续同一个最终 P0、同一 ID / 物流 / 配方 / 研究 / 物料 / 储能初态；目标仍是现有候选经完整预检后冻结，不另选低电量暖机点。无新增装配或研究成本 |
| 正常 N / B / T / F | 配置、120 秒工作机会、A 两单、连续两窗及通过线全部不变。T / F 仍各自相对 B 验收 95% 实收与 25% 节能 |
| 故障 O2 / L2 | 仅替换节拍器启停时表，包括首次供燃推迟到 60 秒、故障延长和相位对应的恢复等窗。两组配置和命令相同，唯一实验处理差异为 C3 是否启用 |
| 成绩比较 | C3 收益只用 L2 对 O2 的同窗结果；F 是无故障背景参考，不替代 O2 分母。旧 O v1 继续记无效，不与新 L2 配对，也不并入正常节能统计 |
| 解释范围 | 验证低储备供燃延误下的开工控制；不代表任意充满储能时的故障韧性，也不把 C3 变成基础生产必选 |
| 产品与运行时 | 不改核心 / G / E2 / C1–C3、schema 15、UI、资产、依赖、普通菜单或发布范围；检查侧增加 v2 时表、恢复事件计时和门禁。原方案尚未实现的自然时钟观测 / sidecar / 独立恢复继续按原范围实施 |

两个问题分开判定：正常节能可以独立报告 T / F 结果；C3 仍须 O2 / L2 有效并通过，不因正常四组完成而消除 C3 待验。本轮自然运行仍以成对预检通过为前提。

## 保留原门槛，先证明可测再进入长测

父方案中样本、物料 / 能量 / 电芯账、期末能量修正、库存稳定、实收来源、自然时钟及存读要求全部沿用。明确保留：

- **每窗 O2 实际缺口 ≥100 kJ**，且真实燃料耗尽；L2 必须出现控制阻断、在制完成和恢复开工。
- **每窗 L2 缺口 ≤ O2 的 50%**；R08 混料板核心实收、R11 入仓、Fd 入仓分别 **≥ O2 的 95%**，不能用完工数或其他物品补足。12 包参考下仍须 12 包；每周期两项订单及其期限保持原样，不吞单 / 清欠单。
- R11 周期末无新增欠单；恢复后 **120 秒内**同时有受控新批及新成品入仓，按上表 600 / 1320 秒起算，包含 C1 等窗和物流时间。
- `C_burn` 与 `C_adjusted` 均 **不高于 O2**；整数物料 / 电芯账精确、能量残差 ≤0.001 kJ，不扩大任何容差。副支路产出、期末物料与剩余缺口完整展示。

确认后的执行顺序：

1. 新建 v2 隔离批次，复核旧候选来源与完整 P0 条件、全拓扑和 24 分钟仓容；明确起点策略差异白名单。保留旧文件，不能覆盖旧批次或重标旧结果。
2. **O2 / L2 都做完整 28,800 固定步预检**，不是只跑 O 再推断 L。记录两窗实收、所有订单 / 副支路、库存、燃料 / 储能、控制候选预算与决定、逐步缺口，以及每个命令边沿。重点检查 0 / 60 / 120 / 600 / 660 / 720 / 1320 / 1380 / 1440 秒、跨窗余燃和恢复计时；现有 600 步只读一致性检查扩到含开工 / 阻断 / 恢复的区间，仍不算自然成绩。
3. O2 无信号、供料 / 仓容不合格或出现观察副作用，判样本无效并停；O2 有效但 L2 达不到 50% / 95% / 欠单 / 耗芯要求，保留策略未达标结论并停。不能改时间、控制成员、储能或订单后静默再试。
4. 全部门禁成立才完成自然驱动与独立恢复接线，按原顺序执行 N / B / T / F 和 O2 / L2、普通矿辅助与六组 600 步跨进程恢复、短窗口复核。自然运行必须重新独立达标，预检数字不补入自然成绩。

如果本时表仍无效，连同 v1 一并复盘，不提供自动备选时表或搜索“最好看的”故障窗口。本方案暂不选增负载：它会新增设备 / 物流 / 供料和成本，影响正常对照的同源条件；也不选清空 B / 暂停 G / 提高 C3 保留量来制造结果。

## 成对预检结果

`20261114-d2-fault-v2-02` 使用同一候选，O2 / L2 各完成 28,800 固定步。O2 正式断燃至恢复供能的实际缺口为 1,349.862 / 1,550.827 kJ，两窗均实际燃尽且超过 100 kJ。L2 唯一一次阻断在首次供燃等待期间，持续 2 秒。第二窗没有控制阻断或相应恢复开工，成对资格不成立。按完整 720 秒窗口核算，缺口由 1,363.695 / 1,550.827 kJ 变为 1,354.131 / 1,551.469 kJ，两窗均未达到减半。交付、周期末欠单、恢复期限与两种耗芯通过各自预检门槛。

正式故障及恢复等窗中，L2 实际采到 A 可开批时的预算余量均为 +50 或 +68 kW。缺口出现时 A 已在制，C3 的新批限制保留了这些批次。该夹具形成了断燃压力，但负载峰值与 A 的受控开工时机错开。按停止条件保留两个版本的证据，等待复盘后决定对照设计；未进入自然长测、正式 P0 发布、独立存档恢复或窗口复核。原始轨迹、计量和批次索引见 [W46](../devlogs/2026-W46.md#d2-c3-fault-v2-preflight)。
