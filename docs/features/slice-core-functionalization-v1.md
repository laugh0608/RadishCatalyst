# Slice Core Functionalization V1

更新时间：2026-07-21

状态：**已收口（2026-07-21，萝卜SAMA正式入口实机复核通过）**。25 项 headless 逻辑断言与 25 项有窗口正式入口 / 输入 / 截图断言均通过，5 张截图完成 AI 视觉复核；人工复测再走“新档采集与合成零件 → 修复核心 → 中央仓库存取晶体和机械零件 → 重启载入再核对”全链路通过。承接已收口的 [L1 手持合成面板](slice-handheld-crafting-panel-v1.md)，把“修复核心”从终点改成基地能力上线节点。本层只做**核心直供电源 + 中央仓库**；后续由 [L3 建造放置 + 扩展供电网](slice-building-placement-and-power-grid-v1.md)承接。

## 定位

玩家用机械零件修复前哨核心后，核心应立刻承担两个真实职责：

1. **直供电源**：修复态即电源在线，核心周边形成固定直供范围，为后续首台基地设备提供电力源。
2. **中央仓库**：玩家走近核心打开仓库，把背包中的晶体 / 机械零件存入核心，或从核心取回；仓库状态进入存档。

L2 不提前实现可放置电线杆 / 中继。原 arc 总览把“扩展供电网”放在 L2、把“通用放置”放在 L3，形成依赖倒置；本专题将固定核心能力留在 L2，把可放置供电网合并到 L3。

## 决策闸门

1. **玩家新增动作**：修复核心后按 `E` 打开中央仓库，用数字键存入 / 取出晶体和机械零件。
2. **世界明确变化**：核心从受损物变成发光的已修复设备，HUD 显示直供电源在线，核心交互从“修复”切为“仓库管理”。
3. **服务基地—冒险闭环**：玩家可把远征采集物集中存进基地，再按后续建造需要取出；核心成为基地资源与电力起点。
4. **5–10 分钟可感知**：新档采集 → 合成零件 → 修核心后立即看到能力切换，并可完成一次存取。
5. **通用系统边界**：复用 `Inventory` 作为中央仓库；只新增明确的仓库存取 API 和核心直供查询，不建立完整电网图。
6. **现有介质**：复用已定稿的核心双态素材与文本面板，不生成新素材、不使用程序绘制范围圈作为主读法。
7. **成功证据**：正式入口人工路径 + 核心仓库面板截图 + 运行时存档重启断言。
8. **失败处理**：若玩家无法理解修复后能力切换，优先调整核心交互 / 面板层级；不叠加 debug 线框或大段说明。
9. **旧系统关系**：不复活旧纵切 `WorldState` / 旧仓储；只在独立 `SliceWorld` 与 `SliceSaveService` 内实现。
10. **切片推进价值**：把“修核心”连接到基地存储和后续工业供电，直接为 L3–L5 空间自动化链提供起点。

## 玩家路径

```text
采集晶体 → B 合成机械零件 → E 修复核心
  → 核心亮起，直供电源在线
  → 再按 E 打开中央仓库
  → 存入 / 取出晶体或机械零件
  → 退出并载入，背包、仓库、修复与电源状态一致
```

## 交互与 HUD

- 未修复核心保持 L1 交互：提示零件缺口，满足后按 `E` 修复。
- 已修复核心提示：直供电源在线、中央仓库当前用量，按 `E` 管理。
- 仓库面板为原型文本 UI：
  - `[1]` 存入全部晶体，`[2]` 取出尽可能多的晶体；
  - `[3]` 存入全部机械零件，`[4]` 取出尽可能多的机械零件；
  - `Esc` 关闭；转移受背包 / 仓库容量限制，并显示实际结果。
- 打开仓库时关闭随身合成面板，避免两个数字键面板同时响应。
- HUD 在核心修复后从“修复核心”切为“核心直供在线｜中央仓库 X / 120”。仓库详细物品只在仓库面板显示，不常驻堆叠。

## 状态与数据

- `core_storage: Inventory`：容量 `120`，保存晶体、机械零件及未来合法物品。
- `core_repaired` 仍是核心功能上线的单一事实源；不额外保存可推导的 `core_power_online` 布尔值。
- 核心直供范围：以核心为中心固定 `6` 格（`192px`）；提供位置供电查询 API，L3 / L5 的设备消费方复用。
- 本层没有用电设备，不伪造反应器运转；玩家可见结果是修复态核心、供电在线 HUD 与中央仓库存取。

## 存档

- `SliceSaveService` schema 从 `2` 升到 `3`，新增 `core_storage` inventory。
- schema 2 存档兼容读入：保留背包、采集器、核心修复态等 L0 / L1 数据，中央仓库初始化为空；下次自动保存写为 schema 3。
- 存档 → 重启 → 载入后，背包与中央仓库数量、核心修复态、核心直供状态必须一致。

## 分包

### 包 1：核心仓库与直供状态（已实现）

- 新增核心仓库状态、双向批量转移 API、仓库面板与修复后交互切换。
- HUD 显示直供在线和仓库用量。
- 核心直供位置查询可供后续设备使用。

出口：玩家能在正式入口修复核心后完成存 / 取，且不能在未修复时使用仓库。

### 包 2：存档兼容与全链路收口（已完成）

- schema 3 保存中央仓库，兼容读取 schema 2。
- 覆盖容量边界、空仓 / 空背包拒绝、存档重启还原、两个面板互斥。
- 留存核心修复后仓库面板截图，并由萝卜SAMA人工确认玩家路径。

出口：自动检查、正式入口输入链、截图与萝卜SAMA人工路径均通过；L2 已回填收口并进入 L3。

## 不做

- 不做电线杆 / 中继素材、制作、放置、连线和扩展覆盖；归 L3。
- 不做反应器、储物箱、传送带、机器耗电与物流；归 L3–L5。
- 不做程序绘制电力范围圈、线框供电网络或 debug 色块作为画面主介质。
- 不做鼠标拖拽、物品格、分页、筛选、堆叠上限和完整背包 UI；像素 UI 换皮留后续专题。
- 不迁移或修改冻结旧纵切的仓储、存档与设备系统。

## 验收与移交

- 未修复时中央仓库不可用；修复后同一核心交互切换为仓库管理。
- 晶体与机械零件能在背包和核心仓库间双向转移，容量边界不丢物品、不复制物品。
- 修复态核心是直供电源的单一来源，范围查询在范围内 / 外和未修复态返回正确。
- schema 2 可兼容载入；schema 3 存档重启后完整还原中央仓库。
- 正式入口截图 / 人工路径证明“修核心 → 电源上线 → 使用仓库”可感知。
- L2 已收口；L3 范围、素材硬闸门与实现包见 [Slice Building Placement And Power Grid V1](slice-building-placement-and-power-grid-v1.md)。
