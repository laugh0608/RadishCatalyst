# Factory Foundation And Persistence V1

更新时间：2026-09-08

状态：萝卜SAMA已确认正式接入、独立存档及 P1–P3 范围，进入实施；实测退出证据逐包补充。

## 决定与玩家结果

萝卜SAMA认可当前独立 Godot 3D Demo 的画面与操作，同时明确精细度尚不满意、当前不必抠细节，并要求继续推进下一步。本包以 Godot 3D 为设计路线，形成可以保存、继续经营和扩建的工厂基础；不再追加同范围的画风比较。认可不等于量产美术定稿，也没有新增大型工厂性能通过的结论。

完成后，玩家通过正式启动入口创建工厂世界，亲手接通第一条产线，再在同一区域建设第二条产线；关闭程序后重新进入，设备、库存、带上物品与加工进度保留，继续生产。先让当前三种设备可多台使用，新增设备种类与产物换构件的经营循环另包设计。

本专题定义玩家范围与分包。状态、存档、并发写入与新旧隔离的提案见 [Factory World State And Save V1](../architecture/factory-world-state-and-save-v1.md)；既有对照依据见 [Godot First Production Line Demo V1](godot-first-production-line-demo-v1.md)。

## 开工十问

1. 新动作：创建 / 继续工厂世界，在多个矿点建造多条产线，保存退出后接着调整。
2. 世界变化：已投入的构件和生产成果长期保留，不随一次窗口关闭而清空。
3. 产品价值：为“探索资源 → 生产 → 扩建”提供可积累的基地；本包不新增探索内容。
4. 感知时长：目标在 5–10 分钟完成接通、保存和重进；第二条线的建设时长由试玩记录，不冒称已验证。
5. 系统需求：需要独立工厂状态、格位 / 端口索引和工厂存档；不建立通用插件、ECS 或联网框架。
6. 素材范围：沿用已认可的设备、角色、配色、视角与光照，只补扩大场坪需要的重复地面组织和相机跟随。
7. 成功证据：正式 Boot 输入路径、跨进程存读、物料守恒、故障恢复、窗口截图和明确负载下的性能记录。
8. 失败处理：按输入、状态、文件发布或渲染瓶颈归因；规模不达标须记录实际限制，不通过增加画面细节掩盖。
9. 旧系统取舍：保留旧切片及其存档，不移植旧战斗、核心任务、无线仓库或二值电网规则。
10. 阶段价值：玩家第一次能积累一座可扩建工厂；经济驱动、长期探索和量产美术仍是后续包。

工程负载世界只由检查入口创建，使用明确标记的静态供给配置；不出现在普通“新建世界”的选择里。它仍通过正式命令校验建造并运行，不直接改库存或复制静态 Mesh 冒充生产。地图与供给配置使用稳定版本标识，修改时须重新审核兼容关系。

## 保持的生产与操作规则

- 采集器 / 仓 2×2、反应器 3×3、带 1×1；设备固定朝向与端口位置沿用 Demo。只放开多个实例和多个合法矿点，不新增设备旋转、端口模式或带速档位。
- 采集 1 晶体/秒、缓冲 50；反应器原子消耗 2 晶体，10 秒产 1 催化剂，输入 2 / 输出 1；终端仓与回收箱各容量 200。终端仓继续只收料，不暗中变成会发料的物流设备。
- 每带格一件、1 格/秒、真实正交弯道、不反向对撞、公平汇流；占用与满仓引发回压。缺料和堵塞状态按单台实例派生，不用一台设备的恢复冒充另一台恢复。
- 原子放置、拖铺、回拖、取消、拆回与回收物投入沿用对照合同；拆回须先校验全部内容能否回收，在制批次折回 2 晶体，不丢料或复制料。
- WASD / 方向键按屏幕方向移动，点空地移动，建造态可走；UI 阻断鼠标落地，人物不穿设备，设备不压人。加载、退出和失焦取消未提交预览。
- 暂停、失焦和退出不继续生产；无离线收益。后台返回与高负载积压须由明确模拟时钟处理，不能简单截断 delta 后悄悄少产。
- Demo 的固定三处参考框、全局断路教学旗标不成为正式经营状态。首包提示说明如何接通、查看状态与保存；累计入仓从真实输送事件统计，手动投入不冒充产出。

## 玩家路径与界面反馈

1. 从 Boot 打开“工厂世界”，新建并命名。只在初始主档成功发布后进入；创建失败留在菜单，显示原因与重试入口。
2. 从空场坪放置采集器、反应器、终端仓并接带；第一件催化剂真实入仓。界面可查看各台设备缓冲、进度、缺料 / 回压和库存。
3. 走到另一矿点建设第二条独立产线；第一条线继续运行。拆断其中一条并补接，分别观察两条线，确保反馈与实例身份对应。
4. 在“带上有料、反应器正在加工”的时刻保存并返回；显示本次保存结果。关闭程序，再从 Boot 进入同一世界，恢复数量、进度和位置，继续获得新产物。
5. 游戏内保留显式保存与“保存并返回”动作；点击窗口关闭也走保存流程。保存失败留在当前暂停世界，提供重试、取消退出和经明确确认的“不保存退出”。
6. 主档损坏而备份有效时，告知恢复来源，完整重建通过后才发布恢复结果；无有效候选时保留文件并在列表显示错误，不能自动创建空场坪。

工厂世界列表首包提供新建、继续和保存状态信息；不追加复制世界、跨世界携带、云同步、导入 / 导出或永久删除功能。旧世界已有列表功能继续保留。

## 实施顺序与退出条件

| 包 | 交付 | 本包退出证据 |
| --- | --- | --- |
| P1 正式工厂状态与入口 | 在 `client/` 建立窄工厂目录与 Boot 路由，适配同三机画面 / 输入；配置化场地、构件与实例身份 | Boot 空场坪操作、单线 Web 规则对照、世界 / HUD 坐标与旧启动入口回归通过；P1 单独不宣称已可长期经营 |
| P2 保存与继续 | 工厂 codec / 存档服务 / 目录、保存时机、独占写入、候选重建和失败反馈 | 跨进程存读、半批 / 载货 / 回压恢复、坏档 / 备份 / 写入失败和旧档保护通过 |
| P3 扩建与规模 | 64×64 多矿点、多实例、相机跟随、占用索引与必要的分区渲染，形成可手建多线和工程负载世界 | 多线实际操作、缺料 / 堵塞互不串线、不同分辨率及首档性能 / 存读记录通过 |

每包先完成对应定向验证再进入下一包；单点失败按真实职责修正。正式依赖不得反向引用 `tools/visual-studies/`；只将必要的同源模型、规则与操作合同适配到正式目录，保留原 Demo / Web 作为对照。

首包完成时必须同时具备 P1–P3 证据，不能以 P1 已开窗或 P2 能写 JSON 宣称整个包通过。若扩大范围导致必须更换画风、存档方案或运行时语言，则重新说明影响；不会自行升级成整仓重写。

## 规模与流畅度验证提案

| 档位 | 负载与用途 | 判定 |
| --- | --- | --- |
| 操作路径 | 至少两条真实独立产线，含人物移动、放置、拖铺、拆回、缺料 / 回压与恢复 | 有窗口输入链与截图；体验由萝卜SAMA复评 |
| 首档 | 100 台设备、1,000 段带、最多 1,000 个在途物品 | 本包工程目标；记录实际活跃 / 缺料 / 堵塞数量，不能只测空设备或静态货物 |
| 扩展档 | 1,000 台设备、10,000 段带 | 本包不做、不作为容量承诺；首档完成后再讨论 |

- 首档分别覆盖局部可见、拉远大面积可见、持续生产、接近满载、汇流和连续拆改；拉远不必在一个屏幕硬塞整张地图。状态由正式规则和明确检查夹具生成，夹具来源必须记录。
- 先在当前 macOS 开发机测 `1920×1080` 与最大化实际像素，分别保留记录；窗口逻辑大小、实际 3D 分辨率、画质和硬件写入证据。
- 采用 20Hz 生产步进；建议首档目标 60 FPS、帧间隔 p95 ≤16.7ms、单次模拟步 p95 ≤10ms，前台持续运行 30 分钟无持续积压。保存 / 读档停顿单列，不用平均 FPS 遮住卡顿。
- 记录完整帧间隔、模拟步耗时、draw calls、内存及保存 / 加载阶段耗时；能取得 GPU 时间时单列，不能以 CPU 提交耗时推算 GPU 表现。
- Windows 仍是产品目标平台；目标机 CPU / GPU / 内存尚未指定，因此本机通过只能作为开发机证据，Windows 性能验收保持未完成，不能擅自以虚拟机结果替代。
- P1–P3 本机证据成立后可交付萝卜SAMA亲测，Windows 项单独保持待验；开发机交付与目标平台最终验收分别记录。
- 以上数值是已确认的工程验收目标，不是当前实测结果或最低配置承诺；若首档失败，记录瓶颈和实际值，不通过缩小负载或降低实际分辨率冒称通过。

## 验证、隔离与交接

- 状态：配置与命令输入校验、占用 / 稳定 ID、材料和构件守恒、单线对照、多线独立性、汇流公平、帧率变化下的推进与暂停。
- 存档：精确状态往返、半批 / 满缓冲 / 转角载货保存、退出重启、未来版本拒绝、重复 ID / 越界 / 超容量 / 非有限数拒绝、并发写入阻断、主档与备份故障。
- 玩家路径：真实 Boot → 工厂列表 → 新建 / 继续 → 多线操作 → 保存返回 → 新进程继续；旧二维新建 / 载入路径单独回归。合成输入、按钮信号与用户亲测分别记录。
- 画面：继承现有按像素渲染检查，复核普通 / 最大化 / 缩回、转角、遮挡、相机跟随边缘和 HUD 输入阻断；精细度不作为本包追加美术的理由。
- 自动与手工验证分别使用 `tools/runtime-intake/check-runs/factory-foundation-v1/`、`tools/runtime-intake/review-worlds/factory-foundation-v1/`。Boot 的旧切片和新工厂目录均注入隔离根，防止启动时旧迁移服务触碰用户正式档。
- 截图存于 `assets/art-intake/<date>-factory-foundation-preview/`，实际目录与检查结果写周志；存档证据保留最终可重进世界。
- 文档与静态入口按仓库规范执行；实施后扩展客户端静态 / Godot 定向检查，保留旧覆盖。Godot 和窗口检查前告知，不以旧独立 Demo 入口替代本包 Boot。

## 当前审阅点

本轮授权已覆盖认可事实同步和首包设计；无需再次确认是否认可同一套 Demo 画面。实施前应审阅本包新增范围：

1. 正式 `client/` 增加工厂世界，旧二维世界保留；世界状态与资产依赖按下列架构提案隔离。
2. 使用独立工厂 schema 1 和新存档命名空间，不自动转换 schema 10 旧世界。
3. 64×64、普通预发供给、100 台 / 1,000 带工程档、暂缓新增设备与美术润色。

上述合同通过后直接按 P1–P3 推进，不逐小步重复索要授权。目标机未指定只影响 Windows 性能验收，不阻塞已批准的本机实现与复核。

进入 P1 前同步正式路线涉及的产品 / 架构真相源，并协调根入口仍保留的旧二维介质限定；两份根入口保持一致，只调整必要长期边界，不把本包规模、批次或临时门禁复制进去。本次设计阶段不提前修改这些长期实现约束。
