# Demo Prototype Visual Pass V1

更新时间：2026-06-18

## 用途

本文定义首版 Demo 原型视觉呈现第一版的范围。它不是最终美术包、完整地图重绘、试玩准备、修 bug 阶段或发布准备；它用于检查现有 12 区画面能否通过色彩层级、前后景分离、危险 / 资源 / 设施视觉权重和对象状态，让玩家在操作前读出当前空间、关键落点和下一步去向。

## 玩家价值

玩家不应只靠 HUD 文案理解场景。进入区域后，应能从画面本身判断：

1. 自己处在哪类空间。
2. 哪些对象是当前要处理或避开的重点。
3. 哪些视觉状态代表已处理、缺条件、危险仍在或可回基地加工。

## 与整体规划的关系

本专题覆盖 [Demo Definition V1](demo-definition-v1.md) 的「区域 / 场景」「核心场景完成度」「功能 / 过渡场景」「UI / HUD」「初步美术」和「自动检查」规格。

它承接已完成的 [Demo Scene Art Foundation V1](demo-scene-art-foundation-v1.md)、[Demo Non-Core Scene Identity V1](demo-non-core-scene-identity-v1.md) 与 [Demo Playable Scene Composition V1](demo-playable-scene-composition-v1.md)：这些专题已解决核心 / 非核心场景身份与 12 区构成，本专题转向原型画面的视觉优先级和层级证据。

## 当前已有基础

- 12 区域范围、核心 / 功能 / 过渡分组和关键对象落点已冻结。
- `VerticalSliceMap.tscn` 已有区域底色、标识层、路线构成和代表性对象节点。
- `PrototypeInteractable`、`InteractableVisualRefresher` 和敌人焦点状态已提供对象色块、焦点和处理后状态。
- HUD / 地图 / 对象提示已能读出区域身份、路线职责、动作结果和受阻恢复路线。

## 本轮范围

- 确认现有 12 区的视觉优先级：背景区域、主路方向、关键对象、危险对象、已处理状态和可回基地处理状态。
- 检查色彩层级与前后景分离是否能支持玩家快速识别资源、污染、遗迹 / 异常、核心设施和前哨设备。
- 必要时只调整既有原型节点、色块、焦点状态或窄职责 visual helper，不新增区域、资源、任务链或最终资产包。
- 新增检查优先放在独立专项文件，避免继续推高 `vertical_slice_flow_check.gd`、`vertical_slice_map.gd`、`prototype_hud.gd` 或 `interaction_prompt_formatter.gd`。

## 第一包实施范围

- 补齐代表性对象视觉状态：可处理、已处理、缺条件、危险仍在、设备可用 / 忙碌、核心写入准备不足。

## 玩家操作路径

1. 前哨与晶体侧路：玩家能从设施色块、资源色块和主路方向分辨出基地整备与外勤采集目标。
2. 污染与遗迹：玩家能从危险对象、异常设施和处理后状态判断哪里需要防护、战斗或回基地加工。
3. 核心稳定站链路：玩家能从核心设施、守卫状态、校验片 / 回写缓存状态读出是否已具备写入条件。

## 运行时、存档与数据边界

- 不新增存档 schema，不迁移稳定 ID。
- 只读取既有 `WorldState`、`CharacterState`、库存、任务、敌人、对象和设施状态。
- 视觉状态必须由真实运行时状态驱动；若画面状态与数据状态不一致，优先修状态来源或 visual refresher。

## HUD / 场景 / 对象反馈

- 场景：区域底色、主路、对象色块和危险标记必须形成清晰层级。
- HUD / 地图：只用于印证当前目标、路线和恢复点，不替代场景视觉；紧凑 HUD 必须优先露出下一步，资源明细不能挤掉当前操作指引。
- 对象提示：说明对象状态和下一步，但不承载完整美术说明。

## 验收条件

- `Demo Prototype Visual Pass V1` 建立并作为当前活跃专题。
- 现有 12 区具备可检查的视觉优先级数据或节点证据。
- 代表性资源、危险、设施、敌人和已处理对象能通过场景视觉、HUD / 地图和对象状态互相印证。
- 未引入当前不做事项，新增检查走独立专项文件。

## 风险与后续决策

- 若只发现低优先级配色或装饰 polish，记录到后续视觉打磨，不阻塞阶段推进。
- 若视觉问题导致主线卡死、任务无法完成、关键对象不可识别或 UI 完全无法判断下一步，按当前阶段阻塞标准处理。
- 首屏看不清属于关键对象不可识别，不按装饰 polish 处理；后续新增视觉层必须优先验证启动可读范围。
