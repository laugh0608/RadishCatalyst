# Demo First Screen Assetized Scene V1

更新时间：2026-06-27

## 用途

本文定义 Demo 新档首屏的低保真资产化场景重建范围。目标是把首屏从程序几何图层和调试式叠线，切到可复用的地貌、设备、管线、角色和 HUD 资产语言。

本专题仍属于「首版 Demo 可玩纵切装配第一版」和 UI / Art 执行线，不是新阶段、试玩验收或最终美术包。

## 玩家价值

玩家进入新档后，不读长说明也应能判断：

- 这里是一处异星化工前哨基地。
- 左侧有晶体资源生态，右侧有污染风险。
- 中央是可维修的前哨核心和基地设备组。
- 玩家角色正在执行恢复核心的现场动作。
- HUD 只辅助目标、补给、状态和地图，不主导画面。

## 与整体规划的关系

- 服务 [Demo First Playable Slice Assembly V1](demo-first-playable-slice-assembly-v1.md) 的新档首屏和后续基地段。
- 承接 [Demo Playable UI And Art Pass V1](demo-playable-ui-and-art-pass-v1.md) 的首屏问题复盘。
- 以 [Visual And UI Direction](../product/visual-and-ui-direction.md) 的工业科幻现场界面为视觉约束。

## 当前已有基础

- 角落 HUD、右下小地图、左下快捷补给和右上状态已经从开发面板中分离。
- 恢复核心前的旧区域色块、跨屏路线、规划层和大边界已经大幅退场。
- `DemoBaseStartupPresentationLayer` 已能作为恢复前专用首屏底稿存在。
- 第十四到十七包证明：继续在 `draw_line`、`draw_rect`、圆环和半透明多边形上加细节，只能把画面推到低保真示意图，无法接近资产化游戏场景。

## 口径收束

- 不继续把“第十八个线框包”作为主推进方式。
- 不再把 shape 注册、透明度调参、提示文案、目标箭头和检查接线当作首屏主成果。
- 程序绘制仍可用于低保真占位、动态高亮和验证辅助，但首屏主读法必须来自资产化地貌、设备、管线、角色和污染 / 晶体场景。
- 自动检查只证明接线和回归，首屏是否成立以实机截图 / 录像观感为主。

## 本轮范围

1. 资产语言与渲染方式包：
   - 明确地面、晶体、污染、设备、管线、角色哪些使用 sprite / atlas / tile，哪些仍允许程序绘制。
   - 建立首屏资产命名、目录、引用和检查口径。
   - 目标是停止把首屏继续做成几何图层补丁。

2. 首屏地貌与生态底图包：
   - 做浅色岩地、金属平台、板缝、污迹、边缘岩石和基础阴影。
   - 左侧放晶体簇和碎晶地貌，右侧放污染滩、警示桩和污染边缘。
   - 目标是截图不看设备也像一个游戏场景。

3. 基地设备资产包：
   - 前哨核心、基础反应器、储存、整备台和管线网络改为低保真设备资产。
   - 每个设备必须有体积、材质色、端口和用途关系。
   - 目标是不再靠圆环、方框和线段解释设备。

4. 玩家与首屏交互包：
   - 统一实际玩家图形和维修姿态，不再叠两套角色读法。
   - 维修动作只保留手 / 工具、端口和短反馈，不用密集线团表达。
   - 目标是第一眼能读成“角色正在修核心”。

## 2026-06-27 第一包：资产语言与渲染方式

- 已建立 `client/assets/sprites/demo_first_screen/` 作为首屏低保真 sprite 目录，先放入地貌底板、晶体生态、污染边缘、前哨核心、管线束和玩家维修姿态六类 SVG sprite。
- `DemoBaseStartupPresentationLayer` 新增首屏资产 manifest，用稳定资产 ID 记录路径、角色和 `sprite` 渲染方式，并在恢复核心前用 `draw_texture_rect` 叠入地貌、晶体、污染、核心、管线和角色资产。
- 程序绘制本轮只保留为阴影、材质细节、维修端口和短反馈补层；后续不继续把主读法建立在 `draw_line` / `draw_rect` 线框堆叠上。
- `demo_prototype_visual_pass_check.gd` 已检查资产目录、加载状态、角色分类、渲染方式和首屏呈现 shape，防止本专题退回纯 shape 注册。
- 本包不代表首屏观感已通过，只建立资产化介质和接线路径；下一包继续推进地貌与生态底图。

## 2026-06-27 第二包：地貌与生态底图

- 地貌底板从大块高不透明深色面改为浅色岩地承托较小金属平台，首屏不再由一整块黑色板面承担主读法。
- 晶体生态 sprite 降低高度并缩小摆放尺寸，左侧晶簇退为资源生态背景，不再大面积裁切压住核心工作面。
- 污染边缘提高可见度并补到右侧 / 右下视野，配合低亮管线填充右侧空场，让污染风险有场景位置。
- `DemoBaseStartupPresentationLayer` 同步收小平台范围、降低平台不透明度，并补资产化地貌、晶体缩放、右侧污染和空场填充检查 shape。
- 新截图显示浅岩地、污染边缘和晶体尺度方向成立，但中央平台仍偏暗、核心仍偏圆盘；下一步优先处理设备体积和平台 / 地貌遮罩关系。

## 2026-06-27 第三包：基地设备资产

- 前哨核心 sprite 改为非对称工业机壳、服务舱、维修端口和小型状态芯，不再由大圆环承担主体识别。
- 新增基础反应器、储存箱组和整备台三类低保真 SVG 资产，分别承担加工、储存和外勤整备用途。
- 首屏呈现层把设备资产放到平台材质之上，并降低中央金属平台和旧设备剪影权重，让浅岩地、平台和设备层次更清楚。
- 设备之间补短管线和端口节点，用场景内关系表达核心、反应器、储存与整备的用途接力。
- 自动检查已覆盖九类首屏资产的路径、加载、角色分类、渲染方式和设备端口 / 平台遮罩 shape；新截图显示设备组体积和用途关系成立，但核心亮色状态芯仍偏圆、右侧底图线框仍需后续收束。

## 2026-06-27 第四包：玩家与首屏交互

- 恢复核心前让真实 `PlayerController` 面向前哨核心，首屏层不再额外绘制一套完整程序角色。
- `player_repair_pose.svg` 改为低透明维修姿态 / 工具臂提示，只作为真实玩家下方的动作辅助，不抢主体角色读法。
- 维修反馈收束为短工具线、端口小状态和少量火花，减少玩家与核心之间的密集线团。
- 核心亮色状态芯改为小状态匣，右侧底图线框加遮罩压低，降低第三包截图中的 UI 圆盘感和背景干扰。
- 新截图显示“玩家正在修核心”已成为首屏主读法；右侧遮罩仍有矩形感，但不继续作为首屏同层调参阻塞，下一步承接到基地入料、反应器和整备交接段。

## 2026-06-27 第五包：基地交接段资产化承接

- `DemoFirstIndustrialPathVisualLayer` 复用首屏设备 SVG，把恢复后的基地入料、基础反应器、储存箱和整备台从流程线框改成低保真设备资产组。
- 基地收料口、反应器进料 / 出料口、储存输出口和整备交接口补局部端口簇，玩家能在短距离内读出“输入进站 -> 反应器加工 -> 产物入库 -> 整备接收”。
- 现有状态只驱动可见反馈：入料包、反应器加热窗、储存输出包和整备锁扣反馈；不新增区域、资源、配方、任务或存档字段。
- `demo_resource_chain_state_check.gd` 已覆盖资产化设备、短物料流和储存 / 整备交接反馈 shape，防止基地交接段退回跨屏箭头或纯文字说明。
- 本包不启动试玩验收，也不重开首屏右侧遮罩同层调参；后续若有观感问题，优先继续沿基地交接段的设备与操作反馈修正。

## 当前不做

- 不做最终美术、完整动画、完整光照系统或完整 UI 组件库。
- 不引入外部大型素材包，不扩完整地图系统。
- 不新增区域、任务、资源、配方、存档字段、联机入口或试玩验收。
- 不重画 12 区全部资产；本轮只做新档首屏及可复用资产语言。

## 玩家操作路径

本专题主验收只覆盖：

```text
新游戏进入 -> 看见基地首屏 -> 走近 / 保持在前哨核心旁 -> 按 E 恢复前哨核心
```

首屏资产语言成立后，可复用到恢复后的基地承接段：

```text
恢复核心 -> 带回晶体 / 废件 -> 基地入料 -> 基础反应器加工
-> 储存输出 -> 整备台交接
```

## 运行时、存档与数据边界

- 资产和呈现层不进入存档。
- 不新增任务目标、资源类型、配方或区域数据。
- 恢复核心前使用首屏资产化呈现；恢复后仍交还既有路线、区域和设备状态系统。

## HUD / 场景 / 对象反馈

- HUD 保留左上当前目标、右上状态、左下快捷补给、右下小地图。
- 场景主读法来自地貌、设备、角色和管线，不来自文字和调试框。
- 当前目标提示只辅助维修端口，不允许跨屏路线或大焦点框重新回到首屏。

## 验收条件

- 首屏截图不读文字也能识别基地、晶体资源、污染风险、前哨核心和玩家角色。
- 中央核心像损坏工业设备，不像雷达圆环或 UI 圆盘。
- 玩家像一个正在维修的角色，不像光标叠在设备上。
- 远处场景不再是大面积空黑或抽象规划底板。
- HUD 不遮挡角色、核心和主要设备组。

## 风险与后续决策

- 若首屏资产化仍只表现为暗色抽象形状，必须优先改地貌和设备资产，不继续加线框细节。
- 若资产化需要新增生成图或外部素材，应先明确来源、授权、文件体量和可维护方式。
- 若首屏通过，再把同一资产语言推进到基地入料、反应器和整备交接段。
