# Slice Game UI Visual Finalization V1

更新时间：2026-08-09

状态：**已通过架构方向闸门；P0 外部参考受控读取已完成，项目现状审计、目标稿和客户端实现尚未开始。**萝卜SAMA确认现有 HUD、制造 / 背包和设备面板只是结构草稿，视觉专题不能据此关闭。

## 玩家结果

把第一可玩切片的全部游戏内界面从“功能齐全的表单原型”推进为正式游戏界面：世界仍是主舞台，玩家能快速找到当前目标、资源、生命、设备身份、物料流程、异常原因和主操作，同时不会被多套高饱和颜色、平均分割的卡片和后台式表格抢走注意力。

## 参考归属

- 游戏本体不再参考 Radish 家族 UI；现有“暖墨、赭色、玉绿、纸张 / Workbench”映射不再是游戏内 Theme、面板或 HUD 的目标。
- 游戏本体主要交叉参考《明日方舟：终末地》《异星工厂》《银河破裂者》：分别提取克制工业科幻界面、生产信息与网络可读性、ARPG 战斗视线和屏幕边缘 HUD。
- 只学习信息层级、色彩纪律、空间占用和交互节奏，不复制具体版式、图标、品牌标识、设备造型或商业作品资产。
- Wiki、资料站、配方计算器和其他官方辅助工具可以继续参考 Radish 家族 UI；它们与游戏只共享名称、稳定 ID、图标语义和分类口径，不反向约束游戏本体的色板与布局。

## 当前草稿判断

- [UI 结构实现 V1](slice-visual-hierarchy-ui-implementation-v1.md) 已证明制造 / 背包和设备操作的功能分组、鼠标路径与权威状态成立，但没有证明视觉定稿。
- 现行右侧舷窗仍由大量等权浅色矩形、细边框、默认式按钮和表单网格主导，设备身份、流程、状态和操作虽可找到，却缺少成品级焦点和节奏。
- HUD、任务条、资源条、制造面板和设备面板同时使用多套赭、青、绿、黄、红，常态与异常都在争夺注意力，整屏显得花哨。
- 自动断言、无截断、无互叠和结构人工通过只作为功能基线；不能替代目标稿、原生窗口观感和最终人工定稿。

## 色彩与材质硬约束

- 常态界面以中性冷灰、深钢和低饱和浅表面建立壳层、抬升、下沉和文字四级关系，不靠多种彩色卡片划分栏目。
- 同一界面常态只保留一个主强调家族，具体色相在目标稿阶段决定；青 / 绿不再同时承担装饰、选中、正常和完成。
- 琥珀只在需要注意或等待时出现，红只用于故障、危险和破坏性确认；状态解除后强色必须退出。
- 污染黄绿属于世界危险语义，不进入普通按钮、标题、库存格或装饰边框。
- 物品颜色来自物品图标本身；容器底色保持中性，不为每种物料复制一套高饱和卡片。
- 禁止用全局换色、统一透明度、加边框或批量调亮冒充定稿；颜色必须服从信息层级、当前操作和异常优先级。

## 2026-08-09 外部参考受控读取

- 萝卜SAMA在本机提供 34 张参考图：17 张约 `2.6K×1.48K` PNG 与 17 张 `3200×1440` JPG。按项目护栏分为 `8 / 9 / 9 / 8` 四批读取，全部使用 `high`，没有调用 `original`，也没有把商业游戏截图复制进仓库。
- PNG 组同时包含《终末地》的工业设施 / 面板、《异星工厂》的生产网络和《银河破裂者》的战斗 HUD；JPG 组覆盖《终末地》的探索 HUD、任务、总览、制造、队伍、用电、设备、仓库、背包、配方和百科链路。
- 《终末地》锁定为面板主要视觉锚点：黑白灰或低饱和半透明壳层承担大面积承载，单一主强调建立当前焦点，物品原色被限制在图标与真实流程节点内，红色只标局部缺失 / 阻塞。
- 《异星工厂》只提取紧贴屏幕边缘的生产工具、中心世界优先和高密度信息服从功能的原则；不照搬棕灰旧工业色、小字号和具体控件。
- 《银河破裂者》只提取 ARPG HUD 的边缘布局、快捷栏和高优先战斗反馈；不照搬高饱和多色条、强光效或整套蓝色面板。
- 目标稿不得机械复制《终末地》的品牌黄：关键合同是“一屏一个主强调家族”，具体色相必须与 RadishCatalyst 的异星地表、设备状态和像素图标同屏验证后再定。
- 设备面板可以保留世界作为上下文；任务、百科和复杂制造等全屏流程可以覆盖世界。两类界面不能继续共用同一遮罩强度和信息密度。

## 界面清单

P0 审计必须覆盖全部现行玩家可见界面，而不是只修两张代表面板：

- 启动与多世界列表、暂停和返回确认。
- 常驻 HUD、当前目标、资源、生命、敌人状态和交互提示。
- 制造 / 背包、放置预览与建造反馈。
- 六类建筑设备面板、核心修复 / 首次充能 / 中央仓库。
- 战斗、样本回收、交付、成功与阻塞反馈。

## 实施包

### P0：界面审计与减色合同

- 从现行正式 `Boot` 截图登记每个界面的主任务、主焦点、常态色、状态色、遮挡范围和仍像草稿的具体原因。
- 形成一份共享的中性表面、文字层级、单一主强调和条件状态色合同；主强调色相不在审计前预设，也不在本包修改客户端。
- 选出能暴露全部核心问题的代表状态，避免为每个页面分别发明视觉语言。

### P1：代表状态目标稿

- 至少完成世界 HUD、制造 / 背包、设备操作、晶体区战斗四张同分辨率目标稿；核心仓库与启动 / 存档界面可在同一视觉合同下补充代表稿。
- 目标稿必须使用现行真实字段、图标、世界截图和交互数量，不通过删功能或伪造大图掩盖信息密度。
- 彩色、灰阶和低饱和复核共同证明：世界主体、当前操作和最高优先异常不会被装饰色抢走。
- 萝卜SAMA逐张批准前不修改正式 Theme、场景和控件。

### P2：共享视觉资源与分面接入

- 只提取两个以上界面真实复用的壳层、文字、按钮、物品格、状态和进度资源；不建设通用 UI 框架。
- 按“HUD → 制造 / 背包 → 设备面板 → 核心 / 系统界面”的顺序分面接入，每一面都保留现有鼠标、键盘和权威业务路径。
- 结构包中已通过的信息分组可以重排视觉权重，但不得重新引入七张长卡、重复状态列表或大型后台表单。

### P3：正式入口与人工定稿

- 从正式 `Boot` 覆盖新档、基地整备、设备异常、晶体区战斗和重载；匹配自动检查只证明行为无回归。
- 原生截图逐张检查色彩数量、焦点、文字、遮挡、按钮状态、物品辨识和世界可见性。
- 只有萝卜SAMA明确确认“不是草稿、颜色不花、主要界面已定稿”后，本子专题和父视觉专题才具备退出资格。

## 边界

- 不新增配方、物品、建筑、敌人、任务、教程、存档字段或玩法状态。
- 不提前实现有限发电、负荷、储能或设备面板伪数值；核心仓库包 2 的新增操作能力继续暂停。
- 不修改 32px 网格、960×540 相机、世界设备锁定资产、端口、物流、足印或碰撞。
- 不使用 Radish 家族 UI 作为游戏内颜色、材质、排版或布局参考；也不要求官方辅助工具复制游戏 HUD。
- 不在目标稿批准前启动大面积 Theme 改造，不以自动检查全绿宣布视觉通过。

## 验收

- 玩家三秒内能指出世界主体、当前操作、当前资源 / 流程和最高优先异常，常态界面不会同时亮起多套强色。
- HUD、制造 / 背包、设备、核心和系统界面属于同一游戏视觉语言，但按冒险与基地节奏保持不同信息密度。
- 面板不再主要读成等权矩形表单；设备身份、物料流、状态和主操作具有明确焦点与路径。
- 不依赖口头说明即可完成既有鼠标主路径，键盘路径、存档、schema 8、物流、电网和完整全链无回归。
- 正式入口代表状态、灰阶 / 低饱和复核和萝卜SAMA人工原生窗口判断全部通过。
