# Slice Game UI Visual Finalization V1

更新时间：2026-08-09

状态：**已通过架构方向闸门；P0 外部参考受控读取、项目全界面审计、减色合同与 P1 代表状态选择均已完成。P1 目标稿和客户端实现尚未开始。**萝卜SAMA确认现有 HUD、制造 / 背包和设备面板只是结构草稿，视觉专题不能据此关闭。

## 玩家结果

把第一可玩切片的全部游戏内界面从“功能齐全的表单原型”推进为正式游戏界面：世界仍是主舞台，玩家能快速找到当前目标、资源、生命、设备身份、物料流程、异常原因和主操作，同时不会被多套高饱和颜色、平均分割的卡片和后台式表格抢走注意力。

## 参考归属

- 游戏本体不再参考 Radish 家族 UI；现有“暖墨、赭色、玉绿、纸张 / Workbench”映射不再是游戏内 Theme、面板或 HUD 的目标。
- 游戏本体主要交叉参考《明日方舟：终末地》《异星工厂》《银河破裂者》：分别提取克制工业科幻界面、生产信息与网络可读性、ARPG 战斗视线和屏幕边缘 HUD。
- 只学习信息层级、色彩纪律、空间占用和交互节奏，不复制具体版式、图标、品牌标识、设备造型或商业作品资产。
- Wiki、资料站、配方计算器和其他官方辅助工具可以继续参考 Radish 家族 UI；它们与游戏只共享名称、稳定 ID、图标语义和分类口径，不反向约束游戏本体的色板与布局。

## 当前草稿判断

- [UI 结构实现 V1](slice-visual-hierarchy-ui-implementation-v1.md) 已证明制造 / 背包和设备操作的功能分组、鼠标路径与权威状态成立，但没有证明视觉定稿。
- 现行右侧舷窗仍由大量等权浅色矩形、细边框、默认式按钮和表单网格主导，设备身份、流程、状态和操作虽可找到，却缺少成品级焦点和节奏。
- HUD、任务条、资源条、制造面板和设备面板同时使用多套赭、青、绿、黄、红，常态与异常都在争夺注意力，整屏显得花哨。
- 自动断言、无截断、无互叠和结构人工通过只作为功能基线；不能替代目标稿、原生窗口观感和最终人工定稿。

## 色彩与材质硬约束

- 常态界面以中性冷灰、深钢和低饱和浅表面建立壳层、抬升、下沉和文字四级关系，不靠多种彩色卡片划分栏目。
- 同一界面常态只保留一个主强调家族，具体色相在目标稿阶段决定；青 / 绿不再同时承担装饰、选中、正常和完成。
- 琥珀只在需要注意或等待时出现，红只用于故障、危险和破坏性确认；状态解除后强色必须退出。
- 污染黄绿属于世界危险语义，不进入普通按钮、标题、库存格或装饰边框。
- 物品颜色来自物品图标本身；容器底色保持中性，不为每种物料复制一套高饱和卡片。
- 禁止用全局换色、统一透明度、加边框或批量调亮冒充定稿；颜色必须服从信息层级、当前操作和异常优先级。

- 《终末地》锁定为面板主要视觉锚点：黑白灰或低饱和半透明壳层承担大面积承载，单一主强调建立当前焦点，物品原色被限制在图标与真实流程节点内，红色只标局部缺失 / 阻塞。

- 设备面板可以保留世界作为上下文；任务、百科和复杂制造等全屏流程可以覆盖世界。两类界面不能继续共用同一遮罩强度和信息密度。

## 界面清单

P0 审计必须覆盖全部现行玩家可见界面，而不是只修两张代表面板：

- 启动与多世界列表、暂停和返回确认。
- 常驻 HUD、当前目标、资源、生命、敌人状态和交互提示。
- 制造 / 背包、放置预览与建造反馈。
- 六类建筑设备面板、核心修复 / 首次充能 / 中央仓库。
- 战斗、样本回收、交付、成功与阻塞反馈。

### 共享减色合同

**中性表面**

- `N0 遮罩` 只服务真正阻断输入的确认 / 暂停模态；右侧舷窗和边缘 HUD 不用深遮罩抹掉世界。
- `N1 壳层` 定义面板外界和结构边界，`N2 内容面` 承载普通信息，`N3 下沉面` 承载物品格、列表项和进度轨道；三者只用中性冷灰、深钢和低饱和浅表面的明度 / 材质差，不按栏目换色。
- 抬头、页脚、卡片、按钮和结果区不得各自发明底色；分组优先依靠留白、对齐、字号和局部层级，边框只说明真实边界。
- 物品、设备和世界信号保留自身像素颜色，但 UI 容器保持中性；世界中的供电线或污染色不得被复制成面板装饰色。

**文字层级**

- `T1 主信息` 用于页面 / 设备身份、当前配方、当前目标和关键数值；同一视区只允许一个最高文字层级。
- `T2 正文` 用于物料流程、计数和操作名；`T3 辅助` 用于实例 ID、容量上限、键位和解释；禁用态只降低到仍可读的中性层，不改成彩色提示。
- `T0 反白` 只用于深色壳层或强状态节点；普通标题、计数和栏目名不再用青、绿、琥珀区分。
- 状态必须以短文字 + 图标 / 形状 / 明度至少两种方式表达，不能只换字色，也不重复在抬头、卡片和结果区写三遍。

**单一主强调**

- 每屏只设一个 `A1` 主强调家族，具体色相留给 P1 彩色 / 灰阶 / 低饱和同屏决定；P0 不指定品牌黄、青、绿或蓝。
- `A1` 统一承担当前选择、键盘焦点、唯一主操作和有效进度；同屏最多一个大面积实心 `A1` 节点，其余只用细标记、图标或局部填充。
- 世界像素资产的物品色和供电信号不是第二套 UI 强调；界面不得用同色大面与其竞争。主焦点切换后，旧焦点必须退回中性。

**条件状态色**

- 常态在线、就绪、已连接和完成不再长期使用独立青 / 绿家族；用中性信息、形状和 `A1` 局部确认。短时成功反馈也使用 `A1` + 勾选 / 结果文字，结束后退出。
- 琥珀只用于确实需要等待、补料、连接或玩家处理的注意态；红只用于故障、危险、敌对生命、非法放置和破坏性确认。
- 污染黄绿只属于世界污染 / 异星危害及其直接 HUD 告警，不进入普通按钮、标题、物品格或边框。
- 放置合法态归入 `A1`，缺地板用琥珀，非法 / 错向用红；`IN / OUT` 依靠标签、箭头和方向，不再各铺一套永久高饱和颜色。
- 强状态只允许出现在离原因或动作最近的局部节点；状态解除后同帧退回中性，不允许结果区继续保留旧强色。

**遮挡与节奏**

- 常驻 HUD 贴边并保持中心战斗 / 建造区开放；目标、资源、生命只在相应阶段升权，不同时形成三块最高对比。
- 制造和设备舷窗继续保留世界语境；打开大面板时，面板外 HUD 降为只读低权重，不与面板主任务同亮。
- 全屏系统流程可以覆盖世界；居中确认只显示决策所需信息。放置覆盖只围绕目标、真实范围与相关端口，不常驻展示无关网络。

### 进入 P1 的代表状态

1. **世界 HUD 常态：**核心已修复并充能、基地正常生产、无异常，角色靠近可交互设备；校正目标 / 资源 / 生命 / `E` 提示与世界主体的常态优先级。
2. **制造 / 背包阻塞态：**选中机械零件或设备套件但材料不足，保留七个对象、动态分类背包、真实数量和禁用主动作；暴露卡片密度、物品原色、选中与阻塞竞争。
3. **设备操作正常态：**反应器在线、`IN / OUT` 已连接且正在加工；以流程中轴验证设备身份、电力、物流、进度和唯一操作的减色层级。
4. **设备操作异常态：**储物箱在线但物流口未连接，保留模式、筛选、分类库存和维护阻塞；与第 3 稿共用布局，只替换条件状态节点。
5. **晶体区战斗态：**敌人近身、玩家非满生命且出现一次伤害 / 闪避反馈；同时验证目标、敌方生命、玩家生命、通知和世界战斗焦点。
6. **核心仓库态：**选中晶体，背包与核心均有数量且两种转移动作可辨；验证密集生产信息不退化为后台表格。

8. **首次充能确认态：**真实 `2` 催化剂成本、确认与取消并存；作为暂停、返回和移入回收区等居中模态的共享代表。

第 1、2、3、5 张是 P1 强制同分辨率目标稿；第 4 张是第 3 张的同布局异常变体。第 6 至 8 张用于补齐宽面板、全屏系统和居中模态三种未被四张主目标稿覆盖的遮挡模型。P1 开始前仍不得修改正式 Theme、场景、控件或生成新资产。
