# Demo First Playable Acceptance V1

更新时间：2026-06-19

## 用途

本文定义首版 Demo 体验主干建设后的阶段验收口径。2026-06-19 的自动化判断只能证明现有路径和检查接线存在，不能证明 Demo 已达到可试玩候选质量，因此本专题暂缓为后续验收入口，不再作为当前活跃开发专题。

后续重新启用本专题前，必须先通过 [Demo Playable Content Substance V1](demo-playable-content-substance-v1.md) 补强场景、角色 / 怪物 UI、初步美术、工业基建和任务节奏等玩家可见缺口。

## 玩家价值

阶段验收要回答一个问题：玩家不依赖开发者解释时，是否能理解为什么出门、为什么回基地、如何加工和整备、如何处理污染 / 遗迹 / 核心稳定站，并看到明确的 Demo 完成反馈。

验收只能在玩家可见内容达到首版 Demo 标准后进行；自动检查通过、专题第一包落地或文档映射齐全，都不能单独作为试玩准备依据。

## 与整体规划的关系

- 承接 [Demo Device Panel Operation Readability V1](demo-device-panel-operation-readability-v1.md)：设备面板已覆盖回基地加工和整备读法。
- 承接 [Demo Core Stabilization Run Playability V1](demo-core-stabilization-run-playability-v1.md)：终点站内路径已覆盖入口确认、侧边补给、阶段守卫、回写缓存和核心写入。
- 承接 [Demo Playable Experience Coherence V1](demo-playable-experience-coherence-v1.md)：已有 S0 / S21 / S22 代表性基线和自动检查。
- 不替代后续人工试玩；本专题只在玩家可见内容补强完成后决定是否进入验收 / 修正节奏。

## 当前已有基础

- 12 区域已封顶，核心区、功能区和过渡区均有路线职责、场景识别、对象提示和自动检查。
- 主线从新档到核心稳定站完成反馈已有运行时连续性检查。
- 基地加工、污染处理、整备台、快捷补给、战斗撤离、动作反馈、失败恢复和设备面板读法均已有专项检查。
- 存档状态契约已覆盖世界、角色、库存、建筑、任务、区域、敌人和关键整备状态。
- 以上只能证明工程路径存在；场景、角色 / 怪物 UI、美术识别、设备体量和任务变化仍需继续开发。

## 本轮范围

- 暂缓阶段验收，不再把当前活跃专题从内容建设切换到验收。
- 保留默认客户端检查、Godot runtime 检查、文档检查、文本卫生和 diff 空白检查作为工程验证。
- 等玩家可见内容补强后，再对照 `Demo Definition V1` 做阶段退出判断。

## 当前不做

- 不新增第 13 区域，不新增规格外资源、配方、设备、敌人、任务链、存档字段或 UI 面板。
- 不继续给核心站完成态、设备面板、资源链、工业主干、交互提示、地图提示或失败反馈追加同类文案包。
- 不做完整菜单、设置页、背包重构、完整装备栏、死亡系统、结算页、联机入口或发布流程。
- 不把阶段验收等同于最终美术完成或外部试玩发布。

## 验收路径

1. 先完成玩家可见内容补强，确认场景、角色 / 怪物 UI、美术识别、工业设备和任务节奏不是只靠提示成立。
2. 自动检查覆盖静态数据、场景引用、主路径、设备面板、存档状态、动作反馈、战斗恢复、地图 / 交互承载面和核心稳定站终点。
3. 复核 S0 / S21 / S22 开发基线，确认新档、终点前准备和 Demo 完成后整理都有状态证据。
4. 人工实机复测跑新档到核心稳定站完成反馈，再决定是否进入试玩准备。

## 验收条件

- `Demo Definition V1` 的必达规格不仅有专题、运行时路径或检查证据，还要有玩家可见实现质量证据。
- `check-client` 默认检查和 Godot runtime 检查通过。
- 文档入口、专题索引、Demo 定义和周志都指向阶段验收，而不是继续内容建设。
- 没有新增规格外区域、资源、配方、设备、敌人、任务链、存档字段或 UI 面板。
- 不存在场景、角色 / 怪物 UI、美术识别、设备体量或任务节奏上的首版 Demo 必达缺口。

## 风险与后续决策

- 自动检查不能替代人工实机体验，也不能替代玩家可见内容完成度。
- 若人工复测发现主线卡死、任务无法完成、关键资源断档、坏档或 UI 完全无法判断下一步，立即回到阻塞修正。
- 若复核发现的是场景、角色 / 怪物 UI、美术、设备或任务节奏未达首版 Demo 标准，应回到内容开发，而不是进入验收 backlog。
