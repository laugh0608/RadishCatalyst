# Demo First Playable Acceptance V1

更新时间：2026-06-19

## 用途

本文定义首版 Demo 体验主干建设后的阶段验收第一版。它不新增玩法内容，而是判断现有 Demo 是否已经能从新档连续走到核心稳定站完成反馈，并进入集中修正和试玩准备前的验收节奏。

本专题覆盖 [Demo Definition V1](demo-definition-v1.md) 的全部必达规格，重点验证主线结构、核心场景完成度、工业基建、资源 / 生产链、角色成长、战斗压力、UI / HUD、存档 / 状态、自动检查和初步美术是否已经形成可试玩的第一版。

## 玩家价值

阶段验收要回答一个问题：玩家不依赖开发者解释时，是否能理解为什么出门、为什么回基地、如何加工和整备、如何处理污染 / 遗迹 / 核心稳定站，并看到明确的 Demo 完成反馈。

验收通过后，后续开发不再默认扩新机制，而是围绕真实阻塞、复测发现和必要表现补强进入集中修正。

## 与整体规划的关系

- 承接 [Demo Device Panel Operation Readability V1](demo-device-panel-operation-readability-v1.md)：设备面板已覆盖回基地加工和整备读法。
- 承接 [Demo Core Stabilization Run Playability V1](demo-core-stabilization-run-playability-v1.md)：终点站内路径已覆盖入口确认、侧边补给、阶段守卫、回写缓存和核心写入。
- 承接 [Demo Playable Experience Coherence V1](demo-playable-experience-coherence-v1.md)：已有 S0 / S21 / S22 代表性基线和自动检查。
- 不替代后续人工试玩；本专题只决定是否停止继续开内容包，并进入验收 / 修正节奏。

## 当前已有基础

- 12 区域已封顶，核心区、功能区和过渡区均有路线职责、场景识别、对象提示和自动检查。
- 主线从新档到核心稳定站完成反馈已有运行时连续性检查。
- 基地加工、污染处理、整备台、快捷补给、战斗撤离、动作反馈、失败恢复和设备面板读法均已有专项检查。
- 存档状态契约已覆盖世界、角色、库存、建筑、任务、区域、敌人和关键整备状态。

## 本轮范围

- 对照 `Demo Definition V1` 做阶段退出判断，不再补同类读法包。
- 执行默认客户端检查、Godot runtime 检查、文档检查、文本卫生和 diff 空白检查。
- 将当前活跃专题从内容建设切换到阶段验收。
- 若验证发现 `P0` / `P1`，只修阻塞主线连续性、功能闭合、坏档、关键资源断档或 UI 完全无法判断下一步的问题。
- 若只发现局部文案密度、色块粗糙、摆位微调或体验 polish，记录到后续，不阻塞本阶段切换。

## 当前不做

- 不新增第 13 区域，不新增资源、配方、设备、敌人、任务链、存档字段或 UI 面板。
- 不继续给核心站完成态、设备面板、资源链、工业主干、交互提示、地图提示或失败反馈追加同类内容包。
- 不做完整菜单、设置页、背包重构、完整装备栏、死亡系统、结算页、联机入口或发布流程。
- 不把阶段验收等同于最终美术完成或外部试玩发布。

## 验收路径

1. 自动检查覆盖静态数据、场景引用、主路径、设备面板、存档状态、动作反馈、战斗恢复、地图 / 交互承载面和核心稳定站终点。
2. 复核 S0 / S21 / S22 开发基线，确认新档、终点前准备和 Demo 完成后整理都有状态证据。
3. 后续人工实机复测优先跑新档到核心稳定站完成反馈；只有 `P0` / `P1` 阻塞项打回内容修正。

## 阶段判断

- 2026-06-19 自动化退出判断通过：所有必达规格已有对应专题、运行时路径或专项检查证据；当前阶段从“体验主干建设”切换到“首版 Demo 阶段验收与集中修正准备”。

## 验收条件

- `Demo Definition V1` 的必达规格均能对应到已落地专题、运行时路径或检查证据。
- `check-client` 默认检查和 Godot runtime 检查通过。
- 文档入口、专题索引、Demo 定义和周志都指向阶段验收，而不是继续开同类内容包。
- 没有新增区域、资源、配方、设备、敌人、任务链、存档字段或 UI 面板。
- 后续只允许 `P0` / `P1` 阻塞修正或明确的验收补证，不再默认扩内容体量。

## 风险与后续决策

- 自动检查不能替代人工实机体验；阶段切换后应优先安排新档全链路实机复测。
- 若人工复测发现主线卡死、任务无法完成、关键资源断档、坏档或 UI 完全无法判断下一步，立即回到阻塞修正。
- 若问题只属于局部视觉、文本密度或手感 polish，进入验收 backlog，不重新打开内容建设阶段。
