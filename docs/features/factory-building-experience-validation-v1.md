# Factory Building Experience Validation V1

更新时间：2026-09-05

状态：**玩家实测反馈实现与系统验证已完成，手感待复评**。上一轮 16:9 的 `67` 项与 16:10 的 `6` 项断言继续保留为原工厂片段事实；本轮已实现设备真实端口接缝，以及建造态移动、鼠标选中和既有面板调整，并通过各自独立的新定向证据。萝卜SAMA尚未复评整改后的完整操作手感，因此仍不宣称体验验证通过；本轮暂不做 Web 对照或全仓重构。

## 玩家结果

玩家在一个小型工业场地中亲手放置采集器、基础反应器和储物箱，用传送带接成真实固体产线；随后从固定高斜角画面依次观察输入末格缺失造成的缺料、补接后的真实加工、输出末格缺失造成的回压，以及补接后催化剂进入储存，并能说清自己为什么这样改。

本轮回答的是“生产、物流与布局是否形成可读且愿意继续操作的核心乐趣”。它是新产品方向的前置验证，不继承旧“基地服务冒险”或 20–40 分钟全链为本轮硬目标。

## 开工十问

1. **玩家动作**：进入 / 退出建造模式，选择、放置和调整设备与传送带，仅旋转传送带，并检查设备状态。
2. **世界变化**：空场地变成一条持续运转的固体产线；断开输入或输出会真实改变货物和设备状态，修复后恢复。
3. **服务产品方向**：直接验证生产、物流、布局与故障排除是否足以承担核心体验。
4. **感知时长**：目标是一轮短时局部复测内完成首件产出与两次故障恢复；实施前再依据现有节拍冻结时间上限。
5. **系统范围**：优先复用现有放置、设备、传送带、库存、加工和供电；只补验证成立所必需的窄缺口。
6. **地图与素材**：使用现有地图小区域和现有像素资产，不生产新地图、新设备家族或新美术。
7. **成功证据**：真实玩家输入路径、权威物流 / 守恒检查、关键状态截图或短录像、玩家复测评价共同成立。
8. **失败处理**：按“可见性、操作、系统连接、介质”归因；同类方案连续两轮失败时停止追加提示并复盘路线。
9. **旧系统关系**：复用已收口固体产线是为了快速检验新核心，不把旧专题的历史验收冒充本轮体验通过。
10. **阶段价值**：结果用于决定先做 Godot 局部实现验证，还是需要同范围 Web 对照；不直接决定迁移或重写。

## 固定片段

### 场地与起点

- 从正式 `Boot` 进入一份仓库内隔离的实验世界；核心已修复，工业地板与电网预先覆盖三台设备候选位置，使用既有小区域中的一块连续、可放置且无关键路径遮挡的场地。
- 场地包含一处现有可采晶体点和足以摆下单线设备、连接带与纠错空间的工业地面；不新增地图区域。
- 起始物资明确标记为**实验预设**：各 1 件采集器、反应器和储物箱套件，7 条完成最短输入 / 输出路线的传送带，另有 2 条可选备用带；起点没有放置被测建筑。不要求玩家另做地板、中继或套件制作，本轮不验证制造资源平衡。
- 几何候选由现有[采集器物流检查](../../client/scripts/checks/slice_logistics_check.gd)与[反应器产线检查](../../client/scripts/checks/slice_reactor_check.gd)的两段直接构造链推导，并非现成正式世界夹具：实验场地采用采集器 `(40,11)`、反应器 `(47,10)`、储物箱 `(53,11)`；输入带为 `(43..46,12)` 并先缺 `(46,12)`，输出带为 `(50..52,12)` 并先缺 `(50,12)`。隔离预设搭建非被测地板与电网，传送带由玩家逐格放置并用 `R` 转向。
- 背包保留足够空位供调整 / 回收，储物箱初始为空，反应器输入 / 输出缓冲为空，传送带无货物。
- 预设只减少旧前置采集与制作时间；允许已有的已修复核心、非被测工业地板和最少中继承担场地准备，但不能注入被测的采集器、反应器、储物箱、传送带、连接拓扑、在制批次或最终产物，也不能称为自然新档 S0。

### 画面合同

- 常态保持固定高斜角主视图，玩家、设备、带上货物和设备工作 / 阻塞状态均可辨。
- 进入建造模式后相机采用一个稳定的拉远档位，完整容纳本片段；退出后回到常态档位，不引入自由旋转或第二观察角度。
- 建造模式必须同时显示对齐网格、设备足印、输入 / 输出接口和物流流向；合法 / 非法落位及原因可直接辨认。
- 会遮住目标格、端口或货流的世界层与非必要 HUD 在建造模式中弱化；弱化不能隐藏碰撞、设备状态或真实连接结果。
- 已实现 HUD 按钮进入 / 退出建造模式；建造态保留 `WASD` 移动与近身 `E`，无放置预览时可鼠标点击已有设备打开既有操作面板并调整，战斗输入仍屏蔽。`Esc` 依次取消当前未提交放置、关闭设备面板、退出空闲建造态；生产和物流不暂停，相机保持以角色为中心并切换一个离散拉远档位。建造缩放已冻结为 `1.5`；首轮 `1.25` 实机图出现上下灰条的结果只保留为历史校准记录。
- 放置继续使用现有无限制鼠标指向，不新增玩家距离限制；传送带保持逐格放置，`R` 选择方向。本轮未实现直线拖铺，是否需要连续铺带留给玩家实机评价，不把未验证的操作优化写成已完成能力。
- 上述信息必须服务放置和纠错，不以长期常驻的 debug 线框、长文案或自动替玩家完成连接来通过。

## 玩家操作流程

1. 玩家从正式入口载入实验世界，到达实验场地并进入建造模式；确认拉远、网格和足印能帮助选择位置。当前自动复测以传送到场地缩短准备时间，不把这段测试辅助描述为步行证据。
2. 玩家把采集器放到晶体点有效位置，把反应器和空储物箱放在同一可观察区域，并把默认 `supply` 储物箱通过真实设备操作切到 `transfer`；全部提交均走现有玩家输入与校验。
3. 玩家根据固定接口和可见流向铺设“采集器右侧输出 → 反应器左侧输入”，但先保留靠近反应器的一格缺口；退出建造模式观察权威“缺晶体”状态，再回到建造模式补上空格，使真实供料开始。
4. 玩家铺设通往储物箱左侧输入的输出线路，但主动保留靠近反应器输出的一格缺口。只有传送带使用 `R` 四向旋转，三台设备保持固定正面。
5. 玩家退出建造模式，观察晶体沿带进入反应器并加工为催化剂；因为输出线路有缺口，产物留在带 / 反应器输出并形成真实回压，设备停止继续消费原料。玩家可打开必要设备面板核对状态，但面板不代替世界反馈。
6. 玩家进入建造模式补接空格，观察积压产物进入通电的 `transfer` 储物箱、再按既有规则无线转入已修复核心且生产继续；最后以货物经过箱入口和储物箱 / 核心催化剂权威数量变化证明到达储存。

## 本轮实测反馈修复合同

### 真实端口接缝

- 设备可见输入 / 输出接口与相邻传送带必须沿设备目录定义的真实端口格和正确物流方向形成连续接缝；玩家无需靠记忆隐藏格位判断“这条带是否接到了设备”。
- 接缝呈现只读取现有设备端口、传送带方向、网格邻接和物流连接结果，复用现有 sprite、固定网格与物流权威状态；不建立第二套视觉拓扑，不新增设备、物流或存档 schema。
- 只有真实可通行的正确方向邻接才可显示为连通。缺格、错侧、反向传送带、输出对输出或输入对输入等断路 / 错向情况必须保留明确断开读法，不能用延长 sprite、覆盖线或高亮把它伪装成连接。
- 世界画面中的接缝、货物流向与权威物流结果必须一致：可见连通却不输送、可见断开却实际输送，均判定本项失败。

### 建造态移动、选中与调整

- 进入建造模式后保留 `WASD` 角色移动，供玩家走近错放设备并继续观察布局；战斗输入仍在建造态屏蔽，生产和物流继续运行。
- 没有活动放置预览且指针未被 UI 消费时，鼠标点击已有设备应打开既有设备操作面板，玩家从该面板进入既有调整流程。近身 `E` 打开设备面板的路径继续保留，两条入口进入同一权威操作与校验流程。
- 有活动放置预览时，世界点击优先提交 / 校验当前放置，不得同时选中下方已有设备；按钮、面板和其他可交互 UI 必须消费点击，不能穿透到世界造成放置或选中。
- `Esc` 按当前上下文逐层处理：先取消活动放置预览，再关闭已打开的设备操作面板，最后在空闲建造态退出建造模式；一次按键只处理当前最高优先级动作。
- 调整继续复用现有回收、背包容量、合法落位和物流校验。载货设备 / 传送带受既有限制时必须给出既有失败结果并保持原货物与原位置，不能为完成调整而丢弃、覆盖、复制或静默转移货物。

### 本轮通过证据

- 定向自动检查应覆盖正确方向接缝、缺格 / 错向不连通、建造态移动、鼠标与 `E` 双入口、放置预览 / UI 输入优先级、`Esc` 层级，以及载货调整失败后的货物与位置守恒。
- 正式 `Boot` 有窗口复测应由玩家看见设备接口与带形成连续接缝，并真实完成“发现错放 → 走近或鼠标选中 → 打开既有面板 → 调整”的路径；还须观察至少一个断路或错向样例没有被画面伪装成连接。
- 本轮实现与系统验证已经成立；完整操作手感仍待萝卜SAMA复评。上一轮 `67 + 6` 项断言不作为本轮接缝读法或调整手感的通过证据。

## 结束条件与判据

### 成功

- 玩家不依赖开发者口头指出格位，能从建造画面完成三类设备与传送带的合法放置，并能在操作后解释至少一个接口或流向判断。
- 首件催化剂由本轮真实采集、运输和反应器权威状态产生，经 `transfer` 箱入口进入储存链；自动断言只证明连接、状态、守恒和恢复，没有替代核心玩家输入。
- 缺料与堵塞都由玩家改动真实拓扑造成；恢复后权威物流继续运转，全链物品守恒。
- 固定高斜角常态能读出运行结果；建造模式拉远后能读出网格、足印、接口、流向、遮挡弱化和合法性。
- 玩家复测记录明确回答：哪里顺手、哪里犹豫、能否理解两次停机原因、调整是否有因果反馈、是否愿意继续扩建。只有正向评价与系统证据共同成立，才算体验验证通过。

### 失败与停止条件

- 玩家需靠口头指挥、记忆隐藏规则或反复试错才能连接，或常态 / 建造画面无法支持落位与纠错。
- 产出、缺料、堵塞或恢复只在文字面板 / 断言中成立，世界中的货流和设备反馈不能对应权威状态。
- 预设直接搭好产线、注入产物或调用内部方法代替关键放置 / 调整输入；这种结果只算测试夹具通过。
- 断开或恢复引起吞物、复制、继续无条件生产、错误端口接收，或需要建立新物流 / 存档框架才能勉强运行。
- 同一可见性或操作问题连续两轮靠增加箭头、蒙层、文字或调参仍失败时，停止同类补丁，由架构复核决定换介质、降范围、Web 对照或暂缓。
