# Factory Conveyor Combination V1

更新时间：2026-10-17

## 用途、授权与状态

承接[附件路线](../planning/factory-conveyor-accessories-roadmap.md) C：把已实现的[分流 / 汇合 A](factory-conveyor-routing-v1.md)、[准入口 B](factory-item-admission-v1.md)用于同一条真实开拓生产路径。萝卜SAMA于 10 月 17 日要求先完成 C 组合方案和验收路径；本次交付设计及静态可行性核查，尚未实现 C 检查驱动或取得 C 运行证据，不宣布 D3 / D4 退出。

主代理主持需求、设计、实际 diff 审阅和关键行为独立验收；边界明确的实现任务委派给 `gpt-6.1-sol`、推理强度 `high`，每次指定允许修改的文件、接口和验收标准。架构问题或连续返工由主代理接管；同类实机失败两次按[开发闸门](../process/development-decision-gates.md)复盘。

## 玩家结果与范围

玩家先用普通线生产 4 件解壳剂打开外矿道，再把新富集矿与普通矿接入组合产线，通过筛选保护两种配方、合并催化剂并分配给库存和制剂线，制备第二次开路的 8 件解壳剂。完成后能解释来料去向、停止原因和恢复办法；保存重进保持同一工厂的货物、批次、轮转及配额。

这是可选择的附件使用路径，不把混料干线或附件改成首程硬门槛。直接分开的专线仍有效；组合方案用于证明共线运输的用途与代价，不承诺比专线吞吐更高。布局确认后，以接通、观察两种加工与一次停复料作为 5–10 分钟可感知目标；首次从空世界游玩时间仍待亲测。

介质沿用导入 GLB、Node3D、既有接口箭头、建造诊断、设备 Control 面板和统计页。无新设备、物品、配方、资产包、保存字段或通用调度系统；沿 schema 5、20Hz 共同物流、普通供给和范围自动供电。液气、仓库出料口、物流桥、优先级 / 比例、循环配额、速率限制、蓝图、经济、多人、离线收益及精细美术保持冻结。

## 组合拓扑与流程

```text
普通晶体采集 ─┐
              ├→ 原料汇合 M1 → 混料带 → 分流 S1
富集晶体采集 ─┘                         ├→ 紧邻准入口 G1：晶体 / 不限量 → 基础催化剂反应器 ─┐
                                        └→ 紧邻准入口 G2：富集晶体 / 不限量 → 富集反应器 ─┤
                                                                                          ↓
催化剂仓 ← 分流 S2 ← 产物汇合 M2 ←────────────────────────────────────────────────────────┘
              └→ 催化剂准入口 G3：不限量 → 解壳剂反应器 → G4：解壳剂 / 本轮 8 件 → 制剂仓
```

G3 在试制阶段使用催化剂 2 件配额，试制完成且空载后改为不限量；保留它可复用 B 的既有起步路径。G4 在试制第一件送出前就配置并启用 4 件配额，不能事后搬入仓库凑数。G1 / G2 的输入必须直接相邻 S1 有效出口，朝向严格相对，中间不能插普通带。G1 / G2 之后可用普通带连接对应反应器；M2 两个来源均为催化剂，S2 才能向两个同物料用途分配。第三个未使用出口不接物料；不用终端仓作为自动供料来源。

| 段落 | 自然玩家路径 | 必须保留的证据 |
| --- | --- | --- |
| C0 起步 | 正式 Boot 新建普通供给 V5 零物料世界；晶体筛选、基础催化剂、手动拾样 / 投样、2 件催化剂试制；试制后 G3 改不限量，G4 总配额 4 | 样本唯一、真实加工与输入来源；试制的 1 件制剂包含在第一轮 4 件中 |
| C1 外矿道 | G4 放完 4 件且空载；从制剂仓近身取 4 件，走到外矿道显式消耗开路并实际穿越 | 首轮 4/4、开路消耗和地形一致；仓内制剂清零。停止 G3 新接收，按下述过渡规则保留旧线残料 |
| C2 组合 | 保留并改接起步设备，布设富集采集和第二套电源；原料 M1 / S1 / G1 / G2 分配到两种加工，产物经 M2 / S2 供仓库和制剂线 | 两种原矿均自然生成且到达正确加工支路，两个加工源均真实完成并送出；富集产出实际进入后续制剂批次 |
| C3 中途保存 | G4 达到已放行 7/8、持货第 8 件、进度在 0 与 1 之间，暂停并关闭接收；通过正式保存返回 | 保存整个世界，记录所有附件游标、在途货物 / batch、在制、统计和发现；不得直接写状态凑检查点 |
| C4 独立继续 | 独立 Boot 恢复 C3，先比对首帧快照，再恢复生产；关闭的 G4 只排出最后一件，重新启用仍不收第 9 件；等待下游运输完成，近身取 8 件并开内矿道 | 恢复后 8/8 且空载、制剂仓恰为 8；第二次消耗 8，实际穿越内矿道。合计开路消耗 12，不把上游剩余产品当丢失 |
| C5 完成恢复 | C4 保存退出后再用独立 Boot 继续，保留两矿道 / 样本事实 / 配额；观察两种加工与催化剂入仓继续 | 新一轮保存链真实可继续，G4 仍用尽；只在独立操作分支显式重置后再验证制剂放行 |

C2 形成组合前，停止相关准入口接收并排空；需改接的带 / 设备用正式无损回收命令处理，近身取回全部财产，满包时先入仓再重试。不得改坐标、清缓冲、注入构件或删除旧设备省略改线过程。配方切换须无输入 / 在制 / 输出；试制与常规制剂复用同一台反应器。

首轮配额用尽并不保证制剂机也空载：关闭 G3 后，其持货仍会排入机器。先暂停，近身取回制剂机输入 / 输出、按正式命令取消在制返料，并回收需改接段和仍持货的 G3 后重新放置 / 配置；所有额外制剂保留在背包或临时存放的催化剂仓，单独记录，不放进已清空的制剂仓或用于第二次开路。G4 空载关闭后改为 8，组合接通、旧残留隔离完成后才启用 G3 / G4；空载改额度明确开始新一轮。

第二次从制剂仓取料前，将背包中的旧制剂全部暂存催化剂仓并核对背包制剂为零；随后只取新轮的 8 件开路，旧制剂数量保持。这样用实际库存变化证明使用的是本轮备料，不对背包中已经混合的同名物品虚构来源身份。

自然路径的外部检查记录须从富集反应器 `output_batch` 跟踪到 M2 / S2 / G3 的货物 batch，再记录实际进入制剂输入、整批投入、完成及该制剂 batch 通过 G4；中途不得人工取放这批原料。制剂输入本身只存物品数量，因此不能只靠最终统计或快照推断原料来源。记录须覆盖实际固定步交接，不能用可能跳过交接的稀疏帧采样猜测；属于检查证据，不新增产品存档字段。第二轮放行的 8 件内至少一件须由该链证明包含富集原料；若已放完 8 件而无见证，路径失败，调整合法开工 / 接收顺序另跑，不以后续补产冒充。

## 地图、供给与电力预算

- 普通采集优先沿用 `(-20,-1)`，外矿道打开后即可使用首个富集矿 `(10,-1)`；富集配方在试制成功时已解锁，不依赖第二矿道。主要加工、仓库和附件优先留在基地区，富集原矿经外矿道返回；不必先开深矿区才能开始 C。
- 外矿壳 `x=4..7` 仅 `z=-2..1` 可通行。穿廊物流、人物路线及供电需同时安排；保留人物连续通路，不能以“矿道已开”代替足印 / 碰撞验证。节点中心之间不超过 12 格、设备中心到接入节点不超过 6 格，电力连线碰到封闭格边缘也会被挡。
- 设计预算为 2 采集器、3 反应器、2 仓、2 分流器、2 汇合器、4 准入口、2 电源；节点不超过 12、带目标不超过 160，合计目标不超过 189 实体。普通供给上限分别为 8 / 16 / 8 / 8 / 8 / 8 / 2 / 12 / 256，总实体预算 326；试制与旧首线包含在上述复用数内，不另算免费设备。
- 以上是设计预算，不是已验证的放置清单。实现前交付逐实体坐标、朝向、足印、连接及行走点清单，静态核对带数量和拓扑后再走 Boot；若需调整带目标，记录原因且仍遵守普通供给。不能先扩供给再宣称布局可行。
- 两采集器 40 kW、基础 40 kW、富集 80 kW、制剂 60 kW，全部可工作时合计 220 kW；两电源 240 kW 足够的前提是设备实际接入可供电网络。主验收让两电源同网并核对各设备接入与无缺口，不能仅看全局装机数。缺电对照可单独关闭一源，真实需求超过 120 kW 时才判断降速。

## 堵塞、数量与诊断合同

| 场景 | 预期行为与恢复操作 |
| --- | --- |
| S1 直接遇到错物品准入口 | 尝试另一兼容出口；不得吞料、越格或改物品。两个原料闸常态不限量 |
| 关闭一种原料接收，混料带队首是该物品 | 该物品会挡住 S1 及后续队列，另一种物品也可能停；重新允许接收并清除下游阻塞后恢复。不要求后面的物品越过队首 |
| 准入口和 S1 中间隔普通带 | 作为独立反例布局验证：错料可先进入带，再在准入口前回压；近身回收错接段并直接对接，货物完整返还。不把反例混入自然主线 |
| 催化剂仓支路断接 / 堵塞 | S2 对当前催化剂可转向仍能接收的制剂支路；先消耗支路空位再形成回压，不能要求远端瞬时感知。全堵时保货，修复后继续 |
| G4 已放行 7，最后一件被下游挡住 | 保持 7/8 和槽内占用 1；修复下游仅计一次成功放行，达到 8/8 后不接新货 |
| G4 达到 8 件 | 仅限制通过该闸的件数；反应器及上游可能已有额外产品 / 在制，均保留并计入库存，不能断言全世界只生产 8 件 |
| 关闭 / 重启、保存 / 恢复、空载旋转 | 不重置计数；关闭仍排空已收货。显式空载重置开始新一轮；持货配置 / 重置 / 旋转拒绝且零变更 |

自然主线证明两种支路都有实际产出，不承诺精确比例、无等待或各设备满速。两采集器供给快于加工，单槽共线以及富集反应器多件出料均会产生正常回压；只有持续具备接收资格的竞争请求才适用局部公平性。

设备面板沿既有查询显示当前货物、直接相邻阻塞、物品许可和本轮计数，统计页区分在途 / 设备 / 仓 / 背包与真实产消。定位后按相邻设备逐段诊断，不新增远端根因推断系统。若现有反馈无法让玩家完成定位，先记录具体断点，再做范围明确的局部修正。

自然 Boot 的首帧恢复比较使用同一发布序号，并另记真实保存序号；恢复后的自然计时检查守恒和结果，不强求不同进程的墙钟时刻完全相同。精确轨迹对照只由 C-S 的同命令 / 同步数重放证明。分流 / 汇合游标与富集半批可在 C2 另留自然检查点，不为追求与 7+1 同帧而修改世界或无限等待。

运行根计划为 `tools/runtime-intake/check-runs/factory-conveyor-combination-v1/`；截图为 `assets/art-intake/<日期>-factory-conveyor-combination-preview/`，亲测另用 `tools/runtime-intake/review-worlds/factory-conveyor-combination-v1/`。本轮未创建这些批次。未来入口分别承载状态、自然 write / read / 完成恢复、故障分支与短窗口；名称与命令以实现后 Tools 登记为准，不能把设计模式当作已存在命令。

C3、C4 各保留成功保存起点、文件 SHA-256 和父批次来源；每次恢复使用独立未消费副本，失败保留并从原起点建新批。双根隔离正式工厂 / 旧二维存档，使用现有 Boot / Catalog 合同；无窗口功能优先，省略截图必须明记。启动 Godot 前告知，窗口只用于必要原图与原生输入，关闭后不自动重开；详细规则见[运行时指南](../reference/godot-runtime-verification-guide.md)。

## 实施拆分与验收责任

1. **设计核查（本轮）**：主代理完成本篇、路线入口和 W42 记录；子代理只读核对现有配方 / 地图 / 供给 / 调度，主代理独立核对关键依据及实际文档 diff。文档治理通过后交付，运行验证保持待办。
2. **组合检查与布局**：后续委派仅允许新增 C 专用检查脚本 / 必需 UID、Shell / PowerShell 入口及 Tools 对应登记；先给主代理审阅精确布局与检查点。复用已有 Boot / 输入助手，不复制整套生产模型，不给既有 B 入口悄悄增加 C 断言；完整文件名单在委派时列明。
3. **暴露问题修复**：先确定失败属于检查驱动、实际模型还是交互；按实际问题另列文件白名单与定向验收。调度、schema、供给、近身权限和配额合同不得由子代理自行改动。跨合同问题先由主代理提出影响与选择。
4. **独立复核与交付**：子代理返回简洁改动 / 测试 / 未解决项；主代理检查实际 diff，独立验证恢复、守恒、配额及关键原图，再准备亲测副本并更新证据。阶段状态只按实际结果写入。

成功证据是可追溯的自然生产、恢复与修复路径，加原图和单列亲测反馈；丢货 / 复制、吞错料、计数重置、越权配置、原档污染或无法诊断恢复均失败。方案在现有地图 / 资产 / 系统内成立才继续；若空间与现有规则不能承载，先改布局或收敛演示路径，不增加新系统掩盖。当前待办为精确布局、C 驱动、全部 C 运行证据和亲测；Windows / 目标硬件、规模性能、D4 与发布边界保持。

## 静态依据

- `client/data/factory/discovery_rules.gd`：普通供给、四配方、两矿道成本、矿点与开放区域；`client/scripts/factory/discovery_model.gd` 的 `recipe_available/work_spec`：富集解锁及实际功率。
- `client/scripts/factory/logistics.gd` 的 `ports/output_status/step` 与 `admission.gd`：相邻准入、共同仲裁、单槽和有限额度；不含远端预筛或队列越货。
- `client/scripts/checks/factory_admission_check.gd` 的 `_combined` 仅验证两个晶体准入口；`factory_admission_boot_check.gd` 止于四件定量与恢复，不能充当本篇两原料组合 / 两次开路证据。
- `client/scripts/factory/power_grid.gd` 的 `line_open/reachability/reconnect_automatic`：矿壳边缘阻挡、6 / 12 格及实际网络；本轮只静态读码，未将预算推导记为运行通过。
