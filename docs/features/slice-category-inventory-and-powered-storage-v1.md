# Slice Category Inventory And Powered Storage V1

更新时间：2026-08-09

状态：**联合包 2 修正版已按萝卜SAMA指令提交为 `b4803e5a`；联合包 5 的自动、正式入口、AI 逐图复核与萝卜SAMA综合人工确认均已完成。**本专题与 [世界设备家族接入 V1](slice-world-device-family-integration-v1.md) 共同拥有 schema 8；分类库存、储物箱双模式、固定端口和存档迁移已在同一原子包切换。

## 玩家结果

核心仓库负责长期资产，背包负责外勤和短期建造，储物箱负责生产线供给或把现场产出汇回核心。每类物品只占一个动态格，玩家不再被总量 `30` 或固定 `36×50` 式整理劳动频繁打断，同时核心仓库和自动物流仍明显优于随身携带。

## 包 1 前现状审计

- `Inventory` 当前只有 `item_id → count` 与全物品合计 `capacity`；背包、核心仓库、储物箱分别为 `30 / 120 / 20`，`free_space()` 无法表达某一类物品还能加入多少。
- 采集、制作、拆除、反应器回收和容器转移都把“总剩余数量”当作容量预检；迁移到逐类上限时必须逐调用改成目标物品或原子批次预检，不能保留含糊兼容层。
- 制造面板预建九个固定物品格，核心仓库与储物箱面板仍按总容量呈现；现行 `contents` 字典已经天然满足“一类物品一个记录”，无需保存格子坐标。
- 储物箱只有单一旋转双向口、总容量 `20`，不耗电，也没有模式、输出筛选或无线传输进度。

## 分类库存合同

| 容器 | 物品类型格 | 单类上限 | 角色 |
| --- | --- | --- | --- |
| 核心仓库 | 不限制类型数量 | 每类 `99999` | 长期资产总库、无线传输终点 |
| 玩家背包 | 不设类型数量硬上限 | 普通物品每类 `200` | 外勤、建造和短期周转 |
| 储物箱 | 最多 `4` 类 | 每类 `200` | 本地供给或现场回收缓冲 |
| 机器缓冲 | 设备专用 | 保持反应器 `2 IN / 1 OUT` 等现值 | 生产状态，不套用普通容器上限 |

- 普通物品包括晶体、机械零件、催化剂与建筑套件；首版统一 `200`，不为每个物品制造难记的零散上限。以后只有明确的平衡证据才允许通过物品定义覆盖。
- 关键样本、任务状态和其他唯一物品继续走独立权威状态，不占普通背包格，也不进入工业物流。
- `SliceItemDefinition` 提供稳定 ID、分类、排序、图标和是否可物流运输；容器 profile 提供类型数与单类上限。显示顺序从定义派生，不把 UI 格子位置写进存档。
- `Inventory` 改为显式 `free_space_for(item_id)`、`can_add_batch(items)` 与原子批次转移；旧无参数 `free_space()` 退出普通业务路径，避免多物品回收只看一个总数。
- 普通添加不得超过单类上限或储物箱类型数；schema 7 合法储物箱可能在总量 `20` 内包含 `5–9` 类已知普通物品，可信迁移会把它作为祖父状态原样保留。祖父箱可补已有类别、取出或自动转出，但在降到四类前不能引入新类别。

## 背包与仓库 UI

- 背包和核心仓库按“原料 / 加工品 / 建筑套件 / 关键物品”分组，动态生成已有或已解锁物品格；不渲染 36 个固定空槽，也不因获得新种类拒绝拾取。
- 每个格子只显示一种物品及数量；背包显示 `137 / 200` 这类单类容量，核心仓库只显示 `137 / 99999`，不再显示误导性的总容量条。
- 制造 / 背包继续使用已经人工通过的右侧舷窗结构，只替换库存数据源、分组和容量表达，不重开外壳、标题或三列设备面板设计。
- 核心仓库、储物箱和制造面板必须读取同一物品定义与排序，不能各自维护图标、中文名或类别副本。

2026-08-26 的试玩整改包 3 在不改变上述分类库存合同的前提下，把核心仓库与设备容器统一为共享成对视图：默认“全部”只平铺实际持有物，分类不再制造已解锁但为空的占位格；拖拽、点击和键盘都转交既有权威 API。该调整不改变背包 `200`、核心 `99999`、储物箱 `4×200`、双模式、无线回传或 schema 10。

## 通电储物箱双模式

| 模式 | 有效物理端口 | 自动行为 |
| --- | --- | --- |
| `supply` 存储模式 | 右侧 `OUT`；左侧 `IN` 关闭 | 玩家手动存入；通电后只输出已选择的 `output_item_id` |
| `transfer` 传输模式 | 左侧 `IN`；右侧 `OUT` 关闭 | 接收传送带物品；通电后定时无线转入 `core_storage` |

- 储物箱升级为真实 `POWER_CONSUMER`，使用固定足印中心做逻辑供电探针，Gate A 的中继—储物箱线因此表达真实连接。
- 手动打开、存入、取出和切换模式不受断电影响，任何时候都不能锁住玩家财产。断电时存储模式停止供货；传输模式仍可被传送带推入物品直到箱满，但无线传输暂停并形成回压。
- 存储模式允许混装最多四类物品，但自动输出只认可运输的 `output_item_id`。空箱首次手动存入可运输物品时自动选择该类；玩家可在现有设备面板操作区切换，选中类别清空后保持筛选但显示“待补货”。
- 传输模式每 `5.0s` 最多向核心转移 `50` 件可运输物品，按物品定义的稳定顺序轮询并跨脉冲继续；核心某类达到 `99999` 时只保留未转移数量，不删除、不溢出。手动存入的非运输物品仍可手动取出，不被无线链偷偷搬走。
- 无电、核心未修复或核心目标无空间时传输进度暂停；恢复条件后继续。切换出传输模式时进度清零，避免反复切换立即触发；模式、输出筛选、轮询游标和 `[0, 5.0)` 进度都进入存档。
- 模式切换同帧重建端口与诊断。已在关闭端口前的带上货物保持原所有权并回压，玩家可用世界设备专题新增的单件带货回收纠错。

## schema 8 联合迁移

schema 8 由本专题与世界设备专题共同拥有，只允许一次原子切换：

```text
pocket / core_storage / inventory: {contents:{item_id:int}}
storage state: {
  inventory,
  mode:"supply"|"transfer",
  output_item_id:String,
  transfer_cursor:int,
  transfer_progress:float
}
```

- 容器 profile 是代码真相源，schema 8 不再保存可漂移的 `capacity`。schema 2–7 的 `contents` 原样迁移并去掉旧容量；旧背包与核心无损进入新单类上限，旧储物箱允许九个既有稳定普通 ID 的祖父多类型状态，不写额外兼容标记。
- 旧储物箱默认迁为 `supply`，防止载入后未经玩家选择就无线抽空；`output_item_id` 取现有内容中排序最前的可运输物品，空箱为空，游标与进度为 `0`。
- 同一迁移同时执行固定设施旋转规范化和显式端口切换；稳定 ID、原点、全部物品、反应器状态与带上货物保持不变，派生物流 / 供电按新合同重建。
- schema 8 候选必须先完成结构校验、库存 profile 校验、建筑校验和世界重建，成功后才写盘；原候选与备份继续遵守多世界回退规则。重复迁移与保存—重启必须幂等。

## 验收

- 新种类不会挤掉已有物品；背包单类 200、核心单类 99999、储物箱四类各 200 的边界与所有原子转移均不丢物。

- schema 2–7 旧档无损进入 schema 8，旧总容量字段退出真相源；真实新档完整生产链和核心充能仍通过。
