# C3 负载组实施合同

更新时间：2026-11-13

方案状态：**萝卜SAMA于 2026-11-13 确认并授权实现**。执行状态：实现及开发机定向、正式 Boot 窗口、跨进程验证已完成。本文是 [D2 测控](factory-grid-controls-d2.md)下的 C3 实施子合同，行为与 schema 15 按本合同冻结；玩家亲测、目标平台及 D2 长期对照分别保留待验。

## 玩家结果、范围与介质

玩家在已研究 C2 的工厂里，给一台储能选定可推迟的加工设备。燃料中断或可持续功率不足时，这组设备暂不开新批；已在制继续沿现有供电规则加工。余量恢复后自动允许开工，玩家能区分手动停机、控制等待、缺料和真实缺电。配置后 5–10 分钟内可通过一次断燃与恢复观察这一变化，帮助生产线恢复，为后续探索提供物资。

复用当前储能、精炼炉、组装机 GLB、设备面板与 Godot 控件；新增研究、组配置、权威开工许可及 schema 15。无新设施、布线种类、通用脚本、优先队列、任务排程或跨网控制，不修改 E2 的储能物理分配和 G 固定燃烧。普通连续供料仍可完成主线。只排除电芯组装，不自动识别或保护它的全部上游；玩家自行选择可延后的材料支路。

成功证据为正式 Boot 的研究、设置、断燃停开新批、在制完成、恢复、手动接管和存读原图，加定向时序 / 物料账与跨进程对照。玩法真相源为本文，身份与严格字段见 [C3 存档合同](../architecture/factory-load-groups-save-v15.md)，实际结果进周志。D2 长期收益和玩家亲测分别验收。

## 研究与配置

- 研究 ID `load_management`，核心 III、已完成 `storage_feedback`，原子支付 **1 构件包、2 金属板、2 多孔载体**。只解锁配置能力，不赠设备、不改变容量或配方；付款由研究集合重建，沿完整物料账。
- 每台 `grid_buffer` 最多承载一组，以储能实体 ID 标识，不另分配组 ID。每个自动电网最多一个启用组；关闭的配置可保留。同一设备在全世界最多属于一份组配置，关闭组仍保留成员归属，转组须先从原组移除。
- 成员为 **1–8 台**已存在、同网的 `refinery` 或 `assembler`，且当前配方不是 `cell_assembly`。允许手动停机或已有在制的成员加入，C3 不改变其本机启停和当前批次。采集机、粉碎机、反应器、G、电芯组装、物流和储能本身不可选。
- 玩家须在所属储能两格内操作。候选列表显示实体 ID、位置、配方、本机启停和已有归属；同网成员不要求同时在玩家两格内。草稿勾选与保留量不影响模拟，点「应用负载组」后按最新状态整笔校验；重复 ID、超额、错类型、跨网、已属于其他组或失效选择均拒绝且无副作用。
- 应用配置要求所属储能接网、所有成员同网；控制关闭时可在储能本机停用状态保存配置。若保留控制启用，则提交时还须满足储能已启用、同网无其他启用组。失效中的清理 / 接管用独立的移除成员或关闭控制操作，不能靠提交半有效新配置绕过校验；空列表用清空操作，不作为启用配置应用。
- 保留量由面板输入整数 kJ，范围 `0..3600`，默认 **100 kJ**；命令与存档为整数 J，必须为 1000 J 的倍数。它只约束本组的开工估算，**不是 E2 放电的锁定底线**；在制及其他负载仍可把储能用至该值以下。
- 新放储能无成员、控制关闭。首次应用只保存配置，须另点「启用负载组」；更改已有配置保留控制启停，但成员或保留量实质改变时置 `pending`、倒计时归零，下一模拟步再评估。完全相同的提交不刷新决定或倒计时。
- 启用须已研究、非空、储能已启用且接网、全部成员仍同网且没有其他启用组；启用后置 `pending / 0`，不得未采样先开批。「关闭控制，恢复普通开工」保留成员与保留量，置 `pending / 0`，下一模拟步只遵循原生产条件；不更改本机停机状态。关闭控制在失效或冲突时仍可执行。
- 「移除成员」允许近身逐项清理失效引用，不要求其余成员当时有效；清空最后一个成员自动关闭组，保留所设保留量，置 `pending / 0`。重新配置不退研究料、不取消在制、不移动货物。

## 有效性、拓扑与生命周期

启用组的实际新批许可要求：所属储能存在、已启用且接网，所有成员仍与其同网，所在网没有第二个启用组，且上次决定为 `allow`。任一条件失败时，**整组暂停新批**；不把仍同网的子集悄悄当新组。有效性每个固定步检查，不等一秒采样，也不改写本机 `enabled`。

- 分网、成员孤立、储能停用时保留成员、保留量、决定及采样节奏，显示具体失效成员 / 原因。有效性恢复后可继续使用保存决定，并在原定采样步更新；`pending` 在有效评估前始终禁止新批。不自动拆组、转绑或换储能。
- 两个各自合法的启用组因合网发生冲突时，两组都暂停新批；不得按 ID 擅选胜者，也不阻止玩家布线。冲突按所属储能的实际网络与组启用标志判断；储能本机停用仍保留该组的启用占位。玩家关闭其中一组，或重新分网后解除冲突；已在制照常。
- 成员成功回收时，同事务从所属组移除；切换到 `cell_assembly` 时也原子解除该成员，遵守原有排空 / 在制限制。失败不清引用。切换其他允许配方保留归属，但重置所属组为 `pending / 0`；成功移除成员同样重置，空组关闭。
- 成员本机启停不改组配置、决定或倒计时；手动停机始终优先且冻结该设备在制。手动再启用后，在制按原供电继续，空闲设备仍须组许可；不能靠启停绕过控制。组许可不会代替玩家自动开机。
- 回收所属储能同时删除该组，释放全部成员控制，下一步按原生产条件开工；回收提示须明确这一影响，存在成员时须确认，即使储能为零。带电仍先停用再确认，损失沿 E2；C2 对该储能的来源清理同事务完成。回收失败不改组或 C2 引用。原位重放是新实体、空储能、无组。

## 一秒评估与开工规则

沿世界 20 Hz 固定步。启用组用 `evaluation_ticks_left` 保存距下一评估的步数：步初为 0 时尝试评估并置 19，否则减 1；因此首次在启用后的下一步，之后每 20 步一次。失效或无候选时也按此节奏计时，但保留原决定，不伪造一次预算结果。关闭组固定 `pending / 0`。暂停 / 离线不走步、不补评估。

每次评估读取与 C2 相同的步初状态，发生在本步电力提交、燃烧推进、开批扣料及物流之前。全部组先从同一份状态计算，再提交各自决定；界面、`power_state()`、保存与预览不得推进倒计时或采样。

### 预算口径

1. 忽略 C3 本身的阻断，取得原生产就绪条件。候选是本组手动启用、尚未在制、配方已掌握、投入齐备且本机输出缓存为空的成员；“出口条件”沿现有开工缓存规则，不预测外部传送带未来能否收货。已在制不是新批候选；无候选时保留决定，显示「暂无可开工批次」。
2. `H_ticks` 为候选配方完整额定工时的最大值，向上折算为 0.05 秒步数；当前配方均可整步表示。采用完整工时，不用一个 tick 的能量余额假装足够完成一批。它是名义估算窗口，不保证缺电降速后的实际完工时间。
3. `P_need` 为该网所有负载在这个窗口内的保守功率和：本机停用为 0；启用且在制按额定配方功率；未纳组且原生产就绪按额定功率；本组新批候选按额定功率；其余启用设备按既有待机功率。每台设备只计一次，工作与待机不重复相加；忽略可能提前完工的减载。先保留在制与非组负载，再判断整组候选能否加入，不逐台抢额度。
4. `P_supply` 只计同网启用的基础电源、**已激活且 `burn_remaining_ticks ≥ H_ticks` 的 G**，以及**本组所属储能**保留量以上的可用功率。G 缓存中的完整电芯、在途电芯、C2 即将放行和未来充电均不计；短于窗口的 G 不按部分能量折算。其他储能仍按 E2 实际参与供电，但不计入本组预算，避免把多台电量隐式合并为一个控制来源。
5. 储能估算以整数 W 向下取整：`P_buffer_w = min(60000, floor(max(0, stored_j - reserve_j) × 20 / H_ticks))`。其他功率按已固定定义转整数 W。`M = P_supply_w - P_need_w`；以下比较不引入浮点容差。

| 采样结果 | 新决定 |
| --- | --- |
| `M < 0` | `block`，暂停新批 |
| `M ≥ 20000 W` | `allow`，允许新批 |
| `0 ≤ M < 20000 W` | 保留已有 `allow / block`；初次 `pending` 转 `block` |

例如无燃料且空储能时，360 kW 核心对 400 kW 总候选需求会阻断；其他负载下降使整组加入后为 340 kW，恰有 20 kW 余量即可恢复。储能低于保留量不单独否决；若核心余量已足够，仍可恢复。

### 消费许可与边界

- 同一组共用决定，不设内部顺序、逐台优先级或功率配额。决定在两次采样间保持；新到料或新完成批次的成员使用当前决定和当步有效性。运行中的供需可在采样间变化，因此这是一秒反馈式开工控制，不是未来产量 / 永不缺电的保证。
- 只令受阻断的空闲成员不能请求生产工时、不能扣投入、不能创建批次；仍保留既有待机请求。已在制不受 C3 阻断，继续按实际供电满足率推进，不强制满速、不退款或回滚。完工后的下一批再判断；取消在制沿原命令，不能借取消绕过组许可。
- 电网不足仍沿现有比例满足率；C3 不把“不给组开工”伪装成对其他设备的硬供电优先级。被推迟的新批不记为电力缺口，等待原因单独显示；在制和其他实际请求的缺口照常入账，不能仅用零缺口宣称产量改善。
- C2 继续读取步初电量并独立更新回差，C3 不改节拍、额度、G 启停或余时。顺序为步初两类控制 → 按许可分配电力 → 原燃烧 / 储能提交 → 在制推进 / 新批开始 → 原物流。共享接缝仅在新身份启用，不改变旧模型与摘要。

## 面板与实现接缝

储能面板提供成员勾选、保留量、应用、启用 / 关闭控制和失效成员移除。显示组归属、成员数量 / 本机状态、控制启停、上次决定、下一评估倒计时及当前失效原因；可展开查看按当前状态估算的窗口、需求、可持续供给和余量。实时估算须标为预览，不能冒充上次样本或触发状态提交。

成员面板显示所属储能 ID / 位置，区分「本机停机」「组待评估 / 预计功率不足 / 绑定失效 / 合网冲突」「缺料 / 出口待清」「在制继续」。库存、配方、取放、取消和启停仍用原入口。失效时必须保留关闭控制的可达操作，1100×720 下列表和按钮可滚动访问。

沿 `storage_feedback_model.gd` 增量接入权威组配置及采样；无副作用的原生产就绪查询用于预算，最终 `work_spec` / 开工路径再消费 C3 许可，避免“上次阻断 → 看起来无需求 → 错误放行”的循环。不得从分配结果倒推原始需求，或为控制而改本机启停。定义、命令、派生预算、UI、codec 按已有职责分离；若共享接缝无法保留 schema 9–14 行为，先说明影响再确认范围。

## 实施顺序与验收

控制改变手动启停、误停在制、丢货 / 复制、读 UI 推进评估、读档多开批、冲突自动选胜者、接受错误身份均阻断交付。玩家无法解释等待或找不到接管入口也不能只凭断言通过；连续两次同类实机失败按决策闸门复盘。执行阶段再运行仓库 / 客户端检查与定向 Godot / 窗口验证，启动前告知并只用规定隔离目录；实际验证与失败记录见 [W46](../devlogs/2026-W46.md#c3-load-group-delivery)。

## schema 16 开工联锁

每个成员可选一台同网、组外的加工设备，条件为「指定设备完成尾批并停机」。已有负载管理研究可配置，默认无条件。配置仍通过储能面板近身应用，来源显示 ID、位置和配方。来源断网时成员等待，回收来源前须解除或改绑；移除成员同时移除其条件。关闭组恢复普通开工并保留配置。

每次真正开批前，按步初状态同时检查原生产就绪、负载组有效、功率允许和联锁。来源必须已停用、无在制，且最近一次启用后开出的最后一批已正常完工。启用但空闲、停机冻结的在制、取消及启用后从未开批都继续等待。来源再次启用即清除旧完工结果。已在制按原供电继续，每个后续新批重新检查；被挡的新批保持原待机和物流。

组预算继续按原生产就绪计算，计入联锁等待成员可能加入时的需求。20 步采样、0 / 20 kW 回差、E2 放电、G 固定燃烧、C1 和 C2 沿原规则。界面分别显示功率决定和联锁原因，预览为只读。存档身份、字段与恢复见 [schema 16 合同](../architecture/factory-load-interlocks-save-v16.md)。目前完成隔离实现与冷档读回，成对首轮短测停在样本门禁，见 [D2 专题](factory-d2-production-comparison.md#d2-c3-interlock-preflight)。
