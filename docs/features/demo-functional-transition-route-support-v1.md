# Demo Functional Transition Route Support V1

更新时间：2026-06-16

## 用途

本文定义首版 Demo 功能 / 过渡路线支撑第一包。它承接已完成的角色成长与战斗第一版，把非核心区域从“地图上有名字”推进到“玩家能读懂为什么经过、当前危险是什么、为什么要回基地整理”。

本专题服务 [Demo Definition V1](demo-definition-v1.md) 中「功能 / 过渡场景」「区域 / 场景」「UI / HUD」「存档 / 状态」和「自动检查」规格。它不是第 13 区域、不是 8 个区域各自独立系统，也不是试玩准备或集中修 bug。

## 玩家价值

玩家离开四个核心区后，应能继续读懂路线：

- 封锁遗迹、裂相脊、回声台地和锚定桥分别展示遗迹门槛、前线回传、异常读数和稳定工程价值。
- 盐壳浅滩、碎晶沟谷、风蚀管廊和锁相框架负责连接节奏、环境压力和终点前压强抬升。
- 每个非核心区都至少说明当前危险、可观察收益和回基地理由。
- HUD、地图、对象提示和专项检查使用同一套区域支撑口径，不靠临时文案拼接。

## 与整体规划的关系

- 服务长期核心：“基地服务冒险，冒险反哺基地”。
- 承接 `Demo Combat Progression V1` 已完成的整备、扫描、防护、工具校准和承压差异，不继续加厚同类倍率。
- 承接 `Demo Scene Art Foundation V1` 的核心区识别，但本轮只延伸到非核心区域的路线支撑，不做完整美术包。
- 复用 12 区域封顶和现有稳定 ID；不新增资源、任务链、敌人类型、装备栏或完整 `loadout`。

## 当前已有基础

- `docs/planning/demo-scope-and-playable-slice.md` 已定义 12 区域职责表和功能 / 过渡区域分组。
- HUD 地图已能显示 12 区域标记和路线阶段。
- `SceneArtFoundationFormatter` 已覆盖基地、晶体、污染和核心稳定站 4 个核心区读法。
- 交互提示、地图目标和多项专项检查已能读取任务、区域、对象和整备状态。
- `vertical_slice_flow_check.gd` 已到 1500 行，`vertical_slice_map.gd` 接近硬上限；本专题检查必须优先走独立专项文件。

## 本轮范围

- 新增或整理非核心区域路线支撑口径，覆盖 4 个功能区和 4 个过渡区。
- 每个区域给出短标题、路线职责、当前危险、玩家可观察收益和回基地理由。
- HUD 地图路线和基地 / 外勤摘要能读出当前非核心区支撑信息。
- 关键对象提示至少覆盖封锁遗迹入口、裂相脊回传点、回声台地读数点、锚定桥稳定点和 4 个过渡区路线锚点。
- 新增专项检查，覆盖区域口径、HUD / 地图文本、对象提示和不新增第 13 区域。

## 当前不做

- 不新增第 13 区域，不平均把 8 个非核心区扩成同等密度。
- 不新增独立支线、长期任务网、随机成功率、新货币、队员或完整装备栏。
- 不重启前线行动台、候选、窗口复盘、高压窗口或 `base_action_state`。
- 不继续加厚战术扫描、防护响应、工具校准、污染边界、遗迹外圈、工业主干、主线完成感或核心区识别同一读法点。
- 不把本专题改成纯提示修补；必须覆盖玩家路线、对象反馈和自动检查。

## 玩家操作路径

1. 玩家从基地或核心区路线进入封锁遗迹，能读懂遗迹门槛、稳相信标和回基地整备理由。
2. 玩家推进到裂相脊，能读懂前线回传、裂隙收益和回投价值。
3. 玩家经过回声台地，能读懂异常读数、相位样本和测绘目标入口。
4. 玩家推进到锚定桥，能读懂稳定窗口、前线结果和核心稳定站前置价值。
5. 玩家经过盐壳浅滩、碎晶沟谷、风蚀管廊和锁相框架时，HUD / 地图 / 对象提示能说明连接方向、当前危险和回基地处理收益。

## 运行时、存档与数据边界

- 第一包优先从 `WorldState.current_region_id`、任务状态、既有对象实例和区域 ID 推导读法。
- 路线支撑 formatter 只负责展示文本和检查数据，不推进任务、不消费库存、不写新存档字段。
- 若后续必须新增路线锚点对象，应使用稳定 `map_object_instance` ID，并加入场景引用、存档来源允许表和专项检查。
- 不把新检查逻辑塞进 `vertical_slice_flow_check.gd`；不把新区域路线分支直接堆进 `vertical_slice_map.gd`。

## HUD / 场景 / 对象反馈

- HUD 地图：当前非核心区显示路线职责、危险和下一步方向。
- HUD 摘要：在没有更高优先级状态时显示当前功能 / 过渡区域的回基地理由。
- 对象提示：关键路线锚点显示所在区域职责和可观察收益。
- 结果或日志：只在玩家触发相关路线对象时补短句，不刷屏。
- 检查：专项 check 覆盖 8 个区域的口径、关键对象提示、HUD / 地图输出和区域总数边界。

## 验收条件

- 4 个功能区和 4 个过渡区都有稳定的路线职责、当前危险和回基地理由。
- HUD、地图和对象提示至少各有一处能读出非核心区域支撑口径。
- 自动检查覆盖区域数量、区域口径、关键提示和不新增冻结项。
- 实现不新增第 13 区域、不新增独立系统、不继续推高接近硬上限的大文件。

## 验证计划

- 文档阶段：`./scripts/check-docs.sh`、`./scripts/check-text-files.sh`、`git diff --check`。
- 客户端实现阶段：`sh ./scripts/check-client.sh`。
- 若新增或调整 Godot 场景节点，再执行 `sh ./scripts/check-client.sh --with-godot`。

## 风险与后续决策

- 风险：8 个区域一起做容易变成平均铺内容；本轮只做路线支撑和必要反馈，不给每区加独立机制。
- 风险：现有地图、HUD 和提示脚本接近行数边界；实现时优先新增 formatter、presenter helper 或专项 check。
- 后续若发现某个功能区已经缺真实操作点，应另建更窄的执行包，不把所有机制塞回本专题。
