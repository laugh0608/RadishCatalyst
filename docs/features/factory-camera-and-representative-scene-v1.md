# Factory Camera And Representative Scene V1

更新时间：2026-11-01

状态：**R1 设计方案，未实施、未定稿镜头或美术。** 萝卜SAMA授权提交资产盘点后准备镜头、现有资产选用、新核心与材质贴图方案；本轮只改文档和离线核算，不改客户端、不制作 / 导入资产、不启动 Godot。它是[整合总合同](factory-demo-integration-v1.md)的视觉准备子包，不取代核心 / 研究 / 能源实施合同。

用途：在同一处可行走工业现场确认镜头取景和目标资产品质，避免以整仓资产重做或无限截图调参代替方向判断。资产需求见[代表资产设计](../design/factory-representative-asset-brief-v1.md)，候选镜头 / 坐标见[取景与布局](../reference/factory-camera-study-layout-and-framing.md)。

## 玩家结果与设计闸门

- 玩家能辨认角色、核心与加工设备，判断可走区域、物流口与流向；在拉远布局和近身操作之间保持空间关系。
- 同一场景先比较镜头，再增加新核心 / 代表材质，确认靠近《银河破裂者》参考的现场感；参考的是取景与品质关系，原作未披露的投影 / FOV 不作事实。
- 介质沿 Godot 3D、导入模型和真实场景，动态网格 / 端口标记只作辅助；不做整幅背景板或第二个正式游戏客户端。
- 成功证据为参数可追溯的同场景原图、原生移动 / 点击 / 建造观察、遮挡记录及性能对照；离线数学只作前置筛选。
- 失败为角色 / 关键端口长期被挡、密集设备不可辨、最小窗口标记重叠、移动或点击错位。两次同类调整仍失败，按[决策闸门](../process/development-decision-gates.md)停手归因。

本包首先新增的是观察与审阅能力，不承诺核心玩法、研究界面、完整能源链或新存档已可玩。角色现场与产线可读性服务后续经营 / 开拓循环；5–10 分钟样板应足以暴露取景与操作问题，不复活旧 ARPG 系统。

## 分步交付与顺序

| 子步 | 内容与可审阅结果 | 退出条件 |
| --- | --- | --- |
| R1-A 镜头与尺度 | 同一静态板、旧资产、固定光照；C0 / C1 / C2 三个首轮候选，普通与密集构图；核心仅保留占地测量框 | 确认较合适的朝向 / 投影 / 取景；占地框不计新核心美术通过 |
| R1-B 核心结构 | 一件导入的新核心轮廓模型，I / II 在同一包围内；12 个实际候选位置接短带；已选镜头复核 | 主体身份、行走、低位端口和升级包围可成立；不接新库存 / 研究逻辑 |
| R1-C 代表材质 | 同一几何比较 M0 原材质与 M1 材质 / 贴图；新核心、一件代表反应器、共享材质与两种地表 | 正常视距可感知改善，图标 / 流向优先，光照和材质变量可解释 |
| R1-D 联合审阅 | 普通移动、密集产线、近身、建造与最小窗口；记录性能增量 | 萝卜SAMA认可镜头和代表品质后，才能作为 R2 规范输入 |

R1-A 尚未实施；R1-B / C 不能跳过 A。C3 / C4 为有明确问题才启用的两个备选，不默认跑全排列。通过任一步不意味着新整合世界可从菜单创建；旧 B1 / B2 / C 联合发布门槛不变。

全部路径相对 `client/assets/factory/`；只读实例使用，原 GLB、清单、导入与角色节点不改。17 项输入的当前哈希见离线报告。

| 对象 | 主选 | 比较 / 使用范围 |
| --- | --- | --- |
| 代表反应器 | `refinement/reactor.glb` | 已有圆润化工结构，首件材质样本；根 `reactor.glb` 保留作现行画面对照，二者不同时换造型 / 镜头 / 材质来判断单项收益 |
| 角色 | `engineer.glb` | 本轮复用比例与 `Body / Limb0..3`，不重做骨骼或角色资产 |
| 物流 | 7 件 `belt-{2,4,6,8,10,12,14}.glb` | 单口、弯道与合流外形组合；样板货物位置不冒充新核心物流模拟 |
| 周边设备 | `collector.glb`、`storage.glb`、`power/power-junction.glb`、`energy/cell_generator.glb` | 提供高低、体积与图标对照，不做首轮全套翻新 |
| 地面 / 资源 | `yard.glb`、`ore.glb` | A 阶段固定现有 yard 变换作背景，24×24 只是摆件评估区；C 阶段保持地面范围 / 高度换材质或候选地面，原场地不重导出 |
| 后续负载补充 | `expansion/refinery.glb` | D 阶段可替换密集板一排以检查不同足印；不纳入首件贴图工作量 |
| 新核心 | 尚无对应 3D 模型 | 依资产设计另制，不能借用二维核心作为成品或修改仓库规则来迁就造型 |

字体 / 现有物品图标继续共用。保留二维、历史参考与 Web / Godot 对照不搬迁，不批量重跑归一 / 导出器。是否需要新材质辅助脚本不由本设计预先引入依赖。

## 场景与交互边界

主板为 24×24 格局部构图，核心预留 6×6，含 12 段独立口邻带；另有 4×4 反应器密集板。两者均是几何 / 材质夹具，不是 S1 完整能源布局、真实供给新档或经营收益证据。

后续可复用隔离 Boot 的开发样板挂载方式，明确样板用途，不添加正式新建世界身份或 schema 9。已有设备交互若复用真实权威模型，才可报告其状态操作；新核心只允许几何选择与端口定位审阅，不展示伪造的已运行库存、研究、供电或存读成功。

镜头参数和审阅配置为样板数据，不写玩家世界；模型 / 材质变体在样板局部实例隔离，不能修改全局缓存材质。鼠标射线、物品屏幕定位、UI 坐标换算、WASD 与镜头朝向均需复核；换投影不改变网格、碰撞、模拟 20 Hz 或设备端口定义。

普通取景维持角色关联；对照图暂锁同一目标点，不能拿固定取景冒充跟随已通过。近身检视与拉远是待验观察档，不在本轮冻结自动变焦、自由旋转范围或新增操作键。若需消隐，先记录遮挡来源，再独立确定方案，不直接搬原作 stencil 系统。

## 证据与审阅要求

| 路径 | 必须回答的问题 |
| --- | --- |
| 同场景 C0 / C1 / C2 | 改善来自水平朝向还是投影？人物与核心占屏尺度是否相近？ |
| 近身 / 四侧抵近 | 北口、东西口和升级模块是否被主体挡住？近身选中与 F / 点击是否一致？ |

| 建造 / UI | 地格、预览、接口与实际落点一致，面板不透传；完整口名按需显示，已配置输出图标不能被省略以掩盖密度问题 |
| 正常 / 最小 / 宽屏 | 记录原生窗口、实际 3D 视口与帧缓冲尺寸；不把 1440×650 等设计视口当成实测尺寸 |
| M0 / M1 | 同几何 / 同灯 / 同镜头下能看出材质层次，正常视距不靠螺丝数量或强发光辨认 |
| 同源性能对照 | 帧时、绘制调用、三角形、材质 / 贴图数量与保存 / 采样干扰单列；旧性能结论不代签新负载 |
