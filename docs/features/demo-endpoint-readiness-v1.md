# Demo Endpoint Readiness V1

更新时间：2026-06-17

## 用途

本文定义首版 Demo 终点前综合准备读法第一包。它承接已完成的外勤回基地收益兑现，把进入核心稳定站到写入核心设备前的主线、补给、整备和承压准备汇总到玩家关键操作面。

本专题服务 [Demo Definition V1](demo-definition-v1.md) 中「推进污染 / 遗迹 / 核心稳定站 -> 完成 Demo 终点」以及「UI / HUD」「装备 / 模块」「战斗压力」「存档 / 状态」和「自动检查」规格。它不是终局菜单、不是试玩准备，也不是完整装备栏。

## 玩家价值

玩家进入 Demo 终点前，应能在基地和核心稳定站读出：

- 当前主线已经进入核心稳定站准备段，而不是只看到分散任务文本。
- 前哨补给、基础过滤模块、整备台收益、核心稳压缓冲包、侧边补给和守卫缓存分别处于什么状态。
- 出发口能给出下一步：进入核心站、回基地整备、处理守卫、回收缓存或写入核心设备。
- 核心设备提示能说明写入前准备项和承压收益，而不是只显示可交互。

## 与整体规划的关系

- 继续服务“基地服务冒险，冒险反哺基地”：终点前准备必须同时读取基地整备和外勤现场结果。
- 承接 `Demo Field Loop Payoff V1`，但不继续加厚同一条回波匣收益链。
- 复用核心稳定站现有任务、补给、缓冲包、守卫、回写缓存、出发整备台和 HUD。

## 当前已有基础

- 核心稳定站已有进入、缓冲包整备、守卫战和核心写入任务。
- 核心稳定站已有侧边补给、守卫缓存、写入承压和完成后复测读法。
- 出发口、前哨核心、HUD 和核心设备提示已经能读取部分出发准备与承压状态。
- 保存与任务状态已经覆盖终点前主路径；本包不新增存档字段。

## 本轮范围

- 新增 `DemoEndpointReadinessFormatter`，集中描述终点前主线、补给、整备、终点准备项和下一步。
- HUD 基地摘要在终点前准备段显示综合状态。
- 前哨核心、外勤出发口和核心稳定设备提示接入同一套终点前读法。
- 新增静态检查和 Godot runtime 专项检查，接入默认 `check-client` 和 `--with-godot`。

## 当前不做

- 不新增资源、配方、区域、任务链、完整背包、完整装备栏、终局菜单或发布准备流程。
- 不继续扩核心写入完成后的回访链。
- 不修改核心稳定站路线、gate 或守卫战压力公式。
- 不迁移旧任务、对象或资源 ID。

## 玩家操作路径

1. 玩家完成锚定桥稳窗校准后，核心稳定站入口开放。
2. 玩家在前哨核心和出发口看到终点前准备总览。
3. 玩家进入核心稳定站，读取侧边补给、缓冲包、守卫和核心设备状态。
4. 玩家回基地整备核心稳压缓冲包，补给后挑战核心阶段守卫。
5. 玩家回收守卫缓存后，在核心设备提示里确认写入准备项，再写入核心稳定数据。

## 运行时、存档与数据边界

- 本包只读取既有任务完成态、当前任务、对象状态、敌人状态、库存、装备和整备台状态。
- 不新增存档 schema，不新增地图对象字段。
- 终点前准备读法不改变任务推进、伤害计算或掉落结果。

## HUD / 场景 / 对象反馈

- HUD：显示“终点前准备”总览、终点准备项和下一步。
- 前哨核心：显示补给、整备和核心站准备总览。
- 出发口：显示是否该进入核心站、回基地整备、处理守卫或写入核心设备。
- 核心稳定设备：显示写入前准备项、承压收益和下一步。

## 验收条件

- 终点入口开放后，HUD、前哨核心和出发口都能读出终点前准备状态。
- 核心写入前，核心稳定设备提示能读出主线状态、准备项和下一步。
- 完成 Demo 后不再显示终点前准备读法，避免和完成态读法冲突。
- 自动检查接入默认 `check-client` 和 Godot runtime 检查。

## 风险与后续决策

- 风险：终点前读法容易和核心完成态读法混在一起；本包只在核心写入完成前显示。
- 风险：HUD 摘要已很密集；后续若继续加终点信息，应先收束 presenter 职责，不直接堆到大文件。
- 第一包完成后应做阶段退出判断；若通过，继续对照 `Demo Definition V1` 选择新的非重复玩家路径缺口。
