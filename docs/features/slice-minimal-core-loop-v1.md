# Slice Minimal Core Loop V1

更新时间：2026-07-17

状态：当前唯一活跃功能专题；切片第三个实现专题（系统层换皮第一步），2026-07-17 由萝卜SAMA择序确认。

## 背景与定位

无缝大地图已成立：西基地（受损核心 + 三设备）与东晶体区（八簇晶体 + 污染角）同图连续，四方向可控行走、相机跟随（见 [Slice Crystal Expedition V1](slice-crystal-expedition-v1.md)，已收口）。本专题把章程核心循环"出门采集、回家建设"第一次立起来：**采集晶体 → 步行回基地 → 修复前哨核心**，并为它接入最小 HUD。这是切片从"可以走"到"有事做"的分水岭。

不迁移旧任务链 / 资源链 / 存档系统；本专题的状态是世界根内的轻量运行时状态，后续专题再定存档与旧系统复用边界。

## 玩家价值

- 看到：左上角晶体计数 HUD、靠近可交互物时的按键提示、修复完成后核心从受损态换为修复态。
- 做：走到晶体簇按 `E` 采集（簇按档产出并耗尽消失），攒够后回基地对受损核心按 `E` 修复。
- 理解：晶体是资源、核心是目标，"出门采集、回家修复"一圈约 3 到 5 分钟，是整个游戏循环的最小样本。

## 数值与交互口径

- 晶体簇产出：小 1 / 中 2 / 大 4，交互一次全额采集并消失；全图共 3 小 + 3 中 + 2 大 = 17 晶体。
- 核心修复消耗 10 晶体：玩家需走访约一半晶体簇，形成往返节奏；剩余 7 为冗余，避免死档。
- 交互键为既有 `interact`（`E`）；交互半径约 1.5 tile，提示实时显示最近可交互目标。
- 核心修复后换 `outpost_core_repaired` 精灵，足印碰撞不变；完成节拍以 HUD 文案呈现（"前哨核心已修复"）。

## 范围（串行推进）

### 包 1：采集交互与资源计数

- 晶体簇挂交互组件（`Area2D` + 产出量），采集后计入世界状态并移除节点。
- 玩家挂交互扫描区，`interact` 触发最近目标；无目标时按键无副作用。
- 新建 `SliceHud`（`CanvasLayer`）：晶体计数、交互提示两要素，原型字体文本即可，不做美术面板。
- 出口：实机可采集任一簇，计数正确累加，簇消失，提示随距离出现 / 消失。

### 包 2：核心修复与完成节拍

- 受损核心挂修复交互：晶体不足时提示所需数量，足够时消耗并换修复态精灵。
- HUD 增加目标行：未修复时提示"采集晶体修复核心（x/10）"，修复后切换完成文案。
- 出口：实机走完"采集 → 回基地 → 修复"全循环，核心换态、计数扣减、文案节拍正确。

### 包 3：全循环验证与收口

- 运行时状态机脚本走真实入口完整循环并断言：计数、簇消失、不足拦截、消耗、换态、完成文案。
- 实机截图：采集提示现场、修复前后核心对比、完成节拍画面，记入当周周志。

## 成功证据

- 正式入口新档可在 5 分钟内完成最小循环；修复后核心为修复态且保持。
- HUD 三要素（计数 / 提示 / 目标行）与世界状态实时一致，无残留提示。
- `sh ./scripts/check-client.sh` 通过；`--import` 与运行时循环复核按需执行。

## 失败退出

- 按 [Development Decision Gates](../process/development-decision-gates.md) 两次失败停手规则执行。
- 交互判定或状态同步两轮实现仍有漏采、重复计数或换态失败，停手复盘交互承载结构。

## 不做

- 不做背包 / 多资源种类 / 配方 / 加工链；晶体是唯一资源。
- 不做敌人、战斗、污染伤害；不做任务链与对话；不生成新素材。
- 不接存档（修复状态暂不持久化）；不迁移旧任务 / 资源 / HUD 系统代码。
- 不删除、不修改冻结的旧场景、旧视觉层与旧检查。

## 状态 / 存档 / HUD / 检查

- 世界状态（晶体数、核心修复标记）存于世界根，仅运行时有效；存档接入留后续专题。
- `SliceHud` 为新建独立 `CanvasLayer`，不复用、不修改旧 `PrototypeHud`。
- 旧运行时聚合检查维持现状；只要求 `check-client` 静态通过与无导入错误，不新建检查脚本文件。

## 验收与移交

- 专题收口以"正式入口完整循环实机路径 + 修复前后截图"判定，记入当周周志。
- 收口后下一专题候选：存档与状态持久化、立绘对话最小接入、采集与建造扩展；由萝卜SAMA择序。
