# Demo Industrial Base Visual And Scene V1

更新时间：2026-06-21

## 用途

本文定义首版 Demo 工业基地视觉与场景化第一版。它把当前阶段从“继续补读法和检查证据”切回“做出能被玩家看见的工业基地、场景和 UI 视觉”。

首版 Demo 的交付目标是内部朋友试玩用的第一版可执行客户端，或由开发者完整跑通 Demo 流程并发布实机演示。当前不追求公开试玩发布质量，但不能继续停留在 debug 色块、长文本提示和流程图式场景。

## 玩家价值

玩家第一次看到 Demo 时，应先相信这里是异星工业基地，而不是一张带任务标签的测试图。

- 基地是核心：反应器、过滤器、储存、整备台和前哨核心要能被识别为工业设施。
- 探索与战斗服务基地：外勤资源、污染、副产、敌压和核心目标都要回到基地能力、产能或风险处理。
- 工具到设备要有升级感：初期玩家用自身工具采样，建出采集设备后应转为设备自动开采、装车和回基地入料。
- UI 服务现场判断：HUD 让玩家知道当前安全、设备状态、关键缺口和下一步，不用大段文字替代场景。
- 低保真可以接受，但必须有风格、轮廓、状态和用途关系。

## 与整体规划的关系

- 覆盖 [Demo Definition V1](demo-definition-v1.md) 的核心场景完成度、工业基建模块、资源 / 生产链、UI / HUD 和初步美术规格。
- 承接 [Visual And UI Direction](../product/visual-and-ui-direction.md)：清晰克制的工业科幻现场界面，叠加危险异星生态和化工设施可读性。
- 参考方向是《The Riftbreaker》一类“工业基地为主，探索 / 战斗反哺基地”的体验，并吸收“玩家先开路、设备接管稳定产出”的基建节奏，而不是纯 ARPG 外勤任务链。
- 本专题取代“继续泛化补场景设备读法”的明日建议；后续专题必须优先回答工业基地如何成立。

## 当前已有基础

- 12 区域、核心稳定站终点、主路径、存档基线、设备面板、加工、过滤、整备、战斗反馈和自动检查均已存在。
- `VerticalSliceMap.tscn` 已有大量可交互对象、敌人、区域块、路线块和运行时图层。
- 当前不足是画面仍像 debug 色块与文本提示，玩家和敌人仍偏圆点 / 方块，基地设备缺少工业设施轮廓和输入输出现场关系。

## 本轮范围

1. 基地平台视觉重建第一包：
   - 前哨核心、基础反应器、污染过滤器、基础储存箱和出发整备台要有可识别轮廓、底座、材质色和状态层。
   - 基地内补出管线 / 物流 / 介质流向，让玩家看出设备之间的工业关系。
   - 场景内保留必要交互，但减少大字标签和半透明 debug 框遮挡。

2. HUD 视觉收束第一包：
   - 左侧和角落 HUD 改成游戏 UI 信息层级：当前目标、生命 / 防护 / 补给、关键材料、设备状态和警告。
   - 调试面板、开发基线和 GM 控件继续存在，但默认不作为玩家第一视野的主要视觉。
   - 场景内目标提示优先改成高亮、图标、短标签或描边，不用长句覆盖操作区域。

3. 第一条工业链可视化：
   - 首轮优先做 `手持工具采样 -> 采集设备自动开采 -> 基地收料 -> 基础反应器 -> 基础零件 / 修复凝胶 -> 出发整备收益`。
   - 手持采样只承担开局引导和第一口资源；建出采集设备后，重复资源产出应由矿机 / 采集器式设备表达。
   - 产物去向要能在设备、HUD 和整备台之间互相印证。
   - 路径层必须能按手采、采集设备出料、回基地收料、反应器进料 / 加工、产物入库和整备交接切换当前操作段；表达方式应少色、少层、单主信号，不能只是常亮路线或彩色叠层。
   - 污染链作为第二优先：`污染沉积 -> 污染过滤器 -> 抗污染药剂 + 污染浆液 -> 回收 / 核心准备`。

4. 12 区工业职责复核：
   - 不平均重做 12 区。
   - 每个区域必须标注它给基地提供什么资源、解锁、设备输入、风险或稳定工程价值。

## 后续执行顺序

1. 先用实机确认新档首屏只突出前哨核心，且不再读成完整基地平面图；再用 3 / 4 号截图点核对采集器出料和基地交接，确认手持采样、采集设备自动出料、基地收料、反应器进料 / 加工、产物入库和整备交接能在同一段画面中读出来，并且当前阶段反馈会随资源和设备状态切换但不造成彩色噪声。
2. 开发截图定位点只作为回归证据，检查全图规划层是否再次压过路径层和局部设备。
3. 若第一工业路径读法成立，再补设备状态灯、资源 / 浆液流动、敌压警告和核心写入反馈，不横向扩新系统。

## 当前不做

- 不做最终美术包、完整动画、完整角色装备外观、完整菜单、设置页、背包重构或发布流程。
- 不新增第 13 区域，不新增完整自动化物流、电网、管网仿真或复杂化工参数面板。
- 不把新增 formatter、专项检查、长文案、目标箭头或场景标签作为当前阶段主线成果。
- 不继续用 `ColorRect + Label` 的 debug 表达作为首版 Demo 可试玩画面目标；临时实现可以用 Godot 基础节点，但必须形成设备轮廓、材质、状态和用途关系。

## 玩家操作路径

```text
新档进入基地 -> 识别前哨核心和工业设备 -> 用自身工具取得第一口晶体 / 残骸 -> 建出采集设备并看到自动出料 -> 回基地入料加工 -> 看到产物进入补给 / 整备 -> 再出发时感到基地能力改变
```

本阶段先把这条第一印象路径做出画面可信度，再把同一视觉语言扩展到污染、遗迹 / 异常和核心稳定站。

## 硬性开发规则

- 每个开发包必须先说明玩家在截图或实机里能看到什么变化。
- 如果截图仍主要由大色块、长标签和调试面板构成，该包不能作为阶段退出证据。
- 自动检查只验证接线和回归，不再作为当前阶段的主要完成物。
- 新增文本必须服务场景和 UI，不得用文字解释本该由设备、地貌、危险边界和交互反馈表达的内容。
- 新增 helper / formatter / check 只能支撑可见实现，不能成为开发包主体。

## 运行时、存档与数据边界

- 优先复用既有区域、设备、资源、配方、任务和状态字段。
- 视觉节点和材质元数据默认不进入长期存档；只有玩家可见状态确实需要保存时，再同步存档契约。
- 新增资产优先放在 `assets/` 或客户端资源目录；若先用 Godot 基础节点搭建，也要按真实设备职责命名。

## 验收条件

- 基地平台截图不再像 debug 流程图，玩家能识别 5 个核心设备和它们的工业关系。
- HUD 第一视野不再被长说明和调试面板主导，当前目标、状态、关键资源和设备警告层级清楚。
- 至少一条工业链能从外勤资源、基地加工到整备收益形成可见闭环。
- 12 区职责已按“服务基地的资源 / 风险 / 解锁 / 稳定工程价值”复核，不继续为没有工业职责的区域堆读法。
- 默认检查通过；涉及 Godot runtime 的场景或 UI 接线时，再执行 Godot 检查或记录未执行原因。

## 风险与后续决策

- 最大风险是把“视觉与场景化”误做成新的检查清单；本专题明确要求先交付玩家可见画面。
- 若第一条工业链做完后仍不像工业基地，应继续补基地设备和 UI，而不是转去扩 12 区外勤内容。
- 若发现首版 Demo 的 12 区规模压垮视觉建设，应回到 `Demo Definition V1` 调整首版完成口径。
