# Demo Playable Scene Rebuild V1

更新时间：2026-06-30

## 用途

本专题把首版 Demo 当前主线从“色块 / 线框 / 截图点可读性修补”切到“真实低保真可玩场景重建”。

它不是最终美术包，也不是完整场景量产；它先用 1 到 2 屏可移动、可交互、可识别的基地 + 晶体边缘场景，证明默认画面能像一款 2D / 2.5D 工业科幻 ARPG，而不是调试流程图。

## 玩家价值

- 玩家第一眼能看见一个受损异星化工前哨，而不是区域色块地图。
- 玩家能用角色、地面、设备体积、阴影和相邻物料关系判断自己在哪里、能操作什么。
- 基地加工、晶体采集和外勤准备先成为场景中的动作与反馈，再由 HUD 做确认。

## 与整体规划的关系

- 继续服务 [Demo First Playable Slice Assembly V1](demo-first-playable-slice-assembly-v1.md)。
- 承接 [Visual And UI Direction](../product/visual-and-ui-direction.md) 的“清晰克制的工业科幻现场界面”方向。
- 暂停把 [Demo Base Handoff Assetized Scene V1](demo-base-handoff-assetized-scene-v1.md) 作为当前主线；其经验保留为素材和风险记录，不继续围绕 #2 / #3 追加同类图层修补。

## 触发原因

- 最近多轮实机图仍主要表现为半透明大框、色块、线框、长标签和旧规划层。
- 基地交接专用工作面在错误语境下出现，说明“图层可见 + shape 检查”不能证明玩家视角成立。
- 玩家 Wiki 和专题说明开始承担“如何绕开旧规划框理解画面”的解释职责，偏离了让游戏画面自解释的目标。

## 本轮范围

1. 重建一块默认可玩场景：
   - 前哨核心、基础反应器、基础储存箱和出发整备台必须是场景物件。
   - 地面、服务沟、管线、托盘、料斗、供给位和整备锁扣要有接地关系和阴影。
   - 晶体矿脉边缘和污染边界只作为环境上下文出现，不再以大色块区域承担主读法。

2. 保留真实操作：
   - 玩家仍能移动、靠近、交互、采集、加工和查看反馈。
   - 任务、资源、配方、存档和自动检查复用既有系统。
   - HUD 只做目标、状态和结果确认，不替代场景主体。

3. 降低旧原型层权重：
   - `ColorRect` 区域块、跨屏路线、调试框和截图定位层退为隐藏或低权重开发辅助。
   - 旧视觉层可保留数据来源，但不能主导默认画面。

## 当前不做

- 不新增第 13 区域、新任务、新资源、新配方、新存档字段或完整美术管线。
- 不继续给基地交接 #2 / #3 追加透明度、线框、短线、标签或 shape 清单。
- 不推进污染处理 / 核心稳压段的同类场景化连续性，直到默认基地场景像游戏。
- 不进入试玩准备、完整路径体感复核或集中修 bug。

## 玩家操作路径

```text
新档或截图定位进入基地
-> 看见受损前哨核心和相邻设备场地
-> 移动到核心 / 反应器 / 晶体边缘对象
-> 执行一次采集或加工相关交互
-> 看见设备、托盘、料斗或整备位给出短反馈
```

## 场景与 HUD 口径

- 场景主体：角色、地面、核心、反应器、储存、整备台、晶体边缘、污染远景。
- 场景反馈：状态灯、短物料包、设备发光、托盘变化、局部阴影和接地关系。
- HUD：左上目标、角色状态、关键资源、小地图和一行交互摘要保留；开发面板默认隐藏。
- 小地图：只辅助定位，不把整张 12 区规划图压回主画面。

## 实现口径

- 优先用场景节点、sprite / texture、低保真 tile 或专用 scene layer 承担主画面。
- 程序绘制只用于短反馈、动态高亮和检查辅助；不能继续承担地貌与设备主体。
- 可复用已有 SVG 设备资产，但必须把它们放进完整场地关系，而不是覆盖在旧色块地图上。

## 验收条件

- 默认截图不看文字也能识别：这是基地平台、玩家角色、核心设备、加工设备和外勤边缘。
- 玩家和设备有明确尺度、体积、阴影和接地关系。
- 旧大色块、跨屏路线、半透明规划框和长标签不再是第一眼主读法。
- 玩家至少能完成一次真实移动与交互，并看到场景内短反馈。

## 验证计划

- `./scripts/check-client.sh`
- 涉及 Godot 场景或运行时接入时执行 `./scripts/check-client.sh --with-godot`
- 文档改动执行 `./scripts/check-docs.sh`、`./scripts/check-text-files.sh` 和 `git diff --check`
- 最终必须用实机截图判断，不以 shape 数量或自动检查单独通过。
