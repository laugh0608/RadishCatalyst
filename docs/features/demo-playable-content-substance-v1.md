# Demo Playable Content Substance V1

更新时间：2026-06-19

## 用途

本文定义首版 Demo 可玩内容实质补强第一版。它修正“自动检查通过就等于可进入试玩准备”的错误判断，重新把当前阶段落回玩家可见开发任务。

本专题覆盖 [Demo Definition V1](demo-definition-v1.md) 中尚未被真实体验证明的规格：场景完成度、角色 / 怪物 UI、初步美术识别、工业基建模块、资源 / 生产链、战斗压力和任务节奏。

## 玩家价值

玩家进入首版 Demo 时，应看到的是一个能理解、能操作、能形成差异的前哨段，而不是只靠 HUD 文案和自动检查串起来的路线：

- 场景要像可探索地点，不只是带标签的路径。
- 角色和敌人状态要能在战斗中读懂，不只靠日志解释。
- 基地设备要支撑真实加工、整备和回收，不只是少数设备承担全部循环。
- 任务节奏要包含采集、处理、整备、风险和回基地收益，而不是反复“外出、打怪、回基地”。

## 与整体规划的关系

- 承接 [Demo First Playable Acceptance V1](demo-first-playable-acceptance-v1.md)：阶段验收暂缓，自动检查证据不足以证明可试玩。
- 承接 [Demo Scene Art Foundation V1](demo-scene-art-foundation-v1.md)：核心区已有第一包识别，但还需要继续做实际场地和美术表达。
- 承接 [Demo Combat Progression V1](demo-combat-progression-v1.md)：战斗成长已有第一轮，但角色 / 怪物 UI 和战斗现场读法仍需补强。
- 承接 [Demo Industrial Tech Spine V1](demo-industrial-tech-spine-v1.md)：工艺主干已有读法，但还要核对 5 个核心模块是否真的形成玩家可操作链路。

## 当前已有基础

- 12 区域、核心稳定站终点、主路径检查和存档状态契约已存在。
- 基地加工、污染过滤、出发整备、快捷补给、战斗撤离和结果反馈已有第一包。
- 原型视觉和场景识别已有检查，但检查主要证明对象、标签、路径和状态存在。
- 当前不足在于真实场景、角色 / 怪物 UI、可操作设备体量、美术表达和任务变化仍未达到可试玩候选标准。

## 本轮范围

- 先按真实体验重新审视 `Demo Definition V1`，把“已落地第一包”与“达到首版 Demo 试玩质量”分开记录。
- 继续开发玩家可见内容，不把阶段限制成只修 `P0` / `P1`。
- 第一轮补强优先覆盖：
  - 场景：基地、晶体、污染、遗迹 / 异常和核心稳定站需要有可走空间、视觉锚点、危险边界和互动对象落点。
  - 角色 / 怪物 UI：玩家生命 / 防护 / 补给、敌人生命 / 威胁 / 状态、命中反馈和承压差异要在战斗现场可读。
  - 工业基建：前哨核心、基础反应器、污染过滤器、基础储存箱和出发整备台都要有真实职责，不让两三个设备承担全部循环。
  - 任务节奏：减少单一外出打怪往返，补上采集、处理、建设、整备、污染处理、核心准备之间的可操作差异。
  - 初步美术：用当前可提交资产或原型图形建立地点、资源、敌人、设备和危险的识别，不追求最终资产量产。

## 当前不做

- 不新增第 13 区域，不开第二星球、第二章节或独立支线任务网。
- 不做完整开放世界、完整科技树、复杂化工仿真、完整装备栏、完整背包、死亡系统、结算页、联机入口或发布流程。
- 不做最终美术包、大规模换皮或过场动画。
- 不用纯文案、纯检查或纯规划替代玩家可见实现。

## 玩家操作路径

本阶段继续围绕首版 Demo 主线：

```text
基地恢复 -> 外出采集 / 战斗 -> 回基地加工 -> 整备获得差异 -> 推进污染 / 遗迹 / 核心稳定站 -> 完成 Demo 终点
```

每个补强包必须说明它改善了上面哪一段，玩家能在场景、HUD、设备、敌人或任务节奏中实际看到什么变化。

## 运行时、存档与数据边界

- 优先复用既有区域、资源、设备、敌人和任务状态；若 Demo 必达规格确实缺口，允许补齐规格内的计划内设备职责、UI 状态或场景对象。
- 不新增长期存档字段，除非玩家可见状态无法通过既有结构表达；如必须新增，需同步存档契约专题。
- 新增检查必须验证真实玩家路径，不只验证文案存在。

## HUD / 场景 / 对象反馈

- HUD 要服务当前操作判断，不用长说明掩盖场景和对象不足。
- 场景对象要通过位置、尺寸、颜色、状态和交互反馈表达职责。
- 敌人和角色状态要在战斗现场可读，日志只作为补充。
- 设备面板要能对应真实加工和整备结果，而不是只显示下一步提示。

## 验收条件

- `Demo Definition V1` 的场景、角色 / 怪物 UI、初步美术、工业模块和任务节奏缺口已重新标注，不能再用“第一包已落地”直接等同通过。
- 至少一个玩家可见补强包落地，并覆盖真实场景 / 战斗 UI / 工业设备 / 任务节奏中的具体缺口。
- 自动检查覆盖新增玩家路径，但不再作为唯一阶段判断。
- 仍遵守 12 区域封顶和首版 Demo 范围，不扩到完整游戏系统。

- `sh ./scripts/check-docs.sh`

## 风险与后续决策

- 最大风险是继续用提示、检查和专题名称替代真实可玩内容；本专题明确禁止这种判断。
- 若补强发现首版 Demo 必达规格本身过大，应回到 `Demo Definition V1` 调整规格，而不是假装已经完成。
- 阶段验收只能在玩家可见内容补强后重新启动。
