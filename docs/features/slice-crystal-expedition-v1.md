# Slice Crystal Expedition V1

更新时间：2026-07-16

状态：已收口（2026-07-17 萝卜SAMA确认）。三包全部完成，最终形态为无缝大地图 + 相机跟随；后续演进见 [Slice Minimal Core Loop V1](slice-minimal-core-loop-v1.md)。

口径修订（2026-07-16，萝卜SAMA拍板）：参照 Factorio / The Riftbreaker 的空间体验，"单基地 + 单远征区"正式解读为**同一张无缝大地图上的两个区域**，相机改为跟随玩家；首版实现的"独立场景 + 边缘切换"箱庭结构废弃。

## 背景与定位

章程定稿的首个交付版结构为"单基地 + 单远征小区域"的 20 到 40 分钟可玩切片（无缝同图两区域口径）。前一专题 [Slice Base First Screen Integration V1](slice-base-first-screen-integration-v1.md) 已收口：基地首屏跑在正式入口、四方向可控行走成立。本专题落地另一半世界骨架——晶体远征区，与基地同处一张连续地图，步行无缝往来。此后所有系统层工作（采集、任务、HUD、未来的建造与物流）都有完整的连续世界可以承载。

介质机械口径以 [Pixel Art And Grid Standard](../reference/pixel-art-and-grid-standard.md) 为准。本专题**不生成任何新素材**：晶体地、污染地、三档晶体簇、受损核心等所需资产已全部在 `client/assets/` 库存中（证据轮 S2 / S3 / S5 定稿产物）。

## 玩家价值

- 看到：基地之外的第二个区域——青色晶体簇散布的采集区，污染地块提示环境压力，与证据轮第三屏读法同构。
- 做：从基地一路向东步行进入晶体区，逛一圈再走回来，全程无切换、无读条，相机跟随。
- 理解：这个世界是连续的，基地是它的一角，为"出门采集、回家建设"与未来向外扩张建立空间直觉。

## 范围（串行推进）

### 包 1：晶体区场景

- 新建 `client/scenes/slice/CrystalExpedition.tscn`：晶体地宏块为主底，污染地宏块作局部点缀混铺（同 TileSet 扩两个 atlas 源）。
- 三档晶体簇按小 / 中 / 大散布摆位，靠近污染区一侧密度更高，读法对照证据轮第三屏；晶体簇加网格对齐足印碰撞。
- 相机、边界围墙、y_sort 容器沿用基地首屏同口径。
- 出口：场景可独立打开，画面与证据轮第三屏读法同构。

### 包 2：无缝大地图与相机跟随

- 基地与晶体区合并为一张连续地图（起步 80x24 tile，西基地东晶体，宏块锯齿过渡带），世界根只持有地图与玩家。
- 相机挂玩家、居中跟随，按地图像素边界钳制；仍为 960x540 虚拟分辨率与整数缩放。
- `新游戏` 入口指向世界根（从基地出生点开始）；`载入存档` 旧链路继续不动。
- 出口：正式入口新档可从基地步行到晶体区并走回，无场景切换、相机连续。

### 包 3：同构验证与收口

- 正式入口实机截图：基地屏与晶体区屏分别对比证据轮预览读法（家族一致、比例一致、无旧视觉层混入）。
- 人工路径：新档 → 从基地向东步行跨过地貌过渡带 → 绕晶体簇与污染区一圈 → 返回基地，全程相机跟随、无切换。
- 收口截图与验证记录写入当周周志。

## 成功证据

- 正式入口（`Boot` 起）新档可完成基地 ↔ 晶体区无缝步行往返，跨区无卡顿、相机跟随无跳变。
- 两区实机截图与证据轮二三屏预览同构；晶体簇被碰撞阻挡，边界不可走出。
- `sh ./scripts/check-client.sh` 通过；场景与脚本改动按需 `--with-godot` 单项验证（`--import` 与运行时路径复核）。

## 失败退出

- 按 [Development Decision Gates](../process/development-decision-gates.md) 两次失败停手规则：同一问题同类方案两轮实机复核不过，停手升级萝卜SAMA。
- 无缝地图或相机跟随两轮实现仍有跨区卡顿、跳变或坐标错位，停手复盘承载结构，不追加补丁式修复。

## 不做

- 不做采集交互、资源数值、任务、HUD、存档接入（系统层换皮是下一候选专题）。
- 不做敌人、战斗、污染伤害等环境机制。
- 不生成新素材；不做立绘对话接入。
- 不删除、不修改冻结的旧场景、旧视觉层与旧检查。

## 状态 / 存档 / HUD / 检查

- 本专题不改存档结构、不接 HUD；世界根只持有地图与玩家实例，不引入全局状态服务。
- 旧运行时聚合检查维持现状；只要求 `check-client` 静态通过与新场景无导入错误，不新建检查脚本文件。

## 验收与移交

- 三包各自出口截图记入当周周志；专题收口以"正式入口无缝往返实机路径 + 两区与过渡带截图"判定。
- 收口后下一专题候选：系统层换皮接入（采集 → 回基地 → 修复核心的最小循环）、立绘对话框最小接入；由萝卜SAMA择序。
