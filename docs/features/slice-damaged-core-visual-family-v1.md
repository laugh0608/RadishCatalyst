# Slice Damaged Core Visual Family V1

更新时间：2026-08-15

状态：**P0—P3 已实现并完成自动、正式 `Boot` 与逐图复核；等待萝卜SAMA人工收口。**

## 玩家结果

新游戏首屏的受损核心必须一眼读成“后来可修复为现行 V5 核心的同一台设备”，而不是旧资产临时摆在新世界中。玩家应从破裂壳体、外露结构、衰弱青色能量和局部故障灯理解它需要修复，同时仍能辨认修复后的竖直能量脊柱、开放式核心与分层服务环。

## 触发证据与根因

- `SliceMap.tscn` 仍硬引用 2026-07-30 的 `103×93px` 旧 `outpost_core_damaged.png`；修复态已在 2026-08-11 切为 `144×128px` V5 核心。
- 旧破损态与 V5 在体量、投影、材质、调色板和接口语言上不是同一家族；新档截图出现深青灰旧机体与脏黄高光，和浅色地表、工程白设备明显割裂。
- 新档运行时使用 `Color.WHITE`，因此异常不是缓存或运行时染色，而是旧 PNG 本身。
- `slice_core_logistics_check.gd` 还把 `103×93px` 写成必须保留的合同；自动检查因此保护了错误基线。

## P0 专题开工十问

1. **玩家动作：**不新增动作；玩家继续采晶体并用既有交互修复核心。
2. **世界变化：**新档破损核心与修复态成为同一设备的可信双态，修复瞬间不再像整台机器被替换。
3. **闭环价值：**首个目标主体和修复回报可读，直接强化“采集 → 修复基地”的第一段闭环。
4. **感知时长：**进入新档第一屏立即可见，并在首次修复时再次验证。
5. **系统范围：**只替换一个固定破损态资产及其视觉合同，不建设通用损坏系统。
6. **现有范围：**沿用现行地图、核心位置、交互、修复、物流、电力、HUD 与 schema 8。
7. **成功证据：**原生候选对比、正式 `Boot` 新档 / 修复 / 重载截图、去色复核与运行时断言。
8. **失败处理：**若只是给 V5 整体变暗、整体染黄或随意削碎剪影，判当前候选失败；两次同类失败后换损坏介质。
9. **旧系统关系：**不复活旧 Demo 核心、旧写实资产或程序绘制破损覆盖。
10. **推进价值：**修复当前第一屏最显眼的资产家族断裂，而不是增加新内容。

## 冻结资产合同

- 编辑目标仅为已批准的 V5 修复核心；正式破损态目标画布为 `144×128px`、透明背景、二值 Alpha，并保持现行核心世界锚点、足印与正面朝向。
- 第一剪影继续由竖直能量脊柱、开放式核心、分层服务环与负空间构成；允许局部壳体断裂、服务环错位、面板脱落、线缆外露和小范围焦痕，不允许换成矮圆桶、封闭箱体、坍塌废墟或另一台机器。
- 大面积顶壳 / 侧壳继续使用工程白、浅暖灰与中灰金属；近黑只用于骨架、裂口、凹槽和接地阴影。禁止整体压暗、统一黄绿染色或恢复旧深青灰机体。
- 青色能量必须比修复态弱但仍可识别；警示红 / 琥珀只作局部故障冗余，不得主导整机。
- 左上光、像素密度、边缘块级、短接口与修复态一致；不烘焙地板、阴影矩形、文字、人物、传送带或背景。

## 实现与状态边界

- `SliceMap` 新档继续装配破损态；`mark_core_repaired()` 与重载只在同一视觉壳中切到既有修复态。
- 不修改核心位置 `(640, 320)`、`2×2` 足印、碰撞、修复费用、交互半径、排序壳、物流端点、电力规则或接驳片。
- schema 保持 `8`；`core_repaired` 仍是唯一持久真相源，不新增破损程度、动画阶段、特效或 UI 字段。
- 撤销 `103×93px` 错误合同，改为双态画布、锚点、资源路径、Alpha 与家族规则检查。

## 实施包

### P1：同族候选与人工闸门

- 以 V5 修复核心为唯一编辑目标，首轮最多生成三张单体候选；每张立即落盘到独立 intake 并更新 manifest。
- 在透明单体、`960×540` 新档首屏和修复态并排对比中检查身份、体量、颜色和损坏读法。
- 出口：萝卜SAMA选定一个方向；未经人工确认不覆盖正式 PNG。

2026-08-15 首轮 `3 / 3` 已完成并按稳定性规则停手。V1 因主体换机、外围增宽和棋盘格假透明淘汰；V2 恢复工程白 / 青能量色域，局部破裂可读；V3 进一步明确左侧线路外露、能量柱分段与局部故障灯，当前推荐 V3。V2 / V3 都扩大了短接口与下基座，只能作为损坏语言参考；后续必须以原 V5 为底做 `144×128px` 原生重投影，禁止整图缩放接入。

萝卜SAMA随后确认 V3 损坏语言。确定性脚本以现行 V5 修复态为底，只改右上服务架缺口、左前维护腔、外露红 / 琥珀线路和分段衰弱青能量；正式候选保持 `144×128px` 二值 Alpha，基座与短接口逐像素不变。客户端已替换旧破损 PNG，并把新档精灵偏移对齐修复态 `-32px`，不修改修复态哈希或任何玩法状态。

## 验收

- 不看文字也能确认两态是同一台核心，且破损态清楚表达“可修复”而不是“已报废”。
- 新档破损态以工程白 / 暖灰壳体为主，衰弱青能量和局部故障色只承担状态语义。
- 修复前后主体基座、中心线和占地稳定，无尺寸突变、脚底漂移或角色排序反转。
- 自动检查、正式入口、原生截图和萝卜SAMA人工判断共同通过。
