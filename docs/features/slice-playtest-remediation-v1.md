# 试玩反馈整改 V1

更新时间：2026-08-25

状态：包 1 已完成，包 2 待确认

关联阶段：[第一可玩切片全链串通](slice-first-playable-journey-v1.md)

## 目标

把 2026-08-16 首轮连续试玩暴露的问题，从“功能能跑”整改为“玩家能理解、能顺手完成、愿意继续玩”。本专题是当前阶段的整改总览，负责统一问题口径、优先级、实施顺序和跨包验收；每个实施包开工前仍须按开发决策闸门确认职责与介质。

玩家最终应获得四个明确结果：

- 样本交付后知道本次 Demo 已完成，也知道可以继续自由建设，而不是面对一条像卡住的任务。
- 建造、传送带、设备端口、足印和碰撞遵循同一套空间规则，不再发生“看得见却接不上、看似空地却过不去”。
- 制造、背包、仓库、设备和装备形成连续鼠标路径，玩家不需要在多个文字按钮之间猜操作。
- 核心、设备、HUD 和声音能持续反馈状态，画面不再像一组只会换色的静态原型。

## 结论与范围

现有 `delivered / 120` 全链、schema 9、世界设备、二值供电和物流存档仍是功能基线，但既有“人工收口”只能证明当时验收范围通过，不能覆盖本轮真实试玩的新证据。当前阶段不进入下一能力专题，先完成本专题并重新做 S0 全链实机验收。

本轮允许调整既有任务收尾、数值、碰撞、放置、UI 信息架构、设备反馈、局部素材和存档节流。新地图、新敌人、技能树、多人联机、完整有限电力和大规模内容扩充继续冻结。

## 《终末地》UI 参考提炼

本轮快速审阅了任务、工业简报、制造 / 放置、角色装备、背包仓库、设备容器、生产链路和俯瞰建造等参考图。适合本项目的不是外观照抄，而是以下信息规则：

1. 制造与放置是两个明确页签 / 状态。制造结果先进入持有物，放置由玩家再次确认。
2. 背包、仓库与设备容器并排出现，物品格就是操作对象；数量、容量、来源和流向就地可见。
3. 默认列表只呈现有意义的条目；“全部”是平铺结果，分类、排序和筛选是辅助工具。
4. 标题、关键数字、状态和主操作拥有明显层级；浅内容面与深功能面可以并存，但正文始终保持高对比。
5. 工业建造保留世界背景和设备实景，端口、流向、状态图标与类别栏共同解释系统，不依赖长段文字。
6. 生产详情把当前产率、消耗、库存和理论值放在同一视野，玩家能直接判断瓶颈。

本项目不照搬移动端大按钮、角色编队、复杂成长页、完整生产统计和多层主菜单。当前 Demo 只移植“状态分离、容器并排、直接操纵、强层级、结果可诊断”五项原则。

## 整改实施顺序

### 包 0 开工闸门

1. **玩家结果：**包 0 不直接宣称体验问题已经修好；它使后续修复只能落在一套空间与保存合同上。包 1 完成后，玩家应能走上传送带但不能穿过设备基座，设备端口与外接格可自然连接，连续射击不会逐发卡顿写盘。
2. **实现介质：**空间合同沿用 `SliceBuildingDefinition`、`SliceLogisticsPortDefinition`、场景节点层级和权威放置校验；保存合同由新的切片保存调度器承接脏标记、防抖、强制落盘和旧档发布上下文，`SliceSaveService` 继续只负责校验、序列化与文件发布。
3. **成功证据：**专项检查证明保存请求合并、约 `2s` 防抖、关键提交点强制落盘、失败保留待保存状态和旧档上下文只在成功后清除；空间专项锁定足印、端口和层级目标；`SliceWorld` 低于硬上限且不再拥有保存计时器。正式 `Boot` 在 16:9 与窗口化非 16:9 下留下整改前基线截图。
4. **失败判据：**调度器需要复制世界状态、存档 schema 或文件 IO；保存失败被清脏或伪造成成功；关键退出路径只排队不落盘；空间规则出现第二份坐标或足印真相源；为了拆行数制造无领域意义的包装层。
5. **文档落点：**稳定合同留在本专题；包 0 的实现、验证与基线证据进入 W35 周志；只有包状态实际变化时才更新 Daily Start 与 Current Plan。

### 空间合同

| 层级 | 权威介质 | 通行 / 排序合同 |
| --- | --- | --- |
| 地表 | `GroundLayer`、`IndustrialFloorLayer`、传送带基体 | 固定在角色和设备主体下方；地板与传送带均可通行，不进入设备主体 Y 排序 |
| 设备基座 | 建筑定义的旋转后 `footprint` | 占用、放置阻挡和角色碰撞共用同一组格；只有实体设备基座阻挡 |
| 角色与设备上部 | `World` 的 Y 排序节点 | 以脚点 / 基座底边为排序锚；上部轮廓可向后上方超出足印，但不得横向欺骗邻格占用 |
| 端口与过渡格 | `SliceLogisticsPortDefinition` | 端口格必须在基座足印内；外向量指向足印外唯一连接格；需要跨地表时由显式 `connection_distance` 描述，不用视觉贴片改逻辑 |
| 动态反馈 | 放置、电力检查、设备选中与状态特效 | 只解释权威结果，不参与占用、碰撞、供电或物流判定 |

- `SliceBuildingDefinition.occupied_cells()` 是基座占用唯一来源；碰撞形状、交互范围和放置预览都从旋转后足印派生。
- 常规传送带从端口连接格之后才进入工业地板检查；设备自带外接过渡格不得被另一设备基座占用。
- 包 0 只冻结目标合同并记录当前偏差；R03、R04、R06、R08、R15、R16 的玩家可见修复仍由包 1 一组实施和验收。

### 保存事件合同

| 事件 | 策略 | 原因 |
| --- | --- | --- |
| 射击耗弹、敌我受伤、生产 / 物流进度、探索揭雾、普通容器转移 | 脏标记 + 约 `2s` 合并保存 | 高频变化不得逐次序列化世界和轮转备份；持续变化仍需周期性检查点 |
| 制造、放置 / 调整、拆除、核心修复 / 充能、样本拾取 / 交付 | 立即保存 | 物品所有权、世界拓扑或主流程里程碑发生不可忽略变化 |
| 暂停返回、退出、窗口关闭、旧 schema 成功重建后的首次发布 | 立即保存并检查结果 | 离开当前运行时前必须确认财产与迁移已发布；失败时不得继续退出 |

- 调度器只接收状态构造回调，在真正写盘时才取一次权威状态；它不复制 `SliceWorld` 状态字段，不修改 schema。
- 普通失败保留脏状态并在后续窗口重试；强制保存失败直接返回 `false`，现有暂停 / 退出界面继续阻止离开。
- schema 9、schema 2—8 确定性迁移、主档 / 临时文件 / 三份备份和世界目录元数据合同全部保持不变。

### 包 0：合同冻结与职责拆分

- 冻结地表层、设备基座层、角色层、设备上部层和动态特效层的排序合同。
- 冻结设备足印、阻挡区、端口、过渡格和自动补板的统一空间合同。
- 从 `SliceWorld` 提取保存调度与本轮所需的放置 / 面板协调职责；同步存档只保留在明确提交点。
- 建立本专题专项检查骨架和两个窗口比例的截图基线，再改玩家行为。

### 包 1：阻断修复与 Demo 收尾

#### 开工五问

### 包 2：制造、资源与装备闭环

#### 待确认开工五问

1. **玩家结果：**制造建筑后仍停留在制造页，产物进入随身套件；玩家只在点击“进入放置”或从已有套件发起放置后回到世界。配方详情同时显示直接材料、从机械零件递归折算的基础晶体、当前可制造数、完整依赖可支撑数，以及该设备足印最多需要的自动补板数；实际选定格后的精确补板数继续由放置预览给出。采集器缓冲提升到 `50`。角色页固定显示一个武器槽、内建切割器和随身持有的步枪，点击或拖入即可装备；“卸下步枪”实际回到不可移除的切割器，数字键 `1 / 2` 与面板走同一装备合同，读档恢复最后选择。

3. **成功证据：**专项检查锁定制造不跳页、显式放置、递归依赖 / 缺口 / 数量、各设备补板上限、采集器 `0—50` 运行与旧档恢复、装备点击 / 拖入 / 数字键同源、非法步枪选择拒绝、schema 10 精确根字段及 schema 2—9 迁移。正式 `Boot` 先在当前 `地板 1→4、中继 6/4` 上跑同一隔离新档 A 基线，再在候选 `1→8、8/6` 上跑 B；两轮都从 25 个有限晶体开始，记录首个通电采集器所需中继、地板制造次数、剩余晶体和返工次数，并继续以同一布局跑完首条 `采集器 → 反应器 → 储物箱` 产线。B 只有在首个采集器由三座中继降到两座、有限晶体由零余量变为至少 `3`、完整首链 `22` 格补板只需三批且仍保留至少一座有意义中继时才冻结。装备证据需制造步枪、角色页装备、完全重启恢复步枪、卸下后再次重启恢复切割器，并逐图确认槽位、持有条件与世界武器外观一致。

#### 开工前审计结论

- 当前 25 个有限晶体自举成本恰为 `修核心 9 + 三座中继 9 + 采集器 6 + 一批地板 1 = 25`，没有误操作余量；历史正式全链使用 `31` 次放置和 `22` 格自动补板。候选 `1→8、8/6` 的目的不是普遍降难度，而是把首个采集器收为两座仍有布局意义的中继并释放 `3` 个晶体缓冲，把 22 格补板从六批降为三批。
- 配方“完整依赖”采用双口径：`当前可制造` 只看已经持有的直接材料，`完整依赖可支撑` 允许把现有晶体按 `3→1` 折算为所缺机械零件；两者都只是诊断，不自动制造中间物。
- 自动补板在配方阶段只能报告足印上限，例如反应器 `9`、储物箱 `4`、中继 / 传送带 `1`、晶体地采集器 `0`；选定世界格后的实际缺板数继续由现有权威放置事务计算。

## 状态与存档边界

- Demo 完成态继续由既有 `field_encounter.state == delivered` 派生，不新增重复完成字段。
