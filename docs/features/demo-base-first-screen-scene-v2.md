# Demo Base First Screen Scene V2

更新时间：2026-06-30

## 用途

本专题接替 [Demo Playable Scene Rebuild V1](demo-playable-scene-rebuild-v1.md)，只重做基地第一屏的默认可玩场景介质。

目标不是继续调透明度、边框、线宽或截图点，而是换掉“线稿设备叠在旧规划层上”的表现方式，让第一眼读成一块实心低保真基地场地。

## 闸门来源

- `DemoPlayableSceneRebuildLayer` 已压下旧规划板、远端路线和大色块，判定为部分通过。
- 连续实机截图仍读成 SVG 线稿设备、半透明叠层和 HUD 原型，不足以作为可试玩画面目标。
- 后续只允许为崩溃、完全遮挡、主线卡死或严重错接回修旧层；观感问题改用新介质处理。

## 玩家价值

- 玩家进入新档时先看到基地房间 / 平台，而不是规划板或流程图。
- 前哨核心、反应器、储存箱和整备台有实心体积、阴影、材质块和用途差异。
- 玩家不依赖 HUD，也能判断自己站在哪里、附近有什么、右侧晶体边缘代表什么。

## 本轮范围

1. 新建独立首屏场景承载层或子场景：
   - 地面、边界、设备和遮挡关系用实心低保真形体承担。
   - 描边只能辅助轮廓，不能成为设备和地貌主体。
   - 旧首屏层只作为数据来源或开发辅助。

2. 保留当前玩法：
   - 不改任务、资源、配方、存档和主路径状态。
   - 玩家仍能移动，并和核心、反应器、储存或整备台执行一次现有交互。
   - HUD 只确认目标、状态和结果。

3. 控制环境范围：
   - 晶体边缘只作为右侧环境上下文，不再承担当前包的主读法。
   - 不扩展污染处理、核心稳定站、敌人或外勤新区域。

## 当前不做

- 不新增区域、任务、资源、配方、敌人、存档字段或完整美术管线。
- 不继续围绕 `DemoPlayableSceneRebuildLayer` 做同类截图微调。
- 不把本包扩成全地图重绘、最终 tile set 或试玩验收阶段。

## 玩家操作路径

```text
新档进入基地
-> 看到一块实心低保真基地首屏
-> 玩家站在核心附近
-> 靠近核心 / 反应器 / 储存 / 整备台
-> 执行一次当前已有交互
-> 看到设备或短反馈确认操作
```

## 场景口径

- 画面主体：实心地面、墙 / 平台边界、前哨核心、反应器、储存、整备台、玩家。
- 反馈主体：设备局部亮点、短物料线、托盘 / 端口变化、接地阴影。
- HUD：保留目标、状态、小地图和一行交互摘要；不参与解释场景是什么。
- 旧层：默认隐藏或降权为开发辅助，不能成为第一眼主读法。

## 2026-06-30 客户端实现包

- 新增 `DemoBaseFirstScreenSceneLayer`，作为基地第一屏独立承载层接入 `VerticalSliceMap`。
- 首屏主体改由实体 `Polygon2D` 子节点承担：地面块、平台边界、玩家服务位、核心、反应器、储存、整备台、阴影、材质块、端口和右侧晶体边缘。
- 新层在第一屏范围内降权 `DemoPlayableSceneRebuildLayer`、旧启动表现层、旧区域色块和路线层；离开第一屏后恢复旧层上下文。
- 交互继续使用现有 `OutpostCore`、`BasicReactor`、`BasicStorageBuildSite` 和 `FieldOutfittingStationBuildSite`，不新增任务、资源、配方、敌人或存档字段。
- 首张实机截图反馈后，平台边界从黑色遮挡条改为低权重边缘，设备阴影和端口缩小降饱和，右侧晶体退为次级环境。
- 第二张实机审阅后，墙脚拆成短段，核心 / 反应器 / 储存 / 整备台补职责化剪影件，核心附近目标标签和焦点降权。
- 第三张实机审阅确认继续用程序色块或 SVG 拆分素材仍缺少贴图质感；V2 保留为首屏承载层、旧层降权和现有交互接线基础，下一步切到 [Demo Base First Screen Raster Art Pack V1](demo-base-first-screen-raster-art-pack-v1.md) 生成真正的低保真 raster 贴图 / sprite。

## 结论

- V2 解决了“旧规划层抢主读法”和“首屏缺少独立承载层”的工程问题。
- V2 没有解决“缺少美术贴图和设备 sprite”的画面问题。
- 后续不再通过继续追加 `Polygon2D`、SVG 色块、线宽、透明度或整图底图来修首屏观感。

## 验收条件

- 默认截图中，场景主体 70% 以上不是线框描边或透明叠层。
- 地面不是卡片底座、流程图底板或半透明大区域。
- 核心、反应器、储存和整备台有明确体积与用途差异。
- 玩家能完成一次真实移动和一次已有交互。

## 复核规则

- 每个实现包只做一次实机截图复核。
- 若截图失败，先判断介质是否失败；介质失败时换实现方式，不继续同类微调。
- 只允许为崩溃、完全遮挡、主线卡死或严重错接做一次小修。

## 验证计划

- `./scripts/check-client.sh`
- 涉及 Godot 场景运行时接入时执行 `./scripts/check-client.sh --with-godot`
- 文档改动执行 `./scripts/check-docs.sh`、`./scripts/check-text-files.sh` 和 `git diff --check`
- 最终结论以一次实机截图和人工观感判断为主，自动检查只证明接线未断。
