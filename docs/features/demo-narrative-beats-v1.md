# Demo Narrative Beats V1

更新时间：2026-06-24

## 用途

本文定义首版可玩纵切的叙事节拍。目标是让任务、场景和 UI 共同讲清楚“前哨受损、基地恢复、污染异常、核心稳定”的 Demo 故事，而不是让玩家只看到任务表。

## 玩家价值

玩家跑完 Demo 后，应能复述：

- 我是前哨工程战斗员。
- 前哨因异常污染和稳定工程失效受损。
- 晶体资源能恢复基础工艺。
- 污染和敌人说明星球正在失衡。
- 核心稳定站暂时压住了异常，但没有解释全部真相。

## 与整体规划的关系

- 服务 [Demo First Playable Slice Assembly V1](demo-first-playable-slice-assembly-v1.md)。
- 承接 [Worldbuilding Premise](../product/worldbuilding-premise.md) 与 [Narrative And Quest Framework](../design/narrative-and-quest-framework.md)。
- 遵守“工业现场任务记录 + 异星异常调查”的叙事定位。

## 当前已有基础

- 主线任务从前哨恢复推进到核心稳定站完成反馈。
- 世界观已明确玩家身份、异星资源、污染、生态、遗迹和化工基地关系。
- 当前任务链有大量异常、相位、稳定和核心站文本，但缺少压缩后的玩家可感知节拍。
- 2026-06-24 第一包已落地：HUD 基地摘要新增 `现场记录` 短线，把前哨事故、晶体输入、基地恢复、污染信号、核心稳定和结尾钩子贴到压短后的主路径；关键对象描述、任务完成反馈和主路径检查已同步。

## 本轮范围

1. 开场事故：
   - 前哨核心低功率运行。
   - 反应器或储运线停机。
   - HUD 给出短工程提示，不展开长背景。

2. 第一口资源：
   - 晶体矿脉被标记为恢复基础工艺的输入。
   - 手采和带回基地让玩家理解资源不能直接使用。

3. 基地恢复：
   - 基础反应器加工出第一批可用产物。
   - 设备状态从停机变为运行。

4. 污染信号：
   - 污染边界显示异常沉积和受扰生态。
   - 药剂 / 模块 / 过滤器说明污染既是危险也是处理对象。

5. 准备有价值：
   - 短战斗或污染承压让玩家看到整备收益。
   - 敌人和污染不是随机路障，而是前哨事故的外部症状。

6. 核心稳定站：
   - 核心站表现为旧稳定工程节点。
   - 写入、复测和回流说明基地正在重新接管稳定过程。

7. Demo 结尾钩子：
   - 前哨恢复一个稳定窗口。
   - 留下“星球异常源头尚未解释”的下一阶段目标。

## 当前不做

- 不写长篇对白、复杂阵营、多分支剧情或完整章节剧本。
- 不新增大量角色。
- 不用长日志解释本该由场景、设备和任务反馈表达的内容。
- 不继续扩后段相位术语密度。

## 玩家操作路径

叙事必须贴合玩家操作：

```text
看见前哨事故
-> 找到恢复输入
-> 带回基地加工
-> 看到基地状态改善
-> 进入污染异常
-> 用基地产物通过压力
-> 写入核心稳定数据
-> 获得结尾悬念
```

## 运行时、存档与数据边界

- 优先更新现有任务展示、HUD 短反馈、对象描述和结尾反馈。
- 不迁移任务 ID；如需压缩展示，保持底层状态兼容。
- 新增叙事标记只用于 HUD、日志或场景反馈，不扩成新系统。

## HUD / 场景 / 对象反馈

- HUD 目标使用短工程语气。
- 场景对象承载叙事证据：损坏设备、泄漏、沉积、旧稳定节点。
- 完成反馈要说明“基地状态变化”和“下一步悬念”，不要只列奖励。

## 验收条件

- 玩家不读长文档也能理解前哨为什么要恢复、为什么要外出、为什么要处理污染。
- 任务目标不只是物品清单，而能对应场景证据。
- Demo 结束时有明确完成感和后续悬念。
- 叙事没有压过操作，仍保持短、明确、工程语气。

## 验证计划

- `sh ./scripts/check-client.sh`
- `./scripts/check-docs.sh`
- `./scripts/check-text-files.sh`
- `git diff --check`
- 涉及运行时任务展示时，再执行 `sh ./scripts/check-client.sh --with-godot`。

## 风险与后续决策

- 若叙事仍像术语清单，应减少相位 / 稳窗后段文本，优先用前哨事故、污染和核心站现场证据表达。
- 若任务目标过长，应拆成短目标和完成反馈，而不是增加说明段落。
