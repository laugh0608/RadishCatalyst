# Demo Functional Scene Gameplay V1

更新时间：2026-06-16

## 用途

本文定义首版 Demo 功能场景玩法第一包。它承接已落地的功能 / 过渡路线支撑、非核心区域场景识别和运行时承载面拆分，把非核心区域从“能读懂区域职责”推进到“能通过既有对象处理形成现场阶段结果”。

本专题服务 [Demo Definition V1](demo-definition-v1.md) 中「功能 / 过渡场景」「UI / HUD」「存档 / 状态」和「自动检查」规格。它不是第 13 区域、不是新任务链，也不是试玩准备或集中修 bug。

## 玩家价值

玩家在封锁遗迹、裂相脊、回声台地、盐壳、碎晶、风蚀、锁相和锚定桥处理对象时，应能读出：

- 这个对象属于哪个现场玩法阶段。
- 处理前后状态是否变化。
- 处理结果为什么要回基地解析、整备或接入下一段路线。
- HUD 能从当前区域状态读出现场玩法进度，而不是只显示路线说明。

## 与整体规划的关系

- 继续围绕“基地服务冒险，冒险反哺基地”：外勤对象处理必须指向基地解析、整备或后续路线。
- 承接 `Demo Functional Transition Route Support V1` 的路线职责和 `Demo Non-Core Scene Identity V1` 的场景身份，但不继续加厚同类文案。
- 复用 `GatherSystem`、`WorldState.map_objects`、既有对象 ID、既有敌人和既有资源，不新增内容型清单。

## 当前已有基础

- 非核心 8 区域已经有路线支撑和场景身份 formatter。
- `GatherSystem` 已能在采集、采样、清理和检查后写 `is_gathered`、`is_sampled`、`is_cleared`。
- `HudStatusPresenter` 和 `InteractionPromptFormatter` 已经支持多个窄职责 formatter 接入。
- `vertical_slice_map.gd` 仍接近硬上限，本包不触碰地图大文件。

## 本轮范围

- 新增 `FunctionalSceneGameplayFormatter`，覆盖 8 个非核心区域和代表性功能对象的现场玩法阶段、处理状态、完成结果和回基地理由。
- HUD 基地摘要在当前区域已有代表性对象状态时读出现场玩法、对象进度和下一步处理目标；没有对象状态时保留已完成的路线支撑读法。
- 交互提示在对象处理前读出现场玩法阶段与状态。
- `GatherSystem` 在采集、采样、清障和现场读数完成后追加现场阶段回执。
- 新增专项检查，覆盖 formatter、HUD、交互提示、真实交互结果和对象状态写入。

## 当前不做

- 不新增资源、配方、区域、任务链、完整背包、完整装备栏或自动化物流。
- 不新增第 13 区域，不平均扩厚 8 个非核心区，不新增独立支线系统。
- 不继续加厚路线支撑、场景身份、资源链状态、存档契约、主路径连续性或运行时承载面拆分同类内容。
- 不改 `vertical_slice_map.gd`；若后续必须触碰地图区域 / gate 逻辑，先拆 helper。

## 玩家操作路径

1. 玩家进入非核心区域，HUD 先保留路线支撑读法；代表性对象进入状态记录后，摘要读出当前现场玩法和对象进度。
2. 玩家靠近功能对象，提示显示场景身份、路线支撑和现场玩法阶段。
3. 玩家完成采集、采样、清障或现场读数，对象状态写入 `WorldState.map_objects`。
4. 交互结果提示现场阶段已完成，并说明回基地解析、整备或接入下一段路线的理由。

## 运行时、存档与数据边界

- 第一包只读写既有 `is_gathered`、`is_sampled`、`is_cleared` 和少量既有对象状态字段。
- 不新增存档 schema、数据 ID、资源、配方或任务字段。
- 现场玩法进度由当前区域和既有对象状态推导；保存读取继续由既有存档契约覆盖。

## HUD / 场景 / 对象反馈

- HUD：当前区域有代表性对象状态时显示“现场玩法”和对象进度。
- 对象提示：处理前显示现场玩法阶段、待处理 / 已处理状态和回基地理由。
- 交互结果：处理后显示现场阶段已完成和后续基地处理价值。
- 场景：不新增视觉层；继续复用非核心场景识别第一包的标识。

## 验收条件

- 8 个非核心区域都有现场玩法阶段定义。
- 至少覆盖一个现场读数和一个清障对象的真实运行时交互结果。
- HUD、交互提示和交互结果都能读出现场玩法状态。
- 自动检查接入默认 `check-client` 和 Godot runtime 检查。

## 风险与后续决策

- 风险：本专题容易变成提示堆叠；后续必须优先落真实对象状态、场景交互或基地处理结果。
- 风险：`interaction_prompt_formatter.gd` 已接近硬上限；后续继续扩交互提示时应拆专用 presenter。
- 第一包完成后应重新做阶段退出判断，优先选择剩余真实玩家路径或场景玩法缺口。
