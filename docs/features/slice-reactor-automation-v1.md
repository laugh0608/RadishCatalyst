## 专题开工十问

1. **玩家新增动作**：旋转并连接反应器的固定入料 / 出料端口，通过储物箱装料、供电和传送带布局让设备自动开工；靠近反应器可查看状态并安全回收机内物料。
2. **世界变化**：晶体不再只在箱—带—箱之间搬运，而会被一台真实通电机器消耗并转成可见催化剂货物。
3. **服务基地—冒险闭环**：远征带回晶体，基地自动线把它变成后续核心能力和成长系统可消费的催化剂；本专题只证明产出，不提前设计催化剂消费树。
4. **感知时长**：从装料到首件催化剂出箱应在 10–20 秒内发生，完整五段产线可在 5–10 分钟内搭出并看懂。
5. **系统范围**：复用 L3 建筑实例 / 供电网、L4 固定步长物流和 `Inventory`；新增窄职责 `SliceReactor`、双端口定义和 schema 6，不复活冻结的旧 `BuildSystem` 或旧 Demo 反应器。
6. **地图与素材**：现有 3×3 四向反应器主体和端口帧可复用；L5-A `cargo_catalyst.png` 已通过素材硬闸门。加工状态只允许固定像素帧 / overlay 与小型状态灯，不程序绘制机器主体。
7. **成功证据**：反应器状态 / 端口 / 守恒 / 步长 / schema 迁移自动断言，真实 `Boot` 玩家输入链，隔离存档重启，完整产线截图 / 联系表与萝卜SAMA人工复核。
8. **失败路线**：催化剂在 32px 带面不可辨则换素材候选；双端口导致货物穿机、端口反接或两次实机仍读不懂时停手复盘，不加箭头 / 文案 / 程序线框掩盖。
9. **旧系统边界**：旧全局 `catalyst_count`、`reactor_active`、`ReactorProcessSite` 和 `_tick_reactor` 只作迁移参照，不恢复“按 E 激活 + 全局扣数”的记账玩法。
10. **切片推进价值**：完成后首次形成“冒险资源 → 基地电力 / 物流 / 加工 → 新工业产物”的完整空间闭环，直接满足配方加工 arc 出口。

## 开工前五问

1. **玩家结果**：无需手动启动，通电、有 2 晶体且出料位可接收时，反应器自动运行；玩家能从主体状态、端口货物和面板读出原因。
2. **实现介质**：`SliceReactor` 场景 + 定义式双端口 + `Inventory` 双缓冲 + 固定步长生产状态 + 催化剂 sprite + 固定加工 overlay + HUD / 建筑面板。
3. **成功证据**：断电暂停、恢复续跑、缺料不启动、出料回压不吞料、四向端口、物流守恒、不同步长一致、schema 5→6 迁移与正式 Boot 重启全部通过。
4. **失败判据**：运行依赖交互激活或全局计数；晶体 / 催化剂瞬移穿过机器；旋转后入 / 出口互换错误；满输出仍消费；重启重置在制批次；加工状态只能靠长文案理解。
5. **文档落点**：本专题保存规则与包边界；阶段状态进 `current` / `daily-start` / `features README`；素材来源进独立 manifest；实现和验证进本周周志。

## 固定配方与状态机

- 唯一配方：`2 crystal → 1 catalyst`，加工时间 `10.0s`；沿用现有常量口径，不在 L5 引入配方选择、多产物、副产物或品质。
- 每台反应器有独立输入缓冲 `2` 格、输出缓冲 `1` 格、`processing` 布尔和 `[0, 10.0)` 的 `production_progress`。
- 自动开工条件必须同时满足：设备通电、未加工、输入缓冲至少 2 晶体、输出缓冲为空。开工时一次性消费 2 晶体并设置 `processing = true`。
- 加工中断电只暂停进度；恢复供电后从原进度继续。输入缓冲可在当前批次加工时接收下一批晶体。
- 完成时向空输出缓冲写入 1 催化剂并清空在制状态；输出未被带走前不得启动下一批。任何路径都不允许删除、复制或溢出货物。
- 结构变化后端口连接同帧派生；电力可达、物流邻接和世界坐标不进存档。

## 端口与物流

- 反应器现有四帧已把琥珀出料口锁定为上 / 右 / 下 / 左，暗青入料口固定在严格对侧；`building_rotation` 仍只选择固定 sprite。
- 基准朝上：出料端口为 3×3 足印上边中格、连接格在其上方；入料端口为下边中格、连接格在其下方。旋转按定义变换两个端口，不运行时旋转贴图。
- `SliceBuildingDefinition` 增加有名称的机器 `input` / `output` 端口字段；储物箱保留现有单个双向舱口，传送带仍只有输出方向。
- 带到入料连接格时，只接受 `crystal` 且输入缓冲有空间；其他物品和满缓冲保持原带所有权并回压。
- 出料连接格只有朝外的空传送带可从输出缓冲提取 `catalyst`；没有带、方向错误或带上已有货物时保持输出缓冲不变。
- L4 运输白名单扩为 `crystal` / `catalyst`；两者使用各自固定 sprite。不得用晶体改色、文字标签或同一占位图冒充催化剂。

## 操作面与视觉状态

- 反应器提示 / 面板至少区分：断电、缺晶体、就绪、加工中、待出料、出料堵塞；显示输入 `x/2`、输出 `x/1` 和加工秒数。
- 不提供“按 E 激活”。交互只查看状态、调整 / 拆除，以及在背包容量允许时原子回收输入、输出和在制批次物料，用于安全纠错。
- 有缓冲物品或在制批次时禁止直接调整 / 拆除；回收必须守恒，容量不足则整次失败，不把物品掉到地上。
- 反应器主体、足印、锚点、GroundShadow、y-sort 和四向端口保持 L3 审定结果。加工反馈优先从同一主体离线派生固定 overlay / 两帧脉冲；状态灯可程序换色，但不能承担机器主体或货物流向主读法。
- 催化剂货物在四向直段、转角、合流和反应器琥珀出口处都要可辨，不能与青色输入 collar、琥珀驱动辊或晶体货物混淆。

## 存档与迁移

- `SliceSaveService` 升至 schema 6；反应器建筑白名单状态为：

```text
input_inventory {capacity: 2, contents: {crystal?: int}}
output_inventory {capacity: 1, contents: {catalyst?: int}}
processing: bool
production_progress: float
```

- `processing = false` 时进度必须为 `0`；`processing = true` 时表示 2 晶体已从输入缓冲扣除，重启不得再次扣料或清空批次。
- schema 5 的已放置反应器迁移为空缓冲、空闲、零进度；既有建筑 ID、旋转、库存、传送带货物 / 游标完全保留。
- 旧顶层 `catalyst_count > 0` 迁移到中央仓库的 `catalyst`，使用受信迁移路径保留全部数量；旧 `reactor_active` 不映射为设备状态。schema 6 停止把二者作为运行时真相源。
- 候选级校验覆盖缓冲容量、物品白名单、加工 / 进度一致性和非法字段；坏主档仍整体失败后回退备份。

## 自动检查

- 四向入 / 出端口严格对置，端口连接格、固定 sprite 与旋转顺序一致。
- 无电、缺料、输出占用不启动；掉电暂停、恢复续跑；完成只生成 1 催化剂。
- 入料 / 出料方向错误、带满、输出满形成回压；多件全链守恒，催化剂不能进入反应器输入。
- `0.1` / `0.25` 步长和建筑数组逆序得到相同库存、进度与产物。
- 调整 / 拆除 / 回收容量门控守恒；结构变化后端口同帧刷新。
- schema 6 精确存读空闲、加工中、待出料三态；schema 2–5 兼容，旧顶层催化剂无损迁移。
