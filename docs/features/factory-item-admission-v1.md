# Factory Item Admission V1

更新时间：2026-10-12

## 状态与决策用途

本篇为[附件路线](../planning/factory-conveyor-accessories-roadmap.md) B 的设计提案。萝卜SAMA同意先补 A 建造诊断并准备 B；本轮只完成可评审设计，尚未确认下述数量、普通供给及 schema 5 合同，也没有新增运行字段、设备或迁移。A 继续沿[分流 / 汇合](factory-conveyor-routing-v1.md)与[保存 V4](../architecture/factory-routing-save-v4.md)执行。

建议 B 采用“单物品白名单 + 不限量 / 本轮总配额”，配额按成功从准入口送出计数，重新启用与读档均不重置。需要确认的是整组玩家行为与版本影响，不能只确认设备外形后默认实施保存变更。

## 玩家结果与主循环

- 玩家在分流支路放一个准入口，选择晶体或富集晶体，保护反应器的配方输入；也可把解壳剂支路设为本轮 4 / 8 件，为两次开路准备确定数量。
- 既有矿壳试制消耗 1 样本 + 2 催化剂；准入口可定量输送两件催化剂，样本仍须亲手拾取并投入，不能由附件自动搬运。
- 面板直接说明允许物品、当前持货、本轮已放行 / 剩余、阻塞位置和重置操作，帮助玩家从产线观察到可解释的控制结果。配置后一批物料即可在 5–10 分钟内看到差别；时间仍待自然路径验证。
- 本包服务现有“发现 → 试制 → 制剂量产 → 开路 → 富集回流”，不引入研究、解锁、经济货币或额外首程必做步骤。

单入口设备只处理紧邻货物。拒收的物料留在上游；它不寻找后面的正确物品，不把混料队列自动分类，也不能保证更远处反应器仍采用匹配配方。连续两种物料需要在分流的不同出口各放相应准入口，或人工清理错误来料。

## 数量方案比较

| 语义 | 玩家看到的结果 | 本包取舍 |
| --- | --- | --- |
| 本轮总配额 | 设 4 后最多送出 4 件，随后停止接收；玩家明确重置才再给 4 件 | **推荐**；与 2 件试制材料、4 / 8 件开路目标直接对应，停点可解释 |
| 循环批次配额 | 每轮送 4 件后开始下一轮 | 暂缓；连续相同物料若立即再开一轮，行为近似不限量；需另定义触发或多物品批次用途 |
| 单位时间速率 | 每秒 / 分钟最多送一定数量 | 暂缓；需要时间窗口、累计额度、失焦与恢复时钟合同，当前定量备料不需要这一层 |

“不限量”只筛物品，不限件数；数量输入仅在“本轮总配额”模式启用。不得把总配额写成“每批”或“每秒”，也不将单槽自然吞吐误标为配置速率。

建议有限配额为 `1..1_000_000` 的整数，支持精确输入；上限用于明确 UI / 文件校验，不与 200 件背包或仓库容量混用。超过容量只会产生正常下游回压，不能自动丢弃多出的物料。

## 构件与端口

提议新增 `admission_gate`：1×1、后方一个输入、前方一个输出、被动单件缓冲、不接电。沿用 A 的 20Hz 固定步、至少 20 步行程和快照空位；相邻两次收货至少间隔 21 步，不增加总吞吐。

普通供给建议新增 8 件，A 各 8 件和既有构件不变，实体预算从 318 增至 326。工程规模供给继续独立设计，不放入普通新建选项。

允许物品为现有 `crystal / catalyst / crust_solvent / rich_crystal`，每台一次只选一种；`crust_sample` 不允许，未知物品严格拒绝。新放下时未配置白名单、停止接收，面板提示“选择允许物品”；配置成功后玩家开启“允许新来料”。不默认通过所有物品，也不默认无限领取样本。

外形采用自有导入 GLB：单向窄壳体、可辨认的前后接口及机械闸口，与 A 圆润化工家族一致；沿用小箭头和建造诊断。面板用现有物品图标选择白名单。资产工具沿仓库现有离线导出流程，依赖不足或需外部资产时另行说明并授权。

## 配额、堵塞与共同调度

有限模式的 `quota_used` 是**本轮成功送出件数**。接收一件时不增加它；该货物在单槽中占用一个剩余额度。必须始终满足 `quota_used + held_count <= quota_limit`，其中 `held_count` 仅为 0 或 1。

| 情况 | 权威行为与玩家反馈 |
| --- | --- |
| 未配置 / 停止接收 | 不提出新接收请求；“未选择允许物品 / 已停止接收” |
| 上游物品不匹配 | 物料留在上游；“只收晶体，当前来料为催化剂”等具体原因 |
| 有剩余额度且单槽空 | 才允许加入现有快照仲裁；输入成功不计产量或消耗 |
| 槽内有货 / 尚在运输 | 不能再收；按实际物品和进度显示，不能把在途当已放行 |
| 下游未接通 / 满载 / 不收物品 | 货物和额度保留；显示直接阻塞处，不退货、不换物品、不清零 |
| 成功向下游交接 | 与清空槽位同一提交中，有限模式 `quota_used += 1`；不限量模式规范 `quota_used=0` |
| 达到总配额 | 排空后停止新接收；“本轮 4/4，额度已用完”；不自动进入下一轮 |

准入判定进入共同物流模块的接收许可，供预览 / 摘要 / 调度复用；A 仲裁轮数、局部公平性、普通带侧入和单步一边不变。分流紧邻准入口拒收时可试其他有效出口；若先进入普通带再遇准入口，错误货物会回压这条支路，不进行远端预筛选。满配额或不匹配入口不构成有效公平请求。

“允许新来料”开关只控制接收，关闭后已收货物仍自然运至出口并计入本轮；面板显示“已停止接收，正在排空”。这样可以安全排空后改配置；手动暂停仍按世界暂停合同执行，不另建设备时钟。

## 配置事务、重置、旋转与回收

- F / Tab 近身打开，配置区给出允许物品、两种数量模式、整数配额及“应用设置”。选择 / 编辑只改未提交候选，Esc 或关闭放弃候选；执行时重新校验近身、设备存活、字段及槽位。
- 修改白名单、模式或有限额度仅在空载时允许；持货则明确拒绝并保留全状态，提示等待排空或无损拆回，不偷偷让旧货按新规则出库。
- 提交实际不同的设置会开始新一轮：`quota_used=0`，保留接收开关，成功反馈明确说明“设置已应用，本轮计数重置”。完全相同设置为无变更，不借反复应用刷新额度。候选变化与新一轮影响在提交前可见。
- “重置本轮”是显式近身命令，只在已配置、有限模式、空载时可用；只把 `quota_used` 归零，不改物品 / 限额 / 接收开关。不增加自动重置定时器或存档次数触发。
- 停止 / 再允许新来料、保存 / 读档、失焦 / 切回均保持计数；达到配额后开关往返不能重新领取额度。
- 空载 R 旋转保持配置与本轮计数；持货旋转拒绝。回收返回完整构件及一件在途物料，满包整件拒绝；不虚增产消。拆回后再次放下是一个未配置的新实体，先前计数不绑定到无身份构件；本轮限额是设施控制，不是不可绕过的经济权益。

配置与计数写入同一个世界快照，不另存独立配额文件；自动保存、手动保存、故障暂停和候选恢复使用既有原子发布合同。

## HUD、统计与首程

建造栏增加构件图标 / 剩余数和模型预览；实际连接、运行拒收原因与接收开关分别展示。面板至少同时可见允许物品、数量模式、已放行 / 剩余、持货图标、阻塞反馈及主操作，普通 / 最小窗口不依赖长文字滚动才能完成配置。

推荐文案：`本轮已放行 3 / 4`、`剩余额度 1（槽内占用 1）`、`额度已用完 · 重置本轮`；不把接入仓库、运输次数或历史产量混为配额计数。库存将槽内货物计入“在途”，物流过闸不生成产消事件，原入仓交付规则不变。统计定位支持新设备，电力页不把它列为消费者；不增加逐闸历史曲线或教程存档。

样本亲手拾取、试制、4 / 8 件开路及推荐富集回流仍可仅用现有产线完成。准入口作为扩展工具介绍，不能成为旧首程继续的隐性前提。

## 保存与版本提案

这部分为**待确认的 schema 5 提案**，当前运行实现仍为 schema 4。确认后再建立正式保存架构专题与 codec；本轮不提前把字段加入 V4。

- 新身份建议为 `factory_3d / 5 / factory_discovery_admission_v1 / factory_discovery_yard_64_v1 / factory_discovery_admission_starter_v1`；map 保持，ruleset / supply 独立。
- 新实体保存共用 `id/type/x/z/dir/cargo/progress/entry/batch`，以及 `filter_item`、`quota_mode`、`quota_limit`、`quota_used`、`accepting`。没有游标或独立计时字段；剩余额度、可接收、端口状态均派生。
- `filter_item` 为上述四种物品之一或未配置空串，`quota_mode` 仅 `unlimited / quota`；`accepting` 严格 bool。未配置规范为空槽、不限量、两个数量字段为 0、停止接收，拒绝半配置状态；不限量规范 `quota_limit=0 / quota_used=0`，有限模式限额在指定整数区间、`quota_used` 在 `0..limit`。
- 持货必须等于白名单，入口方向、单件半程及 batch 沿 A 严格校验，并满足剩余额度约束；非法限额、越额、未知模式、样本、错误物品、额外键、空间重叠及超供给一律拒绝，不自动清货或夹取数值。
- V4 世界可原规则继续；4→5 必须由菜单明确选择，说明新增供给和准入能力，持锁并核对源哈希，保留独立 `backups/pre-admission-v4-<sequence>-<hash>.json` 原文并读回核验，再严格发布。升级瞬间其他实体、财产、发现、统计与时钟保持，只更新身份、供给及发布序号。
- 无准入口的 V5 产线应与 V4 按相同命令 / 步数逐步一致；不同于 3→4 时序变更，本包没有改变普通线仲裁的理由。V5 有准入口时，独立恢复须保留半程与配额，不能重置已放行数。
- 旧 2 / 3 沿已有显式路径逐级升级；schema 1 / 旧二维 10 不迁移。见到 V5 或未来版本不能回退旧候选覆盖；原档副本不进入普通三槽轮换。写入、备份、读回、发布或重建失败保留原世界，不操作玩家正式目录做验证。

## 实施顺序与成功证据

1. **确认本篇整组合同**：数量、接收开关 / 排空、配置重置、8 件供给与版本提案；此后建立保存 V5 真相源。
2. **权威模型与严格保存**：在共同模块增加具体准入许可及提交计数，定向证明配额不越界、货物守恒、旧线轨迹一致、非法配置零变更和文件故障保护；不复制整套模型或 codec。
3. **资产与正式操作**：导入自有 GLB / 图标，建造、近身配置、空载旋转 / 无损回收、诊断与统计；不以占位方块交付。
4. **自然路径与独立恢复**：普通零库存 Boot 中筛晶体供基础线、制剂定量 4 件入仓，在第 3 件已出且第 4 件半程时保存；独立恢复只再放行 1 件，保持额度用尽，显式重置后再送；另测关闭排空、错误来料回压及分流紧邻拒收转送。
5. **C 组合与体验**：分流 → 两种物品准入支路 → 反应器 → 汇合 → 仓，检查堵塞修复、数量理解、面板与最小窗口原图；玩家反馈单列，再按风险评估规模性能。

定向状态还需覆盖限额 1 / 上限 / 非法值、最后一件被下游堵住、配置与收货同帧、重置与邻接改动、满包回收、不同实体遍历顺序及 30 / 60 / 144 FPS 固定步一致。自动功能优先无窗口；新 UI / 模型补短窗口正式 Boot 原图，开窗先告知，双根隔离、失败批次和未消费恢复起点保留。

超额、丢货 / 复制、读档或开关往返重置、错误物料被吞掉、配置能远程操作、普通旧线轨迹改变、玩家不能理解何时再放行，均为失败。若同类实机整改连续两次失败，按开发闸门复盘交互或状态结构。用户理解待验时不能把工程通过写成 D4 退出。

## 专题决策闸门

新增动作是选择允许物品与定量放行；世界变化是错误物料停在上游、目标数量到达后接收停止。用途与即时感知见主循环，现有地图 / 物品 / 权威调度足够，不需要通用策略系统，也不复活旧二维过滤模块。介质为导入模型、小箭头及现有 Control 面板；成功证据为守恒 / 重放断言、自然定量备料、原图和亲测。失败先重审数量语义或接收事务，避免继续堆标签；本包更接近可控的开拓材料生产，而非增加独立工程面板。

本包保留液气、物流桥、地下带、仓库出料口、优先级 / 比例、自动循环批次、速率限制、蓝图、随机地图、多人、量产美术和发布的现阶段边界。
