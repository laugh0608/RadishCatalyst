# Spatial Factory Retest Baselines

更新时间：2026-08-25

## 文档目的

本文定义当前 `Boot → SliceWorld` 像素切片的开发复测基线。冻结旧纵切的 `S0–S22` 代码生成基线仍由 [Development Retest Baselines](development-retest-baselines.md) 说明，不适用于当前正式入口。

## 通用规则

- 玩家可见验证从真实 `Boot` 菜单进入，不直接实例化内部世界充当正式证据。
- 自动检查、临时验证和人工复测存档统一使用仓库内忽略提交的 `tools/runtime-intake/`；不覆盖、删除或改写生产 `user://saves/slice/`。
- 逻辑检查可以 headless；截图必须有窗口运行并按 [Godot Runtime Verification Guide](../reference/godot-runtime-verification-guide.md) 实际审阅。
- 自动检查证明规则成立，截图和人工路径证明玩家能看懂并完成。

## 标准复测路径

### 空档资源与核心

用途：修改采集、背包、随身合成、核心修复、核心仓库或正式入口时。

```text
Boot → 新游戏
-> 采集晶体
-> B 合成机械零件
-> E 修复核心
-> 再按 E 打开核心仓库
-> 晶体 / 零件存入和取出
-> 完全重启并从 Boot 载入
```

检查背包与核心仓库容量守恒、核心直供状态、菜单摘要和读档结果。

### 制造、放置与装备

用途：修改配方、制造诊断、建筑套件、角色装备、武器库存或装备保存时。

- 在材料不足、直接可制造和只满足完整依赖三种状态打开制造页，核对直接成本、基础原料折算、当前可制造数、完整依赖可支撑数和补板上限。
- 制造建筑套件后面板必须保持打开且不自动进入放置；再从已有套件入口进入放置，取消后套件不丢失。
- 制造步枪后以 HUD 可见入口和 `C` 分别打开角色页；点击与拖入使用同一装备规则，数字键 `1 / 2` 结果等价。
- 装备步枪后完全重启并确认恢复；切回切割器后再次完全重启并确认恢复。步枪不在随身背包时不得装备，已装备步枪离开背包时必须立即回退并保存。
- schema 2—9 迁移默认切割器；schema 10 非法武器 ID 或“装备步枪但随身背包无步枪”必须拒绝，不能用默认值掩盖。

### 建造与纠错

用途：修改建筑定义、占用、放置、碰撞、HUD、调整或拆除时。

至少覆盖：

- 工业地板与一种多格设备的合法 / 非法 ghost。
- 鼠标网格吸附；设备左键单放，工业地板按住左键跨格连续铺设且同格不重复扣料。
- `R` 四向切换、`Esc` 取消不丢套件，`E` 兼容确认路径不回归。
- 点击任务、资源、角色、敌人或提示 HUD 时不得穿透落地。
- 缺地表、缺地板、重叠、玩家阻挡和越界短原因。
- 多格设备确认前显示完整足印与逐格缺地板提示。
- `[1]` 调整后取消恢复，以及提交后保留实例 ID / 内部状态。
- `[2]` 二次确认拆除、内容门控、地板支撑门控和背包容量门控。

### 供电中断

用途：修改核心直供、中继、设备端口、状态灯或供电连线时。

搭建“核心 → 至少三段中继 → 采集器”的多跳网络，检查：

- 孤立中继不能放置。
- 中继放置态显示 8 格上游连接范围、6 格设备覆盖和实际可连接上游；预览与最终供电结果一致。
- 通电树连续且不显示冗余父边。
- 调整或拆除桥接中继时下游同帧断电。
- 取消调整或在原格重建后恢复供电。
- 采集器断电暂停进度，恢复后继续。

### 储物箱与传送带

用途：修改物流邻接、带上货物、端点、转角、合流、回压或储物箱时。

至少覆盖三类布局：

1. 源箱 → 直线带 → 目标箱。
2. 含两个正交转角的折线路径。
3. 三只源箱合流到一个目标箱。

检查源 / 目标端点、正交转角、合流固定帧、晶体大小和轨迹；把目标箱填满后确认整线逐格回压，解除堵塞后继续搬运；持续供货时三路入口都必须获胜。

### 存档重启

用途：修改 schema、建筑状态、物流或自动保存时。

在同一隔离目录中从真实 `Boot` 保存后销毁整个 Boot，再重新进入“载入存档”。核对：

- 建筑稳定 ID、原点格、方向和下一序号。
- 采集器缓冲 / 生产进度、储物箱库存。
- 带上货物、在格进度和合流轮询顺序。
- 电网与物流拓扑由布局重建，结果与保存前一致。
- 坏主档能读取备份；不兼容候选不会替换当前运行状态。

### 首次充能、外勤与样本交付

用途：修改催化剂扣料、玩家输入、战斗、敌人、样本、生命或现行 schema 10 时。

- 从核心仓库与背包合计准备 2 份催化剂，经核心确认面板完成一次性充能。
- 核对 `WASD` 移动与鼠标瞄准解耦、左键单击 / 按住攻击、`Space` 闪避无敌和前台 UI 输入互斥。
- 至少覆盖一次受击撤离与重新交战；击败唯一敌人后只能生成一份样本。
- 样本经历 `dropped → carried → delivered`，核心交付优先于仓库操作，完成后生命为 `120/120`。
- 在 hostile、dropped、carried、delivered 中选取受影响状态重启，核对敌人 / 样本存在、生命和世界摘要一致。

### 真实新档全链

用途：修改资源预算、旅程目标、HUD、建造节奏或阶段退出条件时。

- 从真实 `Boot → 新建世界` 出发，不注入最终库存、建筑、战斗或交付状态。
- 完成修核心、通电采集、供电反应器、双端物流、2 催化剂、充能、战斗、样本交付和一次中途重启。
- 核对派生目标按权威状态前进，HUD / 提示在基地和晶体区不截断、不遮挡主要操作视野。
- 自动链记录资源、交互、放置和最低生产等待；20 到 40 分钟与无需口头指导必须由人工路径确认。
- 当前 37 个可再生晶体与反应器的理论最低生产等待不高于 60 秒；旧 `0–10s` 采集进度载入后按当前周期继续结算。

### 视觉遮挡

用途：修改世界 sprite、锚点、阴影、y-sort、ghost 或动态连线时。

同一画面保留核心、中继、采集器、传送带货物、储物箱和角色，分别让角色站在高设备前后。检查：

- 建筑没有斜向偏航、贴地或悬浮。
- 足印底边、接地阴影、碰撞和 ghost 对齐。
- 角色前后遮挡正确，状态灯与供电线不漂移。
- 货物沿带面移动，不斜穿、压带或钻入箱体。

### 核心 / 反应器接驳与角色排序

用途：修改外部端点、设备短口、终端传送带、局部接驳片、固定核心视觉壳或 y-sort 时。

- 同一复测世界覆盖受损 / 未连接、正确单侧或双侧连接、方向错误、拆除与保存重载；连接态必须由真实端点拓扑派生，不写入存档。
- 核心和反应器的完整终端带保持普通世界排序，只允许语义中性的 `12×24px` 左右局部片覆盖短口外段；空口和错向不得显示假连接。
- 角色分别站到固定核心前后，确认主体、局部片和终端带按自然 y-sort 交换遮挡；不得用统一高 `z_index` 压住角色、白色固定框或基座。
- 带货连接时继续核对货物、状态灯、供电线与 HUD；拆除、受损 / 修复切换和重载必须在同一物流 rebuild 周期清除或重算局部片。

### 系统界面与世界目录

用途：修改启动菜单、世界目录、损坏隔离、回收、暂停、保存返回 / 退出或系统 Theme 时。

- 从正式 `Boot` 覆盖启动、正常世界、元数据损坏世界、回收区、可恢复回收确认、暂停和离开确认；不得直接实例化面板充当正式证据。
- 损坏世界保持可见但禁用载入与重命名，正常世界不受阻断；回收项可恢复，危险确认必须明确后果且不能伪造游戏内修复能力。
- `Esc` 仍按前台操作 → 暂停 → 模态取消的既有优先级工作；保存返回与保存退出只有写入成功后才离开，失败时留在当前世界显示错误。
- 启动背景不得混入目标稿 HUD；目录详情、当前选择、禁用动作和危险确认在彩色、低饱和与灰阶下均应可辨，无文字截断、互叠或只靠色相表达。

## 自动检查入口

默认静态入口：

```bash
sh ./scripts/check-client.sh
```

需要 Godot 项目自定义运行时检查时：

```bash
sh ./scripts/check-client.sh --with-godot
```

能力域专项检查由聚合入口调用：

- `slice_building_placement_check.gd`
- `slice_building_operations_check.gd`
- `slice_power_grid_check.gd`
- `slice_logistics_check.gd`
- `slice_core_logistics_check.gd`
- `slice_save_schema_check.gd`
- `slice_save_review_worlds_check.gd`
- `demo_startup_shell_check.gd`
- `slice_combat_package1_check.gd`
- `slice_combat_package2_check.gd`
- `slice_combat_package3_check.gd`
- `slice_first_playable_journey_check.gd`

有窗口正式入口的一次性脚本与隔离存档放在 `tools/runtime-intake/<topic>/`，截图放在 `assets/art-intake/<topic>-preview/`；只有形成稳定、可重复的规则价值时才迁入正式 `scripts/` 或客户端检查入口。
