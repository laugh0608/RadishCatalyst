## 目标与边界

本轮用一张 16:9 目标图回答“小型化工厂是否能在固定高斜角下同时具有生产密度、模块装配感与清楚物流层次”。它只探索视觉方向，不新增玩法、液体 / 气体系统、设备能力或运行时内容。

工厂整图范围为一张目标图及有限修订；2026-09-06 萝卜SAMA另行同意推进透明管道局部状态样板，范围见下节。用户评审前不批量生产资产，不修改 `client/`，不接 Godot，不迁移 Web，不切换 3D，也不做全仓重构。既有工厂片段实现和系统证据保留；功能路径通过不代表本视觉方向通过。

## 构图合同

- 一块连续工业厂坪约占画面 70%，概念占地约 `24×14` 格；外围只保留少量暖砂岩、晶体与污染地表。
- 左侧原料输入、中段反应加工、右侧储存出料；设备采用两排紧凑布局，中间保留约两格宽贯通检修通道与一格服务缝。
- 后排用少量较高的双罐 / 反应容器和沿后缘分段架空管廊建立高度；前排用低矮加工设备、传送带和可读接口承担主要生产流。
- 管线分为地面物流 / 排水沟、设备接口短连接、后沿架空主管三层；不跨越主通道，不遮挡关键接口，不形成随机管线噪声。
- 固定高斜角近正交，轴对齐矩形网格；顶面最大并保留侧壁高度带。左上光，接地阴影，限定色板与克制像素簇遵循现行机械标准。
- 图内不放 HUD 或假游戏截图框；底部只标注 `VISUAL TARGET · NOT IN GAME`。

## 评审问题

1. **规模与密度**：画面是否像可实际扩建的小型化工厂，而不是稀疏巨机或宏伟炼化概念图？
2. **生产可读性**：能否直接读出左侧输入、中段加工、右侧储存出料，以及主通道和关键接口？
3. **投影与模块感**：高斜角、顶面 / 侧壁比例、设备足印和轴对齐关系是否支持后续网格化装配？
4. **材质与气质**：砂岩、平台、漆面顶壳、金属侧壁、状态色、警示条和阴影是否清楚且克制？

## 2026-09-06 管道视觉反馈

**萝卜SAMA提出的方向**：管道可以采用透明管段，连接处使用金属；通过内部流体的不同颜色和状态表达不同物质及其状态。这是本轮视觉设计输入，不代表 v2 整体定稿或液气系统开工。

建议据此分开表达三个问题，以下细化为执行会话建议，尚未冻结为实现合同：

| 玩家需要读懂的信息 | 建议视觉表达 | 必须避免的歧义 |
| --- | --- | --- |
| 管路在哪里、是否相接 | 可辨边缘的透明管段，金属接头 / 法兰衔接设备端口；金属保持结构材质色 | 管壁完全隐形，或金属套环遮住接缝，导致无法辨认连接 |
| 管里是什么物质 | 流体使用稳定识别色，并辅以可区分纹理和选中后的名称 / 图标 | 只靠颜色区分；同一种物质因停机突然变成另一种物质的颜色 |
| 是液体还是气体 | 液体可尝试连续色带，气体可尝试疏散纹理或间隔脉冲 | 把物态纹理误读为断管或缺料；具体示意方式须在游戏比例下验证 |
| 是否输送、方向如何 | 管内纹理沿实际方向移动；有内容但无输送时保留内容并停止位移，空管保留可见管壁 | 停止动画就被认作空管，或有动画却没有实际传输 |
| 为什么停机或异常 | 结合设备状态，在接头 / 设备处给出局部状态提示；流体本身保留物质身份 | 单凭流体静止判定堵塞；停流还可能来自缺料、断电或其他原因 |

- 透明材质建议用少量边缘高光、深色轮廓和可辨内部色带表达，保持像素簇清楚；具体透明度、动画和尺寸需要样板验证，不预设写实玻璃折射或改变画面介质。
- 物质识别色与运行状态分开设计。现有青色 / 琥珀 / 警示红语义继续保留，具体物质配色表尚未定义，不在本次修改全局色板。
- 若后续进入视觉样板，建议用同一段“设备端口—金属接头—透明管段”比较两种物质，以及空管、有料静止、定向输送三种工况；物态表达另作对照。所有样板明确标注为视觉示意。
- 透明管道解决管内内容的观察问题，仍需明确带与管分别服务的真实物流。当前固体链继续由传送带承载，不能把固体端口间的带替换成有动画的透明管而宣称连通。
- 本次仅记录反馈与建议；未生成新图、未接入资产、未定义流体拓扑、压力、混合或液气存档规则。

### 管壁动态流向标识

萝卜SAMA进一步要求参考 `/Users/luobo/Downloads/终末地UI参考/20260730215315.png`，在管道上添加动态流向标识。执行会话已只读查看该图：管段表面有白色双箭头，参考画面中的箭头指向左侧，并与有色透明输送区域及金属接头分层。静态截图只能证明样式和位置；移动速度、循环、停流表现来自本次设计建议，不能冒称已从参考图验证。

- **用户确定的表达方向**：流向标识直接放在管道上并动态表现；透明管体、内部物质色和金属接头方向继续保留。
- **标识建议**：用稀疏、等距、明亮中性的双箭头沿管轴移动，保持深色细描边以便在不同内容色上辨认；箭头与流体色分工，金属接头遮挡经过的标识，不在画面外另设大箭头代替管壁读法。
- **状态建议**：输送时移动；有料停流时保留物质，箭头停止并变淡；空管隐藏动态标识。停流时的静态箭头只表达已知方向，不表示仍在输送；方向未知时应隐藏。停流本身不等于堵塞，故障原因仍由真实设备状态表达。
- **运行时边界**：未来若实现，方向与是否运动必须来自真实输送状态；本次预览的方向切换只用于视觉比较，不承诺管道可逆、压力模型或瞬时流量规则。恒定演示速度不是实际流量标尺。
- **动态预览**：`assets/art-intake/2026-09-06-transparent-pipe-study/pipe-flow-markers-v1.html` 保留交互片段副本；可切换两种流体、左右方向、输送 / 停流 / 空管，并可暂停预览。使用独立的简化管段示意和动态标识，不修改原始 PNG、参考图或游戏资产，不作为像素美术验收。
- **验证范围**：离线模拟 DOM 检查通过动画位置更新、反向、停流保留物质、空管隐藏、颜色切换、暂停与减少动态效果偏好，以及 `736` / `360` / `320` 宽度的 SVG 几何；不是浏览器渲染或真人辨识证据。浏览器 URL 安全策略拒绝打开本地预览文件，未改用其他浏览器或绕过该策略，因此真实画面与主题适配仍未复核。未启动 Godot，未接入液气系统。

### 与现有游戏的主要差距

1. **场景组织**：已有三机实机图显示局部地板与单排设备，连续厂坪和检修通道尚不突出。优先明确生产区边界和通行空间，不能仅靠缩短带长来制造密度。
2. **视觉层级**：实机地表裂纹重复且遍布屏幕，设备周围留白较多；v2 用大块厂坪承托设备，外圈地貌退为边缘。应先验证连续地面的组织效果，再判断是否必须更换地面资产。
3. **设备体量**：现有储物箱正面较强，v2 的低矮设备更强调顶面。需要在原生游戏比例下对照，不能通过整体缩放同时改变足印、角色和端口来掩盖问题。
4. **真实物流**：接缝修复已有专项证据；下一次整体画面仍须能追踪采集、加工、入箱和停机恢复。储物箱 `transfer` 会把货物无线送入核心，不能因箱中数量下降误判产物消失，也不能把概念图右端容器库存当成现有行为。
5. **功能规模**：v2 的两排罐组、多加工单元和管廊超出当前固体链。复现其完整密度需要另行设计资产和功能分工，当前不靠复制无用途设备或假连接填满画面。
