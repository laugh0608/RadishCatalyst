## 授权与五问

萝卜SAMA在完成独立 Godot 3D 对照后，要求制作 Web Demo，并明确选择“同场景对照手绘 2.5D 与现有像素样板”。本轮从干净的 `dev / e7b60b66` 开始。授权限本机画面验证，不构成正式 Web 迁移、视觉验收、发布或新玩法授权。

1. **玩家结果**：在两幅同步场景中移动角色，观察设备前后、架空玻璃管、落地投影和正常 / 放大尺度；比较手绘素材与现有像素素材的可读性。
2. **实现介质**：`tools/visual-studies/web-style/` 内独立 HTML / CSS / JavaScript 与 Canvas 2D。主体使用真实位图素材；像素侧复用现有资产，手绘侧限设备 / 管段 / 支架、单姿态角色和地面三个生成类别。不以 CSS / SVG 几何拼画替代美术。浏览器运行使用本机既有 Node，无依赖安装。
3. **成功证据**：本地 HTTP 入口、浏览器实际输入、同步位置、设备碰撞与前后排序、透明 / 不透明开关、视口缩放和原始截图。机制检查与主会话看图分开记录；视觉结论由用户决定。
4. **失败判据**：素材不能分层、玻璃遮挡与接地锚点不一致、像素缩放模糊或正常尺度体积仍不可读，均必须记录。不得以网页易开发推导美术已经通过；同类两次失败停止盲调。
5. **文档落点**：本合同记录范围和限制；Current / Daily 路由本合同，本周周志记录生成批次与浏览器证据。

这是介质对照，移动只是观察工具，豁免新增玩法专题十问。正式 Boot、客户端逻辑、存档、流体系统、全局像素标准均保持既有边界。保留已完成的 [Topdown 3D Comparison Demo V1](topdown-3d-comparison-demo-v1.md) 与二维 Godot 证据，不冒称 Web 复现了完整游戏。

## 对照合同

- 两侧共用一套世界坐标、移动速度、碰撞和接地排序；设备与管线占位一致，材质、轮廓和地面图不同。并非严格等资产的引擎性能测试。
- 像素侧保留原生纹理，以整数世界像素绘制、最近邻显示；手绘侧平滑缩放。同一控制可选择单侧和放大档位。
- 管道只做透明 / 不透明对照；像素原图内的青色内容保留，不称为空管。不新增流体输送、流向、液位或生产模拟。
- 角色为单姿态位图平移，不冒称四向行走动画；阴影为素材投影近似，无实时 3D 光照、折射或光向切换。
- 原始图和生成清单保存到 `assets/art-intake/2026-09-06-web-handpainted/`；经审阅选用的原图复制到本 Demo 的 `assets/`，运行不依赖忽略目录。
- 验证日志 / 数据使用 `tools/runtime-intake/check-runs/web-style/`，截图使用 `assets/art-intake/2026-09-06-web-style-preview/`；无持久化和游戏存档访问。

## 入口与验收

入口：`sh tools/run-web-style-demo.sh`，默认 `http://127.0.0.1:4317/`，可通过 `WEB_STYLE_PORT` 指定另一个本机端口。仅监听 `127.0.0.1`，文件服务使用逐文件允许列表，不暴露仓库根目录。退出启动进程即停止服务；此页没有构建器、包管理依赖或部署配置。

浏览器开窗前已告知。没有安装依赖、引入第三方资产包、部署或上传；新增素材由本轮三次内置图像生成产生。

## 实际执行与证据

- 工业 / 角色 / 地面三个类别各调用一次内置 `image_gen`，共三次，无重试。原图及全提示、来源、尺寸、alpha 和 SHA-256 在 `assets/art-intake/2026-09-06-web-handpainted/`；选用原图逐字节复制到 Demo `assets/`，`generation-record.json` 随代码保留。工业图 `1536×1024` RGBA，角色 / 地面 `1254×1254`，后两者未遵循请求的 `1024×1024`；工业底排有 `198` 个 alpha=1 残留。运行时按上排三个格与 alpha 范围取图，不修改原始 PNG，不宣称已归一为量产资产。
- 世界范围 `416×288`；角色高度上限 `42` 世界像素，设备占位上限 `128×128`。像素 Canvas 为 `416×288`，手绘 Canvas 为 `1664×1152`，用于保留平滑轮廓；显示区域、世界坐标和碰撞共用。像素素材以最近邻适配有限占位，未声称每个原始 texel 始终按整数倍显示。
- 初次浏览器帧的 RAF 时间戳早于注册时的 `performance.now()`，触发负步长错误，导致首屏空白。修复为从首个 RAF 回调建立时间原点。键盘短按可能在两个渲染帧之间结束，补首按小步响应，长按仍由帧循环驱动。两项均在浏览器暴露后修正；失败控制台记录保留，不算通过证据。
- 定向机制测试入口：`node --test tools/visual-studies/web-style/verify.mjs`，五项测试通过，覆盖斜向等速、设备 / 细支架碰撞、接地排序、缩放坐标映射、目标移动和 HTTP 允许列表 / 禁止写请求。首次 HTTP 测试与启动被沙箱拦截，获得授权在沙箱外监听 loopback 后通过。
- 实际浏览器入口为 Codex In-app Browser。桌面 `1440×900 / DPR 2`，原始截图 `2880×1800`；小屏为 `390×844 / DPR 2`，页面宽度实测 `390`、无横向溢出。截图在 `assets/art-intake/2026-09-06-web-style-preview/`：常态、管后透明 / 不透明、机后 / 机前、关投影、网格与放大、键盘移动、小屏共九张。
- 已逐张查看关键实机画面：机后角色被遮挡、机前角色显示；管后角色透过玻璃可见，不透明时躯干被挡。像素与手绘都使用同一接地排序；投影开关有可见变化。观察位置按钮直接设置位置，不冒称人工绕行。
- 浏览器真实方向键短按使坐标由 `X 218 / Y 226` 向右变化；在机前连续短按 W，最终停在 `X 132 / Y 200`，没有穿过设备。触屏右按钮短按到 `X 219 / Y 226`；点击画面中心后前往 `X 208 / Y 184`，被支架挡住。没有自动绕障寻路。两种单侧切换均检查了另一画面的隐藏状态。
- 浏览器记录：`tools/runtime-intake/check-runs/web-style/browser-result.json`。记录包含首轮失败控制台日志，修复后无新增浏览器错误；临时视口覆盖已经清除，默认并排模式和入口位置恢复，标签页保留供用户操作。
- 最终仓库治理通过（`1590` 文件），文档预算、文本规范、差异空白与五项 Node 定向测试通过。检查日志汇总在同目录 `validation-result.json`；没有运行正式客户端 Godot 套件。

## 路线判断与未覆盖项

本轮说明 Web 能以较短的代码 / 浏览器反馈链完成交互样件和素材比较；它没有证明 AI Agent 在所有游戏开发任务中都优于 Godot。前一轮 Godot 场景验证的真实模型、光向、投影和深度缓冲也没有被此 Canvas 样件替代。

手绘侧的罐身曲面、墨线与连续材质更容易在当前样件尺度保留；像素侧继续复用既有小尺寸素材，其轮廓粒度和体积表现不会因浏览器渲染而自动提高。两侧机型、角色轮廓、地面纹理与原生分辨率不同，这是路线样件对照，不是排除全部变量的美术或性能实验。

当前手绘图仍带边缘光晕、角色细节偏密，支架与管口只有有限装配；投影是位图压缩着色近似，不能动态换光。玻璃只调整有限直管中段 alpha，金属两端保留，非通用材质掩码或折射。像素管道的静态青色内容仍来自旧图，无任何真实流体状态。

四向动画、完整工厂资产家族、复杂管网与排序、设备量产、长场景性能、触屏设备实机浏览器、存档和联机均未验证。正式 Boot 与完整 Godot 回归没有重跑；本次没有修改客户端。用户选择后才能定义下一包，不能据此自行迁移正式工程。
