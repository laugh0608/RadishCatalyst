# Spatial Factory Building And Logistics

更新时间：2026-07-25

## 文档目的

本文定义当前像素切片中空间工厂的长期玩法规则，覆盖网格建造、建筑操作、扩展供电和固体物流。它描述玩家能依赖的系统口径，不记录开发包、提交过程或阶段进度。

当前正式入口中的基础循环是：

```text
采集晶体
-> 随身合成机械零件与建筑套件
-> 修复前哨核心
-> 铺工业地板、部署供电与设备
-> 用储物箱和传送带形成稳定晶体物流
-> 把物流接入后续反应加工
```

## 网格与建筑定义

- 世界使用 `32px` 正交网格。
- 建筑以左上原点格、占地、基数方向和稳定实例 ID 表达。
- 旋转只选择上 / 右 / 下 / 左四张审定帧，不运行时旋转像素素材。
- 地板层与设施占用层分开；设施可以占据已有地板格，但不同设施不能重叠。
- 可放置建筑共用套件、预览、放置、调整、拆除和存档规则。

| 建筑 | 占地 | 放置表面 | 供电角色 | 制作口径 |
| --- | --- | --- | --- | --- |
| 工业地板 | `1×1` | 可建岩地 | 被动 | 晶体 `1` → 地板套件 `8` |
| 晶体采集器 | `2×2` | 晶体地 | 用电设备 | 机械零件 `2` |
| 基础反应器 | `3×3` | 完整工业地板 | 用电设备 | 机械零件 `4` |
| 电力中继 | `1×1` | 工业地板 | 中继 | 机械零件 `1` |
| 传送带 | `1×1` | 工业地板 | 被动 | 晶体 `1` + 机械零件 `1` → 传送带套件 `4` |
| 储物箱 | `2×2` | 完整工业地板 | 被动 | 机械零件 `2` |

反应器的加工、双缓冲和催化剂物流由反应加工规则承接，不在本文预先定义未接入行为。

## 放置与失败反馈

建筑套件是普通背包物品。玩家在随身合成面板制造套件后选择建筑，预览吸附到角色面前的网格：

- `E`：提交合法放置。
- `R`：顺时针切换基数方向。
- `Esc`：取消放置，套件不损失。
- 合法预览使用青色真实资产；非法预览使用红色真实资产并显示短原因。

放置按顺序检查：

1. 全部占地格在地图边界内。
2. 地表符合建筑定义。
3. 设施需要的每一格工业地板已存在，或能由背包中的地板套件在可建岩地上原子化补齐。
4. 地板层或设施层没有同层占用。
5. 玩家和其他物理对象没有挡住占地。
6. 新电力中继能连接核心或既有通电中继。

失败原因使用可执行短句，例如“越界”“需晶体地”“工业地板不足”“此处无法自动铺设工业地板”“已有占用”“玩家阻挡”或“超出电网连接距离”；合法预览同时标出待自动铺设格数。

## 调整与拆除

靠近已放置建筑按 `E` 打开操作面板：

- `[1] 调整位置`：暂时释放原占用并进入放置预览；取消会恢复原位置、方向、实例 ID 和内部状态。
- `[2] 拆除`：需要再次按 `[2]` 确认；成功后返还一个对应套件。
- 工业地板支撑设施时不能调整或拆除。
- 采集器、储物箱或传送带仍有内容时不能拆除；传送带有货物时也不能调整。
- 背包没有空间接收返还套件时不能拆除。

调整或拆除会在同一帧重建供电与物流拓扑，不保留幽灵连接。

## 扩展供电

供电是二值可达网络，不模拟电量、功率或负载：

- 修复后的前哨核心是唯一电源。
- 核心可在 `6` 格范围内直供设备或连接中继。
- 通电中继可以在 `8` 格范围内继续连接下一座中继。
- 用电设备的定义式电力探针需要位于核心 `8` 格或任一通电中继 `6` 格范围内。
- 电网结构变化后从核心重新计算全部可达中继与设备。
- 每座通电中继只显示一条派生父连接，形成低干扰供电树；连接关系不是存档权威数据。

设备断电后保留内部进度。晶体采集器会暂停而不是清零，重新通电后继续推进。

## 固体物流

当前固体物流遵守以下规则：

- 每格传送带最多持有一件货物，速度为每秒一格。
- 传送带方向就是输出方向；相邻上游、储物箱端口和既有方向共同派生直线、转角、源端点、目标端点或合流外观。
- 储物箱只有一个随旋转变化的双向舱口。传送带背离舱口时从箱内取货，指向舱口时向箱内入库。
- 储物箱容量为 `20`；当前自动运输白名单只有晶体。
- 下游带格被占、目标箱满载或线路断开时，货物停在输出边缘并形成逐格回压；不得丢失、复制或穿越堵塞。
- 多路输入竞争同一空带格时使用持久轮询游标；持续有货的入口应轮流获胜，不能长期饿死。
- 转角货物沿“入口边缘 → 格心 → 出口边缘”的正交折线移动，不斜穿格子。
- 放置传送带时持续显示附近既有储物箱 `IO`、反应器 `IN / OUT`、外接格与箭头；落在外接格后必须用绿色 `✓` / 红色 `×` 和 HUD 短句说明方向是否成立。
- 储物箱与反应器操作面板显示各端口“未接 / 方向错误 / 已接”的权威拓扑结果，箱体边缘视觉贴合不能冒充有效连接。

传送带拓扑是布局的派生结果。玩家只负责决定每格输出方向，不需要手工选择“转角”或“合流”配方。

## 视觉与空间读法

- 建筑运行时根节点落在足印底边中心，sprite、碰撞、状态灯和放置预览分别使用定义式偏移。
- 建筑以足印底边参与 y-sort；角色从设备前后经过时，遮挡关系应随脚点变化。
- 世界对象使用统一左上光、右下接地阴影；阴影说明接地，不替代碰撞或占地。
- 电力连线、状态灯和货物是动态反馈，可以程序绘制或移动；建筑主体、传送带拓扑和地板仍使用固定像素资产。

## 存档与系统边界

玩家拥有的套件、建筑稳定 ID、原点格、方向和建筑内部状态进入存档。占用索引、供电可达性、供电父边、物流邻接和拓扑外观都由布局重新计算。

详细状态所有权和 schema 规则见 [Slice Runtime Systems](../architecture/slice-runtime-systems.md)。

本文不定义：

- 电力容量、峰值负载、燃料或电池。
- 分流器、优先带、筛选器、堆叠货物或地下带。
- 自由角度旋转、蓝图、框选、升级和建筑损耗。
- 反应器加工状态、催化剂货物或机器输入 / 输出缓冲。
