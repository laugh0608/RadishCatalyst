### 排错记录

- 首次导入枚举名拼写错误，修正为 `Environment.REFLECTION_SOURCE_SKY` 后解析通过。原 Godot 导入尝试写默认用户 / 编辑器目录受沙箱拦截，未算通过。为隔离导入数据，将本机已有的 `331MiB` 可执行文件复制到 `tools/runtime-intake/check-runs/topdown-3d/runtime/`，添加 `_sc_`；复制后 macOS 签名校验失败，经本地临时签名后导入成功，没有修改原 Godot 或系统证书。
- `run-1788682257-48606` 的 Compatibility / 初始光照组合地面过曝，节点检查虽过但视觉不可用；转 Forward+ 后 `run-1788682493-48985` 暴露厂坪与地砖顶面共面、首次鼠标事件未命中的两项失败。分离厂坪 / 地砖表面，补鼠标移动与本地坐标输入后，`run-1788682618-49352` 的检查通过。
- 阴影仍未有效显示时停止调整造型，转 `shadow-probe.gd` 检查光源状态及阴影图集；单幅正交覆盖 / 范围 / 偏移组合产生可读投影后才回到最终复核。保留 `shadow-orthogonal.png` 与 `shadow-atlas.png`，不将此诊断推断成所有 Godot 分割阴影的缺陷。
- 自包含模式只隔离编辑器数据。引擎曾在 `~/Library/Application Support/Godot/app_userdata/RadishCatalyst - 3D Visual Study/` 创建自身 shader cache / 空 objectdb 目录；它是本 Demo 独立引擎目录，没有游戏存档。日志、检查记录和全部截图均在仓库规定的忽略目录；没有访问正式 RadishCatalyst 存档。
- 默认 Shell 入口使用已安装的 Godot，可用 `GODOT_EXE` 指定其他现有可执行文件；仓库内副本只是本次导入诊断工具，不是新依赖或运行必需的提交文件。

## 路线差异与评审问题

| 比较项 | 当前二维像素样板 | 本次三维样件 |
| --- | --- | --- |
| 体积 | 顶侧面与光照写入各方向像素，需要归一后仍可读 | 曲面法线、顶盖、机座与圆管在同一光照下形成明暗 |
| 空间 | 接地锚点、排序和独立阴影素材维持高度关系 | 深度缓冲、真实高度与光源投影统一产生遮挡关系 |
| 透明 | 像素 alpha、内容掩码与流向 shader，粒度受原生尺寸限制 | 真实空心管表面与独立液面截面，角色可透见；仍为透明近似 |
| 资产成本 | 可继续复用既有工程；各方向、接缝、动画帧与烘焙光向需逐项维护 | 模型可复用不同角度 / 光向；模型制作、材质、骨骼动画、性能和透明排序需要生产规范 |
| 若继续推进 | 局部修订投入较小，但原生像素体积 / 玻璃细度问题仍待选择 | 先验证代表场景与资产生产；正式迁移还涉及场景、选取、碰撞、建造投影及回归 |


二维继续使用现有网格、Sprite2D、素材与玩法基础，但设备每个方向的明暗、透明掩码、接缝、投影与接地排序需要资产合同保证。三维让同一个模型随光向和视角自然变化，深度缓冲统一处理不透明遮挡；代价是模型 / 材质 / 动画生产、阴影与透明排序、GPU 预算，以及未来若迁移时的场景、选取、碰撞和建造投影工作。

这里只比较当前样件的视觉机制，不把单场景帧率推广成完整工厂性能，也不估算未经拆解的全项目迁移工期。玻璃采用实时透明近似，非物理折射 / 焦散；透明物体相交仍须专门治理，参见 [Godot 3D rendering limitations](https://docs.godotengine.org/en/stable/tutorials/3d/3d_rendering_limitations.html)。
