# Development Retest Baselines

更新时间：2026-06-29

口径说明（2026-07-25）：本文基线只针对冻结保留的旧纵切运行时（`S0` 到 `S22`），在旧代码复用与回归时仍有效。当前正式 `Boot → SliceWorld` 的空档、建造、供电、物流、重启和视觉路径见 [Spatial Factory Retest Baselines](spatial-factory-retest-baselines.md)。

## 文档目的

这份文档定义首小时原型当前使用的“开发复测基线”。

它回答三件事：

- 为什么不应再把“每次人工复测都从空档重打”当默认。
- 当前有哪些标准阶段基线，分别适合复测哪一段。
- 开发时应该怎样在“局部基线复测”和“全链路空档复测”之间做取舍。

## 设计目标

开发复测基线的目标不是替代空档复测，而是把空档复测从“每次都做”降级为“在真正需要时做”。

当前设计遵守以下原则：

- 基线由代码生成，不手工维护长期 JSON 快照。
- 基线必须同时覆盖任务状态、区域解锁、场景完成态、敌人状态、已建结构和关键库存。
- 基线必须能直接载入当前运行时，不要求先跑外部脚本。
- 载入基线后，若需要长期保留，仍可保存到普通槽位。
- 新内容扩展时，优先补对应基线，而不是让人工复测链无限变长。

当前运行时实现位于：

- `client/scripts/save/development_baseline_catalog.gd`
- `client/scripts/save/development_baseline_builder.gd`
- `client/scripts/ui/hud_development_baseline_presenter.gd`

## 核心稳定站局部开发复测基线

核心稳定站终点链已登记为代码生成 `S21` 和 `S22` 基线。`S21` 是写入前的短跑起点，用于确认地图 / HUD 指向 `region.demo_stabilization_core`，再跑核心稳定站终点链；`S22` 是写入完成后回到前哨的整理起点，用于确认完成态不会把玩家重新导回行动台、高压窗口或新章节。若本地已有高压窗口归档后或核心写入后的普通槽位，也可直接载入对应槽位。

复测步骤：

1. 从高压窗口反馈归档后出发，确认当前目标指向核心稳定站，且未要求再新增行动台方案或高压窗口分支。
2. 进入 `region.demo_stabilization_core`，确认 `quest.enter_demo_stabilization_core` 完成，并激活 `quest.prepare_demo_stabilization_buffer`。
3. 返回污染边界末端回收补料沉积物并清理补料守卫，回处理点过滤出抗污染药剂和污染浆液，再回基地用基础反应器整备 `item.core_stabilization_buffer`。
4. 确认核心稳压缓冲包目标完成并激活阶段守卫目标；带核心稳压缓冲包回核心稳定站后，可先回收侧边补给缓存取得修复凝胶和抗污染药剂，再击败 `enemy.demo_stabilization_guard`。守卫第一次回写压力应读取缓冲包、侧边补给和抗污染药剂，准备越充分，生命 / 防护承压越低。
5. 击败守卫后回收 `map_object.demo_stabilization_guard_cache`，确认拿到 `item.core_write_charge`、基础零件、终点前补给和回写校准；HUD、前哨核心和基地设备面板应能读出守卫战消耗、缓存补回和写入前整备建议。若未回收校验片，核心设备应拒绝写入。
6. 在 `map_object.demo_stabilization_core` 写入稳定数据；若已回收核心站侧边补给、守卫回写缓存、阶段守卫反击消耗过核心稳压缓冲包或带有抗污染药剂，设备写入应读取这些终点前整备并降低反冲；没有药剂时仍可完成但承压更高。
7. 完成后回前哨平台，检查 HUD、前哨核心、出发整备台、外勤出发口和核心设备面板能读出核心写入已归档、前哨核心可补修复凝胶 / 抗污染药剂、生命 / 防护恢复和基础过滤模块确认；地图目标应在前线时回指基地，回到基地后指向核心稳定站复测，出发口对象不应把玩家引回行动台、高压窗口或新的区域入口。
8. 在出发整备台接入核心归档维护后，回污染边界处理归档维护回访口袋：受扰掠行体守卫应读取双药剂余量和归档维护收益，沉积物过滤完成后，过滤器完成提示、HUD、前哨核心、出发整备台和外勤出发口应指向补满双药剂并继续复测核心站或回污染边界验证承压。

`S22` 复测补充：载入后玩家应位于前哨整理状态，已保留核心写入完成、核心阶段守卫败退、守卫回写缓存已回收、核心归档维护已接入、基础过滤模块已装配 / 校准和基础补给。HUD、地图、前哨核心、出发整备台、外勤出发口和核心设备完成态应统一读出“Demo 已完成后整理 / 复测”，不能开启新的行动台方案、终局菜单、结算页或更东侧区域入口。

污染边界局部复测补充：从 `S1` 后半段或普通进度进入污染边界深处时，带有抗污染药剂攻击污染脊守卫、污染侧翼守卫、副产回收口袋守卫、药剂储备守卫、归档维护回访守卫或门前受扰敌人，应自动消耗 1 个药剂并降低首次反击承压；没有药剂时仍可清理敌人，但压力完整命中。

门前准备补充：清掉 `enemy_instance.polluted_skitter_gate_pressure` 后，封锁入口 prompt 和确认反馈应读取基础过滤模块、抗污染药剂和污染浆液携带状态；若背包仍有污染浆液，HUD 和基础反应器设备面板应提示可先回收基础零件，再确认入口信号。

遗迹外圈局部复测补充：从 `S2` 进入 `quest.salvage_signal_echo` 时，带基础过滤模块清理 `enemy.ruin_phase_guard` 应明显降低外圈回波反击造成的生命 / 防护承压；无模块仍可清理守卫，但战后更依赖修复凝胶和过滤器处理回波沉积。

`S2` 回基地解析深段回波时，`recipe.deep_signal_analysis` 应消耗 `item.signal_echo_trace` 和 `fluid.polluted_slurry`；若身上还有污染回波沉积且缺污染浆液，污染过滤器应推荐 `recipe.cleanse_residue`，设备缺料提示应指回相位守卫后暴露的过滤处理线。

污染过滤器补充：`recipe.cleanse_residue` 完成后的下一步应按当前任务分流；组装稳相信标时指向 `recipe.phase_anchor`，回收深段回波时指向回波匣和裂相坐标解析，核心缓冲包整备时指向 `recipe.core_stabilization_buffer`，门前压力尚未处理时指向带药剂回污染边界排压；若进入门前确认阶段且仍携带污染浆液，基础反应器应推荐回收基础零件。

角色套件与整备状态补充：从 `S1` 之后或已建出发整备台的普通进度进入局部复测时，`C` 战术扫描必须能标记近身敌人或污染采集点，并在下一次反击或采集后消费标记；防护响应和工具打击校准必须通过真实出发整备台交互确认待命，再由下一次外勤反击触发并写回已触发状态。

检查口径：

- 自动检查已覆盖区域边界、地图标记、任务规则、守卫门控和核心设备写入事件；默认 `check-client` 不启动 Godot，导入工程和项目自定义 GDScript 运行时检查需用 `-WithGodot` / `--with-godot` 显式执行。若本机 Godot 无法启动，应记录该运行时检查未执行，不把它写成通过。
- 局部实机复测只阻塞 `P0` / `P1`：崩溃、主线卡死、坏档、任务无法完成、核心资源断档，或 UI 完全无法判断下一步。
- 文案密度、局部路径拥挤、战斗数值偏软 / 偏硬、资源点数量不足先记入后续核心区域尺度规划，不阻塞 demo 收束阶段。
- 若后续调整该切点，应同步更新 `DevelopmentBaselineCatalog`、`DevelopmentBaselineBuilder`、`development_baseline_save_check.gd` 和相关 HUD 基线展示检查。

当前口径补充：

- `S4` 应保留第二轮裂相脊链继续推进所需的基础零件、裂相样块与污染浆液；基础反应器推荐和设备用途必须指向“裂相样块解析 -> 裂相阵列台点亮”。
- `S4` 到 `S5` 的缺料提示应覆盖裂相样块、相位导管和污染浆液来源，避免玩家被引回已收口的首小时内容包。
- `S5` 若载入到基地，HUD / 地图应直接把玩家指向相位回投台，并在回到裂相脊后要求先写入两处共振读数，再处理猎手和碎屑回收；基线还应保留当前前线回传锚点和基础补给。
- `S5` 到 `S13` 的读数点应显示当前进度和读数完成后打开的回收线；井底余烬壳、锁相框架侧路和锚场压力钉应使用各自专用清障提示，不回落到通用地块清理文案。
- 晚期基线载入后，生命 / 防护上限必须按已完成裂相脊后半里程碑自动同步，不再固定停在 `100 / 100`。
- `S6` 应保留前线回传锚点在线、基地回投链可直接使用、内层故障轨迹已入包，并让玩家在基地起跑时立刻进入“故障轨迹解析 -> 故障脉冲读数 -> 裂相锁位”的后续链路。
- `S6` 之后应能看到相位中继锚点完成态已解锁 `回收基础零件`；若后段配方缺基础零件且背包有污染浆液，基础反应炉推荐应优先切到该回收配方。
- `S7` 应保留回声定位器已带回且基地起跑可直接解析的状态，让玩家立刻进入“定位器解析 -> 回声泄压阀 -> 回声碎屑 -> 回声探针 -> 回声台地”的后续链路。
- `S8` 应保留回声芯样本已带回且基地起跑可直接解析的状态，让玩家立刻进入“回声芯样本解析 -> 盐壳清障 -> 盐壳整备 -> 盐壳浅滩”的后续链路。
- `S9` 应保留碎晶心核已带回且基地起跑可直接解析的状态，让玩家立刻进入“碎晶心核解析 -> 碎晶整备 -> 碎晶沟谷”的后续链路。
- `S10` 应保留风蚀张力核已带回且基地起跑可直接解析的状态，让玩家立刻进入“风蚀张力核解析 -> 风蚀整备 -> 风蚀管廊”的后续闭环。
- `S11` 应保留锁相织构核已带回且基地起跑可直接解析的状态，让玩家立刻进入“锁相织构核解析 -> 锁相框架整备 -> 锁相框架”的后续闭环。
- `S12` 应保留锚定结核已带回且基地起跑可直接解析的状态，让玩家立刻进入“锚定结核解析 -> 锚定桥整备 -> 锚定桥”的后续闭环。
- `S13` 应保留稳场锚核已带回且基地起跑可直接解析的状态，让玩家立刻进入“稳场锚核解析 -> 锚场整备 -> 锚场回稳”的非同构后续闭环。

## 运行时使用方式

当前原型里，按 `Tab` 打开调试面板后，会看到“开发基线”区。

使用步骤：

1. 点击“上一个 / 下一个”切换基线。
2. 点击“载入”把当前运行时重置到该阶段。
3. 如需长期保留，再用现有普通槽位按钮保存到 `slot_01`、`slot_02` 或 `slot_03`。

同一面板里的“截图定位”区用于当前视觉阶段的实机截图复核。它复用开发基线生成运行时状态，并把玩家直接放到 1 到 6 号观察点；载入后可直接截图，必要时仍可保存到普通槽位。

截图定位点只服务本地开发观感复核，不改变正式存档规则，也不代表玩家流程新增快速传送。当前 1 到 6 号点的复核重点分别是：1 号基地首屏只读前哨核心，2 号晶体矿脉像可采集矿面和回基地资源路线，3 号采集器输出能读出设备自动出料，4 号入库整备交接能读出基地收料、反应器、储存和整备台，5 号污染边界像沉积 / 过滤 / 回收现场，6 号核心稳定站像写入设备和复测站点，而不是旧流程图块。3 / 4 号使用专用运行时状态，不继承污染边界任务进度；若目标、交互对象或小地图仍处在晶体 / 污染语境，应先修正复测位或状态触发。

视觉定位复核时，3 / 4 号应优先看设备状态灯、物料槽和短资源流是否能说明采集器有料、收料口装入、反应器加工、储存输出和整备交接。4 号成立的画面证据是反应器料斗、仓储供给件和整备锁扣成为主体，而不是旧路线层、目标标签或远端资源点。5 号应确认污染处理工作面、过滤床、药剂 / 浆液输出和回收 / 核心准备端口压过旧横带与跨区路线；6 号应确认红色守卫压力退为完成态残压，核心写入、复测读数和物流回流集中在站内短线、独立读数面板和回流端口里。

同一调试侧栏里现在还附带一组开发期 GM 控件：

- 可轮换关键资源并做 `+1 / -1` 数量调整。
- 可一键回满生命和防护。

它只服务本地开发复测，不面向正式玩家。

这套机制默认用于本地开发和人工复测，不面向正式玩家。

## 什么时候仍然必须跑空档

以下情况不应只依赖局部基线：

- 涉及首版 Demo 初始链路、共享状态或阶段收口时，必须从 `S0` 新档开始，局部基线只用于定位已发现的问题段；这属于开发复核，不代表进入试玩阶段。
- 改了早期主线顺序或新档初始状态。
- 改了共享任务推进、区域解析、地图目标来源、HUD 全局提示口径。
- 改了存档迁移、存档校验或旧进度补激活逻辑。
- 改动跨越多个阶段，且你怀疑基线之间的衔接本身可能出错。
- 一个较大功能包准备收口，想确认从头到尾仍然通顺。

这类情况仍应补一轮 `S0` 全链路开发复测，必要时再配合中后段基线做局部追踪。

## 维护规则

新增或调整首小时内容时，如果影响了标准阶段切点，需要同步更新三处：

1. `DevelopmentBaselineCatalog` 的阶段定义和用途描述。
2. `DevelopmentBaselineBuilder` 的任务推进、场景完成态和库存口径。
3. 相关检查与文档，确保基线、任务链和人工复测规则一致。

如果某个阶段已经不再适合作为稳定复测起点，应替换它，而不是继续堆更多一次性临时快照。

## 当前结论

首小时原型后续继续扩展时，人工复测的默认姿势应改为：

**先从最接近问题的开发基线开始，再决定是否需要回到 `S0` 全链路重跑。**
