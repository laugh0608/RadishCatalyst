## 反馈与目标

萝卜SAMA在查看 [Web Style Comparison Demo V1](web-style-comparison-demo-v1.md) 后反馈“似乎 Web 更容易，效果更好”，并希望进一步接近《银河破裂者》或《逃离鸭科夫》的俯视 / 斜俯视 3D 感。此反馈表明用户希望继续探索，不等于现有像素、手绘、Web 平台或正式迁移已经验收。

本提案将下一包定义为本机 Web 真 3D 场景：固定高斜角为主要观察方式，用真实几何、统一光照、接地投影与深度缓冲比较空间表现。画面追求可读的风格化工业体块与材质，不把参考游戏的完整内容、美术量产水准或运行性能承诺为本包目标。

## 五问与有限范围

1. **玩家结果**：在一块可走动的小型工业场坪内，观察设备顶面 / 侧面、不同高度管线、机器与角色前后遮挡，比较更高俯视和更低斜俯视的取景。
2. **实现介质**：新增 `tools/visual-studies/web-topdown-3d/`，使用 Three.js 的真实网格、材质、光源和相机；参考既有 Godot 3D 样件的几何设计，不直接运行 GDScript。主体为真实模型。
3. **成功证据**：浏览器实际移动 / 碰撞输入、相机档位、透明 / 不透明和投影开关的截图；记录测试视口与本机耗时，性能结论限当前有限场景。与现有 Web 2D 和 Godot 3D 原始证据共同评审。
4. **失败判据**：正常尺度仍像无厚度图标、模型接地错误、玻璃或层次遮挡严重失真，或性能不足以连续操作，则记录问题并缩小诊断范围；不靠堆设备数量、描边和辉光掩盖。同类两轮失败停止盲调。
5. **文档落点**：本合同承接下一包范围、授权与证据；用户确认后才更新 Current / Daily 活跃任务，本周周志记录实际实施。

提议的场景组成：

- 约 `24×18m` 工业场坪，以 `3` 种设备家族组成 `6–8` 个设备实例，保留可绕行的通道。
- 连续短管线、有限架空透明管与支架、少量高低平台 / 地形边缘，检验工业空间的层次。
- 一个可移动、能转向的简化三维工装角色；基础行走姿态仅服务观察，不接入正式战斗。
- 相机向下俯角以相对水平面的 `55°` 为起点，提供 `40° / 55° / 70°` 对照；这些是本包候选值，不声称是参考游戏的实际参数。支持有限缩放和方位旋转。
- 统一方向光、环境填充、接触阴影与金属 / 粗糙表面 / 玻璃材质。优先确认体积和空间，后处理只按实际可读性需要添加。

这是介质对照，豁免新增玩法专题十问。正式 Boot、存档、流体、建造系统、像素标准与平台路线保持现行边界；本包不承担内容迁移、联机、发布或完整工厂负载验证。

## 依赖与授权

当前仓库没有已声明的 Three.js / Babylon.js 依赖。建议只新增 Three.js，沿用本机 Node 和有限文件服务，不为此包引入 UI 框架或资产包。Three.js 官方提供本地 npm 安装与直接 ES module 使用方式，见 [Installation](https://threejs.org/manual/en/installation.html)。

拟在独立 Demo 目录执行：

```sh
npm install --save-exact --ignore-scripts --no-audit --no-fund three \
  --cache ../../runtime-intake/check-runs/web-topdown-3d/npm-cache
```

首次解析的发布版本写入 `package.json` 与 `package-lock.json`；依赖落在该目录的 `node_modules/`，缓存放入仓库忽略的检查目录。新增局部忽略规则，不修改全局 Node / npm / 编辑器配置，不使用运行时外部 CDN。

## 已实现与操作

- `24×18m` 厂坪、三台反应器、两台压缩机、两台储罐；十二段架空管、四副支架、低位管线与场坪边缘。静态网格按材质与投影属性合并。
- 工装角色使用三维身体与关节组，随移动转向、摆动四肢。角色约 `1.64m` 高，玻璃管底 `2.13m`、最低横梁 `1.96m`；有限平面碰撞覆盖设备基座、支柱和低管，不包含通用物理或高低地形行走。
- 正交相机默认俯角 `55°`、方位 `25°`，支持 `40° / 55° / 70°`、Q / E 每次转动 `15°`、滚轮及滑杆缩放。WASD / 方向键、点击地面和小屏方向按钮用于移动；观察位置按钮直接设置复核起点。
- 统一方向光、环境贴图照明、真实投影；玻璃开关比较透明与不透明遮挡，管内色样默认关闭。玻璃为双层网格 alpha 近似，色样是静态圆柱，未实现折射或流体。

启动 `sh tools/run-web-topdown-3d-demo.sh`，访问 [本地 Demo](http://127.0.0.1:4318)。前一 Web 2D 对照仍在端口 `4317`。两者只监听 `127.0.0.1`，不读写游戏存档。

## 实际验证与证据

- 六项 Node 定向测试通过：空心管 / 净空、碰撞、对角及相机相对移动、点击目标取消、角色姿态和本机文件服务边界。命令为 `node --test tools/visual-studies/web-topdown-3d/verify.mjs`。
- 浏览器保存十五张原图到 `assets/art-intake/2026-09-06-web-topdown-3d-preview/`：桌面 `1440×900 / DPR 2`，窄屏 `390×844 / DPR 2`。覆盖三档俯角、投影、光向、反应器前后、管下与透明 / 不透明遮挡、静态色样、碰撞、旋转放大、点击移动和小屏。
- 实际短按 W 从反应器前 `(0,-1.9)` 移至约 `(-0.7,-2.2)`，受基座阻挡；从管下短按移到约 `(-1.3,-2.2)`，同位置截图确认透明管后可见身体、不透明管遮挡身体。鼠标点击地面从入口移至约 `(-0.1,-0.1)`；小屏方向按钮三次短按改变位置。未把观察点定位或短按输入写成纯人工长时间绕行。
- 小屏宽度与 scrollWidth 均为 `390`，无横向溢出。临时视口覆盖已清除，默认入口 / 55° / 玻璃与投影开启 / 色样关闭状态恢复，预览保留。
- 默认视图报告 `102` 次绘制、约 `99768` 个渲染三角形。界面显示的是 `renderer.render()` CPU 提交平均耗时，截图约 `0.8–2.6ms`；不等于 GPU 帧耗时或 FPS，不推导大工厂性能。结构化记录在 `tools/runtime-intake/check-runs/web-topdown-3d/browser-result.json`。

首次安装 / HTTP 监听受沙箱限制，获授权后成功；初次合并混合索引几何失败，统一索引形式后通过。初始光照过曝，定向降低曝光和填充光；修正环境贴图模糊采样警告与旧投影常量，后续浏览器日志未见新警告或错误。完整截图曾因视口捕获失败而重试。最终视觉复核发现只关闭 shadowMap 会保留材质旧阴影状态，补充光源投影状态与材质刷新后，重新拍摄确认投影真实消失 / 恢复；不能以绘制次数减少代替视觉证据。

执行会话观察：40° 的侧面与管下空间最明显，55° 平衡体积与布局，70° 更偏布局观察。这是本样场判断，不是参考游戏参数。玻璃偏乳白、模型重复与细节简化仍可见；真实网格机制通过不代表量产美术验收。移动设备实机、长时操作、复杂透明交叉、战斗、生产、存档和联机均未覆盖。
