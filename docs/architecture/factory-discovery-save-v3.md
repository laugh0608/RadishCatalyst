# Factory Discovery Save V3

更新时间：2026-10-12

## 身份与严格校验

对应[范围供电与拾取](../features/factory-range-power-and-pickup-v1.md)。新身份为 `factory_3d / 3 / factory_discovery_auto_power_v1 / factory_discovery_yard_64_v1 / factory_discovery_starter_v1`。schema 3 改变连接语义，沿用 schema 2 的字段形状、预算、物料、发现、统计、活动时钟及文件发布合同；不伪装为 schema 2。

`power_links` 和各设备 `power_node_id` 保存为规范化的自动图快照。解码先完成原联合合同的全字段、守恒、位置、引用和统计校验，再按自动规则重算并核对连接完全一致；不以重算掩盖伪造或损坏字段。运行时唯一权威为实体布局、启停和矿道事实，连接不接受手工修改；网络编号与分配仍不保存。未知未来 schema、规则 / 地图 / 供给混配继续阻断备份回退。

## schema 2 升级

- 世界列表明确标记旧手动接线世界。玩家可按旧规则继续，或明确选择升级；选择升级时先说明范围自动接电与备份，玩家确认后才准备升级；取消不写世界、不持有写锁。
- 仍用原 schema 2 校验器读取候选，持有既有世界锁并核对来源及主档哈希。保持世界 ID、名称、实体 / 库存 / 批次、发现、统计、时间及余量，只启用自动模式并重算图。
- 正式视图成功重建后才接受升级。将来源原文写入独立 `backups/pre-auto-power-v2-<sequence>-<hash>.json`，校验哈希后再保存 schema 3；该副本不参与三个普通备份槽的轮换，不覆写不同内容。
- 沿既有临时写入、读回、哈希复核与原子改名发布；sequence 增加一次。任何备份、校验、读回或发布失败都保留旧主档及有效来源，关闭失败会话时释放自己的锁。
- 新程序仍可严格解码未升级的 schema 2；旧程序遇 schema 3 明确拒绝，不能回退旧备份。新程序在发现 schema 3 主档后也不自动回退为 schema 2 运行。

schema 1 与旧二维 schema 10 不迁移。本包不读取或批量改写用户正式目录，迁移路径在仓库隔离根验证，实际世界由玩家从菜单选择升级。

2026-10-08 后新勘探世界使用 [schema 4](factory-routing-save-v4.md)。10 月 12 日新建已接续 [V5](factory-admission-save-v5.md)。本篇保留 V3 自动电网与 2→3 合同；3→4 与 4→5 分别明确选择，不与范围供电升级合并。
