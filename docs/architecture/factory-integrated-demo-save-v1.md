## 权威字段

顶层沿世界 ID、名称、序号与 `state`，另增加完整身份中的定义哈希。字段精确白名单，未知 / 缺失不补默认值。

| 状态 | 必须保存 / 校验的内容 |
| --- | --- |
| 世界时钟 | `simulation_tick` 非负整数，固定 20 Hz；`remainder_s` 为已采样未消费活动时间，沿既有有界积压；暂停 / 离线不补产 |
| 通用生产 | 稳定实体 / 批次 ID、下一序号、人物位置 / 朝向、构件库存、背包、设备缓冲 / 在制 / 输出 / 进度与活批来源、采集 / 配方 / 制造计数 |
| 核心 | `core.entity_id / level / items / outputs / input_cursors / output_cursors`，实体表只有一座核心的几何 / ID，库存不在实体表另存一份 |
| 出料口 | 完整固定端口 ID 集，每口 `{id,item,enabled,cooldown_ticks}`；冷却 `0..20`，非物流 / 未知物品拒绝；空物品必须关闭 |
| 研究 | `research.completed`，排序、唯一、只含本内容包 7 个合法节点；B0 必须存在，无进行中 / 半扣料状态 |
| 发现 | `sample_taken`、既有两矿道开路等实际事实；试制次数从完成配方账推导，不单独存一份可伪造的解锁事实 |
| 电力 | 源 / 设备启用、自动图实际连接、G 完整燃料与 `burn_remaining_ticks`；显示秒数由整数 tick 派生 |
| 统计 | 采集 / 生产 / 消耗 / 交付、安装 / 可用 / 请求、核心实际供能、燃料释能、设备用电 / 待机、缺口 / 弃能 / 回收损失；累计和有限近期桶 |

`simulation_tick / 20` 派生模型时间；计数只接受有限、非负、可精确 JSON 往返的整数（不超过 2^53−1）。实体范围 / 总拥有量、库存、统计能量均使用当期定义和历史合法上界检查，不复用旧固定 165 / 326 / 240 假设。浮点累计容差沿既有 1e-9 等已确认口径，不能放宽整数。

首包不保存：核心 III、储能、控制器、脚本、优先负载组或 PWM 相位的空字段；这些在后续实际内容引入时有独立身份 / 映射。相机、鼠标焦点、轮廓、端口图标与已解锁效果为派生显示；不持久化第二份解锁列表。

## 核心与研究一致性

- 地图恰好一座核心，与 `entity_id` 相同、固定足印 / 端口 / 合法位置；等级仅 I / II。核心不在可制造 / 回收构件中，不能用库存伪造第二座。
- 每物品 `0..99,999`，游标仅引用合法端口；相同物品游标没有其他语义字段。所有已建 / 在制机器必须满足研究与等级；未研究的构件可以留在初始库存但不可放置。
- 已研究集合满足 DAG、核心等级和不可逆发现事实。核心 II 必须有 B1 / M1 / X1；不要从拥有产物反推已研究。
- 科技 / 核心升级 / 装配均在命令事务边界完成，快照不允许半笔支付。研究消费由已完成节点及冻结定义重建，等级消费由当前等级推导；不保存可以独立改小的“研究已消费”副本。
- X1 不消费唯一样本，真实样本消费只由 R02 配方账扣；`sample_taken` 与实际剩余 / 在制 / 消费总账一致。

## 完整物料与构件账

对每种物品：

```text
初始物料 + 实际采集 / 拾取 + 完成配方产出 − 完成配方投入
− 研究成本 − 核心升级成本 − 构件装配成本 − 开路消费 − 已激活燃料
= 核心库存 + 背包 + 机器输入 / 输出 + 在制原投入 + 在途 + G 完整燃料
```

在制原投入只在右侧计持有，完成后才进入完成配方账的投入 / 产出；不重复扣在制。位置迁移与自动出仓不算新增产出 / 消耗。经核心汇入共同库存的物品出仓时使用批次 0，仍按完整物料账核对。初始物料为零，唯一样本实际拾取加入一次；无限免费库存不可通过定义之外字段注入。

构件初始数量 + 累计真实装配产出 = 已放实体（含不可回收核心一次）+ 构件库存；研究赠送不再另送已有起步件。上限含场内与库存，不只限制场内。核心升级消耗的是物品构件包，不凭空销毁 / 产生设备构件。

## 固定燃烧与能源账

G 的 `burn_remaining_ticks` 取 `0..burn_duration_ticks`；候选 60 秒为 1,200 tick，不接受浮点或超时。未激活燃料总数 ≤5；本步激活只扣一次，初始剩余 0。G 停机 / 暂停 / 离线保留整数余时。

```text
激活颗数×单颗能量 = fuel_released_kj + Σ(余时 tick×STEP×额定 kW) + discarded_kj
base_supplied_kj + fuel_released_kj = used_kj + spill_kj
0 ≤ standby_kj ≤ used_kj
```

每个累计和近期桶的量有限、非负、来源一致。累计释能不能超过已激活能量；弃能不能超过释能；核心实际供能不能超过当期合法核心功率×活动时长。各历史阶段的上界由当期定义推导，不拿目前布局已拆设备数约束过去。

旧 V8 的 `cell_supplied_kj` 不重命名后套入新释能字段：旧规则实际按需送能，新规则包含弃能，语义不同。首包无储能，供用差由 `spill_kj` 显式解释；新世界能源历史从零开始，不制造复制来源或追扣旧历史。

## 文件事务与读档顺序

复用已实现 Store 的世界创建锁 / 单写入会话、预期主档序号 / 哈希、临时文件、严格读回、三槽备份与原子发布。单文件内同时保存核心、研究、机器、发现与能量账；禁止分多个独立文件分别提交库存和研究。

1. 识别完整身份 / 定义哈希，检查未来版本和主档 / 备份身份冲突；不支持的主档不回退成旧规则。
2. 获得单写锁并验证文件结构 / 数量 / 数值边界，创建对应权威模型；未知字段 / 科技 / 配方失败并保留原文件。
3. 验证等级 / 研究 DAG 与发现、核心唯一性、实体 / 构件 / 物料全账、固定燃烧和统计时间轴；重建占用 / 端口与自动电图，核对连接。
4. 场景重建成功后才接受会话，第一步模拟之前恢复冷却 / 余时 / 积压；重建失败释放锁，不覆盖主档。
5. 主档确属损坏且同身份备份有效时按已有显式恢复流程处理；全部损坏明确失败，不能新建空世界伪造恢复。

保存失败暂停并保留内存 / 原文件，允许重试或明确退出选择；成功后序号单调增长。发布后释放锁失败显式报告警告，不伪装成未创建。新档不能被旧客户端当成基础 V1 解码；旧版本未来身份阻断须纳入测试。
