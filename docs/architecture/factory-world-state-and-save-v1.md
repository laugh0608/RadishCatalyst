## 用途与适用范围

承接 [Factory Foundation And Persistence V1](../features/factory-foundation-and-persistence-v1.md)，定义 Godot 3D 工厂的状态权威、新旧世界边界和保存 / 恢复合同。功能与规模以该专题为准；本文不包含多人实现、离线收益、旧世界导入或量产美术规范。

用户已认可同规则 Godot Demo 的画面方向与操作，精细度暂缓。已将可复用成果接入正式工程，旧二维实现及其证据继续保留。

## 状态、输入与渲染

- 世界状态为不依赖 `Node2D / Node3D` 的数据对象；设备由稳定正整数 ID 标识，删除后不复用，`next_id` 必须大于所有已分配实例 ID。
- 逻辑格使用二维整数 `(x, z)`；显示映射到三维 X/Z 平面，每格沿用样件单位。足印、端口与物流均从定义和实例位置派生，高度不改变地面拓扑。
- 放置 / 拖铺 / 拆回 / 投入由协调层接收命令并提交给权威模型。UI、视图、动画和性能脚本不能直接写库存；批量命令先完整校验，失败零变更。
- 常驻维护 ID、格位占用与端口邻接索引，在有效结构变化时更新局部邻接；生产步不重新遍历整个地图构建索引。索引可随时从状态重建，不持久化。
- 生产保持 20Hz、1 格/秒与原配方；模拟时间独立于渲染。长帧的未处理活动时间保留并计量，不使用 `min(delta, 0.1)` 丢弃时间；每帧推进预算与持续积压必须可观察。
- 停止生产的会话态包括手动暂停、失焦、加载 / 保存退出确认；这些时间不追加到生产时钟。正常运行中的调度余量随快照保留，关闭后不按系统日期补产。
- 设备和物流的进度、货物入口方向、争用轮询游标均由模型持有；视图只插值和显示。分区隐藏节点不能暂停区域内生产。
- 同类模型按实际瓶颈合批 / 分区，拾取先定位空间候选；不能用改变已认可端口、弯道或物品数量换取性能数字。
- 工厂协调层直接处理自己的物理键码和鼠标事件；工厂与旧世界不同时实例化，避免旧 `E` / `Q` / 数字槽消费同一输入。本包未新增全局 InputMap 名称或改动 `project.godot`；切换世界时释放输入和取消预览。
- 工厂节点显式配置纹理过滤与 3D 目标尺寸，不修改旧二维全局像素过滤；在普通 / 最大化 / 缩回窗口下保持画面与拾取坐标一致。

## 世界和存档边界

首包实现采用独立类型与格式：

| 字段 / 位置 | 实现 |
| --- | --- |
| 世界类型 | `world_kind = "factory_3d"` |
| 工厂格式 | `save_schema_version = 1`，独立于旧切片 schema 10 |
| 规则标识 | `ruleset_id = "factory_foundation_v1"`；地图和供给配置引用各自稳定 ID |
| 默认目录 | `user://saves/factory/worlds/<world_id>/` |
| 主档与临时档 | `autosave.json`、同目录 `autosave.tmp.json` |
| 恢复副本 | `backups/autosave.bak.1.json` 至 `3.json` |
| 列表信息 | `metadata.json` 为可重建摘要；主档中的身份 / 版本与世界状态为真相 |
| 工厂世界数 | 首包最多 30 个；不新增永久删除或复制世界 |

不把旧切片 schema 10 升成 11，不修改旧世界类型、目录或迁移路径，也不把二维位置改名为三维坐标冒充迁移。工厂服务拒绝旧档；旧入口继续使用原服务。测试存档通过构造 / Boot 注入根目录，与用户路径完全隔离。

新存档包含世界和人物，不创建跨世界角色库存。本地窗口 / 音量偏好沿用独立设置；新地图或规则版本不默默解释为旧版本。未来兼容变更另写迁移合同。

## 快照最小合同

| 状态组 | 必须保存 | 关键校验 |
| --- | --- | --- |
| 身份 | 世界 ID、类型、schema、规则 / 地图 / 供给 ID、保存序号、展示名称 | ID 与目录匹配，已知类型 / 版本，不信任外部路径 |
| 时钟 | 已推进时间和不足一步 / 尚待处理的活动时间 | 有限、非负；恢复不会凭系统时间补产，畸形积压拒绝 |
| 人物 | 平面位置与朝向 | 有限、在合法范围且不落入设备阻挡；不以默认出生点掩盖坏档 |
| 资产 | 剩余构件、回收箱、世界配置确定的初始供给 | 非负整数、类型合法、容量正确；剩余与在场构件总数守恒 |
| 实例 | ID、类型、原点、带方向、下一个 ID | 唯一、有效足印、无占用重叠、矿点合法、方向合法 |
| 采集器 | 缓冲与采集进度 | 缓冲 0–50，进度属于有效采集周期 |
| 反应器 | 输入、输出、加工中标志、加工进度与批次标记 | 输入 0–2、输出 0–1；在制批次已扣两份晶体，不能载入时再扣或再发 |
| 终端仓 | 各种物料实际数量 | 只接受当前物料类型，总量不超过 200 |
| 传送带 | 货物、推进进度、入口方向、轮询游标和货物批次标记 | 每格最多一件、进度 0–1、入口与方向合法；空带状态一致 |
| 累计统计 | 采出晶体、完成批次、实际输送入仓等计数 | 非负整数、物料当量一致；手动投入不重复增加输送统计 |

JSON 的整数语义须显式校验，不能用强制取整接受 1.5 个物品。拒绝 NaN / Inf、重复实例、未知字段 / 版本和不一致状态；不得静默删掉坏实体后称读档成功。

轮询游标和批次来源可指向已拆除的历史实例 / 批次，不能要求该实例仍在场；但数值范围须与已分配序列一致。拓扑、可达状态、缺料 / 回压标签、可见模型、选中项、拖铺预览和相机跟随过渡都从合法快照重建或重置，不保存第二份真相。

## 保存、恢复与失败合同

### 保存时机

- 新建世界先生成并完整校验初始状态，成功发布初始主档后才进入。
- 建造 / 拆回 / 投入及人物移动触发 2 秒脏状态合并保存。持续生产另每 30 秒请求一次保存，不能仅等用户建造才保存进度，也不能每次物品移动都写 JSON。
- 显式保存、保存返回和正常关闭窗口强制处理当前一致快照。首次用同步发布，独立测量停顿；若超预算再按实际耗时拆分工作，不提前加线程框架。
- 保存成功后才清除对应脏状态并完成返回 / 退出。失败保留内存、脏状态、主档与有效恢复候选，显示原因；用户可重试或明确选择不保存退出。

### 读取与发布

1. 获取世界写入权并检查目录身份。按主档、备份新到旧读取候选，读取和完整校验阶段不写盘。
2. 识别到未来 schema / 未支持规则时明确拒绝继续，不因旧备份恰好可读就自动回退版本。普通缺失 / 损坏才按已支持恢复合同尝试备份。
3. 在隔离的候选状态中重建实例、占用、物流、人物与必要视图；全部成功前不允许自动保存，也不显示可继续操作的半个世界。
4. 恢复候选携带来源和内容哈希；提交前再确认候选未变化。来源变化或完整重建失败时保留文件，返回明确失败。
5. 对待保存状态做完整校验，同目录写临时文件、关闭并读回校验；安全保留现有有效副本后才原子替换主档。不得把唯一有效备份轮换掉后再尝试写主档。
6. 使用备份恢复时，原恢复来源在主档成功发布前保持不变。遗留临时档不自动升级为主档；主档 / 备份全部无效时保留证据，阻止空世界覆盖。
7. 元数据由已提交主档重建。主档已成功、摘要更新失败时分别报告“进度已保存”和摘要警告，不把两者混为全成功或全失败。

### 单写入方与实现复用

- 同一世界只允许一个可写会话；第二个客户端尝试打开时明确阻断，不以最后写入覆盖另一个会话。
- 用原子取得的世界锁记录会话身份；正常退出只释放本会话持有的锁。异常退出遗留锁不能按超时自动抢占，须确认所有者已退出再通过显式恢复流程释放；所有者无法确认时保留阻断。
- 保存序号和来源哈希辅助发现外部更改，不能替代独占写入。锁取得、冲突、退出清理与异常恢复须在本机及目标 Windows 环境分别验证。
- 工厂调度由 `app.gd` 的 `_tick_save` / `_save_now` 负责，未复用 `SliceSaveScheduler` 实例；文件协议由 `save/store.gd` 独立实现，严格快照由 `save/codec.gd` 负责。少量协议代码重复用于限制旧迁移链回归面，不复制旧内容校验或把 3D 分支堆进旧服务。
- 若实施发现必须改变旧保存协议才能复用，应将具体影响另行提出；本包不进行无边界的“统一所有存档框架”重构。

- 新字段、目录、锁和保存触发已在获批 P1–P3 范围内实现；未来 schema 的迁移规则仍未选择。

## 实现细节与尚未闭合项

- `model.gd` 是 `RefCounted` 权威状态，常驻维护格位、ID 和传送带邻接；每帧最多推进 8 个 20Hz 步。`active_clock.gd` 使用 `Time.get_ticks_usec()` 归集活动区间；暂停 / 失焦切换时结算切换前的余量，加载完成才开始新会话，关闭后不按日期补产。正常同步保存停顿计入活动时间，失败后暂停；移动仍使用原有受限 delta，不因长帧瞬移。脏状态保存按实际帧间隔计时，生产保存按累计活动时间计时。
- 实机无窗口探针中，约 1.179 秒长帧只得到约 0.135 秒引擎 delta，证明原上层输入会漏时；原长测还包含失焦与采样边界，不能声称历史全部差额已逐帧归因。新时钟的正式 Boot 长帧 / 延迟 IO 定向检查通过；性能脚本按同一已处理边界比较墙钟与“推进时间 + 余量变化”，容差 10 微秒用于微秒采样及浮点运算，不允许少一个 50 毫秒步。30 分钟窗口验证继续待验。
- 暂停与失焦取消未提交拖铺；保存失败暂停世界并保留内存 / 脏状态，提供重试、留在世界和二次确认放弃进度。二次确认归属于失败对话框，避免两个独占子窗争用根窗口；取消与确认放弃已有无窗口按钮信号证据，原生窗口仍待复验。成功重试后暂停状态仍由玩家恢复，不把异常期间当生产时间补产。
- 世界锁使用原子创建的 `session.lock/` 目录和带 PID / token / host 的 `owner.json`；根目录 `creation.lock/` 串行化新建和 30 世界上限检查。显式恢复用 `recovery.guard/` 防并发；列表选中世界时恢复该世界锁，未选中且存在创建锁时恢复创建锁。
- 同 PID 视为活跃，其他主机或无法判断进程时拒绝恢复。macOS 用 `/bin/ps -p <pid> -o pid=` 只读查询，Windows 使用 PowerShell 进程查询；不能用只识别自身子进程的 `OS.is_process_running()` 判断其他客户端。macOS 分进程冲突 / 恢复已有证据，Windows 查询与文件替换尚未实测。
- JSON 写入使用完整浮点精度，临时档读回按原字节 SHA-256 与完整解码校验；整数数量 / 批次要求完全一致。解析器约一个 ULP 的浮点差异在时钟往返检查中用 `1e-12` 秒绝对误差处理，不据此放宽数量或非法值校验。
- 工厂正式资源引用仅指向 `res://assets/factory/`。14 个 GLB 沿用已批准的仓库内 Demo 导出，原始大小与哈希见 `source-manifest.json`；本包未下载外部资产。源码依赖与验证夹具分离，测试可引用 Web 期望，正式运行不依赖 `tools/`。
- 实际验证及未覆盖分支以[首包专题](../features/factory-foundation-and-persistence-v1.md)和 [W37 周志](../devlogs/2026-W37.md)为准。本文的目标合同不能被读成所有平台和故障路径均已通过。
