## 固定步与统计

规则常量提供采集 / 粉碎 2 kW、炉 6 kW、组装 / 反应 4 kW。未启用时工作与待机请求均零；V7 及其他旧规则的工作规格明确返回零待机。运行额定不叠加待机，消费者公平满足率和基础源优先不变。

每个 0.05 秒步由起点状态预算：有工作时 `w=min(dt, 剩余工作秒数)`，否则 `w=0`。电网请求 `Pr*w + Ps*(dt-w)`；同网满足率 `f` 同比作用于工作进度、运行能量和待机能量。欠供后不把尚未完成的工作预算二次折算待机。电网只生成计划，模型固定步提交实际供电 / 燃料，统计随该步累计；暂停、离线、查询及视图刷新不补账。

V8 在统计 `totals`、`current` 和各历史桶增加 `standby_kj`；运行用电由 `used_kj - standby_kj` 派生，不存两份可分歧的累计量。当前功率面板和最近 600 秒曲线同源展示。

```text
基础实际供电 + 电芯实际供电 = 总实际供电 = used_kj
运行实际用电 + standby_kj = used_kj
0 ≤ standby_kj ≤ used_kj
```

严格校验器先按模型规则检查精确字段，再投影公共统计字段交给时间轴校验。新增电量必须有限且非负，不能超过合法拥有消费者待机上限乘以记录时长；近期待机与派生运行均不能超过累计，完整历史期要求桶与累计相等。V7 不接受 `standby_kj`，V8 缺项也不默认补零。浮点比较沿既有能量容差，物料 / 制造整数不放宽。

电芯激活、供能、回收损失、余能与完整物品守恒沿 V7。设备 `enabled`、输入 / 在制 / 输出、半批进度和被动物流字段不变；图标、焦点、轮廓及鼠标模式属于派生视图，不持久化。

## 保留源档的复制

`energy_copy.gd` 复用原创建锁、来源锁、主档序号 / SHA-256 比对、隐藏暂存目录、严格读回与目录原子发布事务，仅扩展为有效 V6 / V7 主档输入、V8 输出。取消不写入；坏主档待恢复、锁占用、来源变化、写入或读回失败均拒绝。主档 / 三槽备份身份不得混用，未来身份继续阻止回退。

- V6 先按 V7 已有映射增加零能源字段和消费者启用标志，原用电历史归入基础供电，再增加零待机历史。
- V7 保留全部人物、布局、库存、在制、余能、制造账及能源历史，仅向每条统计记录加入 `standby_kj=0`；不补发电芯、构件或材料。
- 两者均生成新世界 ID，记录直接来源的 `source_id`、`source_sequence`、`source_sha256`，初始序号为 1。旧用电仍全部计为运行用电，复制之后才开始计待机。
- 源字节始终保持，复制后的两份进度独立。发布成功但释放来源锁失败时保留既有明确警告，不伪装成未发布。

`codec_v8.gd` 在完整身份校验后复用 V6 / V7 的公共实体、物料与时间轴重建，避免另一套能源状态结构；任何未知字段或非法组合仍拒绝。复制不是任意世界克隆或通用修档入口。

## 检查与证据

入口见 [Tools](../../tools/README.md#正式工厂定向检查)：`check-factory-energy-feedback` 覆盖固定步、独立恢复、正式菜单、自然 Boot 与窗口反馈；`--legacy-source` 只从成功旧 E2 检查批次另建副本，再通过正式复制事务接续。原 `check-factory-energy` 状态脚本保留 V7 规则回归。

状态夹具、自然主循环、模拟输入操作和截图分别记录；同源对照剔除新世界 ID / 名称后必须完全一致。所有证据位于忽略目录，不消费用户活动世界。开发机通过不代签 Windows、目标硬件或玩家体验。
