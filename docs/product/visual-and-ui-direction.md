# Visual And UI Direction

更新时间：2026-06-25

## 文档目的

这份文档用于在进入 MVP 功能清单和具体界面制作之前，先明确 RadishCatalyst 的美术气质和 UI 方向。

它回答以下问题：

- 游戏整体看起来应该像什么。
- UI 应该偏工程终端、ARPG HUD，还是后台管理面板。
- 冒险、基地、设备、地图、Wiki 和官方工具之间如何保持视觉一致。
- 哪些视觉方向当前不采用。

## 总体视觉结论

RadishCatalyst 的视觉方向是：

**清晰克制的工业科幻现场界面，叠加危险异星生态和化工设施的可读性。**

它不应是纯硬科幻仿真软件，也不应是厚重赛博霓虹或明亮卡通工厂。正确感受应接近：

- 玩家在一颗异常星球上操作真实可用的前哨基地。
- 设备、管线、储罐、污染和危险状态都能被快速读懂。
- UI 有工程终端感，但不会变成专业软件考试。
- 冒险画面仍然优先保证角色、敌人、弹道、危险区域和可交互物的清晰度。

## 美术气质

### 核心关键词

- 工业开拓。
- 异星生态。
- 危险现场处置。
- 化工设备可读性。
- 克制科技感。
- 明确状态反馈。

### 推荐画面方向

- 2D / 2.5D 俯视或斜俯视表达，优先保证战斗和基地布局可读。
- 基地设施应体现反应、分离、储运、供能、污染处理等工业功能，而不是泛用科幻盒子。
- 新档首屏应先像可维修的工业现场：浅色岩地、金属平台、损坏核心、局部管线、维修端口和玩家姿态要共同说明“正在恢复前哨”。
- 异星区域应有明显生态与地貌差异，例如腐蚀滩地、晶化矿脉、污染雾区、遗迹裂隙、活性菌毯。
- 时间和天气应服务可读性与危险提示，例如夜晚、雨雪、酸雾、粉尘和孢子雨不能遮蔽关键敌人、资源和交互点。
- 颜色用于区分物质、危险和系统状态，不能只作为装饰。
- 设备轮廓、敌人轮廓、掉落物轮廓要优先清楚，避免复杂背景吞掉玩法信息。
- 程序绘制可用于占位、动态高亮和检查辅助，但不能让圆环、矩形、跨屏线和半透明规划层成为首屏主读法。

### 多星球视觉差异

RadishCatalyst 可以以统一的工业科幻基地语言为核心，通过不同星球的生态、地貌、污染形态和资源体系形成视觉与玩法差异。

统一部分：

- 基地设备、管线、储罐、反应器、污染处理设施保持同一套工程识别语言。
- UI、图标、颜色语义、信息层级和官方工具视觉保持统一。
- 物品、资源、设备、区域和危险等级使用同一套分类与数据 ID。

变化部分：

- 星球地貌和主色调。
- 原生生态、晶体、矿脉、菌毯或遗迹结构。
- 污染颜色、扩散形态和危险表达。
- 资源类型、采集方式和设备需求。
- 怪物轮廓、生态行为和环境适应性。

推荐方向示例：

- 首颗星球：冷白日光、蓝绿色晶体生态、浅色岩地、少量黄色污染，作为项目标准视觉基准。
- 腐蚀星球：黄绿酸雾、盐壳地貌、腐蚀湖、耐腐蚀管线，强调污染治理和材料防护。
- 赤铁荒漠星球：红褐岩层、金属尘暴、裸露矿脉、高温设备，强调采矿、散热和粉尘处理。
- 冰封挥发物星球：蓝白冰原、低温储罐、蒸汽羽流、冻结管线，强调低温流体和保温。
- 生物催化星球：菌毯、发光植被、生物反应池、活性孢子，强调生态风险和生物样本。
- 遗迹星球或区域：几何结构、异常能量、古代工艺核心，强调主线调查和秘境挑战。

设计边界：

- 不同星球不应只是换色皮肤，必须对应不同资源、危险、设备需求或探索准备。
- 不同星球也不应像完全不同的游戏，玩家仍应一眼认出这是同一套基地、UI 和工业科幻规则。

### 当前不采用

- 不做纯写实硬科幻，让每个界面像真实工控软件。
- 不做霓虹赛博朋克，把画面重点变成光污染和城市夜景。
- 不做可爱休闲工厂风，避免削弱危险异星和现场处置感。
- 不做纯后台管理系统，玩家仍然要亲自探索、战斗和移动。
- 不用单一色系统治整个游戏，基地、野外、污染、遗迹和 UI 状态需要可区分。

## UI 总原则

UI 要服务两种节奏：

1. 冒险状态：玩家正在移动、战斗、探索和规避危险。
2. 基地状态：玩家正在规划、制造、排障和查看生产状态。

设计原则：

- 信息清楚优先于装饰复杂。
- 核心状态常驻，深层细节按需展开。
- 鼠标键盘优先，后续再考虑触控和手柄适配。
- 图标、颜色、标签和数字共同表达状态，不只依赖颜色。
- UI 允许有较高信息密度，但不能遮挡角色操作和地图观察。
- 同一个物品、设备、区域、怪物在游戏内、Wiki 和官方工具中使用同一套名称、图标和分类口径。

## 信息密度分层

### 第一层：即时生存信息

始终保持可见或半常驻：

- 生命。
- 护盾或防护服完整度。
- 体力 / 能量。
- 当前武器、弹药或技能资源。
- 技能冷却。
- 快捷物品。
- 锁定敌人的生命、威胁、状态和最近命中承压。
- 当前环境危险，例如毒雾、腐蚀、辐射、污染浓度。
- 当前时间或天气危险，例如夜间低能见度、酸雾、粉尘、低温、孢子雨。

### 第二层：当前任务和现场提示

在玩家需要时出现：

- 当前目标。
- 附近可采集资源。
- 危险区域边界。
- 设备异常提示。
- 背包容量或关键材料不足提示。
- 主线调查线索。

### 第三层：规划与反查信息

只在面板、地图、Wiki 或官方工具中展开：

- 配方上下游。
- 设备输入输出。
- 产能、瓶颈、库存和副产物。
- 区域资源分布。
- 怪物掉落。
- 污染扩散趋势。

## 冒险 HUD

冒险 HUD 应偏 ARPG，而不是工程面板。

必须优先表达：

- 玩家是否安全。
- 当前能不能战斗。
- 还能不能继续深入。
- 周围有什么危险。
- 关键补给是否不足。

推荐结构：

- 左下或左上显示生命、防护、能量等角色状态。
- 底部显示武器、技能和快捷栏。
- 角落显示小地图、危险层级和当前目标。
- 危险状态使用边缘提示、地面覆盖层或简洁图标提示，避免大段文字弹窗。
- 进入污染、腐蚀、低氧或异常能量区域时，HUD 应快速告诉玩家危险类型和剩余安全余量。
- 天气或昼夜变化影响外勤时，HUD 应用简洁图标和短标签提示风险，不用大段文字打断战斗。
- 当前原型的主 HUD 已去掉 `Prototype` 标题，并把目标、关键资源、基地摘要、角色状态、快捷补给、行动状态条和战斗现场拆成固定分组；底部只保留当前交互与行动日志的一行摘要，基地摘要用外勤输入、基地加工、整备收益、污染承压和核心写入短读法说明当前循环段，远景说明、开发注释和长场景文案不常驻遮挡操作视野。

不建议：

- 在战斗中展开复杂生产统计。
- 用大量文本说明当前所有状态。
- 把基地设备异常强行覆盖在战斗中心区域。

## 基地与设备面板

基地 UI 应偏工程终端，但保持游戏化。

设备面板需要稳定表达：

- 设备名称、等级、状态。
- 输入、输出、副产物。
- 当前库存和容量。
- 当前处理速率。
- 能源消耗。
- 关键工艺条件，例如温度、压力、纯度或稳定性。
- 异常原因，例如堵塞、缺料、满仓、过热、压力异常、污染超标。
- 当前配方是否可执行；不可执行时必须显示原因和下一步建议。
- 加工完成后产物进入哪里、下一次外勤或基地操作应该做什么。

表达方式：

- 用图标和短标签表达材料与状态。
- 用条形、环形或小型趋势图表达容量、速率和危险余量。
- 用明确颜色表达状态：正常、等待、警告、故障、停机。
- 对复杂工艺参数做游戏化抽象，不要求玩家理解真实化工公式。
- 首版 Demo 的基础反应器和污染过滤器优先采用“配方 -> 输入 / 产出 -> 状态 -> 下一步 -> 操作”的结构；不要只显示一个缺料结论。

## 交互提示结构

靠近采集物、样本、建造点、清障点或设备时，提示必须帮助玩家判断三件事：正在操作谁、为什么操作、不能操作时下一步做什么。

当前原型采用这组基础结构：

- 普通采集 / 采样：对象、用途、产物或样本、状态、操作。
- 设备加工：设备、配方、输入 / 产出、状态、下一步、操作。
- 建造 / 清障：建造点或地块、材料或工具、前置状态、阻塞原因、下一步、操作。

提示可以短，但不能只写“条件不足”“缺少材料”这类结论；必须说明是补资源、清障、铺地基、回设备加工，还是等待当前加工完成。

基地总览需要帮助玩家发现：

- 哪条生产链缺料。
- 哪个设备成为瓶颈。
- 哪个储罐即将满。
- 哪片区域污染或事故风险升高。
- 当前基地能否支撑下一次远征。

## 地图视觉

地图不是单纯导航工具，也应服务“基地支撑冒险，冒险反哺基地”的循环。

地图至少应预留这些层级：

- 地形与区域边界。
- 已探索 / 未探索。
- 资源点。
- 危险等级。
- 污染或异常能量覆盖。
- 当前时间和天气状态。
- 任务线索和调查点。
- 可回收设施或遗迹节点。
- 已建立的前哨、传送点或补给点。

地图视觉应与游戏内地貌保持一致，不要变成完全抽象的表格。资源、怪物、危险和设备图标应与 Wiki / 官方工具共用同一套分类。当前原型阶段允许用场地块、主路、关键对象框、危险 / 设施 cue 和当前目标导引表达优先级，但这些 cue 必须服务玩家眼前路线，不能把整张 12 区规划图压到启动视野里。

## Wiki 与官方工具视觉一致性

玩家 Wiki 和官方工具不需要复刻完整游戏 HUD，但必须共享识别系统。

应保持一致的内容：

- 物品、设备、区域、怪物、配方的稳定 ID。
- 显示名称。
- 图标风格。
- 分类颜色。
- 稀有度或危险等级表达。
- `public`、`spoiler`、`internal` 的公开等级口径。
- 输入、输出、副产物、来源和用途的展示顺序。

官方工具的视觉应更偏数据查询和规划：

- 信息更密集。
- 表格、筛选、依赖图和反查链更重要。
- 不使用过多游戏内装饰。
- 仍保持工业科幻终端感，使它看起来属于同一项目。

## 可访问性与平台适配

从方向阶段就要预留：

- 字号可读，不能把关键数字压得过小。
- 颜色之外还要有图标、形状或文字状态。
- 高危提示需要有足够对比度。
- 鼠标悬停、键盘快捷键、后续触控点击区域要能共存。
- Web 技术验证和 Android 远期适配不能依赖过小按钮或过密悬停信息。

## 当前阶段结论

当前不需要制作完整 UI 规范、组件库或高保真界面，但首版 Demo 不能继续停留在 debug 色块、长文本标签和流程图式地图。

当前需要固定的是：

- 美术气质：工业科幻现场 + 异星生态。
- 低保真底线：玩家、敌人、设备、资源、污染和核心目标至少有轮廓、材质色、状态和用途关系；旧大色块只能做低权重底纹，主要读法应来自局部工作面、地貌材质、状态灯、物料槽、端口框和站内短流带。
- 基地优先：前哨核心、基础反应器、污染过滤器、储存箱和出发整备台要先像工业设施。
- UI 气质：克制、高可读、工程终端感；启动界面可以用受损前哨、核心灯、管线和污染远景建立第一印象，但进入游玩后首屏不能由调试面板和长说明主导。
- 冒险 HUD：ARPG 优先，少量环境危险提示；场景内提示优先短标签、图标、描边或高亮。
- 地图：资源、危险、污染、探索和任务线索并重；原型视觉先保证基地、晶体、污染、遗迹 / 异常和核心稳定站的可读差异，不能让跨屏长路线、场景大标签或旧区域色块压过当前设备工作面。
- Wiki / 官方工具：与游戏共享名称、图标、分类、ID 和公开等级。
