# VOXELSKY 对照复盘与切片方向建议

更新时间：2026-07-18（Asia/Shanghai）

来源：一次围绕 AI 生成 3D Demo（VOXELSKY）、RadishCatalyst 旧 2.5D 路线失败根因与当前像素切片方向的外部对话复盘，经架构复核会话核对仓库现状后修订入库。

> 本文属参考材料，不是当前规范。当前阶段、活跃专题和冻结边界以 `docs/planning/current.md` 与当前 `docs/features/*.md` 为准；本文的现状快照按 2026-07-18 仓库实际状态修订，原对话中"存档接线推进中"等描述已过期并更正。

## 一、执行摘要

1. VOXELSKY 的成功不能归结为"3D 比想象中容易"。它选择的是非常适合 AI 和程序实现的 3D：体素、第一人称、程序生成、简单材质、合成音频，主动避开传统 3D 最昂贵的建模、绑定、角色动画、复杂材质和关卡美术。
2. 旧 2.5D 路线的失败也不能归结为"2.5D 太难"。根因是旧路线试图让一张最终画面同时承担场景布局、碰撞、交互、状态变化、遮挡和 HUD 安全区，信息方向与游戏运行时需要相反。
3. 当前像素 + 2D 俯视网格路线已修复根因：世界重新由 `TileMapLayer`、`Sprite2D`、场景节点和运行时状态组成，最终画面由可编辑对象正向产生。
4. 不应因看到优秀 AI 3D Demo 就重回 3D。现阶段最重要的不是再选介质，而是连续证明"工业转化"和"冒险压力"两个核心产品环节。

一句话总结：

> RadishCatalyst 以前不是败给 2.5D 的技术难度，而是败给"用不可编辑的最终画面承载高度可变的游戏状态"；当前像素切片已纠正方向，下一步应停止证明基础设施，转而证明基地加工确实能够改变冒险。

## 二、VOXELSKY 要点

纯前端 Three.js 体素宇宙沙盒 Demo：无后端、无框架，`localStorage` 存档，Web Audio 合成音效，Canvas 运行时生成纹理，自研 JS 约 5400 行。

它显得内容丰富，靠的是大量"成本较低但感知很强"的系统：第一人称移动与喷气背包、采矿建造、生命维持、物品栏合成科技交易、飞船起降、太空飞行、扫描任务罗盘、HUD 动效与转场。这些系统不追求真实模拟，只保证玩家能感知到动作、目标和变化。

它主动绕开的高成本问题：第一人称避开主角模型和角色动画；体素风避开建模、UV、PBR；程序生成避开手工关卡美术；手写运动插值代替物理模拟；少量固定类型 + 种子代替五套行星内容；本地存档避开后端。技术分类上是 3D，但没有承担传统 3D 的完整生产成本。

AI 擅长它用到的一切：Three.js 渲染循环、Simplex Noise、体素区块、射线检测、第一人称控制、Web Audio、DOM HUD、简单状态机——都是输入输出明确、模式常见、可局部验证的标准算法组合。AI 不擅长的恰是旧路线要求的：多批次复杂场景统一透视、精确交互插槽、同一设备多状态严格一致、一张画面同时满足布局 / 碰撞 / 遮挡 / HUD 安全区。

## 三、旧路线失败根因

### 3.1 信息方向相反

VOXELSKY：游戏状态 / 坐标 / 种子 → 生成几何与材质 → 摄像机产生最终画面（确定性正向生产）。

旧 2.5D 整景路线：先生成一张最终场景图 → 再从图中反推道路、设备、碰撞和交互区域 → 再叠加状态变化与 HUD（从最终像素反推游戏结构的逆向问题）。

游戏需要的是"受损核心 = 一个有位置、碰撞、交互、状态和持久化 ID 的对象"；旧路线得到的是"一张包含受损核心的图片"。当核心需要修复、发光、改变碰撞、参与存档或被 HUD 指向时，整景图无法充当可靠的游戏状态载体。

### 3.2 其余四条根因

- 表现介质与游戏状态冲突：生成式图片可偶得优秀构图，但难以持续保证统一透视、可行走路径、多状态切换、多场景一致性，也难以低成本产出第二、第三张变体。
- 首版范围叠加过多专业：人物战斗 + 基地化工 + 12 区纵切 + 复杂 HUD + 写实场景一致性，是环境美术、角色动画、UI、关卡、技术美术和系统设计的叠加，不是单纯编码问题。
- 开发顺序倒置：在证明"核心循环是否有趣"和"美术介质能否稳定量产"之前，过早积累系统、formatter、检查和文档，仓库长期工程能力强、可识别的游戏体验弱。
- 把路线问题当局部调参：程序几何、SVG、线框标签、更多提示词候选反复尝试，但根因是介质无法稳定表达可编辑对象。后来的"两次失败停手规则"和决策闸门正是对此的治理。

底层错误是能力错配：旧路线期待 AI 用自然语言稳定控制复杂视觉约束（AI 弱区）；VOXELSKY 让 AI 组合标准可验证的程序模式（AI 强区）。

## 四、当前现状判断（2026-07-18 修订）

### 4.1 根因已修复，且证据超出原对话快照

现路线信息方向：`TileMapLayer` / `Sprite2D` / 场景节点 / 运行时状态 → 组合世界 → 状态变化替换具体节点 → 摄像机产生画面。与 VOXELSKY 的正确部分同属一种信息结构。

截至 07-18 已收口：基地首屏与四方向行走、无缝大地图与相机跟随、最小核心循环（采集 → 修复换态 + HUD 三要素）、存档持久化（独立 `SliceSaveService`，双进程闭环 42 项断言）、采集与建造（整备台制造采集器 + 放置 + 每 10 秒自动产出进存档）。首条化工链第一步（采集自动化）与建造 / 放置动词已落地。当前活跃专题为介质呈现层收尾（高机位视角修正轮），属"不重选介质、只校准口径"性质，与本文结论一致。

### 4.2 仍未证明的产品承诺

- 化工生产本身是否有趣（采集自动化只是第一步，尚无"转化"）；
- 基地是否实际改变冒险能力；外出是否存在风险和选择；
- 角色或基地是否有肉眼可见成长；20-40 分钟体验是否形成节奏。

已证明"游戏能运行"，尚未完全证明"这个游戏为什么值得玩"。

### 4.3 主要风险

1. 旧代码约 8.2 万行对新主干的心理和架构引力；
2. 文档、检查和基础设施再次跑到玩家体验前面；
3. 因优秀 AI 3D Demo 重新否定已通过证据的像素介质；
4. 下一专题若优先纯立绘对话，只加包装、不证明核心玩法；
5. 直接做自由建造、通用背包、完整配方或通用战斗会再次范围膨胀；
6. 晶体簇与采集器以场景节点名 / 简单键作持久化身份，适合当前切片，不适合长期建造和动态实体基础（采集器已是动态实体，扩展前应复查）。

## 五、推荐专题顺序（按仓库现状修订）

原对话的"专题 0：存档收口"已完成；采集建造包超前完成了化工链第一步。修订后的顺序：

```text
视角修正轮收口（当前活跃）
→ 第一次工业转化（配方加工：原料经设备加工产出改变世界的产物）
→ 第一次冒险压力与成长
→ 最小叙事、音效和表现收口
→ 20-40 分钟切片里程碑复核
→ 再决定旧系统清理与长期扩展
```

### 5.1 第一次工业转化

下一玩家功能专题不建议是纯立绘对话或自由建造，而是一条固定工业转化链：

```text
采集污染晶体 → 投入反应器 / 工作台 → 一次可见加工
→ 产出滤芯或缓冲剂 → 安装到目标设备 → 污染区发生明显变化
```

只需要：一种原料、一种中间产品、一台加工设备、一个安装目标、一次明确的世界变化。不需要：通用背包、多级配方树、自由物流、流体模拟、通用建造模式、设备参数面板。

需要证明的是：玩家在野外带回的东西，经基地加工后，确实改变了下一次外出的条件。

### 5.2 第一次冒险压力与成长

在现有晶体区加入一种压力即可：一个污染爬虫、一块持续消耗防护的区域、或一个只能短暂停留的高污染采集点。第一次进入只能撤退；完成过滤设备 / 抗性产物后能停留更久、进入更深、取得下一阶段资源。形成第一次产品闭环：

```text
冒险遇阻 → 回基地加工 → 获得能力 → 再次出发 → 突破阻碍
```

不需要通用战斗框架、技能树或复杂伤害类型，只证明一次成长能改变冒险结果。

### 5.3 最小叙事与表现收口

已有值得解释的玩法后，再接入最小立绘对话、任务起止节拍、高频动作音效（采集 / 加工 / 安装 / 警告 / 完成）、状态灯粒子相机反馈、更正式的像素 HUD。叙事和 UI 解释并强化已存在的玩法，不代替玩法。

### 5.4 切片里程碑复核

按 20-40 分钟完成定义复核：无人指导能否完成；是否理解资源 / 基地 / 外出关系；十分钟内是否分别出现工程感、冒险感、成长感；是否存在明显无反馈时间；能否被朋友识别为"一款游戏"。通过后再决定旧系统清理、第二种资源、自由建造、更多敌人和完整工业物流。

## 六、推荐的 20-40 分钟体验节拍

| 时间 | 玩家经历 | 主要证明 |
|---|---|---|
| 0-5 分钟 | 苏醒、认识基地、发现受损核心 | 世界目标和基地身份 |
| 5-10 分钟 | 前往晶体区采集，首次接触污染压力 | 外出与风险 |
| 10-15 分钟 | 返回修复核心，基地首次明显启动 | 工程反馈 |
| 15-22 分钟 | 加工晶体产出滤芯或缓冲剂 | 第一次工业转化 |
| 22-30 分钟 | 安装设备，污染下降或抗性提升 | 基地反哺冒险 |
| 30-36 分钟 | 再次远征，突破此前无法通过的位置 | 成长改变结果 |
| 36-40 分钟 | 带回催化样本，开启下一阶段 | 切片收束与未来承诺 |

现有地图足够承载这段体验。优先让同一地点随污染、设备、资源和任务状态变化，而不是增加第三个区域。

## 七、设计原则

- 一次状态变化，至少三种反馈：世界反馈（换态 / 状态灯 / 污染退散）+ HUD 反馈（资源 / 目标 / 解锁）+ 感官反馈（音效 / 粒子 / 短暂相机冲击）。
- 先做可信错觉，不做完整工业仿真：首版化工设备统一"输入 + 处理时间 + 一项关键条件 + 输出 + 一项副作用"；先让玩家看到生产线改变冒险条件，再扩展温度、压力、纯度和物流。
- 玩家动词优先于通用系统：每个新模块回答"玩家新增什么动作、世界发生什么可见变化、下一步选择因此如何变化"；只增加字段、formatter、检查和接口的开发包应暂停评估。

## 八、工程与架构建议

- 新切片是唯一增长主干：新功能沿 `client/scripts/slice/` 发展；旧系统只在出现明确需求时提取概念、数据或算法，不整套复活旧 `GameRoot`、旧 HUD、旧任务链，不强迫新切片适配旧接口。
- 控制 `SliceWorld` 职责：适合作状态权威源和编排者，不应承载具体加工、战斗、危险区和任务实现。按真实需求增加小职责节点（如设备加工、污染压力、目标节拍、反馈演出）；只有出现第二种真实需求时才抽象通用接口，不提前建 Manager / Service 层级。
- 持久化身份：节点名作存档 ID 在当前切片可接受；进入自由建造、动态生成资源、可移动设备、多地图或同类实体重复实例化之前，应升级为显式 `persistent_id`、稳定网格坐标或"场景 ID + 实体 ID"结构化键。采集器已是动态实体，相关扩展开工前先复查其存档键。
- 测试真实玩家路径：优先保留强集成路径（新档采集修复自动保存；重启读档一致；加工安装改变污染；远征失败 → 升级 → 远征成功），真实闭环断言比大量"字符串 / 节点存在性"检查更能证明产品状态。
- 控制新主干规模：完整切片成立前建议约 3000-5000 行量级——这是防吞没警戒线而非硬指标，当前主干远低于此线，无需现在设限，核心是不以复用旧系统快速堆表面功能。

## 九、美术、UI 与音频

- 保持当前像素介质：固定网格、调色板、光向和相机口径继续作为生产真相源；不恢复程序绘制视觉层，程序绘制只用于规则允许的动态高亮、状态灯、选中描边和调试辅助。
- 提前加入低成本声音与动态反馈：优先补齐高频动作音效（采集、拾取、设备启动、加工完成、安装成功、污染警告、UI 确认与错误）。声音和短特效能显著增加"这是一款游戏"的感受，成本远低于新增系统。

## 十、关于是否重新考虑 3D

当前不建议主线切换：像素介质已通过重复生产证据；切片已形成可编辑世界和状态链；切换 3D 会重新打开角色、动画、导航、灯光和资产生产问题；当前最大未知不是介质，而是核心循环是否有趣。

未来若需重新评估，做一个不进主线的 2-3 天隔离实验（正交相机 + 低模角色 + 一台模块化设备 + 一簇资源 + 一次状态变化），比较的不是单张截图是否惊艳，而是：第二、第三台设备能否稳定生产；多状态是否易维护；布局是否易修改；比例是否稳定；同等时间是否比像素管线更快形成完整玩家路径。实验未明确胜出前不动主线介质与像素规范。

## 十一、继续做与暂时不做

继续做：固定设备的第一次工业加工；污染或单一敌人的第一次冒险压力；一次基地升级改变外出结果；音效、粒子、状态灯和 HUD 反馈；少量真实玩家路径检查；实机截图、录像和朋友试玩证据。

暂时不做：主线转 3D；第三个区域或更大地图；自由建造；完整背包和多资源经济；通用任务框架；技能树；多种敌人和 Boss；通用化工仿真；联机、云存档、账号；大规模旧代码清理；只加包装不证明核心循环的独立立绘专题。

## 十二、最终结论

VOXELSKY 最值得学习的不是 Three.js、体素或 3D，而是四件事：

1. 选择能由结构化状态稳定产生画面的表现语法；
2. 用简单系统制造强烈、连续的玩家反馈；
3. 对不影响核心体验的复杂度主动造假和降级;
4. 先完成一条有开始、有阻碍、有成长、有结果的玩家路径。

当前像素切片已修复旧路线的信息结构根因。真正需要证明的是：

> 玩家从危险区域带回资源，经基地加工获得新能力，再回到危险区域突破原来的阻碍——这个循环能否在 20-40 分钟内产生工程感、冒险感和成长感。

在此产品证明完成前：不重新选择介质，不扩地图，不建设完整通用系统，不让文档和检查替代玩家可感知的进度。
