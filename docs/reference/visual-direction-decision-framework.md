# Visual Direction Decision Framework

更新时间：2026-08-09

状态：**视觉路线复盘、目标稿与实现开工的长期判断框架。**

## 用途

本文用于纠正视觉开发中“看到局部症状就开始调色”的惯性，同时避免用一套固定色值、固定构图或外部作品复刻要求压死探索空间。

它不替代 [Visual And UI Direction](../product/visual-and-ui-direction.md) 的气质结论，也不替代 [Pixel Art And Grid Standard](pixel-art-and-grid-standard.md) 的机械口径。本文只回答三件事：

1. 视觉问题应按什么顺序归因。
2. 哪些结果必须锁定，哪些方案允许探索。
3. 什么证据足以让目标稿进入实现。

## 当前路线结论

第一可玩切片的目标画面必须同时组织五个可读层：

```text
异星环境
→ 工业平台与基础设施
→ 设备家族
→ 物流 / 供电 / 端口网络
→ HUD 与操作面板前景
```

玩家应先理解自己处在什么现场、设备如何组成生产关系、当前能做什么，再感知具体配色和装饰风格。单独让地表变亮、设备变浅或面板换色，都不能替代上述系统关系。

## 归因与决策顺序

每次视觉开发必须依次回答，前一层未成立时不得用后一层掩盖：

1. **玩家结果：**玩家要看到、做出和理解什么？成功发生在哪个瞬间？
2. **场景组织：**角色、移动通道、战斗视线、设备组和环境边界是否形成明确构图？
3. **系统连接：**平台、物流、供电、端口、输入与输出是否在空间中可读？
4. **资产家族：**地表、基础设施、各类设备是否共享比例、材质、光向和工业类型学？
5. **UI 结构：**信息是否按物品、流程、状态、操作和结果组织，而不是按大段文字和表单容器组织？
6. **色彩数值：**色相、明度、饱和度和透明度是否强化前五层？
7. **装饰：**磨损、纹样、灯光和动效是否增加气质且不抢读法？

不得从十六进制色值、透明度、亮度中位数或边框粗细开始定义路线。局部症状不能直接触发全局换色；数值只能证明某项约束被满足，不能单独证明观感正确。

## 硬边界与探索空间

### 必须锁定的硬边界

- 世界层保持固定网格像素资产，32px 网格、960×540 虚拟画面、高斜角俯视和左上光不变。
- 已通过的玩家结果、权威库存、生产守恒与存档兼容仍是运行基线。视觉目标若要求改变端口、设施朝向或旋转语义，必须先记录为架构迁移目标；在独立实现和验证完成前，不得把目标稿描述成现行功能。
- 前哨核心与化工反应器是两台独立设备：核心承担修复、仓储、首次充能和样本交付，反应器承担晶体加工与催化剂产出；两者必须拥有不同剪影、各自完整且明显的设施基座和明确空间间隔，禁止共用壳体、共用基座、合并成一台机器或以附属模块读法相连。
- 设备资产的判断单位不是悬空机身，而是“设备本体 + 自有基座 + 占地边缘可接物流接口”。核心必须表达可存入和流出多种物品的仓储 `IN / OUT`，反应器必须表达配方加工 `IN / OUT`；两者都有物流端口，但端口职责不能混同。
- 大型设施主体固定正面朝向玩家，不再用四张整机方向帧改变设备正面；传送带等方向性网络构件仍可旋转。大型设施统一左侧输入、右侧输出；多个真实通道只能在对应侧扩展，不在前 / 后侧补装饰口或四向假接口。
- 设施端口使用中性深色停靠口，方向标记直接嵌入口内，以连续两到三个同向 `》` 形像素楔纹表达流向；不使用箭杆、基座顶面贴花或文字。滚轮与运动方向只属于外接传送带，颜色只作语义冗余。
- 当前客户端已通过 schema 8 完成固定正面设施、显式运行时端点与旧档方向迁移：核心和反应器统一左 `IN` / 右 `OUT`，采集器使用右 `OUT`，储物箱按模式启用单侧端口。后续视觉目标不得回退旋转耦合或伪造第二套端点；端点、拓扑和相邻接驳继续由运行态派生，不写入存档。
- 核心的主体中心轴必须在屏幕上稳定竖直并与世界网格朝向一致；高斜角俯视只影响可见顶面和基座深度，不能让主体质量向屏幕下方斜伸，读成倾倒或对角线设备。
- 反应器可以横向宽于核心，但不能贴平成基座上的面板；主腔体必须在自有基座上形成可读上盖、肩部、前侧壁和下部承重层，设备高度不能由扩大占地或加厚底板代替。
- 核心必须以竖直能量脊柱、开放式发光核心、悬臂服务层和负空间建立维修 / 仓储 / 充能 / 交付枢纽身份；反应器必须以横向承压反应腔、两端结构环、过程窗口和下部承重框建立加工身份。禁止用同一封闭箱体、储物柜立面或白盒加不同灯条区分二者。
- 世界设备的第一读法必须由工程白、浅暖灰或其他明亮壳面与平台建立；中灰承担侧壁，暗青 / 近黑只承担骨架、凹槽、下部结构和接地阴影，不得再次占据整机与基座的大多数连续表面。
- 世界目标稿必须在原生 `960×540` 尺度证明可读，并能由当前固定网格像素管线确定性复制；依赖预渲染 2.5D / 类 3D 体积、连续光照或超出原生像素密度的整屏生成图只能作为构图参考，不能通过 Gate A。
- 当问题包含资产家族、材质或比例时，单纯重排现有素材只能作为现状基线，不能充当目标稿；目标必须先用少量关键资产小样证明新答案，再进入整屏组合。
- 功能色继续表达通电 / 运行、交互 / 等待、危险 / 故障、污染和被动 / 禁用，并有文字、图标、形状或明度冗余。
- 主视觉不得退回程序色块、线框或脚本生成贴图；正式判断必须包含玩家可见实机证据。
- 基地构图必须保留角色移动、战斗和交互视线，不能为展示产线把画面填满。

### 允许探索的变量

- 具体冷暖关系、色相、饱和度和局部明度。
- 金属、岩地、污染、生物和界面表面的精确材质表达。
- 面板透明度、轮廓、倒角、纹样、局部发光和动效强度。
- 在玩法边界内的设备组构图、平台尺度、网络密度和 HUD 排布。

规范锁定玩家结果、失败判据、决策顺序和不可破坏的工程事实，不锁死具体审美答案。若两个方案都满足硬边界，应通过目标稿比较和人工判断选择，不新增更多规则强行消除选择。

## 开工前校正问题

视觉任务开工前至少回答：

1. 当前症状的根因位于七层顺序中的哪一层？
2. 是否正用可量化指标代替玩家观感？
3. 外部参考的效果是否依赖本项目尚未建立的空间网络、资产家族或 UI 结构？
4. 是否把一个局部问题扩成了全局换色、全资产重出或全界面改版？
5. 什么截图或人工反馈会推翻当前判断？

无法回答第 1 和第 5 问时，任务仍处于诊断阶段，不进入资产、Theme 或场景修改。

## 双目标稿门禁

恢复视觉实现前，先完成两个带版本号的 960×540 原生画面目标。目标稿可由现有素材重组、绘制或受控生成完成，但必须明确表达最终关系，不能只做情绪板。

### A：世界目标稿

必须同屏包含：

- 玩家、异星环境和可移动 / 可战斗通道。
- 前哨核心、采集器、中继、储物箱、传送带、化工反应器六类设备；核心与反应器必须是固定正面、相隔明确地面距离、各有独立明亮基座并统一左进右出的两台机器。仓储吞吐与加工流向必须由口内连续楔纹和实际连接关系读出。
- 工业平台、供电 / 物流 / 端口关系和局部状态反馈。
- 不遮挡主体的边缘 HUD。

### B：UI 目标稿

必须至少表达制造 / 背包与一种设备操作面板：

- 世界关系仍可感知，不被整页表单完全盖住。
- 物品、流程、状态、操作和结果形成结构，不靠长说明或重复卡片主导。
- 鼠标主路径、阻塞原因和真实功能色可读。

## 通过、失败与停手

目标稿通过需要同时满足：

- 五层画面关系和七层决策顺序可以从图中直接说明。
- 硬边界未被破坏，探索变量有明确取舍理由。
- 与项目自有失败证据相比，设备不再孤立、UI 不再是覆盖世界的大型表单。
- 萝卜SAMA确认它可以作为后续资产、场景和 UI 实现的共同目标。

以下任一情况应停手复盘：

- 连续两次只调整色值、透明度、亮度或边框，仍没有改善玩家读法。
- 目标稿无法同时容纳角色、网络、六类设备和关键 UI，只能靠文字解释缺失关系。
- 实现开始后才发现参考依赖另一套投影、网格、玩法或 UI 结构。
- 局部修复造成其他资产家族、功能色或世界关系漂移。
