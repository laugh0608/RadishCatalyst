# Visual Direction Decision Framework

更新时间：2026-07-31

状态：**视觉路线复盘、目标稿与实现开工的长期判断框架。**

## 用途

本文用于纠正视觉开发中“看到局部症状就开始调色”的惯性，同时避免用一套固定色值、固定构图或外部作品复刻要求压死探索空间。

它不替代 [Visual And UI Direction](../product/visual-and-ui-direction.md) 的气质结论，也不替代 [Pixel Art And Grid Standard](pixel-art-and-grid-standard.md) 的机械口径。本文只回答三件事：

1. 视觉问题应按什么顺序归因。
2. 哪些结果必须锁定，哪些方案允许探索。
3. 什么证据足以让目标稿进入实现。

## 当前路线结论

第一可玩切片的目标画面必须同时组织五个可读层：

```text
异星环境
→ 工业平台与基础设施
→ 设备家族
→ 物流 / 供电 / 端口网络
→ HUD 与操作面板前景
```

玩家应先理解自己处在什么现场、设备如何组成生产关系、当前能做什么，再感知具体配色和装饰风格。单独让地表变亮、设备变浅或面板换色，都不能替代上述系统关系。

## 归因与决策顺序

每次视觉开发必须依次回答，前一层未成立时不得用后一层掩盖：

1. **玩家结果：**玩家要看到、做出和理解什么？成功发生在哪个瞬间？
2. **场景组织：**角色、移动通道、战斗视线、设备组和环境边界是否形成明确构图？
3. **系统连接：**平台、物流、供电、端口、输入与输出是否在空间中可读？
4. **资产家族：**地表、基础设施、各类设备是否共享比例、材质、光向和工业类型学？
5. **UI 结构：**信息是否按物品、流程、状态、操作和结果组织，而不是按大段文字和表单容器组织？
6. **色彩数值：**色相、明度、饱和度和透明度是否强化前五层？
7. **装饰：**磨损、纹样、灯光和动效是否增加气质且不抢读法？

不得从十六进制色值、透明度、亮度中位数或边框粗细开始定义路线。局部症状不能直接触发全局换色；数值只能证明某项约束被满足，不能单独证明观感正确。

## 硬边界与探索空间

### 必须锁定的硬边界

- 世界层保持固定网格像素资产，32px 网格、960×540 虚拟画面、高斜角俯视和左上光不变。
- 已通过的玩家结果、schema、端口、足印、碰撞、旋转帧和权威状态不因视觉探索而改变。
- 功能色继续表达通电 / 运行、交互 / 等待、危险 / 故障、污染和被动 / 禁用，并有文字、图标、形状或明度冗余。
- 主视觉不得退回程序色块、线框或脚本生成贴图；正式判断必须包含玩家可见实机证据。
- 基地构图必须保留角色移动、战斗和交互视线，不能为展示产线把画面填满。

### 允许探索的变量

- 具体冷暖关系、色相、饱和度和局部明度。
- 金属、岩地、污染、生物和界面表面的精确材质表达。
- 面板透明度、轮廓、倒角、纹样、局部发光和动效强度。
- 在玩法边界内的设备组构图、平台尺度、网络密度和 HUD 排布。

规范锁定玩家结果、失败判据、决策顺序和不可破坏的工程事实，不锁死具体审美答案。若两个方案都满足硬边界，应通过目标稿比较和人工判断选择，不新增更多规则强行消除选择。

## 开工前校正问题

视觉任务开工前至少回答：

1. 当前症状的根因位于七层顺序中的哪一层？
2. 是否正用可量化指标代替玩家观感？
3. 外部参考的效果是否依赖本项目尚未建立的空间网络、资产家族或 UI 结构？
4. 是否把一个局部问题扩成了全局换色、全资产重出或全界面改版？
5. 什么截图或人工反馈会推翻当前判断？

无法回答第 1 和第 5 问时，任务仍处于诊断阶段，不进入资产、Theme 或场景修改。

## 双目标稿门禁

恢复视觉实现前，先完成两个带版本号的 960×540 原生画面目标。目标稿可由现有素材重组、绘制或受控生成完成，但必须明确表达最终关系，不能只做情绪板。

### A：世界目标稿

必须同屏包含：

- 玩家、异星环境和可移动 / 可战斗通道。
- 核心、采集器、中继、储物箱、传送带、反应器六类设备。
- 工业平台、供电 / 物流 / 端口关系和局部状态反馈。
- 不遮挡主体的边缘 HUD。

### B：UI 目标稿

必须至少表达制造 / 背包与一种设备操作面板：

- 世界关系仍可感知，不被整页表单完全盖住。
- 物品、流程、状态、操作和结果形成结构，不靠长说明或重复卡片主导。
- 鼠标主路径、阻塞原因和真实功能色可读。

## 通过、失败与停手

目标稿通过需要同时满足：

- 五层画面关系和七层决策顺序可以从图中直接说明。
- 硬边界未被破坏，探索变量有明确取舍理由。
- 与项目自有失败证据相比，设备不再孤立、UI 不再是覆盖世界的大型表单。
- 萝卜SAMA确认它可以作为后续资产、场景和 UI 实现的共同目标。

以下任一情况应停手复盘：

- 连续两次只调整色值、透明度、亮度或边框，仍没有改善玩家读法。
- 目标稿无法同时容纳角色、网络、六类设备和关键 UI，只能靠文字解释缺失关系。
- 实现开始后才发现参考依赖另一套投影、网格、玩法或 UI 结构。
- 局部修复造成其他资产家族、功能色或世界关系漂移。

复盘记录使用简表：

```text
问题 / 玩家结果：
根因层级：
锁定边界：
本轮探索变量：
成功与失败证据：
结论与下一步：
```
