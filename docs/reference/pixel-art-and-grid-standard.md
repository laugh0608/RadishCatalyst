# Pixel Art And Grid Standard

更新时间：2026-07-12

## 用途与地位

本文是 RadishCatalyst 美术介质的机械口径真相源：网格、分辨率、调色板、光向、尺寸与生产管线。所有专题、提示词和检查涉及“像素资产怎么做、怎么对齐、怎么算一致”时以本文为准。

气质与 UI 方向见 [Visual And UI Direction](../product/visual-and-ui-direction.md)；本文只定可度量参数，不重复气质描述。

介质方向由 2026-07-12 项目级复盘确认：由“写实 2.5D 整景”切换为“像素 + 2D 俯视网格”。切换理由、失败证据与第一目的见 [Project Purpose And Solo AI Development Review](../planning/project-purpose-and-solo-ai-development-review.md)。

## 为什么是像素网格

写实 2.5D 路线的一致性只能来自渲染器或资深画师整景绘制，二者都超出个人 + AI + 无美术预算的边界；单张生成图不可重复、不可装配。像素网格把“一致性”从主观审阅问题变成生产前锁定、可脚本强制的数据问题：

- 固定 tile 尺寸 + 限定调色板，可用脚本做缩放归一和色板量化。
- 非画师也能逐像素修补 AI 出稿，废图可修而非只能重掷。
- 像素 CC0 生态最厚，补位混用违和最低。
- 存在“低保真但成立”的市场档位，低保真是风格而非残次。

## 核心纪律（先于任何资产生产锁定）

参照 Factorio 的三条纪律，落到本项目：

1. 固定投影与网格先于一切资产：3/4 俯视立面、单一光向、统一 tile 单位。
2. 所有资产在约束内产出：出稿后必须能被脚本归一到网格与调色板。
3. 世界网格 = 玩法坐标 = 碰撞单位 = 构图坐标 = 资产尺寸基准，五者同源，不分别设计再对齐。

## 网格与分辨率

| 参数 | 口径 | 说明 |
| --- | --- | --- |
| 玩法网格 tile | 32px | 玩法与碰撞基准单位，定死 |
| 建筑 / 设备占位 | 2x2 起 | tile 是站几格，不是作画像素上限；96px+ 去画大设备 |
| 相机虚拟分辨率 | 960x540（已定稿） | 1080p 整数 2 倍；2026-07-15 证据轮以同批素材 A/B 对比 640x360 后由萝卜SAMA定档 |
| 放大方式 | 整数倍 | 虚拟画布整数放大到目标分辨率，禁止非整数缩放糊边 |

- tile 尺寸不决定细腻度；细腻度由虚拟分辨率与作画密度决定。
- 细腻度上限口径：停在“仍可人工点修、仍可脚本强制一致性”的档位，不追 HD 像素插画档。
- 虚拟分辨率档位已于 2026-07-15 定稿为 960x540：证据轮以同批定稿素材拼合 960x540（2 倍）与 640x360（3 倍）两版 1080p 取景并排对比，960x540 在视野、设备精致度和工厂一屏可读性上占优，640x360 使本批细密度素材发噪。相机与接入实现按本档执行。

## 精灵尺寸口径

以 32px tile 为基准；数值为游戏内目标像素高度，出稿可放大若干倍再由仓库侧归一。

| 类别 | 目标尺寸 | 说明 |
| --- | --- | --- |
| 地面 tile | 32px | 无缝可平铺；AI 源图归一为 128x128 的 4x4 宏块（16 个 32px tile），按宏块坐标整组铺放保留宏观纹理，不压成单 tile（2026-07-13 `S2` 复核确认，沿用 `R1` 宏块结论） |
| 玩家 | 48 到 64px 高 | 不绑 tile；越高越可表达细节 |
| 敌人（小型） | 48px | 单体 |
| 一般设备 | 64 到 96px | 反应器、储存、整备台、过滤器、采集器，占 2x2 / 3x3 |
| 前哨核心 | 96px | 受损 / 修复两态 |
| 核心稳定站 | 128px+ | 全场最大单体 |
| 资源 / 小件 | 16 到 48px | 晶体、残骸、道具 |
| 二次元立绘 | UI 层原生分辨率 | 只在对话 / 角色界面，不进世界层，不参与 tile 归一 |

## 调色板

世界层使用限定调色板，出稿后统一量化到该板。首颗星球标准色（沿用前期已验证的色域，改为像素量化口径）：

| 用途 | HEX |
| --- | --- |
| 浅暖砂岩地表 | `#A99572` |
| 岩缝 / 深阴影 | `#151C1E` |
| 平台暖灰中间调 | `#6F6B5E` |
| 金属结构中间调 | `#2E4145` |
| 金属高光 | `#4A6165` |
| 青色能量 / 状态 | `#56C8C4` |
| 晶体亮青 | `#7FD8E8` |
| 琥珀工业灯 | `#E0A43C` |
| 警示红（敌人 / 故障） | `#C7503F` |
| 污染黄绿 | `#B7B646` |

- 世界层像素资产收敛到本板；每颗星球可派生自己的地貌与污染色，但基地设备、UI、状态语义色跨星球保持一致。
- 立绘不受本板约束，但其画面出现的设备 / 图标语义色应与世界层呼应。

## 光向

- 全局单一光向：左上。所有设备、角色、建筑烘焙同一方向的明暗与接地阴影。
- 无 normal map，不接只会均匀增亮的动态 2D 光；场景整体色调由统一环境光与区域色调关系表达。

## 生产管线（AI 出稿 → 归一 → 人工点修）

分三段，人与 AI 职责分离：

1. AI 出稿：按提示词生成候选，分辨率放大若干倍，纯色深底或透明底。
2. 仓库侧归一（可脚本化）：整数缩放到目标尺寸、调色板量化、去底、对齐到 tile 网格。归一是像素一致性的机械保证环节，不可跳过。
3. 人工点修：萝卜SAMA选稿并逐像素修补接缝、剪影和状态灯。

- CC0 像素包可直接作为基底或补位，按同一归一环节并入；角色行走动画优先由像素素材包承担。
- 图像生成会话稳定性约束（单会话最多 3 张、生成与接入分离、立即复制到 art-intake 等）仍以 `CLAUDE.md` / `AGENTS.md` 为准。

## 介质证据轮（恢复实现前的唯一前置）

任何引擎实现前，先证明这条管线能稳定复制，而非做出一张偶然成功的图：

1. 锁定网格、调色板、光向（本文默认值）。
2. 第一屏：同屏内地形 + 3 台设备 + 角色 + 4 帧行走。
3. 重复性：第二、三屏（新设备与新地形变体），三屏并排无违和，不了解项目者能识别为一款游戏。
4. 立绘小样：1 个角色 x 3 表情差分的一致性验证。
5. 失败退出：同类两轮不成触发决策闸门，退向扁平几何风或 CC0 像素包基底。

## 参照系与差异化

- 星露谷：基地经营节奏与亲和力（其 tile 16px，本项目 32px 精度更高）。
- Factorio：网格与自动化纪律（其画面为预渲染 sprite，取纪律不取管线）。
- 银河破裂者：基地建设与 ARPG 战斗融合的循环（取玩法，不取 3D 画面）。
- CrossCode：像素世界 + 二次元对话立绘分层组合的成立范例。
- 差异化落点：异星化工题材、“基地服务冒险”循环、限定调色板的工业科幻现场感。
