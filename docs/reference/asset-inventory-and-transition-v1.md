## 引用边界与不能误判的关系

- `project.godot → scenes/boot/Boot.tscn → scripts/boot/boot.gd` 仍包含工厂与二维切片两条正式入口。`_start_slice()` 用 `SLICE_BASE_SCENE`，因此二维资源不是仅供归档。
- 同一 Boot 脚本的 `GAME_ROOT_SCENE / _start_game()` 保留冻结旧入口，注释说明菜单已不再通往它。常量仍存在不证明菜单可达；旧首屏 / GameRoot 候选要先梳理场景、检查与对照工具再退役。
- 正式工厂 `view.gd` 以 `ASSET_ROOT`、构件数组和 world 规则拼出 GLB 路径；设备预览有独立选择分支。替换须覆盖世界与预览，不只搜 `preload()`。
- 切片 `slice_building_catalog.gd` 拼接四向资产，`slice_conveyor.gd` 拼接转弯、合流、source / sink。脚本中缺少完整文件名不代表未用；报告保留候选族与拼接代码行号。
- 视觉样板 / Web server 仍读取旧呈现的角色、地板及像素模块；Theme 还会引用其他 `.tres` 和字体，调用方须追到资源链。

## 本轮核对结果

- 11 份清单：正式 3D 7、独立 Godot 对照 1、像素实验 3。76 条产物 SHA-256 与 35 条源文件 SHA-256 全匹配；含图标与对照副本，因此条数不等于独立文件数。
- 16 组逐字节相同资源：14 组正式 / 对照 GLB、1 组立绘锚点 / 运行立绘、1 组核心 / 设备 StyleBox。副本用途不同，哈希相同不是删除授权。
- 已核对 5 项当前复制来源：立绘，以及切片采集器、储物箱、中继、修复态核心。源图当前均存在且字节匹配；其他来源状态逐项记在报告，不凭老脚本名称宣称当前可重建。
- 字体当前 SHA-256 与其 README 一致，SIL OFL 1.1 文件保留。旧生成图、概念稿的原始输入 / 导出记录完整度不同，来源缺口需逐项补证；本轮不做全项目授权 / 可分发性背书。
- 27 个客户端 GLB 的头部 / JSON 元数据可读取，均无 `images` / `textures` / `normalTexture` 条目；这说明尚没有贴图细节生产链，不能通过提高面数就声称达到参考图质感。它不等于材质不存在，也不是完整 glTF 合规或画面验证。
- 本机 `assets/art-intake/` 180 个可见批次目录，2,102 文件、1,051,269,737 字节；其中混有原图、工具、截图与验证证据，仅盘元数据和已知源输入。`assets/third-party/` 本机只有 README，不能据此推断所有资产历史上都无外部来源。

## 代表场景的选材与缺口

| 对象 | 可复用输入 | 样板前需明确 |
| --- | --- | --- |
| 新唯一核心 | 现有正式 3D GLB 中无对应核心；旧二维核心只可追溯历史 | 需要新模型设计，不能以旧像素图充当新 6×6 核心或把足印候选当定稿 |
| 反应器 / G | 根目录正式反应器、refinement 独立反应器、energy G | 指定一种用于镜头对照；实验模型不直接覆盖正式同名资源 |
| 传送带 | 根目录 7 种 `belt-*.glb` | 保留方向 / 转弯组合、接地高度、接口和货物位置的可读性 |
| 角色 | `engineer.glb` | `Body` / `Limb0..3` 是视图绑定节点；精细角色替换另审比例 / 绑定，不只看外观 |
| 地表 | `yard.glb` 与现行场景组织 | 参考图地表层次 / 光照是新增制作任务；不直接引入旧整景图或外部资产包 |

## 替换与退役计划

| 顺序 | 交付 | 可进入下一步的条件 |
| --- | --- | --- |
| R0 本轮 | 归属 / 引用 / 来源 / 导出映射与机器清单；标注旧覆盖工具、源图缺口、重复文件语义 | 文件覆盖可复算；不改变资产或运行路径；未证来源明确列出 |
| R1 镜头 / 代表场景准备 | 选择一套核心、反应器、带、角色、地表候选；先确认俯角 / 投影 / 取景和正常尺度 | 获样板实施授权后，独立隔离验证；不提前量产全套模型 |
| R2 代表资产规范 | 从 R1 冻结单位 / 原点 / 足印 / 口 / 材质 / 光照 / 细节预算与命名 | 近身、密集产线、正常 / 最小窗口和性能证据可审阅 |
| R3 随功能替换 | 新核心先制；加工设备 / G / 带 / 角色 / 地表按实际功能包逐件替换 | 新旧世界读法与接口分别验证；来源、清单、导入和截图同步；旧功能资产不被无关替换影响 |
| R4 旧路线退役 | 先列完整引用与替代 / 保留入口，再提出搬迁或删除清单 | 旧世界保留策略明确，检查 / 样板 / 制作源均已处理，取得本批独立授权后才动文件 |

R1–R4 均是后续计划，本轮没有执行。旧首屏可成为“待退役候选”，保留二维仍属保留内容；没有任何资产被本轮标为“已可安全删除”。现有 `.import` / UID、GLB 内部节点、端口与材质子资源也需在未来替换时纳入，不能只改路径。

## 已知缺口与退出判断

1. 部分旧 PNG / 概念图没有版本库内逐文件生产清单；报告保留历史文档、工具候选或未知状态。要重新制作 / 分发时再补实际来源、变换和授权，不能拼一个猜测 lineage。
2. 七月 pack / L3 工具可能覆盖八月同名正式切片；L3-F 当前只输出忽略目录候选，不是现行采集器的发布入口。运行前必须明确目标资产与锁定源，详见来源映射。
3. 首批 14 GLB 有可追源和独立导出器，但导出器写独立样板目录；正式目录发布复制未发现单独的版本库自动入口。未来替换需补明确发布步骤，不能让正式代码读取 `tools/`。
4. 字面未命中、仅检查提及与动态候选均需人工收敛；本报告不计算完整可执行可达性，也未运行 Godot 验证。

本轮退出是盘点可复算、归属与风险可审阅、后续替换顺序明确；不要求把所有历史源缺口伪装成已解决。资产与客户端保持原样，下一步为 R1 样板范围 / 资产选择的设计准备。
