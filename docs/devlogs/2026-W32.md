## 关键决策

- 核心与反应器不仅逻辑职责不同，视觉上也必须使用不同剪影、独立占位、独立平台和明确间隔；它们只能通过电力、物流和地面网络建立系统关系，不能共壳或互为附属模块。
- 世界目标必须在原生 `960×540` 尺度证明可读并能由固定网格像素管线复制；整屏类 3D 生成图不能因构图好看而通过 Gate A。
- 现有素材拼装只能证明容纳关系，不能解决资产家族和材质目标；不追加 V4 摆位或调色，先做核心 / 反应器关键设备小样。
- 关键设备生成用角色作为固定尺度尺，并以单一变化迭代比例；达到 `3 / 3` 后停手，不把授权扩展到裁切、归一、整屏世界或 UI。
- 下一轮设备判断单位改为完整设施模组而非孤立机身：明亮大面先行，暗色退到骨架 / 凹槽；核心有独立枢纽基座和仓储 / 交付吞吐位，反应器有独立加工基座及相对两侧 `IN / OUT`。
- 首轮“剪影不共底座”判据不完整：禁止共享底座不等于允许没有底座。后续同时锁定“不可共享”和“每台必须自有”，物流接口也必须参与占地轮廓与连接，而非贴图装饰。
- 候选选择不按调用顺序：V3 若偏离单一修正或现有足印，即使视觉结构仍成立，也不自动覆盖约束更完整的 V2。
- 核心高斜角透视不能破坏屏幕竖直主体轴；反应器的设备高度必须由抬起的主腔体、上盖、肩部和前侧壁建立，不能靠等比放大整块基座解决。
- 第 3 轮继续按单一变量迭代：先证明轴向 / 高度，再补缺失输出口，最后收窄横向体量；后一次调用只有在前一张落盘和量测后才执行。
- 大型设施主体固定正面朝向玩家，传送带等方向性网络构件继续旋转；下一轮统一采用所有大型设施左侧输入、右侧输出，多个真实通道只在对应侧扩展。
- 设施停靠口采用中性深色结构，连续两到三个 `》` 形方向楔纹直接位于口内；不再使用基座顶面箭头、文字或设施自带滚轮，颜色只作冗余。
- 核心与反应器都有物流端口，但职责不同：核心是可存入和流出多种物品的仓储枢纽，反应器是固定配方加工设备。当前核心物流尚未实现，不能只画假箭头后宣称功能完成。
