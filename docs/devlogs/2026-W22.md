## 关键决策

- 首个装备 / 模块变量选择防护方向，不同时铺开战斗、探测和回收。
- 防护涂层先作为确定性整备模块，不进入完整装备栏，也不增加成长货币。
- 第二个装备 / 模块变量选择探测方向，但仍沿用同一前线窗口和行动台承接，不新增独立探测系统。
- 第三个装备 / 模块变量选择回收 / 补给方向，仍只改变行动台承接和下一轮资源判断，不新增资源 UI 或物流系统。
- 回基地收益优先体现在下一轮行动台判断和清障防护消耗回落，而不是新增孤立奖励。
- 压力清障的下一步不再继续加模块变量，而是先把已确认的高风险清障口径接到现有短战斗、任务和反击系统。
- 自动检查不能替代人工读法复核；本轮反馈说明关键计划 / 模块信息必须出现在玩家路径上的 HUD、日志和交互失败原因里。
- `S20` 人工短跑通过后，不继续围绕三类模块补同口径小提示；下一步把已归档模块收益收束成一个更危险的高压窗口目标，验证闭环最后一段。
- 高压窗口目标是三类模块收益的收束验证，不是第 4 个常规行动方案；完成后仍按原型边界收口。
- 个人开发阶段必须控制阶段粒度：达到足以判断方向的退出条件后及时进入下一阶段，不再用 `P2` / `P3` 细节、局部读法或状态字段洁癖拖住主线推进。
- 首版 demo 范围冻结为 12 个区域：当前算基地共 11 个区域，只允许再补 1 个关键区域；后续优先扩核心区域尺度、UI 可读性和 demo 主线终点，不继续横向堆区域。
- `region.locked_ruin_gate` 继续按门槛 / 路标处理，不作为本轮扩尺度区域；第 12 区域必须服务 demo 终点，不沿相位井继续追加同构断面。
- 区域命名优先保证玩家可读性；科技感和远古感通过“封锁遗迹、裂隙入口、相位井口、下沉井道、核心腔室、织相大厅、锁相框架、锚定桥”等显示名表达，现有 `region.*` ID 暂作为兼容层保留。
